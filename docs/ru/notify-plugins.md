# Плагины уведомлений

Плагины уведомлений отправляют события выпуска сертификатов, развёртывания, мониторинга и системные события в корпоративные IM, электронную почту или Webhook. При использовании в организации основное внимание уделяйте **маршрутизации оповещений, доступности каналов, ротации ключей и контролю шума**.

## 1. Встроенные и плагинные каналы

| Тип | Канал | Встроенный | Описание |
| --- | --- | --- | --- |
| Встроенный | Электронная почта (SMTP) | Да | Поддержка SSL; по умолчанию неявный TLS |
| Плагин | Gotify, ServerChan, ntfy | Нет | Собственные/сторонние push-уведомления |
| Плагин | Telegram, Bark, PushDeer | Нет | Push-уведомления на мобильные устройства |
| Плагин | DingTalk, WeCom робот/приложение/умный робот, Feishu | Нет | Корпоративные IM |
| Плагин | GoCQHTTP, iGot, PushPlus, WePlus, WxPusher, WxPusher SPT, OpenILink, WPush, Synology Chat, PushMe, ChronoCat | Нет | Другие каналы |
| Плагин | Универсальный пользовательский Webhook | Нет | Интеграция с внутренней платформой оповещений |

Если helper не установлен или не включён, на странице уведомлений будет только электронная почта; конфигурация прежних каналов не теряется и остаётся доступной после установки helper.

## 2. Конфигурация

```yaml
notify_plugins:
  enabled: true           # включено по умолчанию
  dir: ""                 # пусто означает <data_dir>/plugins/notify
  memory_limit_mb: 128    # верхний предел постоянной памяти одного helper
  timeout_seconds: 30     # тайм-аут одной отправки send
  max_output_kb: 64       # верхний предел вывода helper
```

Три типа плагинов используют отдельные подкаталоги в `<data_dir>/plugins`:

- DNS: `<data_dir>/plugins/dns`
- Развёртывание: `<data_dir>/plugins/deploy`
- Уведомления: `<data_dir>/plugins/notify`

Изменения конфигурации вступают в силу после перезапуска сервиса. При запуске выполняется автоматическое сканирование; после установки нового helper на странице «Плагины» можно нажать «Пересканировать плагины» или вызвать:

```bash
curl -X POST -H "Authorization: Bearer $LACTSSL_TOKEN" \
  https://ssl.example.com/api/plugins/rescan
```

## 3. Установка и включение

1. Откройте страницу «Плагины», проверьте адрес репозитория и нажмите «Обновить индекс».
2. В «Магазине плагинов» установите нужный канал уведомлений.
3. Сначала включите файл плагина, затем включите конкретный канал в списке каналов; новые загруженные файлы и записи по умолчанию отключены.
4. На странице «Уведомления» настройте учётные данные канала и отправьте тестовое сообщение.

Состояние включения хранится в таблице settings в `plugins.notify.enabled_channels` и сохраняется после перезапуска и повторного сканирования. Только включённые каналы отображаются на странице «Уведомления» и в узле уведомлений задачи.

Электронная почта не является плагином, всегда доступна и не может быть отключена.

## 4. Проектирование корпоративных оповещений

### 4.1 Маршрутизация

| Событие | Рекомендуемое назначение | Описание |
| --- | --- | --- |
| Сбой выпуска сертификата | Дежурная смена эксплуатации | Требует немедленного вмешательства, может повлиять на продление |
| Сбой развёртывания | Эксплуатация + ответственный за целевую систему | Проверьте целевую систему и команду перезагрузки |
| Приближение срока действия сертификата | Эксплуатация + ответственный за бизнес | Градация 30/14/7 дней |
| Аномалия мониторинга сайта | Эксплуатация | Различайте проблемы сети, цепочки, имени хоста |
| Сбой резервного копирования | Платформа | Отдельно от оповещений о сертификатах |
| Инцидент безопасности | Безопасность | Аномальный вход, сбой проверки плагина и т. п. |
| Тестовое сообщение | Отдельный тестовый канал | Не должно попадать в производственную дежурную группу |

### 4.2 Снижение шума

- Используйте разные каналы и группы для разных сред.
- В узле уведомлений задачи выбирайте «всегда/только успех/только ошибка», чтобы сообщения об успехе не заглушали ошибки.
- Для однотипных событий настройте агрегацию или окно молчания (реализуется внешней IM/платформой оповещений).
- Классифицируйте объекты мониторинга по важности для бизнеса, чтобы не отправлять частые оповещения по нестабильным целям.
- Регулярно удаляйте недействительные каналы и дублирующиеся конфигурации.

### 4.3 Доступность

- Настройте как минимум два независимых канала (например, электронная почта + корпоративный IM), чтобы избежать единой точки отказа.
- Регулярно отправляйте тестовые сообщения и убеждайтесь, что Token/Webhook не истёк.
- Следите за ограничениями скорости и модерацией контента у поставщика канала.
- Сбой уведомления записывается в журнал; рекомендуется также включить сбой уведомлений в мониторинг.

## 5. Управление учётными данными каналов

- Используйте выделенного робота/приложение, не используйте Token личной учётной записи.
- Предоставляйте только права, необходимые для отправки сообщений; не предоставляйте права управления организацией, чтения адресной книги и т. п.
- Используйте разных роботов для разных сред/команд.
- Фиксируйте ответственного за Token, время создания и период ротации.
- Учётные данные шифруются перед записью в базу данных; при возврате через интерфейс маскируются.
- Не записывайте Token, URL Webhook в имена задач, примечания или журналы.
- При утечке немедленно отзовите на стороне канала и обновите конфигурацию LACTSSL.

## 6. Электронная почта (SMTP)

- По умолчанию используется неявный TLS (`smtp.ssl=true`).
- При отключении неявного TLS, если SMTP-сервер не поддерживает STARTTLS, сервис откажется отправлять сообщение, чтобы избежать передачи конфиденциальных писем, таких как сброс токена, в открытом виде.
- Рекомендуется использовать корпоративный почтовый шлюз, выделенную учётную запись отправителя и SPF/DKIM/DMARC.
- Почта восстановления и учётная запись отправителя уведомлений должны быть раздельными, чтобы не влиять друг на друга.
- Для тестовых писем и производственных уведомлений используйте разных получателей.

## 7. Протокол Helper v1 (разработка интеграций)

helper — это исполняемый файл, поддерживающий две подкоманды:

```bash
notify-helper manifest   # вывести JSON-манифест
notify-helper send       # прочитать запрос из stdin и отправить уведомление
```

Пример вывода `manifest`:

```json
{
  "protocol": "v1",
  "name": "example notify helper",
  "version": "1.0.0",
  "sha256": "необязательная контрольная сумма файла helper",
  "channels": [
    {
      "id": "example-push",
      "name": "Example Push",
      "description": "Отправка уведомлений в сервис Example",
      "fields": [
        {"key": "url", "label": "Адрес сервиса", "type": "text", "required": true},
        {"key": "token", "label": "Token", "type": "password", "secret": true, "required": true}
      ]
    }
  ]
}
```

Описание полей:

- Поля с `secret: true` или `type: "password"` маскируются при возврате через интерфейс и хранятся в зашифрованном виде вместе с конфигурацией канала.
- Поддерживаемые типы полей: `text`, `password`, `textarea`, `number`, `select`, `switch`.
- ID канала `id` может содержать только строчные буквы, цифры, подчёркивания или дефисы; плагины с ID, совпадающим со встроенной почтой (`mail`), игнорируются.
- `label_key` необязателен; официальный интерфейс сначала локализует по ключу i18n; сторонние плагины могут указывать `label` напрямую.

stdin для `send`:

```json
{
  "action": "send",
  "protocol": "v1",
  "channel": "example-push",
  "config": {"url": "https://push.example.com", "token": "..."},
  "title": "Сертификат успешно выпущен: example.com",
  "body": "Задача: example.com\nСтатус: успех"
}
```

Соглашения:

- Код выхода `0` означает успех, отличный от `0` — ошибку; stderr попадает в журнал уведомлений (чувствительные значения маскируются).
- stdout может быть пустым или содержать одну строку JSON: `{"ok": true, "message": "..."}`; если `ok` равен `false`, результат считается ошибкой.
- Некорректный JSON считается ошибкой; отладочные журналы записывайте в stderr.
- helper получает бюджет памяти из `LACTSSL_PLUGIN_MEMORY_LIMIT` (в байтах).
- Основная программа периодически проверяет `VmRSS` helper и при превышении `memory_limit_mb` завершает всю группу процессов и записывает ошибку.
- Основная программа передаёт только минимальный набор переменных окружения и не раскрывает серверные ключи.
- Файл плагина должен быть исполняемым и не должен допускать запись группой или другими пользователями; если `manifest.sha256` не пуст, выполняется проверка.
- Основная программа записывает дайджест файла при сканировании и повторно проверяет его перед каждой отправкой; после замены helper требуется повторное сканирование.

## 8. Рекомендации по безопасности

- Включайте только доверенные helper; плагин уведомлений может читать ключи каналов и эквивалентен доверенному коду.
- Каталог плагинов `0700`, helper `0755`, владелец — пользователь, от имени которого работает сервис.
- В производственной среде указывайте `sha256` в манифесте и обновляйте дайджест после обновления.
- Устанавливайте разумные `memory_limit_mb` и `timeout_seconds`, чтобы аномальный плагин не замедлил отправку уведомлений.
- Содержимое уведомлений может включать домены, подробности ошибок и внутренние адреса; не отправляйте его в публичные каналы.
- Для цели Webhook используйте HTTPS и проверку подписи, чтобы предотвратить подделку и повторное воспроизведение.

## 9. Устранение неполадок

| Симптом | Причина | Действие |
| --- | --- | --- |
| На странице уведомлений только почта | Плагин уведомлений не установлен/не включён | Установите и включите плагин notify |
| Канал отсутствует в узле задачи | Канал не включён | Включите на странице плагинов и странице уведомлений |
| Сбой тестового сообщения | Token/URL/сеть | Проверьте конфигурацию канала и исходящую политику |
| Сбой отправки почты | SMTP TLS/аутентификация/отправитель | Проверьте неявный TLS, STARTTLS, SPF/DKIM |
| Задержка уведомления | Ограничение скорости канала/сеть | Проверьте состояние канала и журналы |
| В уведомлении конфиденциальная информация | Недостаточное маскирование шаблона/журнала | Измените содержимое, не отправляйте учётные данные и закрытые ключи |

Дополнительные сведения об устранении неполадок см. в разделе [Мониторинг и устранение неполадок](troubleshooting.md).
