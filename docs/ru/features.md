# Возможности продукта

Эта статья описывает по бизнес-возможностям, что умеет LACTSSL, ключевые параметры и ограничения, что удобно для проектирования решения и приёмки. Конкретные шаги операций распределены по разделам [Быстрый старт и ввод в эксплуатацию](getting-started.md), [Рабочая консоль управления](administration.md) и [Интеграция API](api.md).

## Карта возможностей

| Область возможностей | Основное содержание | Типичные пользователи |
| --- | --- | --- |
| Сертификатные активы | Заявки в публичный CA, автоматическое продление, сведения о сертификатах и очистка | Платформа/эксплуатация |
| Оркестрация задач | Обычный процесс: заявка → развёртывание (может быть несколько) → уведомление; целевой процесс Beta: чтение сайтов → группировка сертификатов → заявка → развёртывание | Платформа/эксплуатация |
| Доставка сертификатов | Локальный каталог, SSH/SFTP, FTP, Webhook, облачные CDN, панели | Платформа/эксплуатация, бизнес-системы |

| Мониторинг и оповещения | Мониторинг сертификатов внешних сайтов, уведомления о задачах/развёртывании | Эксплуатация, дежурство |
| Аудит и восстановление | Журнал операций, системный журнал, зашифрованные резервные копии | Безопасность, аудит, эксплуатация |

## 1. Заявка и продление сертификатов

### 1.1 Способы проверки

- Заявки в публичный CA используют только проверку **DNS-01**, поддерживаются сертификаты на один домен, несколько доменов и подстановочные.
- Для DNS-01 нужно настроить учётные данные API провайдера в «Учётные записи DNS»; при выполнении задачи TXT-записи создаются и очищаются автоматически.
- Выдача частным CA не проходит проверку ACME, система выдаёт сертификат напрямую.
- Встроенный сервер ACME поддерживает HTTP-01, DNS-01, TLS-ALPN-01 для внутренних клиентов.

### 1.2 Встроенные удостоверяющие центры

| CA | Пояснение |
| --- | --- |
| Let's Encrypt | Публичный CA по умолчанию, EAB не нужен |
| ZeroSSL | Требуется EAB |
| Google Trust Services | Требуется EAB |
| LiteSSL | Требуется EAB |
| ZoTrus | Требуется EAB; KID — зарегистрированная почта. Используется ручная DNS-проверка; подстановочные сертификаты не поддерживаются |
| Actalis | Требуется EAB |
| SSL.com | Требуется EAB; эндпоинт ECDSA/RSA выбирается по типу ключа |

В «Публичных CA» также можно добавить несколько **универсальных ACME-апстримов**:

- Настройка адреса каталога ACME, версии протокола ACME v1/v2 и необязательного EAB.
- Универсальные апстримы появляются в списке выбора задач и CA по умолчанию.
- Пользовательский адрес каталога должен использовать HTTPS; HTTP разрешён только для loopback на локальной машине.
- ACME v1 поддерживает только DNS-01 и не поддерживает EAB.

### 1.3 Ключи и продление

- Типы закрытых ключей: `ecdsa` (по умолчанию), `ecdsa384`, `rsa2048`, `rsa4096`.
- Автоматическое продление по умолчанию срабатывает за 30 дней до истечения срока, можно настроить для каждой задачи.
- В узле запроса можно включить «Не хранить закрытый ключ сертификата на сервере»: ключ хранится только в памяти во время выпуска и развёртывания, не записывается в базу данных и недоступен для скачивания. При автопродлении сертификат выпускается и развёртывается заново; в стандартном сценарии нужен хотя бы один включённый узел развёртывания.
- Фоновый планировщик проверяет задачи каждые 30 секунд.
- Причина сбоя задачи видна в журнале задачи; для проблем с учётными данными, доменами и CA выдаются понятные ошибки.
- Страница управления сертификатами поддерживает поиск, фильтрацию по статусу и источнику (выпуск по задаче, ACME-сервер, запрос CSR), сведения и анализ безопасности.
- Скачивание цепочки сертификатов, просмотр или скачивание закрытого ключа зависят от сеанса входа; для скачивания цепочки через API требуется `certificates:read`, для просмотра или скачивания закрытого ключа дополнительно требуется `certificates:key`.
- Очистка одним нажатием может фильтровать по статусу (просроченные, отозванные или все), длительности, времени выдачи, домену, удостоверяющему центру, источнику и «сохранить последний сертификат каждой задачи»; после очистки ссылки на сертификаты в соответствующих задачах очищаются.

### 1.4 Конфигурация по умолчанию

«Публичные CA» поддерживает настройку:

- Почта учётной записи ACME.
- CA по умолчанию.
- Тип закрытого ключа по умолчанию.
- Количество дней продления по умолчанию.
- Учётные данные EAB для каждого CA.

### 1.5 Целевой процесс Beta

Целевой процесс Beta подходит для сценария «сертификат следует за сайтом панели»: сначала через возможность `plan` плагина развёртывания считываются реальные сайты и привязанные домены в цели, затем сертификаты запрашиваются с группировкой по стратегии и, наконец, развёртываются обратно на соответствующие сайты.

- На странице задач вкладки «Все / Обычный процесс / Целевой процесс Beta» разделяют два процесса, диалоги создания/редактирования также используют тот же переключатель сегментов.
- Поддерживается несколько источников сайтов; список сайтов берётся из целевой системы и не зависит от ручного ввода имён сайтов.
- Стратегии распределения сертификатов:
  - Умная рекомендация: автоматический выбор по количеству сайтов, количеству доменов и распределению основных доменов.
  - Один сертификат на сайт.
  - Объединение по основному домену.
  - Объединить все выбранные сайты в один сертификат.
  - Один сертификат на каждый целевой источник.
  - Пользовательская группировка: вручную объединить произвольные сайты в одну группу сертификатов.
- Поддерживается выбор сайтов, правила включения/исключения доменов, добавление дополнительных доменов.
- При автоматическом продлении целевые сайты считываются заново: режим «Все сайты» автоматически включает новые сайты, режим «Только выбранные сайты» сохраняет только сохранённые стабильные ключи сайтов.
- Одна задача Beta может быть связана с несколькими сертификатами; `certificates.task_id` сохраняет все сертификаты, список задач отображает сводку сайтов/групп сертификатов.
- Если при очистке одним нажатием включено «сохранить последний сертификат каждой задачи», сертификаты задач Beta не очищаются, чтобы не удалить по ошибке другие группы сертификатов той же задачи.

### 1.6 Заявка CSR с клиента

- API поддерживает отправку CSR клиентом; сервер как промежуточное звено выполняет проверку DNS-01 в публичном CA и выдаёт сертификат.
- Сервер не создаёт и не сохраняет закрытые ключи; сертификат привязывается к открытому ключу из CSR клиента, закрытый ключ всегда остаётся у клиента.
- Заявка выполняется асинхронно, можно запросить статус, отменить, повторить и скачать цепочку сертификатов по номеру заявки.
- Поддерживаются только публичные CA ACME v2 и DNS-01; для подстановочных сертификатов обязательно используется DNS-01.
- Требуется новое право API-ключа `certificates:request`, можно ограничить домены для заявок через `csr.allowed_domains`.

## 2. DNS-провайдеры

DNS-провайдеры предоставляются DNS-плагинами. Основная программа не содержит встроенных провайдеров; список провайдеров появляется только после установки и включения плагина.

Распространённые провайдеры и учётные данные:

| Провайдер | Основные учётные данные |
| --- | --- |
| Alibaba Cloud DNS (alidns) | AccessKey ID / Secret, опционально Region |
| Alibaba Cloud ESA (aliesa) | AccessKey ID / Secret, опционально Region |
| Cloudflare | API Token или Email + Global API Key, опционально адрес API-апстрима |
| DNSPod | API Token |
| Tencent Cloud (tencentcloud) | SecretId / SecretKey, опционально Region |
| Huawei Cloud (huaweicloud) | AccessKey ID / SecretAccessKey / Region |
| Volcano Engine (volcengine) | AccessKey / SecretKey, опционально Region, хост API и протокол |
| AWS Route 53 | AccessKey / SecretAccessKey, опционально Region, Hosted Zone, частная зона |
| Google Cloud DNS | JSON сервисной учётной записи, опционально ID проекта |
| Azure DNS | Tenant ID / Client ID / Client Secret / Subscription ID / группа ресурсов |
| West.cn (westcn) | Имя пользователя / пароль |
| PowerDNS (pdns) | Адрес API / API Key, опционально имя сервера и версия API |
| RFC 2136 динамическое обновление | DNS-сервер, опционально TSIG Key / Secret / алгоритм и список зон |

- После установки официального DNS-плагина поддерживаются все провайдеры lego (около 190).
- Провайдер `manual` требует ручного добавления TXT-записей и не входит в автоматический процесс.
- Учётные данные шифруются перед записью в базу данных; при редактировании пустое поле ключа означает сохранение прежнего значения.
- Cloudflare, DNSimple, PowerDNS, Volcano Engine и другие поддерживают пользовательский адрес API-апстрима, который можно использовать для прокси, собственных служб или совместимых шлюзов.
- Полный список провайдеров определяется выпадающим списком провайдеров на странице «Учётные записи DNS».

Установка плагинов, офлайн-зеркала и управление цепочкой поставок см. в разделах [Управление плагинами](plugins.md) и [DNS-плагины](dns-plugins.md).

## 3. Оркестрация задач

Задача состоит из узлов, процесс по умолчанию — «заявка → развёртывание (может быть несколько) → уведомление».

| Узел | Ключевые параметры |
| --- | --- |
| Заявка | Домен, учётная запись DNS, CA, тип закрытого ключа, автоматическое продление, количество дней заранее |
| Развёртывание | Учётные данные цели, путь к сертификату/закрытому ключу, сайт/домен/имя сертификата, команда перезагрузки |
| Уведомление | Канал, момент срабатывания (всегда / только успех / только сбой) |

Ключевые моменты:

- Узлы можно включать/отключать и упорядочивать; задача может содержать несколько узлов развёртывания, доставляя один сертификат на несколько целей.
- Если в старых задачах нет явного процесса, система выводит эквивалентный процесс по исходным полям домена, учётных данных цели и т. п.
- При обновлении пути развёртывания, сайты и домены из старых учётных данных переносятся в узлы развёртывания задачи, затем параметры развёртывания очищаются из учётных данных.
- Список задач поддерживает выбор всех и множественный выбор в заголовке таблицы, позволяет массово выполнять, приостанавливать или запускать автоматическое продление.
- Массовое выполнение пропускает выполняющиеся задачи; массовое включение/отключение только изменяет состояние планирования и не прерывает уже начатую выдачу.
- Перед выполнением повторно используется сертификат того же домена, всё ещё действительный и не вошедший в окно продления, выполняется только развёртывание; если нужно перевыпустить, используйте «Принудительный перевыпуск» или API `?force=1`. При ограничении частоты вышестоящего CA задача переходит в «Ожидание из-за ограничения частоты» и повторяется по времени восстановления, указанному CA, а не как обычный сбой каждые 6 часов.

## 4. Развёртывание сертификатов

«Учётные данные цели» хранят только информацию аутентификации и подключения; путь к сертификату, команда перезагрузки, домен развёртывания, сайт и другие параметры заполняются в узле развёртывания задачи. Поэтому одни и те же учётные данные могут использоваться несколькими задачами.

### 4.1 Встроенные цели

| Цель | Учётные данные | Параметры развёртывания |
| --- | --- | --- |
| Локальный каталог | Нет | Путь к сертификату/закрытому ключу, необязательная команда перезагрузки |
| SSH / SFTP | Хост, порт, имя пользователя, пароль или закрытый ключ, отпечаток хоста | Удалённый путь к сертификату/закрытому ключу, необязательная удалённая команда перезагрузки |

SSH по умолчанию требует указать отпечаток целевого хоста (`SHA256:...`). Только при явном включении «автоматически доверять ключу хоста при первом подключении» используется запись TOFU; при последующем несовпадении отпечатка подключение отклоняется.

### 4.2 Цели плагинов

Следующие цели предоставляются плагинами развёртывания и доступны после установки и включения:

- FTP / FTPS: поддержка обычного FTP, явного TLS, неявного TLS.
- Webhook: адрес обратного вызова, пользовательские заголовки аутентификации, пропускать ли проверку TLS.
- Alibaba Cloud CDN, Qiniu Cloud, панель BaoTa, 1Panel, SafeLine WAF и другие.
- Конкретные продукты и параметры выбираются в «Объект развёртывания» узла развёртывания задачи.

Плагины развёртывания получают сертификат и закрытый ключ и эквивалентны доверенному коду, по умолчанию отключены. Без установленных плагинов отображаются только локальные файлы и SSH; исторические учётные данные сохраняются.

### 4.3 Цепочка доверия внутреннего CA

«Системные настройки → Цепочка доверия TLS» позволяет импортировать открытые ключи внутренних CA (PEM, может одновременно содержать корневой CA и подчинённые CA). После импорта:

- При доступе плагинов целей учётных данных к внутренним HTTPS-службам проверка TLS выполняется с использованием системных корневых сертификатов плюс импортированных CA, без необходимости пропускать проверку.
- Мониторинг сертификатов доверяет сертификатам сайтов, выданным этими CA; сертификаты частного CA этой программы автоматически добавляются в цепочку доверия.
- Развёртывание, команды перезагрузки и дочерние процессы плагинов читают цепочку доверия через объединённый `SSL_CERT_FILE`, также поддерживаются `CURL_CA_BUNDLE` и `REQUESTS_CA_BUNDLE`.
- Файл цепочки доверия сохраняется в каталоге данных как `trusted-ca-bundle.pem`, его также можно скачать на странице настроек.

Импортировать следует только действительно контролируемые внутренние CA; ошибочный CA ослабит проверку TLS. После удаления CA цели, использующие выданные им сертификаты, снова станут недоверенными. Импорт CA решает только проблему «сертификат не доверен»; если сертификат просрочен, ещё не вступил в силу или не соответствует домену/IP, всё равно нужно обновить сертификат или использовать соответствующий адрес.

### 4.4 Записи о развёртывании

- Каждое развёртывание создаёт запись, результат можно увидеть в сведениях о сертификате и журналах.
- Ручное развёртывание в первую очередь повторно использует параметры узла развёртывания задачи, к которой относится сертификат, также можно заполнить параметры отдельно для цели.
- Локальное/SSH-развёртывание выполняет команду перезагрузки, для запуска API-ключ должен явно иметь `deploy:execute`.
- При сбое развёртывания старый сертификат в целевой системе не откатывается автоматически; нужно сохранять предыдущую версию файлов на целевой стороне или использовать механизм атомарной публикации.

## 5. Мониторинг сертификатов сайтов

После добавления внешнего сайта служба периодически считывает сертификат через TLS-подключение:

- Цель поддерживает `example.com`, `example.com:8443` или полный URL, порт по умолчанию `443`.
- По умолчанию проверка раз в 24 часа, можно настроить для каждого элемента мониторинга.
- Проверяются имя хоста сертификата, издатель, срок действия и статус.
- Остаток менее 30 дней помечается как «скоро истекает»; просроченный, сбой подключения, недоверенная цепочка, неполная цепочка или несовпадение имени хоста помечаются как аномалия.
- При переходе статуса из нормального в «скоро истекает», «просрочен» или «аномалия» отправляется уведомление.
- Мониторинг проверяет системную цепочку доверия, чтобы промежуточный злоумышленник не скрыл реальные проблемы сертификата самоподписанным сертификатом; импортированные администратором внутренние CA и частные CA также включаются в цепочку доверия.

## 6. Уведомления

### 6.1 Встроенные каналы

- **Электронная почта (SMTP)**: сервер, порт, имя пользователя, пароль, отправитель, поддержка SSL.
- По умолчанию используется неявный TLS (`smtp.ssl=true`); при отключении неявного TLS, если сервер не поддерживает STARTTLS, служба откажется отправлять, чтобы избежать передачи токенов сброса и других конфиденциальных писем в открытом виде.

### 6.2 Каналы плагинов

Gotify, ServerChan, ntfy, GoCQHTTP, PushDeer, Bark, Telegram, DingTalk, робот WeCom, приложение WeCom, интеллектуальный робот WeCom, iGot, PushPlus, WePlus, WxPusher, WxPusher SPT, OpenILink, WPush, Synology Chat, Feishu, PushMe, ChronoCat, а также универсальный пользовательский Webhook.

- Каналы, кроме электронной почты, предоставляются плагинами уведомлений.
- Каналы можно включать отдельно и отправлять тестовые сообщения.
- Узел уведомления задачи может выбирать конкретный канал или использовать все включённые каналы.
- Момент срабатывания поддерживает «всегда», «только успех», «только сбой».

## 7. Частный CA

Управление внутренними удостоверяющими центрами выполняется в «Частный CA».

### 7.1 Создание

- Типы закрытых ключей: ECDSA P-256 / P-384, RSA 2048 / 4096.
- Срок действия задаётся по необходимости.
- Можно создать корневой CA или выбрать «Промежуточный/выдающий CA», чтобы существующий частный CA выдал подчинённый CA.
- При создании можно настроить полный набор полей X.509 и параметров PKI:
  - Субъект: ST, L, OU, Email, пользовательский серийный номер.
  - Расширения: длина пути, Key Usage, Extended Key Usage, SAN (DNS/IP), Name Constraints (разрешённые/исключённые DNS-домены и IP-подсети).
  - Инфраструктура: вышестоящий CA, точка распространения CRL, адрес ответа OCSP, адрес издателя CA, OID политики сертификатов и адрес CPS.
- SKI, AKI и базовые ограничения CA генерируются системой автоматически.
- При выборе вышестоящего CA срок действия и длина пути автоматически ограничиваются допустимым диапазоном вышестоящего CA.

### 7.2 Импорт

- Вставьте сертификат CA и закрытый ключ в формате PEM.
- Проверяются базовые ограничения CA, назначение подписи сертификата, соответствие сертификата и закрытого ключа.
- При импорте промежуточного CA можно выбрать вышестоящий CA, система проверит подпись и установит иерархическую связь.

### 7.3 Скачивание и удаление

- Можно скачать сертификат CA, закрытый ключ или полную цепочку сертификатов (промежуточный CA + цепочка вышестоящего CA).
- Интерфейс списка не возвращает содержимое сертификата или закрытого ключа; для скачивания закрытого ключа требуется `private_cas:key`.
- Удаление удаляет запись CA и закрытый ключ, сохранённые на сервере; при наличии подчинённых CA сначала нужно удалить их.

### 7.4 Ограничения

- Закрытые ключи частного CA шифруются перед записью в базу данных, но это не HSM/KMS.
- Корневой CA и промежуточный/выдающий CA могут использоваться как орган выдачи в «Заявке на сертификат»; полная цепочка сертификатов сохраняется и развёртывается вместе с сертификатом.
- Срок действия сертификата по умолчанию 365 дней и не превышает срок действия CA.
- Адреса распространения CRL/OCSP записываются в новые сертификаты, но фактические списки отзыва и службы онлайн-статуса должны предоставляться внешней инфраструктурой PKI.
- Существующие сертификаты не получают расширения CDP/AIA автоматически, требуется перевыпуск.

## 8. Сервер ACME

Встроенный сервер ACME v2 включён по умолчанию и позволяет открыть частный CA клиентам certbot, lego, acme.sh и другим. Если конечная точка не создана и не включена, сертификаты не выдаются.

### 8.1 Конечные точки

- Каждая конечная точка привязана к одному частному CA.
- Используется случайный URL slug, например `/acme/internal/directory`.
- Поддерживаются переключатель EAB, белый список доменов, переключатели возможностей HTTP-01 / DNS-01 / TLS-ALPN-01.
- Возможен отдельный порт прослушивания, поддержка прямого TLS и опционального mTLS.
- Можно настроить срок действия сертификата, ограничение частоты заказов и белый список CIDR внутренней сети для HTTP-01.

### 8.2 Возможности протокола

- Учётная запись хранит только открытый ключ, закрытый ключ клиента не сохраняется.
- Поддерживается ротация ключа учётной записи (`keyChange`).
- Поддерживаются рекомендации по продлению ARI (RFC 9773): по умолчанию окно продления предоставляется примерно за 1/3 срока жизни до истечения сертификата (не более 30 дней); для отозванных или просроченных сертификатов возвращается прошлое окно, чтобы указать на немедленное продление.
- Поддерживается поле ARI `replaces`: новый заказ может объявить заменяемый старый сертификат, сервер проверяет принадлежность старого сертификата, пересечение идентификаторов и повторную замену.
- Поддерживаются идентификаторы DNS и IP; для IP-идентификаторов разрешены только HTTP-01 / TLS-ALPN-01 и требуется настроить белый список IP-подсетей.
- Для новых сертификатов записываются расширения CRL Distribution Point и OCSP AIA, статус отзыва можно проверить через `/pki/{ca}/crl` и `/pki/{ca}/ocsp`.
- Частный CA должен иметь назначение `cRLSign`; это проверяется при включении конечной точки ACME.

### 8.3 Диагностика и очистка

- На странице «Диагностика ACME» можно просмотреть состояние учётных записей, заказов, авторизаций, проверок и сертификатов.
- Поддерживается очистка недействительных заказов и давно неиспользуемых учётных записей по конечной точке, статусу и времени.
- Очистка учётной записи удаляет её исторические заказы, но не влияет на уже выданные сертификаты.
- CRL/OCSP организуются по CA; после отключения конечной точки регистрации ACME они всё равно должны оставаться доступными (если клиентам нужно проверять отзыв).

## 9. Панель управления и журналы

### 9.1 Панель управления

Интерфейс поддерживает упрощённый китайский и английский языки, переключается в настройках. Главная страница сводит:

- Общее количество сертификатов, количество «скоро истекает»/«просрочено».
- Состояние задач и мониторинга.
- Доля успешных развёртываний.
- Распределение сроков действия и динамика выдачи.

### 9.2 Журналы: журнал операций

- Относится к странице «Разное → Журналы» вместе с системным журналом, переключение по вкладкам сверху.
- Записывает выполнение задач, выдачу сертификатов, развёртывание, уведомления, мониторинг и изменения настроек.
- Поддерживает фильтрацию по источнику, уровню, ключевым словам и диапазону времени, можно включить автообновление.
- Сопоставление ключевых слов выполняется по исходному сохранённому содержимому и значениям параметров (например, имени задачи, домену), а не по отрендеренному тексту шаблона на текущем языке.
- Можно экспортировать в CSV или JSON, CSV с UTF-8 BOM, открывается напрямую в Excel/WPS; экспорт и список используют один набор условий фильтрации.
- Можно очистить; при включённом архивировании сначала выполняется запись в `data/archives/logs/`, затем удаление. Само действие очистки записывается в журнал аудита; для этой возможности требуется отдельное чувствительное право `logs:write` и повторное подтверждение на странице.
- Объём экспорта ограничен последними 90 днями.
- Время экспорта по умолчанию соответствует часовому поясу браузера; если он не указан, используется `TZ` сервера.

### 9.3 Журналы: системный журнал

- Относится к странице «Разное → Журналы» вместе с журналом операций, переключение по вкладкам сверху.
- Отфильтровывается из журнала процесса и асинхронно записывается в базу данных.
- Можно фильтровать по уровню, компоненту, ключевым словам и диапазону времени.
- Можно экспортировать CSV/JSON и очистить; при включённом архивировании сначала выполняется запись в архив, действие очистки записывается в журнал операций.
- По умолчанию записываются уровни `info` и выше, хранение 7 дней или 20 000 строк.
- Журнал доступа HTTP по умолчанию не пишется в базу данных, можно настроить в `log.system`.

### 9.4 Журналы: архивы

- Относится к странице «Разное → Журналы» вместе с журналом операций/системным журналом, доступ через третью вкладку.
- Ручная очистка, очистка журнала операций старше 90 дней, очистка системного журнала по сроку хранения/максимальному количеству строк автоматически создают архив перед удалением.
- Архив состоит из `*.ndjson.gz` и `*.manifest.json` и сохраняет исходные поля журнала, количество строк, диапазон ID/времени, причину срабатывания, оператора, SHA-256 и размер файла.
- Поддерживается фильтрация по категории, причине, ключевым словам и диапазону времени, скачивание или удаление архива.
- Архивы по умолчанию хранятся бессрочно; можно настроить `log.archive.retention_days`, `max_total_mb` и `quota_policy`.
- Сбой архивирования блокирует удаление: ручная очистка возвращает ошибку, автоматическая очистка ждёт следующего раунда повтора.
- Каталог архивов не входит в резервную копию ZIP по умолчанию, его нужно переносить отдельно; файлы архивов может удалить администратор с правами на каталог данных, они не относятся к неизменяемому аудиту.

## 10. Границы возможностей

| Граница | Пояснение |
| --- | --- |
| Проверка публичных сертификатов | Только DNS-01; заявка в публичный CA по HTTP-01 не поддерживается |
| Многопользовательский режим | Одна учётная запись администратора, без RBAC/организационной структуры |
| Федерация идентификации | Нет LDAP/OIDC/SAML/SCIM |
| Высокая доступность | Нет встроенного кластера/режима «активный-активный»; SQLite с одной записью |
| Хранение закрытых ключей | Локальное зашифрованное хранение, без HSM/KMS |
| Вывод мониторинга | Нет конечной точки метрик Prometheus; предоставляются журналы и API аутентификации |
| Откат развёртывания | Старые сертификаты в целевой системе автоматически не откатываются; нужно сохранять версии на целевой стороне |
| Сертификация соответствия | Сертификаты MLPS/ISO не прилагаются; предприятие проводит оценку самостоятельно |
