# 部署架构

本文面向平台架构师和运维负责人，说明 LACTSSL 的部署单元、网络边界、容量估算和可用性设计。所有建议都以当前版本的**单实例、单租户、SQLite 单写**为前提。

## 1. 部署单元

LACTSSL 是一个自包含的 Go 二进制：

- 前端构建产物嵌入二进制，不需要独立的 Web 服务器或 Node 运行时。
- 数据存储在本地 SQLite，不依赖外部数据库、缓存或消息队列。
- DNS、部署、通知插件以一次性子进程运行，插件文件放在数据目录下。
- 运行时只有两类持久化输入：`config.yaml` 和 `data/` 目录。

```text
/opt/lactssl/
├── lactssl                 # 二进制
├── config.yaml             # 配置与密钥，0600
└── data/                   # 0700
    ├── lactssl.db          # SQLite 主库
    ├── lactssl.db-wal      # WAL（运行时）
    ├── lactssl.db-shm      # 共享内存（运行时）
    ├── plugins/            # dns / deploy / notify helper
    ├── plugin-icons/       # 插件图标缓存
    ├── upgrade-backups/    # 迁移与程序升级备份
    └── restore-pending/    # 待应用的恢复包
```

备份边界就是 `config.yaml` + `data/`。只备份数据库会丢失 `salt`，导致加密凭据无法解密。

## 2. 参考拓扑

### 2.1 单机 + 反向代理（推荐起点）

```text
Internet / 企业内网
        │ HTTPS 443
┌───────▼────────┐
│ Nginx / Caddy  │  TLS 终止、来源限制、访问日志
│ / WAF / 负载均衡│
└───────┬────────┘
        │ HTTP 127.0.0.1:8080
┌───────▼─────────────────────────────┐
│ LACTSSL                             │
│  ├─ 管理控制台 / API                │
│  ├─ 调度器（每 30 秒检查到期任务）  │
│  ├─ 私有 CA / ACME 服务（可选）     │
│  └─ SQLite + 本地插件               │
└───┬──────────┬──────────┬───────────┘
    │          │          │
 DNS API    部署目标    通知/邮件
```

适用：大多数企业单环境部署，几十到数千张证书。

要点：

- 主程序本身不提供管理端口的 TLS 配置，生产必须由反向代理终止 TLS。
- 反向代理与 LACTSSL 最好同机或同网段；后端端口只监听回环或内网。
- 反向代理必须传递 `X-Forwarded-For`、`X-Forwarded-Proto`，并在 `server.trusted_proxies` 中登记代理地址。
- `security.public_url` 必须配置为对外固定地址，密码重置等链接不依赖请求 Host。

### 2.2 DMZ 代理 + 内网应用

```text
用户 ──HTTPS──► DMZ 反向代理 ──内网 HTTP──► LACTSSL（应用网段）
                                              │
                                              ├─► DNS API / 公网 CA（出站 443）
                                              ├─► SSH / 面板 / CDN（按目标）
                                              └─► SMTP / Webhook（按渠道）
```

适用：安全要求较高，管理面不直接暴露在业务网段。

要点：

- 在防火墙上只放行代理到 LACTSSL 的管理端口。
- LACTSSL 的出站访问按目标做白名单；如果无法做域名白名单，至少限制目的端口和网段。
- 如需在 DMZ 单独暴露 ACME 服务端，使用独立监听端口，不要复用管理端口。

### 2.3 内网 PKI / ACME 服务

```text
内部服务 / certbot / lego / acme.sh
        │ ACME v2（HTTPS 或 mTLS）
┌───────▼─────────────┐
│ LACTSSL ACME 端点    │ 独立端口 :14000
│ 绑定私有 CA          │ 域名白名单 / EAB / 挑战类型
└───────┬─────────────┘
        │
   私有 CA 层级
```

适用：内部服务证书、设备证书、测试环境证书。

要点：

- ACME 端点未创建并启用时不会签发证书；每个端点必须配置域名白名单。
- 公网可达时建议开启 EAB，并在网络层限制来源；更高要求使用 mTLS。
- `acme.base_url` 必须是客户端实际访问的固定地址；公网部署不要依赖请求 Host。
- CRL/OCSP 端点按 CA 组织，停用 ACME 报名端点后仍应保持可达（如客户端需要检查吊销）。

### 2.4 容器平台

```text
Ingress / Service
        │
┌───────▼────────┐
│ Pod: lactssl    │
│  /app/config    │── PVC 或配置卷
│  /app/data      │── PVC
└────────────────┘
```

要点：

- 使用官方镜像时，容器内固定读取 `/app/config/config.yaml`，数据目录为 `/app/data`。
- 入口脚本会修正挂载目录归属后降权到 `lactssl` 用户运行；Compose 默认只读根文件系统、丢弃 capabilities。
- **单副本**：不要让多个 Pod 同时写同一个 SQLite 数据卷。
- 容器内自升级不会改变镜像，重建后仍回到镜像版本；生产通过镜像标签升级。
- 使用 `restart: unless-stopped` 或编排平台的等价策略，恢复备份后需要自动拉起。

## 3. 端口与网络流

| 方向 | 端口/协议 | 用途 | 建议 |
| --- | --- | --- | --- |
| 入站 | 443/TCP | 管理控制台与 API（经反向代理） | 仅对受控来源开放 |
| 入站 | 8080/TCP | LACTSSL 主监听（默认） | 只监听回环/内网，由代理访问 |
| 入站 | 自定义/TCP | ACME 独立监听（可选） | 独立端口，限制来源 |
| 出站 | 443/TCP | DNS 服务商 API、公共 ACME CA、通知、Webhook、面板、云 CDN | 按域名/网段白名单 |
| 出站 | 22/TCP 或自定义 | SSH/SFTP 部署 | 仅放行目标主机 |
| 出站 | 21/990/TCP | FTP/FTPS 部署（插件） | 优先 FTPS，限制目标 |
| 出站 | 25/465/587/TCP | SMTP 通知 | 使用企业邮件网关 |
| 出站 | 自定义 | 自建 Gotify、内网 Webhook、监控目标 | 按需放行，注意 SSRF 边界 |

说明：

- 服务端会对出站目标做 SSRF 校验，拒绝云元数据、链路本地、保留网段等地址；回环与私网仍允许，便于内网集成。
- 部署 Webhook 会携带证书私钥，公网目标强制 HTTPS；回环、私网、`.local`、`.internal` 允许 HTTP。
- 反向代理如果做 TLS 终止，后端按 HTTP 访问；必须正确传递 `X-Forwarded-Proto`，否则 Cookie 的 `Secure` 判断和限流识别会出错。

## 4. 容量规划

以下为**参考起点**，不是厂商承诺。实际容量取决于证书数量、任务频率、日志量、插件类型和备份策略，建议在生产前用真实负载压测。

| 规模 | 证书/任务量 | 建议配置 | 说明 |
| --- | --- | --- | --- |
| 试点/小规模 | < 100 张证书，少量任务 | 2 vCPU / 1 GB / 10 GB | 避免同时安装大型插件包 |
| 中等规模 | 100–1,000 张，日常续期 | 2–4 vCPU / 2 GB / 20 GB | 建议开启日志轮转和定期清理 |
| 较大规模 | 1,000–5,000 张，频繁部署 | 4–8 vCPU / 4 GB / 50 GB+ | 关注 SQLite 写放大、备份窗口和插件峰值 |

内存要点：

- 主进程空闲基线约几十 MB；插件是每次调用启动的子进程，单个 helper 受 `memory_limit_mb` 限制（默认 128 MB）。
- 插件安装/更新解包会带来瞬时内存峰值，大型 DNS 包更明显；不要把容器内存压到刚好等于空闲占用。
- 多个任务并发运行时可能同时拉起多个 helper，需为峰值留余量。

存储要点：

- 数据库增长主要来自证书、任务日志、操作日志、系统日志和 ACME 订单。
- 操作日志与系统日志共用 `logs` 表，通过 `category` 区分；保留与清空策略按分类隔离，清空系统日志不会影响操作日志。
- 证书、日志和 ACME 诊断数据都提供清理入口；系统日志有 `retention_days` 和 `max_rows`。
- `data/upgrade-backups/` 默认保留最近 5 份迁移快照，程序升级默认保留 3 份旧二进制。
- 备份文件不要写回同一数据目录；备份空间按数据库大小的数倍预留。

## 5. 可用性与灾难恢复

### 5.1 当前版本的可用性边界

- **不支持内置集群/双活**。SQLite 单写，多个实例同时挂载同一数据目录会造成锁竞争或数据损坏。
- **不提供自动故障切换**。反向代理可以探测存活，但不应把流量自动切到另一个写同一份数据的实例。
- **单管理员账户**是单点：账户丢失需要通过备份或密码重置恢复，建议把管理员职责绑定到岗位并做好交接。

### 5.2 单活 + 快速恢复（推荐）

```text
主实例 ──定时加密备份──► 独立备份存储
   │
   └─ 故障 ──► 新主机/新容器 ──恢复备份──► 切流量
```

建议目标：

| 指标 | 建议 |
| --- | --- |
| RPO | 按业务容忍度，至少每日一次；关键环境可缩短到小时级 |
| RTO | 以“准备主机 + 恢复备份 + 启动验证”估算，建议演练后写入 Runbook |
| 备份保留 | 至少 7–30 天，关键环境按合规要求延长 |
| 演练频率 | 每季度至少一次完整恢复演练 |

恢复步骤见[运维手册](operations.md)。

### 5.3 容器与主机层高可用

可以用编排平台保证**进程**重启，但不能解决数据单写问题：

- 副本数固定为 1。
- 使用持久卷，避免 Pod 重建后数据丢失。
- 健康检查使用 TCP 端口或带认证的 `/api/status`；不要用需要门禁 Cookie 的页面做未认证探测。
- 节点故障时，由平台重新调度单副本；数据卷必须能重新挂载。

### 5.4 多环境隔离

生产、预发、测试应使用独立实例：

- 独立 `config.yaml`、独立 `security.salt`、独立数据目录。
- 独立 DNS 子账号和部署凭据，避免测试任务影响生产。
- 独立通知频道，避免测试告警进入生产值班群。
- 不要把生产数据库复制到测试环境后继续使用同一套凭据；如必须复制，先轮换凭据。

## 6. 监控与可观测性

LACTSSL 不提供 Prometheus 指标端点，但可以通过以下信号建立监控：

| 信号 | 方式 | 建议 |
| --- | --- | --- |
| 进程存活 | TCP 端口探测 | 30–60 秒一次 |
| 深度健康 | `GET /api/status`，使用具备 `system:read` 的 API 密钥 | 1–5 分钟一次，检查 200 与响应时间 |
| 任务失败 | 操作日志筛选或通知渠道 | 任务失败/部署失败即时告警 |
| 证书临期 | 仪表盘、站点监控、任务续期状态 | 到期前 30/14/7 天分级提醒 |
| 日志异常 | 系统日志关键字、反向代理 5xx | 接入企业日志平台 |
| 磁盘/备份 | 主机或平台监控 | 磁盘 < 20% 告警，备份失败告警 |

`/api/status` 需要认证，不能直接作为匿名健康检查；匿名探测只能判断端口是否可连。

## 7. TLS 与证书边界

- 管理控制台的 TLS 由反向代理提供；LACTSSL 主端口不直接配置 TLS。
- 反向代理应使用企业 CA 或公共 CA 签发的证书，并配置 HSTS、TLS 1.2+、禁用弱套件。
- ACME 独立监听可以直接提供 TLS（`acme.tls.cert/key`），也可以由反向代理终止；启用 mTLS 时必须同时配置 ACME TLS 证书和私钥。
- LACTSSL 管理的证书私钥存储在数据库中，使用 `security.salt` 派生的密钥加密；不提供 HSM/KMS 托管。
- 备份包内的数据库与配置包含加密凭据和密钥材料，按机密文件管理。

## 8. 架构决策清单

在方案评审时建议明确以下决策：

| 决策 | 选项 | 建议 |
| --- | --- | --- |
| 部署方式 | Docker / 二进制 / 编排平台 | 有容器平台时优先镜像；否则二进制 + systemd |
| TLS 终止 | 反向代理 / ACME 独立监听 | 管理面统一走反向代理 |
| 数据存储 | 本地盘 / 持久卷 / 网络盘 | 只用单写挂载；网络盘需验证 SQLite 锁语义 |
| 可用性 | 单活 + 备份 / 平台重启 | 不用双活；明确 RTO/RPO |
| 出站策略 | 全放行 / 域名白名单 / 代理 | 生产按目标白名单，必要时经企业代理 |
| 插件来源 | 官方仓库 / 内部镜像 / 手动上传 | 生产优先内部镜像 + 签名校验 |
| 升级方式 | 镜像标签 / 二进制替换 | 容器用镜像，二进制用发布包并保留回滚 |
