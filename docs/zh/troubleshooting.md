# 监控与排障

本文给出企业上线和运行阶段最常见的故障、诊断路径和应急处理。排障时先保留现场，再按“依赖 → 认证 → 业务 → 数据”的顺序定位，避免直接重启或清空日志。

## 1. 首轮排查

### 1.1 确认影响范围

- 是单个证书、单个任务，还是全部任务失败？
- 是管理入口不可用，还是只有签发/部署失败？
- 是单个部署目标，还是所有目标？
- 是升级/配置变更后出现，还是运行中突然出现？
- 是否同时影响通知、监控或 ACME 客户端？

### 1.2 收集基础信息

```bash
# 版本与进程
curl -fsS -H "Authorization: Bearer $LACTSSL_TOKEN" \
  https://ssl.example.com/api/status

# Docker 日志
docker compose logs --since=30m lactssl

# systemd 日志
sudo journalctl -u lactssl --since "30 min ago"

# 端口
ss -lntp | grep -E '8080|14000'
```

同时记录：

- 发生时间、时区、是否在变更窗口内。
- 相关任务/证书/部署记录 ID。
- 响应头 `X-Request-ID`。
- 错误信息原文（脱敏后）。

### 1.3 检查依赖

| 依赖 | 检查方式 |
| --- | --- |
| 反向代理 | 代理日志、后端端口、转发头 |
| DNS API | 凭据权限、配额、域名/Zone、TXT 记录 |
| 公共 CA | 状态页、速率限制、CAA、EAB |
| 部署目标 | 网络、认证、路径、权限、重载命令 |
| SMTP/IM | 连通性、认证、频道配置 |
| 主机 | 磁盘、内存、文件权限、时间同步 |

## 2. 访问与登录

### 2.1 根路径返回 404

**现象**：访问 `https://ssl.example.com/` 返回 404。

**原因**：未通过门禁入口。入口是随机路径，裸根路径统一返回 404。

**处理**：

1. 查看启动日志中的门禁入口。
2. 或查询数据库 `settings` 表中的 `security.entry`。
3. 或设置 `config.yaml` 的 `security.entry` 并重启覆盖。

### 2.2 忘记门禁入口

- 启动日志（初始化时会打印完整入口）。
- 数据库 `settings` 表 `security.entry`。
- 启动前修改 `config.yaml` 的 `security.entry`，重启后覆盖。

修改入口后旧链接立即失效；记录新入口并通知相关方。

### 2.3 登录后立即掉线/会话失效

**可能原因**：

- 服务重启且显式关闭了 `security.session_persistence`。
- 修改了密码，全部会话被删除。
- 使用了不同的 `jwt_secret` 启动。
- 反向代理未传递 `X-Forwarded-Proto`，导致 `Secure` Cookie 异常。
- 浏览器/代理缓存了旧 Cookie。

**处理**：

1. 确认是否刚重启或改密。
2. 检查代理头与 `trusted_proxies`。
3. 清理浏览器 Cookie 后重新从门禁入口进入。
4. 会话保持默认开启；如曾被设为 `security.session_persistence: false`，改回 `true` 可在重启后保留会话。

### 2.4 Cookie 异常、限流不准

**现象**：登录循环、CSRF 失败、所有请求共享同一 IP 配额。

**原因**：未配置可信代理、代理未传递转发头，或多级代理只信任了最近一跳。

**处理**：

```yaml
server:
  trusted_proxies: ["127.0.0.1"]
security:
  public_url: "https://ssl.example.com"
```

确认代理设置了：

```nginx
proxy_set_header X-Real-IP $remote_addr;
# 推荐覆盖模式：只信任这一层代理即可
proxy_set_header X-Forwarded-For $remote_addr;
proxy_set_header X-Forwarded-Proto $scheme;
```

如果使用追加模式 `$proxy_add_x_forwarded_for`，多级链路（例如 CDN → Nginx → LACTSSL）必须把链上所有会出现在 XFF 的代理加入 `trusted_proxies`，否则客户端 IP 会停在上游代理。

在「设置 → 配置文件 → 自动检测」中对照：

- `peer_ip`：TCP 对端；
- `applied_trusted_proxies`：当前生效的可信列表；
- `effective_client_ip` / `client_ip_source`：最终识别结果与来源；
- `trusted_skipped`：从右向左跳过的可信代理数量；
- `header_warnings`：XFF 非法、超长等解析问题。

访问日志中的 `ip_source`、`ip_skipped`、`ip_warnings` 也可用于排障。保存配置后需要重启；重启前 `configured_trusted_proxies` 与 `applied_trusted_proxies` 可能不同。

### 2.5 429 请求过多

- 按响应 `Retry-After` 退避。
- 检查是否共享了代理 IP；配置可信代理后按真实客户端 IP 计数。
- 登录、TOTP、密码重置、备份下载、私钥导出、ACME 协议等都有独立限流。
- 不要通过提高限流阈值掩盖暴力破解或脚本失控。

### 2.6 通行密钥不可用

- 必须通过 HTTPS 域名或 localhost 访问；IP 地址不能作为 WebAuthn 来源。
- 检查浏览器是否支持 WebAuthn、系统是否启用生物识别/PIN。
- 通行密钥不能替代密码；丢失设备时使用密码 + TOTP 或其他恢复路径。

## 3. 证书签发失败

### 3.1 DNS-01 验证失败

| 可能原因 | 检查 |
| --- | --- |
| 凭据无权限 | API Key 是否有目标 Zone 的读写权限 |
| 域名/Zone 不匹配 | 域名是否在当前账号可见的 Zone 内 |
| TXT 传播慢 | 等待 TTL；检查权威 DNS 是否返回 TXT |
| 多级域名/CNAME | 确认 `_acme-challenge` 的解析路径 |
| 通配符 | 通配符必须使用 DNS-01 |
| 服务商限制 | 配额、频率限制、API 变更 |
| 代理/网关 | 自定义 API 地址是否可达、证书是否受信 |

处理：

1. 在任务日志中查看具体 DNS 服务商错误。
2. 用 `dig`/`nslookup` 检查 `_acme-challenge.<domain>` 的 TXT。
3. 用同一凭据在服务商控制台手动创建/删除 TXT，确认权限。
4. 检查 CA 的 CAA 记录是否允许该 CA。
5. 修正后重新运行任务。

### 3.2 CA 速率限制/EAB 错误

- Let's Encrypt 等公共 CA 有账户、域名、失败验证等速率限制；查看 CA 状态页和错误详情。
- ZeroSSL、Google Trust Services、LiteSSL、零信 ZoTrus、Actalis、SSL.com 需要 EAB；确认 EAB KID/HMAC 正确且未过期（零信 ZoTrus 的 KID 为注册邮箱）。
- 零信 ZoTrus 的 dns-01 记录名由服务端 `tokenPath` 决定（通常形如 `_<tokenPath>.<domain>`），不是标准的 `_acme-challenge`。选择零信的任务运行后会进入“等待 DNS 验证”，在任务日志或“DNS 验证”面板中添加记录后点击“继续验证”。零信暂不支持通配符、CA 调度组和目标流程 Beta。
- 通用 ACME 上游目录必须是 HTTPS；本机回环除外。
- 为关键域名准备备用 CA，避免单一 CA 限流导致全部失败。

### 3.3 证书签发成功但浏览器不信任

- 公共 CA 证书应受信任；检查是否部署了完整链（fullchain）。
- 私有 CA 证书需要把根 CA 安装到客户端信任库。
- 检查是否部署了错误的证书/私钥配对。
- 检查 SNI、域名和证书 SAN 是否匹配。
- 检查系统时间是否准确。

### 3.4 私有 CA 签发失败

- 确认 CA 未过期、具备签发用途、路径长度允许下级 CA。
- 确认证书有效期不超过 CA 到期时间。
- 导入的 CA 必须证书与私钥匹配，且具备 CA 基本约束。
- 删除 CA 前先删除下级 CA。

## 4. 部署失败

### 4.1 SSH/SFTP

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 主机指纹不匹配 | 服务器更换密钥或配置错误 | 核对指纹；清空旧指纹重新记录 |
| 首次连接被拒绝 | 未填写指纹且未开启 TOFU | 填写 `SHA256:...` 或显式开启首次信任 |
| 认证失败 | 用户名/密码/私钥错误 | 检查凭据和目标 SSH 配置 |
| 路径无权限 | 部署用户无写权限 | 调整目录权限或使用有权限的用户 |
| 重载命令失败 | 命令不存在/权限不足/服务名错误 | 在目标主机手动执行验证 |

### 4.2 本地目录

- 运行用户对目标目录无写权限。
- 路径不存在；需要预先创建目录。
- SELinux/AppArmor 限制。
- 重载命令失败，但证书文件已更新；检查服务是否实际加载新文件。

### 4.3 面板/CDN/Webhook

- 凭据过期、权限不足或 API 版本不匹配。
- 部署参数（站点、域名、证书名称）与目标系统不一致。
- 目标系统开启了 IP 白名单，未放行 LACTSSL 出口。
- Webhook 公网目标必须 HTTPS；回环/私网允许 HTTP。
- 部署插件未安装、未启用或文件校验失败。

### 4.4 证书更新了但业务仍旧证书

- 部署节点未配置重载命令，或命令未生效。
- 目标系统有缓存（CDN、WAF、负载均衡）。
- 部署到了错误路径/站点。
- 多实例部署只更新了其中一台。
- 检查证书序列号/指纹是否与目标系统一致。

## 5. 通知与监控

### 5.1 通知未送达

- 渠道是否在插件页启用，通知页面是否启用。
- Token/Webhook 是否过期，目标是否可达。
- SMTP 是否使用隐式 TLS；服务器不支持 STARTTLS 时会拒绝发送。
- 任务通知节点是否启用，触发时机是否匹配。
- 检查操作日志/系统日志中的发送错误；敏感值会被脱敏。
- 安全提醒未送达：在「设置 → 安全提醒」确认总开关、登录模式、失败聚合、事件和渠道已开启；查看「最近安全事件」弹窗中的逐目标状态和错误。超过每小时上限时只会收到一条摘要；修改 SMTP/渠道时旧收件人使用旧 SMTP 配置快照发送。安全提醒与证书通知开关独立。

### 5.2 站点监控误报

- 监控会校验主机名和系统信任链；自签、链不完整、主机名不匹配都会标记异常。
- 检查目标端口、SNI、系统 CA 信任库和时间。
- 负载均衡后面的不同节点可能返回不同证书；确认监控目标稳定。
- 监控频率和超时是否合理；避免对不稳定目标频繁告警。

### 5.3 没有收到到期提醒

- 任务自动续期是否开启，`RenewDays` 是否合理。
- 调度器是否运行（日志中查看调度记录）。
- 通知渠道是否可用。
- 证书是否已被清理或任务引用被清空。

## 6. 插件问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 插件条目不可用 | 类别关闭或条目未启用 | 检查插件类别配置与条目白名单 |
| 安装失败 | 签名、SHA-256、平台、`min_host` 不匹配 | 查看错误详情；核对公钥和版本 |
| 安装后服务商不出现 | 文件/条目未启用 | 启用 helper 文件和具体条目 |
| 插件被拒绝加载 | 组/其他用户可写、符号链接、摘要变化 | 修正权限或重新安装 |
| 旧插件迁移失败 | 旧 helper 占用/文件冲突 | 按迁移提示处理，失败会回滚 |
| 部署插件不可用 | `deploy_plugins.enabled: false` | 显式启用并重启 |
| 通知渠道缺失 | helper 未安装/未启用 | 安装并启用通知插件 |

插件目录：

```text
data/plugins/dns
data/plugins/deploy
data/plugins/notify
```

权限要求：目录 `0700`，helper `0755`，属主为服务运行用户。

### 6.1 导入信任链后插件仍提示 TLS 校验失败

先根据具体提示判断原因：

- **证书已过期或尚未生效**：续签或更新目标证书；导入 CA 不能延长证书有效期。
- **证书与访问地址不匹配**：改用证书 SAN 中的域名访问；如果用 IP 访问，证书必须包含对应的 IP SAN。
- **证书不受信任**：确认导入的是签发该证书的 CA 公钥（根 CA 或中间 CA），而不是站点叶证书；一次导入 PEM 可包含多张 CA。导入后无需重启。
- 其他情况：用 `openssl s_client -connect host:port -servername host -showcerts` 检查目标实际返回的证书链是否完整。

插件子进程通过 `SSL_CERT_FILE` 读取 `<data_dir>/trusted-ca-bundle.pem`。信任链会合并系统根证书、导入的 CA 与私有 CA；只有确实受控的内部 CA 才应导入。

## 7. 备份与恢复

### 7.1 备份下载失败

- 需要重新输入当前密码；启用 TOTP 时还需动态验证码。
- 备份密码至少 12 位。
- 反向代理请求体/响应体限制。
- 磁盘空间不足。
- 检查操作日志和系统日志。

### 7.2 恢复后无法解密凭据

- 备份中的 `config.yaml` 与数据库不配套，`salt` 不同。
- 只恢复了数据库，丢失了配置。
- 解决：使用完整 ZIP 备份恢复；不要单独替换数据库。

### 7.3 恢复后登录不上

- 使用备份中的管理员账户。
- 默认开启会话保持，重启后无需重新登录；如设为 `security.session_persistence: false`，重启会清空会话。
- 门禁入口可能已变化，查看启动日志。
- `jwt_secret` 不同会导致旧令牌失效。
- 恢复包在 `data/restore-pending/`，检查是否已应用。

### 7.4 恢复后服务未自动拉起

- Docker：确认 `restart: unless-stopped`。
- systemd：确认服务已启动。
- 直接运行二进制：需要手动重启。
- 检查启动日志中的配置校验错误。

## 8. 数据库、磁盘与内存

### 8.1 数据库变大

- 证书、任务日志、操作日志、系统日志、ACME 订单都会增长。
- 使用证书一键清理、ACME 诊断清理、系统日志清空。
- 在低峰期执行 `/upgrade` 的“仅优化数据库与配置”，必要时开启 VACUUM。
- 检查 WAL 大小；优化工具会执行 `wal_checkpoint(TRUNCATE)`。

### 8.2 磁盘不足

- 检查 `data/`、日志、`upgrade-backups/`、备份文件。
- 清理旧升级快照和旧二进制备份（按保留策略）。
- 确认备份没有写回同一数据目录。
- VACUUM 需要临时空间，磁盘不足会失败。

### 8.3 内存高/被 OOM

- 主进程空闲基线约几十 MB；插件是一次性子进程，受 `memory_limit_mb` 限制。
- 插件安装/更新解包有瞬时峰值，大型 DNS 包更明显。
- 多个任务并发会同时拉起多个 helper。
- 检查容器内存上限是否过低；为峰值留余量。
- 降低并发或调低 helper 内存限制，但要确保插件能正常工作。

### 8.4 数据库锁/写入失败

- 确认只有一个实例挂载数据目录。
- 不要把 SQLite 放在多写共享存储上。
- 检查磁盘满、权限、文件系统只读。
- 备份/恢复期间避免大量并发任务。

## 9. 升级与迁移

### 9.1 启动时迁移失败

- 查看日志中的失败步骤。
- 检查磁盘、权限、数据库完整性。
- 修复后直接重启重试；迁移步骤幂等，不会推进失败版本号。
- 不要手动删除 `upgrade.schema_version`。

### 9.2 升级后页面不可用

- 检查反向代理/静态资源缓存。
- 强制刷新或清理 CDN 缓存。
- 检查二进制/镜像版本是否匹配。
- 查看启动日志和浏览器控制台。

### 9.3 程序自升级被拒绝

- 只读文件系统、`dev` 构建、无发布包平台、缺少校验和/签名都会拒绝。
- 容器内升级不改变镜像；使用镜像标签升级。
- 检查 GitHub API 速率限制和出站代理。

## 10. ACME 服务端排障

| 客户端错误 | 可能原因 | 处理 |
| --- | --- | --- |
| `badNonce` | 服务重启或 nonce 过期 | 客户端自动重试；检查是否多实例共享 |
| `unauthorized` | 账户/JWS 错误、EAB 缺失 | 检查 EAB、账户密钥、端点 |
| `rejectedIdentifier` | 域名不在白名单 | 检查端点域名白名单 |
| `caa` | CAA 不允许该 CA | 调整 CAA 或换 CA |
| `orderNotReady` | 挑战未完成 | 完成授权后 finalize |
| `rateLimited` | 触发端点限流 | 按 `Retry-After` 退避 |
| HTTP-01 失败 | 目标不可达/私网被拒绝 | 检查 CIDR 白名单、端口、路由 |
| mTLS 失败 | 客户端证书不受信 | 检查 `mtls.client_ca` 和客户端证书链 |
| 资源 URL 错误 | `base_url` 未配置 | 配置固定 `acme.base_url` |

诊断：

- 「ACME 诊断」查看账户、订单、授权、挑战和证书。
- 检查 `acme.base_url`、端点白名单、EAB、挑战类型。
- 公网部署不要依赖请求 Host 推导 URL。
- CRL/OCSP 端点按 CA 组织，确认客户端可访问。

## 11. 应急处理

### 11.1 怀疑 API 密钥泄露

1. 在「API 密钥」页面停用或删除该密钥。
2. 创建新密钥并更新调用方。
3. 检查操作日志中的异常调用、部署和私钥下载。
4. 如涉及部署目标，轮换对应凭据。
5. 记录事件并复盘。

### 11.2 怀疑管理员账户泄露

1. 立即修改密码；这会删除全部会话、API 密钥和通行密钥。
2. 检查恢复邮箱是否被篡改。
3. 检查操作日志、系统日志和反向代理日志。
4. 轮换 DNS/部署/通知凭据。
5. 如怀疑 `salt` 泄露，按密钥泄露流程处理，必要时重建实例并重新录入凭据。
6. 评估是否需要重新签发受影响证书。

### 11.3 证书被错误部署/覆盖

1. 暂停相关任务，避免继续覆盖。
2. 从目标系统备份或证书历史恢复上一版。
3. 检查任务部署节点参数和重载命令。
4. 重新部署正确证书并验证序列号/指纹。
5. 记录根因，补充部署前校验。

### 11.4 ACME 端点被滥用

1. 停用端点或关闭 `acme.enabled`。
2. 检查账户、订单和来源 IP。
3. 开启 EAB、mTLS 或网络 ACL。
4. 清理异常账户和订单。
5. 评估是否签发过非预期证书。

## 12. 升级信息收集

向供应商或社区求助时，提供：

- LACTSSL 版本、构建时间、架构、部署方式。
- 操作系统、容器/编排版本、反向代理类型。
- 复现步骤、期望结果、实际结果。
- 相关日志片段（脱敏）：时间、`X-Request-ID`、错误码。
- 任务/证书/部署记录 ID。
- 是否近期升级、改配置、换插件或轮换凭据。
- 已尝试的处理和结果。

不要提供：

- 管理员密码、TOTP 种子、API 密钥明文。
- 证书私钥、CA 私钥、备份密码。
- 未脱敏的 DNS/部署/通知凭据。
