# 插件治理

LACTSSL 的 DNS、证书部署与通知能力都由插件提供。主程序只负责加载插件、执行一次性 helper 子进程，并管理安装、启用与卸载。对企业而言，插件不是普通扩展，而是**供应链边界**：

- DNS 插件接收域名服务商 API 凭据。
- 部署插件接收证书与私钥。
- 通知插件接收渠道 Token/Webhook。
- 所有插件以服务账号运行，等同受信代码。

因此插件应纳入变更管理和准入审查，而不是由任意用户随时安装。

## 1. 插件模型

- **按类型合并包**：官方插件仓库按类型构建合并包：DNS 常用、DNS 大型云厂商、部署、通知；另提供覆盖全部 194 家服务商的 DNS 全量·重构包。每个包内含该类型多个实现，共享一份 Go 运行时。
- **按需安装**：主程序发布包不内置任何插件；需要哪一类能力就安装对应的合并包。
- **协议 v1**：插件是可执行文件，通过 `manifest`、`present/cleanup`、`deploy`、`send` 等子命令与主程序通信。
- **独立目录**：
  - DNS：`<data_dir>/plugins/dns`
  - 部署：`<data_dir>/plugins/deploy`
  - 通知：`<data_dir>/plugins/notify`
- **一次性子进程**：每次调用启动、执行完退出，不常驻内存。

## 2. 仓库与信任

```yaml
plugins:
  repo:
    enabled: true
    url: "https://github.com/AXmishell/LACTSSL-Plugins/releases/download/plugin-index/index.json"
    channel: stable
    auto_update: false
    public_key: "t7Q4vd0B1zh3mRf0t6Q6qlBViL7cKhoipgpGWx5WSss="
    timeout_seconds: 30
    max_download_mb: 256
    check_interval_hours: 24
```

也可以在「插件」页修改仓库地址、渠道、自动更新和公钥。界面设置保存在数据库，优先级高于 `config.yaml`，但不会写回配置文件。

### 2.1 校验链

1. 配置公钥时，强制校验 `index.json.sig`（Ed25519）。
2. 本地缓存索引额外使用服务端密钥做 HMAC 保护。
3. 下载前要求索引提供 asset SHA-256；缺失或格式错误直接拒绝。
4. 下载后强制校验 asset SHA-256。
5. 安装时校验 `plugin.json`、manifest 中的 ID 与版本、平台和 `min_host`。
6. 安装记录保存文件摘要；发现、注册和每次 DNS/部署/通知调用前复核，文件被替换时拒绝加载或执行。
7. 任一步失败都会回滚，不留下半成品。

未配置签名公钥时会显示风险提示，且跳过无人值守自动更新。生产环境不建议关闭验签。

## 3. 企业部署模式

### 3.1 官方仓库直连

适用：网络可访问 GitHub，插件数量少，能接受官方仓库作为信任源。

要求：

- 配置官方公钥并强制验签。
- 关闭自动更新，按变更窗口手动升级。
- 记录每次安装/升级的版本和摘要。

### 3.2 内部镜像（推荐）

适用：生产环境、离线/半离线、需要固定版本和准入审查。

方式一：把索引指向内部 HTTPS 镜像：

```yaml
plugins:
  repo:
    url: "https://mirror.example.com/lactssl-plugins/index.json"
    public_key: "<企业签名公钥>"
```

方式二：离线目录：

```yaml
plugins:
  repo:
    url: "file:///srv/lactssl-plugins/index.json"
```

内部镜像应做到：

- 同步官方索引和资产，保留原始 SHA-256。
- 用企业自己的 Ed25519 密钥重新签名索引，或至少校验官方签名后再提供。
- 只同步经过准入的版本，不自动跟随 `latest`。
- 镜像目录只读，只有同步账号可写。
- 记录版本、来源、摘要、审批人和回滚版本。

### 3.3 手动上传

可以在「插件」页上传单个 helper，或把文件放入插件目录后重扫。适用于临时验证或第三方插件。

- 上传仅接受单个 helper 可执行文件，最大 256 MB。
- 上传后先以临时文件探测 `manifest`，校验协议、ID 和 SHA-256，通过后才写入插件目录并重扫。
- 默认拒绝覆盖同名文件；升级时可勾选“允许覆盖同名插件”，旧文件会先备份。
- 手动上传的插件标记为 `manual`，不参与官方仓库升级。
- 只上传可信文件；helper 以服务账号执行。

## 4. 安装与启用

### 4.1 安装

1. 打开「插件」页，确认仓库地址，点击「刷新索引」。
2. 打开「插件市场」，按 DNS / 部署 / 通知筛选或搜索。
3. 安装需要的插件；完成后在对应列表中启用。

每个插件显示：

- 名称、ID、版本、大小。
- 当前平台是否有安装包。
- 是否兼容当前宿主版本。
- 已安装版本与可更新状态。

新安装的插件默认停用；升级或重装保留原启用状态。

### 4.2 两级启用

插件页每一行对应一个 helper 文件，启用状态分为两层：

1. **文件级**：行首开关控制 helper 是否参与发现与加载。停用后不再执行该文件的 `manifest`，其中条目也不会注册到运行时；已有条目勾选会保留，重新启用文件后恢复。
2. **条目级**：点击「管理条目」逐个启用服务商、部署目标或通知渠道，也可以勾选后批量启用/停用。新安装插件的条目仍默认停用。

说明：

- 文件停用时其条目仍会显示（来自宿主缓存的 manifest 摘要），但开关置灰，需先启用文件。
- 合并包（例如提供 184 个条目的 `lactssl-dns-core`）不会被行首开关一次性全开；一次启用超过 10 个条目会要求确认。
- 删除文件或卸载插件会同时清理 manifest 缓存、文件级状态，并从条目白名单移除该文件的全部条目。

## 5. 更新、回滚与卸载

- **更新**：在插件市场点击「更新」，或开启自动更新后按 `check_interval_hours` 定期检查。
- **批量更新**：`POST /api/plugins/repo/update` 空请求体表示更新全部已安装插件。
- **回滚**：生产建议在内部镜像保留上一版本；升级失败时重新安装旧版本。
- **卸载**：只允许卸载由插件仓库安装的插件；卸载会删除插件文件、安装记录，并从启用白名单移除。
- **删除文件**：每个插件页签都会列出插件目录中的实际 helper 文件（含手动上传与旧版全量 bundle），可直接删除；删除会移除该文件提供的全部条目、安装记录与启用状态，并立即重扫。

升级采用“下载 → 校验 → 备份 → 原子替换 → manifest 校验”的流程；任一步失败都会恢复旧文件。

### 5.1 变更流程建议

1. 在预发环境安装目标版本。
2. 验证 `manifest`、条目列表和关键链路（DNS 签发、部署、通知）。
3. 记录版本、摘要和测试结果。
4. 生产变更窗口内升级，观察任务日志。
5. 失败时回滚到镜像中的上一版本。

## 6. 包体积与资源

插件市场显示的大小按**解压后**计算，也就是安装到磁盘上的实际 helper 大小。当前官方合并包（linux/amd64）约为：

| 包 | 解压后 |
|---|---:|
| DNS 常用（184 个服务商） | 约 21 MiB |
| DNS 大型云厂商（10 个服务商） | 约 39 MiB |
| DNS 全量·重构（194 个服务商） | 约 18 MiB |
| 部署（7 个目标） | 约 7 MiB |
| 通知（23 个渠道） | 约 7 MiB |

- 常用 DNS 包只安装约 21 MiB，运行 manifest 时峰值内存约 22 MiB。
- 需要 Google Cloud、Yandex、Sakura、Route53、Azure DNS 等大型 SDK 服务商时安装约 39 MiB 的重型包。
- 想覆盖全部 194 个服务商时，只需安装约 18 MiB 的全量·重构包。
- 全部安装约 73 MiB，仍比 224 个单插件包约 1.7 GiB 的解压总量低约 96%。

安装/更新解包会带来瞬时内存峰值；容量规划需留余量，见[部署架构](architecture.md)。

## 7. 旧版全量插件迁移

升级前使用过 `lactssl-dns-helper-extra`、`lactssl-deploy-helper` 或 `lactssl-notify-helper` 的部署，会在「插件」页看到迁移提示：

1. 系统读取旧插件的 manifest，找出当前已启用或仍被账户/任务使用的服务商。
2. 下载对应的合并包并安装；合并包会覆盖旧版单服务商/旧全量 helper。
3. 全部成功后删除旧文件并重扫。
4. 任一步失败则回滚本次安装，旧插件继续可用。

迁移完成前旧插件不会被删除，避免正在签发的站点中断。

## 8. 服务商图标

DNS 与部署服务商的 logo 属于插件元数据，由插件仓库下发，主程序不再内置图标表：

- **未安装时**：仓库索引 `icons` 内联图标，随索引签名校验，用于插件市场展示。
- **安装后**：插件包内 `icons/` 写入 `<data_dir>/plugin-icons/<kind>/<插件 ID>/`，断网或关闭仓库后凭据页仍能显示。
- **读取接口**：前端通过 `GET /api/plugins/icons` 一次拉取；未提供图标、图标损坏或旧版本宿主时回退为首字母头像。
- **别名**：`aliyun_cdn`、`baota_site`、`qiniu_kodo` 等历史 ID 由仓库 `assets/icons/icons.json` 映射到规范图标。
- **合并包图标**：只使用包 ID 对应的包级图标；未提供包级图标时直接不展示，或由包条目声明 `hide_icon: true` 强制关闭。

图标仅允许 svg / png / webp，单张不超过 64 KB；非法条目会被丢弃，不影响插件安装与升级。

## 9. 安全控制

- 只使用可信仓库；生产配置签名公钥并强制验签。
- 下载前要求 asset SHA-256，安装后复核文件摘要。
- 部署插件接触私钥，默认关闭，只安装可信来源。
- 插件目录 `0700`，helper `0755`，不允许组或其他用户写入。
- 不允许符号链接；文件被替换时拒绝加载。
- 限制 `memory_limit_mb`、`timeout_seconds` 和 `max_output_kb`，避免异常插件拖垮主机。
- 插件以服务账号运行，不要给 `lactssl` 用户额外权限，也不要让插件目录位于共享可写路径。
- 记录插件安装/升级/卸载操作，纳入变更审计。

## 10. API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/plugins` | 插件状态、条目与目录中的 helper 文件 |
| GET | `/api/plugins/repo` | 仓库配置与索引状态 |
| PUT | `/api/plugins/repo` | 修改配置 |
| POST | `/api/plugins/repo/refresh` | 强制刷新索引 |
| GET | `/api/plugins/repo/plugins` | 仓库插件列表 |
| POST | `/api/plugins/repo/install` | 安装 `{kind,id,version}` |
| POST | `/api/plugins/repo/update` | 更新 `{kind,id}` 或全部 |
| DELETE | `/api/plugins/repo/plugins/:kind/:id` | 卸载 |
| DELETE | `/api/plugins/files/:kind/:file` | 删除插件目录中的 helper 文件 |
| GET | `/api/plugins/repo/legacy` | 检测旧版全量插件 |
| POST | `/api/plugins/repo/migrate` | 迁移 `{kind}` |

插件管理需要 `plugins:read` / `plugins:write`。上传、安装、更新、卸载和修改仓库配置都属于敏感操作。

## 11. 排障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 索引拉取失败 | 仓库地址、网络代理、TLS 证书 | 先用浏览器访问 `index.json`；检查出站策略 |
| 签名校验失败 | 公钥与仓库签名密钥不匹配 | 核对公钥；不要在生产随意清空 `public_key` |
| 平台不可用 | 当前平台没有对应插件包 | 检查 `GOOS/GOARCH` 和索引 `assets` |
| 宿主版本不兼容 | 插件 `min_host` 高于当前版本 | 升级宿主或安装兼容版本 |
| ID 冲突 | 同一服务商已由旧 bundle 或手动插件提供 | 完成迁移或卸载旧文件 |
| 安装后未出现 | 对应插件类型未启用或条目未启用 | 检查 `plugins.enabled`、`deploy_plugins.enabled`、`notify_plugins.enabled` 和条目开关 |
| 文件被拒绝 | 组/其他用户可写、符号链接、摘要不一致 | 修正权限或重新安装 |

更多排障见[监控与排障](troubleshooting.md)。

## 12. 插件准入清单

- [ ] 来源：官方仓库或企业内部镜像，版本固定。
- [ ] 完整性：索引签名、asset SHA-256、安装记录摘要校验通过。
- [ ] 权限：插件目录和文件权限符合要求。
- [ ] 风险：部署插件是否接触私钥；通知插件是否持有长期 Token。
- [ ] 兼容：宿主版本、平台、`min_host` 匹配。
- [ ] 测试：预发环境完成 DNS/部署/通知链路验证。
- [ ] 回滚：保留上一版本和回滚步骤。
- [ ] 记录：版本、摘要、审批人、安装时间、变更单。
