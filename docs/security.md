# 安全

## 安全入口

管理页面不直接暴露在根路径，而是先通过随机生成的安全入口进入：

```text
https://your-domain/<entry>/
```

- 入口默认随机生成 20 位大小写字母与数字组合，保存在数据库中。
- 未通过入口的页面与接口统一返回 `404`，包括裸 `/`、`/api` 等常见探测路径。
- 访问正确入口后会写入一个有效期为 24 小时的签名 `HttpOnly` 门禁 Cookie（服务端同时校验过期时间，不能无限重放），然后跳转到 `/login`；只有携带该 Cookie（或已登录）才可打开登录页。
- 入口探测有频率限制，避免被暴力枚举。
- 可在「设置 → 安全入口」中修改，修改后立即生效。手工入口要求 8-32 位，短于 8 位的入口会被拒绝，避免被分布式扫描快速枚举。
- 首次初始化时会打印完整入口地址到启动日志；初始化完成后不再打印，避免日志系统长期保存入口。忘记入口时可设置 `LACTSSL_ENTRY` 覆盖，或在数据库 `settings` 表中查看 `security.entry`。

入口是额外的一层防护，不能替代 HTTPS 和强密码。

## 会话与 CSRF

- 登录会话保存在 `HttpOnly` Cookie 中，前端脚本无法读取；Cookie 使用 `SameSite=Strict`。
- HTTPS 部署时会话、CSRF 与入口 Cookie 自动使用 `__Host-` 前缀，避免共享父域下的兄弟子域用同名 Cookie 覆盖。
- 所有会改变服务端状态的请求（POST/PUT/DELETE 等）必须携带 `X-LACTSSL-CSRF` 请求头，且必须与 `lactssl_csrf` Cookie 一致，否则拒绝。旧会话首次请求会自动补发该 Cookie，不再接受仅携带请求头的降级校验。
- 登录、初始化、忘记密码和密码重置等未认证接口额外校验 `Origin`/`Sec-Fetch-Site`，阻止跨站发起的状态变更请求。
- 修改密码会提升令牌版本并删除全部服务端会话记录，包括当前设备在内的所有登录都会立即失效，需要使用新密码重新登录。
- 显式使用 `Authorization: Bearer <token>` 调用 API 时不受 CSRF 校验约束，便于脚本或外部集成。
- 页面响应使用每次请求随机 CSP nonce，`script-src` 不再允许任意内联脚本；样式仍允许内联以满足组件库需要。

## 密码重置与对外地址

密码重置邮件中的链接必须基于固定地址生成：

```yaml
security:
  public_url: "https://ssl.example.com"
```

- 未配置 `security.public_url` 时，仅允许本机回环地址且 Host 为 `localhost`/回环 IP 的请求按当前 Host 推导链接；其他请求调用“忘记密码”会被拒绝。
- 不再信任客户端可伪造的 `X-Forwarded-Host`。反向代理场景请配置 `public_url`，不要依赖请求头。
- 这可以避免攻击者伪造 Host 把重置链接（含 token 与安全入口）指向自己的域名。

## 凭据保护

- 管理员密码使用 bcrypt 哈希存储，密码长度至少 8 个字符。
- DNS 凭据、部署凭据、SMTP 密码、通知 Token、TOTP 密钥、私有 CA 私钥和证书私钥等敏感字段使用 AES-256-GCM 加密后写入数据库；旧版本明文数据会在启动时自动迁移。
- 目标凭据只保存认证与连接信息；部署路径、站点、域名等参数保存在任务流程中，不属于凭据配置的加密范围。
- 加密密钥来自 `config.yaml` 的 `security.salt`；JWT 使用 `security.jwt_secret` 签名。
- JWT 签名实际使用由 `jwt_secret` 经 HKDF 派生的独立子密钥，与数据库 AES-GCM 密钥分离；旧版本即使复用同一串密钥也不会让两类密钥材料直接相同。升级后旧登录令牌会失效一次，需要重新登录。
- 接口返回配置时会对密钥字段脱敏，编辑时留空表示保留原值。
- SSH 部署首次连接会记录目标主机指纹（TOFU），后续指纹不一致会拒绝连接；也可在凭据中手动填写 `SHA256:...` 指纹。服务器更换密钥后需要清空该字段重新记录。
- FTP 部署默认使用显式 TLS，避免证书私钥和登录密码明文传输；只有明确选择 `none` 才会使用明文 FTP。

因此 `config.yaml` 与 `data/` 同等重要，请一并备份并限制访问权限。`security.jwt_secret` 和 `security.salt` 手动配置时至少需要 32 个字符，过短会拒绝启动。

下载备份时必须设置至少 12 位的加密密码，备份包使用 PBKDF2-HMAC-SHA256（600000 次迭代）+ AES-256-GCM 加密；不要分发未加密的数据库或配置副本。

恢复包在写入 `data/restore-pending` 前会完整校验配置（密钥长度、安全入口、监听地址、TLS/mTLS 组合等），非法配置会被直接拒绝，避免下次启动反复失败。首次初始化成功后会清理尚未应用的恢复包，防止初始化前暂存的内容在后续重启时覆盖新账户。

邮件默认使用隐式 TLS（`smtp.ssl=true`）。关闭隐式 TLS 时，如果 SMTP 服务器不支持 STARTTLS，服务会拒绝发送，避免重置令牌等敏感邮件明文传输。

## 敏感操作的二次验证

修改安全入口、恢复备份、下载备份、导出私有 CA 私钥、导出/查看证书私钥、修改系统与通知设置、发送通知测试、修改 DNS/部署凭据、创建/修改/删除任务、执行证书部署、删除或清理证书、修改站点监控、修改 ACME 服务配置与清理诊断记录、修改私有 CA，都会在会话鉴权之外再要求完成一次“二次验证”。语言切换等纯展示设置不受影响。可在系统设置 → 账户安全中切换为“无”“密码验证”“TOTP 验证”或“密码和 TOTP”。默认使用密码验证；需要 TOTP 的模式仅在已启用两步验证时可选。选择“无”后，上述操作只依赖登录会话，安全性显著降低，请仅在充分了解风险时使用。切换验证方式本身需要使用当前生效方式的凭证确认身份，不能只凭登录会话修改；“密码和 TOTP”模式需要同时提供密码和动态验证码。若 TOTP 被关闭、账户通过邮箱重置密码，或从旧备份恢复后 TOTP 数据不可用，验证方式会自动回退为密码，避免账户被锁死。同一 TOTP 验证码在有效窗口内只能使用一次，切换验证方式后应立即执行的操作可能需要等待下一个验证码。

在「系统设置 → 账户安全 → 切换验证方式」对话框中，可以逐项开启/关闭部署、任务增改删、DNS/部署凭据、SMTP/通知设置、通知测试、ACME/私有 CA 配置、证书私钥导出、证书删除/清理、站点监控增改删的二次验证。备份下载/恢复、修改安全入口和导出私有 CA 私钥始终强制验证，不受开关影响。

二次验证采用短期 token：前端先调用 `/auth/secondary-verify`，服务端按当前验证方式校验密码/TOTP，成功后签发 2 分钟有效、绑定当前用户、会话和具体操作的 token；业务接口在 `X-LACTSSL-VERIFY` 请求头中校验该 token，不再直接接收账户密码。token 过期或操作不匹配时需要重新完成二次验证。

这项限制用于降低会话被盗后的影响：备份包含 `config.yaml` 中的 `jwt_secret` 与 `salt`，拿到备份即可解密全部凭据并伪造登录令牌，因此不能只凭 Cookie 会话导出。修改密码、修改邮箱、启用/关闭 TOTP 等账户操作本身仍要求当前密码，并受独立失败限流。

## 出站请求与 SSRF

部署 webhook、通知渠道、面板对接和站点监控会由服务端主动发起出站请求：

- 字面量与解析后的目标地址会拒绝云元数据、链路本地、保留、文档、NAT64 等网段（如 `169.254.169.254`、`100.100.100.200`、`fd00:ec2::254`、`0.0.0.0/8`、`240.0.0.0/4`）。
- 回环与私网地址仍允许使用，便于 Gotify、自建面板、内网 webhook 等场景；如不需要可在网络层进一步限制。
- 部署 webhook 会携带证书私钥，公网目标强制使用 `https://`；回环、私网、`.local`、`.internal` 目标允许 HTTP。
- 拨号阶段会重新校验 DNS 解析结果并直接连接校验后的 IP，避免 DNS 重绑定绕过。
- 第三方请求失败写入日志前会脱敏 URL 路径与查询参数，避免 Telegram bot token、Gotify token、Server酱 SendKey 等进入日志或备份。

## 两步验证

支持 TOTP（如 Google Authenticator、1Password 等）。启用后登录需要输入动态验证码，TOTP 验证有独立的频率限制，且同一验证码在有效窗口内不能重复使用。

启用 TOTP 需要重新输入当前密码，避免被盗会话把验证器绑定到攻击者设备。通过邮箱重置密码时会同时关闭 TOTP，作为丢失验证器后的恢复手段；请确保邮箱本身安全。修改密码、邮箱、安全入口、关闭 TOTP、切换二次验证方式和恢复备份等验证操作均有独立失败限流。

## 频率限制

以下操作均有限流，按客户端 IP 或账户维度计数：

- 初始化管理员
- 登录（IP 与账户分别限流）与 TOTP 验证
- 忘记密码 / 重置密码
- 安全入口探测
- 修改密码、邮箱、安全入口、启用/关闭 TOTP、二次验证、恢复备份等操作
- 备份下载、私有 CA 私钥导出、证书私钥导出、通知测试和私有 CA 生成
- DNS/部署凭据、任务、ACME 配置与私有 CA 的敏感变更
- ACME 账户创建、订单创建、全部 ACME 协议请求（含 new-nonce/directory）以及 CRL/OCSP 请求

触发限流时返回 `429`，并带有 `Retry-After` 头。

## ACME 服务端

内置 ACME 服务端默认开启，但在创建并启用端点前不会对外签发证书。启用后它提供独立的协议入口，不使用管理端安全入口、会话 Cookie 或 CSRF 校验；不需要该入口时可在 `config.yaml` 中将 `acme.enabled` 设为 `false`。

- 公网部署建议使用独立端口，并在防火墙或反向代理层限制访问。
- 每个 ACME 端点必须配置域名白名单；启用端点时白名单为空会被拒绝。
- EAB 可开关，默认建议开启。关闭 EAB 时，任何能访问该端口的人都可以创建账户，必须配合域名白名单、mTLS 或网络 ACL。
- mTLS 是传输层门禁，不能替代 ACME 的 JWS 账户认证。
- `acme.base_url` 应配置为固定公网地址，避免 Host 头注入导致资源 URL 指向错误位置。
- HTTP-01 验证默认拒绝回环、私网、链路本地及 CGNAT/保留网段（如 `100.64.0.0/10`、`192.0.0.0/24`）；内网场景需要通过端点级 CIDR 白名单显式放行。
- ACME 协议资源使用随机公开 ID，不使用数据库自增 ID。
- 单实例部署使用内存 nonce；服务重启后客户端会收到 `badNonce` 并自动重试。
- CRL 与 OCSP 端点位于 `/pki/{ca}/...`，通常需要公网可达；它们按 CA 组织，即使停用 ACME 报名端点也应保持可用。`acme.addr` 留空时会与 `/acme/` 一起挂载到主端口；使用独立端口时由独立监听提供。
- 启用 ACME 时建议配置固定的 `acme.base_url`（或 `security.public_url`）；未配置时会按请求 Host 推导资源 URL，公网部署不应依赖该回退。
- CRL/OCSP 端点按 IP 限流；CRL 会缓存相同吊销集合的结果，只有吊销内容变化时才递增 CRL Number，避免匿名请求放大签名和数据库写入开销。
- ACME 服务端限流会读取 `server.trusted_proxies` 中的可信代理，并按真实客户端 IP 计数；反代场景请正确配置可信代理，否则所有客户端会共享代理 IP 的配额。
- CRL/OCSP 只对会主动检查吊销状态的客户端生效；浏览器对私有 CA 的检查行为不一致。存量证书需要重新签发才能带上 CRL/OCSP 地址。

站点证书监控会读取目标证书并校验域名与系统信任链；链不受信任、链不完整或主机名不匹配都会标记为异常，避免中间人用自签证书掩盖真实证书问题。

## 反向代理

当 Nginx、Caddy、Traefik 等反向代理终止 TLS 时：

1. 将代理地址加入 `server.trusted_proxies` 或 `LACTSSL_TRUSTED_PROXIES`，例如 `127.0.0.1,10.0.0.0/8`。
2. 确保代理传递 `X-Forwarded-For`、`X-Forwarded-Proto` 等标准头。
3. 配置 `security.public_url` 为代理后的固定公网地址，密码重置等邮件链接不会依赖请求 Host。
4. 生产环境始终通过 HTTPS 访问，避免安全入口、Cookie 和密码在明文链路上传输。

未配置可信代理时，服务不会信任代理头，所有请求会被视为来自代理 IP，导致按 IP 的限流失效、`Secure` Cookie 判断错误。

注意：如果 TLS 已在代理终止，而后端仍按 HTTP 访问，需要确认代理正确传递 `X-Forwarded-Proto`，否则会话 Cookie 的 `Secure` 属性可能不符合预期。

## 部署建议

- 使用独立用户运行服务，`config.yaml` 保持 `0600`，数据目录保持 `0700`。
- Docker 镜像通过入口脚本修正卷权限后，使用非 root 的 `lactssl` 用户运行主程序；Compose 默认丢弃全部 capabilities 后按需添加 `CHOWN`/`SETUID` 等，并启用只读根文件系统、`/tmp` tmpfs、`pids_limit` 与 `init`。
- 不要把 `data/`、`config.yaml` 提交到版本库或放入公开目录。
- 定期检查「日志」页面中的异常登录、入口探测和部署失败记录。
- 公网部署时启用 TOTP，并使用较长的随机安全入口。管理员会话等价于完全控制（包括本地部署命令执行与私有 CA 签发），请勿在共享浏览器或不可信设备上保持登录。
- 服务默认限制普通接口请求体为 2 MiB（备份恢复除外），并设置读写超时；反向代理层也建议配置请求体大小和超时。
