# 安全

## 安全入口

管理页面不直接暴露在根路径，而是先通过随机生成的安全入口进入：

```text
https://your-domain/<entry>/
```

- 入口默认随机生成 20 位大小写字母与数字组合，保存在数据库中。
- 未通过入口的页面与接口统一返回 `404`，包括裸 `/`、`/api` 等常见探测路径。
- 访问正确入口后会写入一个有效期为 24 小时的签名 `HttpOnly` 门禁 Cookie，然后跳转到 `/login`；只有携带该 Cookie（或已登录）才可打开登录页。
- 入口探测有频率限制，避免被暴力枚举。
- 可在「设置 → 安全入口」中修改，修改后立即生效。

入口是额外的一层防护，不能替代 HTTPS 和强密码。

## 会话与 CSRF

- 登录会话保存在 `HttpOnly` Cookie 中，前端脚本无法读取。
- 所有会改变服务端状态的请求（POST/PUT/DELETE 等）必须携带 `X-LACTSSL-CSRF` 请求头，否则拒绝。
- 显式使用 `Authorization: Bearer <token>` 调用 API 时不受 CSRF 校验约束，便于脚本或外部集成。

## 凭据保护

- 管理员密码使用 bcrypt 哈希存储。
- DNS 凭据、部署凭据、SMTP 密码、通知 Token 等敏感字段使用 AES-256-GCM 加密后写入数据库。
- 目标凭据只保存认证与连接信息；部署路径、站点、域名等参数保存在任务流程中，不属于凭据配置的加密范围。
- 加密密钥来自 `config.yaml` 的 `security.salt`；JWT 使用 `security.jwt_secret` 签名。
- 接口返回配置时会对密钥字段脱敏，编辑时留空表示保留原值。

因此 `config.yaml` 与 `data/` 同等重要，请一并备份并限制访问权限。

## 两步验证

支持 TOTP（如 Google Authenticator、1Password 等）。启用后登录需要输入动态验证码，TOTP 验证有独立的频率限制。

## 频率限制

以下操作均有限流，按客户端 IP 或账户维度计数：

- 初始化管理员
- 登录（IP 与账户分别限流）与 TOTP 验证
- 忘记密码 / 重置密码
- 安全入口探测

触发限流时返回 `429`，并带有 `Retry-After` 头。

## ACME 服务端

内置 ACME 服务端默认关闭。启用后它提供独立的协议入口，不使用管理端安全入口、会话 Cookie 或 CSRF 校验。

- 公网部署建议使用独立端口，并在防火墙或反向代理层限制访问。
- 每个 ACME 端点必须配置域名白名单；启用端点时白名单为空会被拒绝。
- EAB 可开关，默认建议开启。关闭 EAB 时，任何能访问该端口的人都可以创建账户，必须配合域名白名单、mTLS 或网络 ACL。
- mTLS 是传输层门禁，不能替代 ACME 的 JWS 账户认证。
- `acme.base_url` 应配置为固定公网地址，避免 Host 头注入导致资源 URL 指向错误位置。
- HTTP-01 验证默认拒绝回环、私网和链路本地地址；内网场景需要通过端点级 CIDR 白名单显式放行。
- ACME 协议资源使用随机公开 ID，不使用数据库自增 ID。
- 单实例部署使用内存 nonce；服务重启后客户端会收到 `badNonce` 并自动重试。
- CRL 与 OCSP 端点位于 `/pki/{ca}/...`，通常需要公网可达；它们按 CA 组织，即使停用 ACME 报名端点也应保持可用。
- CRL/OCSP 只对会主动检查吊销状态的客户端生效；浏览器对私有 CA 的检查行为不一致。存量证书需要重新签发才能带上 CRL/OCSP 地址。

## 反向代理

当 Nginx、Caddy、Traefik 等反向代理终止 TLS 时：

1. 将代理地址加入 `server.trusted_proxies` 或 `LACTSSL_TRUSTED_PROXIES`，例如 `127.0.0.1,10.0.0.0/8`。
2. 确保代理传递 `X-Forwarded-For`、`X-Forwarded-Proto` 等标准头。
3. 生产环境始终通过 HTTPS 访问，避免安全入口、Cookie 和密码在明文链路上传输。

未配置可信代理时，服务不会信任代理头，所有请求会被视为来自代理 IP，导致按 IP 的限流失效、`Secure` Cookie 判断错误。

注意：如果 TLS 已在代理终止，而后端仍按 HTTP 访问，需要确认代理正确传递 `X-Forwarded-Proto`，否则会话 Cookie 的 `Secure` 属性可能不符合预期。

## 部署建议

- 使用独立用户运行服务，`config.yaml` 保持 `0600`，数据目录保持 `0700`。
- 不要把 `data/`、`config.yaml` 提交到版本库或放入公开目录。
- 定期检查「日志」页面中的异常登录、入口探测和部署失败记录。
- 公网部署时启用 TOTP，并使用较长的随机安全入口。
