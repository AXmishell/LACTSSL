# 外掛治理

LACTSSL 的 DNS、證書部署與通知能力都由外掛提供。主程式只負責載入外掛、執行一次性 helper 子程序，並管理安裝、啟用與解除安裝。對企業而言，外掛不是普通擴充套件，而是**供應鏈邊界**：

- DNS 外掛接收網域服務商 API 憑據。
- 部署外掛接收證書與私鑰。
- 通知外掛接收渠道 Token/Webhook。
- 所有外掛以服務帳號執行，等同受信程式碼。

因此外掛應納入變更管理和准入審查，而不是由任意使用者隨時安裝。

## 1. 外掛模型

- **按型別合併包**：官方外掛倉庫按型別構建合併包：DNS 全量·重構、DNS 全量·lego、DNS 全量·lego v5、部署、通知。每個包內含該型別多個實現，共享一份 Go 執行時。
- **按需安裝**：主程式釋出包不內建任何外掛；需要哪一類能力就安裝對應的合併包。
- **協議 v1**：外掛是可執行檔案，透過 `manifest`、`present/cleanup`、`deploy`、`send` 等子命令與主程式通訊。
- **獨立目錄**：
  - DNS：`<data_dir>/plugins/dns`
  - 部署：`<data_dir>/plugins/deploy`
  - 通知：`<data_dir>/plugins/notify`
- **一次性子程序**：每次呼叫啟動、執行完退出，不常駐記憶體。

## 2. 倉庫與信任

```yaml
plugins:
  repo:
    enabled: true
    url: "https://github.com/AXmishell/LACTSSL-Plugins/releases/download/plugin-index/index.json"
    channel: stable
    auto_update: false
    public_key: "t7Q4vd0B1zh3mRf0t6Q6qlBViL7cKhoipgpGWx5WSss="
    timeout_seconds: 30
    max_download_mb: 256
    check_interval_hours: 24
```

也可以在「外掛」頁修改倉庫地址、渠道、自動更新和公鑰。介面設定儲存在資料庫，優先順序高於 `config.yaml`，但不會寫回配置檔案。

### 2.1 校驗鏈

1. 配置公鑰時，強制校驗 `index.json.sig`（Ed25519）。
2. 本地快取索引額外使用服務端金鑰做 HMAC 保護。
3. 下載前要求索引提供 asset SHA-256；缺失或格式錯誤直接拒絕。
4. 下載後強制校驗 asset SHA-256。
5. 安裝時校驗 `plugin.json`、manifest 中的 ID 與版本、平臺和 `min_host`。
6. 安裝記錄儲存檔案摘要；發現、註冊和每次 DNS/部署/通知呼叫前複核，檔案被替換時拒絕載入或執行。
7. 任一步失敗都會回滾，不留下半成品。

未配置簽名公鑰時會顯示風險提示，且跳過無人值守自動更新。生產環境不建議關閉驗籤。

## 3. 企業部署模式

### 3.1 官方倉庫直連

適用：網路可訪問 GitHub，外掛數量少，能接受官方倉庫作為信任源。

要求：

- 配置官方公鑰並強制驗籤。
- 關閉自動更新，按變更視窗手動升級。
- 記錄每次安裝/升級的版本和摘要。

### 3.2 內部映象（推薦）

適用：生產環境、離線/半離線、需要固定版本和准入審查。

方式一：把索引指向內部 HTTPS 映象：

```yaml
plugins:
  repo:
    url: "https://mirror.example.com/lactssl-plugins/index.json"
    public_key: "<企業簽名公鑰>"
```

方式二：離線目錄：

```yaml
plugins:
  repo:
    url: "file:///srv/lactssl-plugins/index.json"
```

內部映象應做到：

- 同步官方索引和資產，保留原始 SHA-256。
- 用企業自己的 Ed25519 金鑰重新簽名索引，或至少校驗官方簽名後再提供。
- 只同步經過准入的版本，不自動跟隨 `latest`。
- 映象目錄只讀，只有同步帳號可寫。
- 記錄版本、來源、摘要、審批人和回滾版本。

### 3.3 手動上傳

可以在「外掛」頁上傳單個 helper，或把檔案放入外掛目錄後重掃。適用於臨時驗證或第三方外掛。

- 上傳僅接受單個 helper 可執行檔案，最大 256 MB。
- 上傳後先以臨時檔案探測 `manifest`，校驗協議、ID 和 SHA-256，透過後才寫入外掛目錄並重掃。
- 預設拒絕覆蓋同名檔案；升級時可勾選“允許覆蓋同名外掛”，舊檔案會先備份。
- 手動上傳的外掛標記為 `manual`，不參與官方倉庫升級。
- 只上傳可信檔案；helper 以服務帳號執行。

## 4. 安裝與啟用

### 4.1 安裝

1. 開啟「外掛」頁，確認倉庫地址，點選「重新整理索引」。
2. 開啟「外掛市場」，按 DNS / 部署 / 通知篩選或搜尋。
3. 安裝需要的外掛；完成後先啟用外掛檔案，再按需啟用其中的條目。

每個外掛顯示：

- 名稱、ID、版本、大小。
- 當前平臺是否有安裝包。
- 是否相容當前宿主版本。
- 已安裝版本與可更新狀態。

新下載或上傳的外掛預設停用：helper 檔案以停用狀態落盤，不會執行 `manifest`；啟用檔案後，其中的條目仍然預設停用。升級或覆蓋同名檔案保留原啟用狀態。

### 4.2 兩級啟用

外掛頁每一行對應一個 helper 檔案，啟用狀態分為兩層：

1. **檔案級**：行首開關控制 helper 是否參與發現與載入。停用後不再執行該檔案的 `manifest`，其中條目也不會註冊到執行時；已有條目勾選會保留，重新啟用檔案後恢復。
2. **條目級**：點選「管理條目」逐個啟用服務商、部署目標或通知渠道，也可以勾選後批次啟用/停用。新安裝外掛的條目仍預設停用。

說明：

- 檔案停用時其條目仍會顯示（來自宿主快取的 manifest 摘要），但開關置灰，需先啟用檔案。
- 合併包（例如提供 194 個條目的 `lactssl-dns-all-native`）不會被行首開關一次性全開；一次啟用超過 10 個條目會要求確認。
- 刪除檔案或解除安裝外掛會同時清理 manifest 快取、檔案級狀態，並從條目白名單移除該檔案的全部條目。

## 5. 更新、回滾與解除安裝

- **更新**：在外掛市場點選「更新」，或開啟自動更新後按 `check_interval_hours` 定期檢查。
- **批次更新**：`POST /api/plugins/repo/update` 空請求體表示更新全部已安裝外掛。
- **回滾**：生產建議在內部映象保留上一版本；升級失敗時重新安裝舊版本。
- **解除安裝**：只允許解除安裝由外掛倉庫安裝的外掛；解除安裝會刪除外掛檔案、安裝記錄，並從啟用白名單移除。
- **刪除檔案**：每個外掛頁籤都會列出外掛目錄中的實際 helper 檔案（含手動上傳與舊版全量 bundle），可直接刪除；刪除會移除該檔案提供的全部條目、安裝記錄與啟用狀態，並立即重掃。

升級採用“下載 → 校驗 → 備份 → 原子替換 → manifest 校驗”的流程；任一步失敗都會恢復舊檔案。

### 5.1 變更流程建議

1. 在預發環境安裝目標版本。
2. 驗證 `manifest`、條目列表和關鍵鏈路（DNS 簽發、部署、通知）。
3. 記錄版本、摘要和測試結果。
4. 生產變更視窗內升級，觀察任務日誌。
5. 失敗時回滾到映象中的上一版本。

## 6. 包體積與資源

外掛市場顯示的大小按**解壓後**計算，也就是安裝到磁碟上的實際 helper 大小。當前官方合併包（linux/amd64）約為：

| 包 | 解壓後 |
|---|---:|
| DNS 全量·重構（194 個服務商） | 約 18 MiB |
| DNS 全量·lego（194 個服務商） | 約 58 MiB |
| DNS 全量·lego v5（235 個條目） | 約 37 MiB |
| 部署（25 個目標） | 約 8 MiB |
| 通知（23 個渠道） | 約 7 MiB |

- 大多數使用者安裝約 18 MiB 的 DNS 全量·重構包即可覆蓋全部 194 個服務商。
- 需要完整 lego v4 能力（例如 rfc2136 GSS-TSIG）時安裝約 58 MiB 的 DNS 全量·lego 包。
- 想跟進 lego v5 與新增 provider 時安裝約 37 MiB 的 DNS 全量·lego v5 包；三個 DNS 包互斥。
- 全部安裝約 73 MiB，仍比 224 個單外掛包約 1.7 GiB 的解壓總量低約 96%。

安裝/更新解包會帶來瞬時記憶體峰值；容量規劃需留餘量，見[部署架構](architecture.md)。

## 7. 舊版全量外掛遷移

升級前使用過 `lactssl-dns-helper-extra`、`lactssl-deploy-helper` 或 `lactssl-notify-helper` 的部署，會在「外掛」頁看到遷移提示：

1. 系統讀取舊外掛的 manifest，找出當前已啟用或仍被帳戶/任務使用的服務商。
2. 下載對應的合併包並安裝；合併包會覆蓋舊版單服務商/舊全量 helper。
3. 全部成功後刪除舊檔案並重掃。
4. 任一步失敗則回滾本次安裝，舊外掛繼續可用。

遷移完成前舊外掛不會被刪除，避免正在簽發的站點中斷。

## 8. 服務商圖示

DNS 與部署服務商的 logo 屬於外掛後設資料，由外掛倉庫下發，主程式不再內建圖示表：

- **未安裝時**：倉庫索引 `icons` 內聯圖示，隨索引簽名校驗，用於外掛市場展示。
- **安裝後**：外掛包內 `icons/` 寫入 `<data_dir>/plugin-icons/<kind>/<外掛 ID>/`，斷網或關閉倉庫後憑據頁仍能顯示。
- **讀取介面**：前端透過 `GET /api/plugins/icons` 一次拉取；未提供圖示、圖示損壞或舊版本宿主時回退為首字母頭像。
- **別名**：`aliyun_cdn`、`baota_site`、`qiniu_kodo` 等歷史 ID 由倉庫 `assets/icons/icons.json` 對映到規範圖示。
- **合併包圖示**：只使用包 ID 對應的包級圖示；未提供包級圖示時直接不展示，或由包條目宣告 `hide_icon: true` 強制關閉。

圖示僅允許 svg / png / webp，單張不超過 64 KB；非法條目會被丟棄，不影響外掛安裝與升級。

## 9. 安全控制

- 只使用可信倉庫；生產配置簽名公鑰並強制驗籤。
- 下載前要求 asset SHA-256，安裝後複核檔案摘要。
- 部署外掛接觸私鑰，預設關閉，只安裝可信來源。
- 外掛目錄 `0700`，helper `0755`，不允許組或其他使用者寫入。
- 不允許符號連結；檔案被替換時拒絕載入。
- 限制 `memory_limit_mb`、`timeout_seconds` 和 `max_output_kb`，避免異常外掛拖垮主機。
- 外掛以服務帳號執行，不要給 `lactssl` 使用者額外權限，也不要讓外掛目錄位於共享可寫路徑。
- 記錄外掛安裝/升級/解除安裝操作，納入變更審計。

## 10. API

| 方法 | 路徑 | 說明 |
|---|---|---|
| GET | `/api/plugins` | 外掛狀態、條目與目錄中的 helper 檔案 |
| GET | `/api/plugins/repo` | 倉庫配置與索引狀態 |
| PUT | `/api/plugins/repo` | 修改配置 |
| POST | `/api/plugins/repo/refresh` | 強制重新整理索引 |
| GET | `/api/plugins/repo/plugins` | 倉庫外掛列表 |
| POST | `/api/plugins/repo/install` | 安裝 `{kind,id,version}` |
| POST | `/api/plugins/repo/update` | 更新 `{kind,id}` 或全部 |
| DELETE | `/api/plugins/repo/plugins/:kind/:id` | 解除安裝 |
| DELETE | `/api/plugins/files/:kind/:file` | 刪除外掛目錄中的 helper 檔案 |
| GET | `/api/plugins/repo/legacy` | 檢測舊版全量外掛 |
| POST | `/api/plugins/repo/migrate` | 遷移 `{kind}` |

外掛管理需要 `plugins:read` / `plugins:write`。上傳、安裝、更新、解除安裝和修改倉庫配置都屬於敏感操作。

## 11. 排障

| 現象 | 原因 | 處理 |
| --- | --- | --- |
| 索引拉取失敗 | 倉庫地址、網路代理、TLS 證書 | 先用瀏覽器訪問 `index.json`；檢查出站策略 |
| 簽名校驗失敗 | 公鑰與倉庫簽名金鑰不匹配 | 核對公鑰；不要在生產隨意清空 `public_key` |
| 平臺不可用 | 當前平臺沒有對應外掛包 | 檢查 `GOOS/GOARCH` 和索引 `assets` |
| 宿主版本不相容 | 外掛 `min_host` 高於當前版本 | 升級宿主或安裝相容版本 |
| ID 衝突 | 同一服務商已由舊 bundle 或手動外掛提供 | 完成遷移或解除安裝舊檔案 |
| 安裝後未出現 | 對應外掛型別未啟用或條目未啟用 | 檢查 `plugins.enabled`、`deploy_plugins.enabled`、`notify_plugins.enabled` 和條目開關 |
| 檔案被拒絕 | 組/其他使用者可寫、符號連結、摘要不一致 | 修正權限或重新安裝 |

更多排障見[監控與排障](troubleshooting.md)。

## 12. 外掛准入清單

- [ ] 來源：官方倉庫或企業內部映象，版本固定。
- [ ] 完整性：索引簽名、asset SHA-256、安裝記錄摘要校驗透過。
- [ ] 權限：外掛目錄和檔案權限符合要求。
- [ ] 風險：部署外掛是否接觸私鑰；通知外掛是否持有長期 Token。
- [ ] 相容：宿主版本、平臺、`min_host` 匹配。
- [ ] 測試：預發環境完成 DNS/部署/通知鏈路驗證。
- [ ] 回滾：保留上一版本和回滾步驟。
- [ ] 記錄：版本、摘要、審批人、安裝時間、變更單。
