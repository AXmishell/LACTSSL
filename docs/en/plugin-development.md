# Development: plugin protocol and contribution guide

This page is intended for plugin developers, integrators, and enterprise platform teams. It describes the LACTSSL plugin protocol, repository layout, development workflow, build, packaging, index, signing, and release process. **Operations staff usually only need [Plugin governance](plugins.md) and the relevant DNS, deployment, or notification plugin pages.**

Official DNS/deploy/notify implementations live in `internal/plugin/impl/` and are compiled into the host. `plugins/` is the external plugin development SDK (protocol, helper framework, and shared utilities). Uploaded plugins still use protocol v1 subprocesses. The host no longer uses a plugin index or external plugin repository.

Generators, bundle packaging, and index tooling described below live in `internal/plugin/impl/`, and commands are run from that directory. External plugins only need `plugins/protocol` and `plugins/sdk`.

## 1. Architecture

A plugin is not a dynamic library. It is a **one-shot subprocess**:

```text
LACTSSL host
  └─ exec lactssl-dns-all-native <subcommand>
       ├─ manifest          emit self-describing JSON
       ├─ present / cleanup stdin JSON → write/remove TXT → exit
       ├─ verify            read-only probe (optional)
       └─ exit 0 on success; non-zero on failure, errors on stderr
```

Four helpers:

| Helper | Type | Subcommands |
|---|---|---|
| `cmd/dns-helper` | DNS (v4 / native) | `manifest` / `present` / `cleanup` / `verify` |
| `cmd/dns-helper-v5` | DNS (lego v5) | `manifest` / `present` / `cleanup` / `verify` |
| `cmd/deploy-helper` | Certificate deployment | `manifest` / `deploy` / `options` / `plan` / `verify` |
| `cmd/notify-helper` | Notification | `manifest` / `send` |

The plugin repository is a **modular monolith**:

- one directory per provider;
- metadata, translations, and icons are split per provider;
- aggregate files are generated by `make manifest` and must not be edited by hand;
- multiple contributors can work in parallel with minimal file conflicts.

## 2. Protocol v1

The protocol remains `v1`; only breaking changes bump it to `v2`. New capabilities are added through optional fields and feature flags. Older hosts ignore unknown fields.

### 2.1 Subcommands and output

DNS:

```text
dns-plugin manifest
dns-plugin present   # stdin JSON
dns-plugin cleanup   # stdin JSON
dns-plugin verify    # stdin JSON
```

Deployment:

```text
deploy-plugin manifest
deploy-plugin deploy
deploy-plugin options
deploy-plugin plan
deploy-plugin verify
```

Notification:

```text
notify-plugin manifest
notify-plugin send
```

Conventions:

- Exit code `0` means success; any non-zero value means failure. stderr goes to the host log.
- DNS `present` / `cleanup` must keep stdout empty.
- Deployment `deploy` keeps stdout empty on success; `verify` / `options` / `plan` emit JSON.
- Notification `send` emits `{"ok":true,"message":""}` on success; failures also emit `{"ok":false,...}` and exit non-zero.
- Requests and responses are UTF-8 JSON, with non-ASCII characters unescaped.

### 2.2 Environment variables

| Variable | Meaning |
|---|---|
| `LACTSSL_PLUGIN_PROTOCOL` | Protocol version, currently `v1` |
| `LACTSSL_PLUGIN_MEMORY_LIMIT` | Resident memory budget in bytes; helpers should call `debug.SetMemoryLimit` |
| `LACTSSL_DNS_PLUGIN_FEATURES` | Comma-separated DNS feature flags |
| `LACTSSL_DEPLOY_PLUGIN_FEATURES` | Comma-separated deployment feature flags |

Current features:

| Feature | Meaning |
|---|---|
| `merged-deployers-v1` | Deployment targets emit only canonical merged IDs |
| `dynamic-options-v1` | Support `options` and `options_source` / `multiple` |
| `verify-v1` | Support read-only `verify` |
| `plan-v1` | Support `plan` pre-matching |

### 2.3 Security conventions

- Private keys and tokens are passed only through stdin, never argv or environment variables.
- The host passes only a minimal environment variable set.
- Helper files must be executable and must not be writable by group or other users; symbolic links are rejected.
- The host polls `VmRSS` and terminates the process group when it exceeds `memory_limit_mb`.
- `manifest.sha256` may be left empty; repository installs rely on the index asset SHA-256 and installation records.

## 3. Repository layout

```text
protocol/                    protocol v1 wire format
sdk/                         shared HTTP, signing, DNS utilities, helper framework
outbound/                    SSRF-safe outbound HTTP client
catalog/
  dns/<id>.json              per-provider DNS metadata (hand-written)
  deploy/<id>.json           per-target deployment metadata (hand-written)
  migrations.json            historical deploy IDs and migrations
  data.json                  generated: aggregated metadata
i18n/
  core/<locale>.json         shared translations
  providers/<kind>/<id>/     per-provider translations
  locales/<locale>.json      generated: aggregated translations
dns/providers/<id>/          lego v4 wrappers (generated)
dns/native/providers/<id>/   native DNS implementations (hand-written)
dns/groups/                  generated: DNS groups
dnsv5/                       lego v5 wrappers, groups, metadata (generated)
deploy/providers/<id>/       deployment targets (hand-written)
notify/providers/channels/   one channel_<id>.go per channel
cmd/                         helper entrypoints
assets/icons/                icons
plugins.json                 generated: bundle manifest
scripts/                     generators and build tooling
```

Generated files:

```text
catalog/data.json
i18n/locales/*.json
cmd/dns-helper/group_*.go
cmd/deploy-helper/imports_gen.go
dns/groups/**
dnsv5/**
plugins.json
```

After changing source files, run:

```bash
make manifest
```

It runs `catalog`, `i18n`, `deployimports`, `gen-v5`, then regenerates `plugins.json` and groups. CI verifies the generated files; same-repository PRs are updated by the `Update generated files` bot.

## 4. Developing a DNS provider

### 4.1 Native implementation

Location: `dns/native/providers/<id>/provider.go`

```go
package example

import (
    "github.com/AXmishell/LACTSSL-Plugins/dns"
    "github.com/AXmishell/LACTSSL-Plugins/sdk/dnsutil"
)

type plugin struct{}

func (plugin) ID() string        { return "example" }
func (plugin) Aliases() []string { return nil }
func (plugin) New(cfg map[string]string) (dns.ChallengeProvider, error) {
    return newProvider(cfg)
}

func init() {
    dns.Register(plugin{})
    // Declare only when Verify is implemented:
    // dns.MarkVerifiable("example")
}
```

`ChallengeProvider` has only two methods:

```go
Present(domain, token, keyAuth string) error
CleanUp(domain, token, keyAuth string) error
```

DNS-01 rules:

- Write `dnsutil.TXTValue(keyAuth)`, not the raw `keyAuth`.
- Use `dnsutil.ChallengeFQDN(domain)`.
- Use `dnsutil.ZoneName` for zone matching and `dnsutil.RelativeName` for relative names.
- `CleanUp` removes only this challenge value and preserves other TXT records; missing records are treated as success.
- Keep TTL defaults consistent with lego (usually 60s).

Optional read-only verification:

```go
func (p *provider) Verify(ctx context.Context, domain string) (string, error)
```

After implementing it, call `dns.MarkVerifiable("example")`; otherwise the host will not invoke `verify`.

### 4.2 lego v4 wrappers

`dns/providers/<id>` is generated:

```bash
go run scripts/gen_dns_plugins/main.go
make manifest
```

Do not edit generated files. Change the generator or `catalog/dns/<id>.json` when adjusting aliases, fields, or environment variables.

### 4.3 lego v5

```bash
make gen-v5
make manifest
```

The generator rewrites `dnsv5/providers`, `dnsv5/legacy`, `dnsv5/groups`, and `dnsv5/meta`. Fields for new v5 providers come from upstream `.toml`; existing catalog entries keep their historical fields.

### 4.4 Metadata and translations

Example `catalog/dns/<id>.json`:

```json
{
  "value": "example",
  "label_key": "meta.dns.example.label",
  "desc_key": "meta.dns.example.desc",
  "fields": [
    {
      "key": "token",
      "label_key": "meta.field.token.label",
      "type": "password",
      "required": true,
      "env": "EXAMPLE_TOKEN"
    }
  ]
}
```

`env` applies only to lego wrappers; native implementations read `cfg["token"]` directly.

Translations:

```text
i18n/providers/dns/<id>/zh-CN.json
i18n/providers/dns/<id>/en-US.json
```

Shared field labels live in `i18n/core/<locale>.json`. Missing translations fall back to the default language, then to `label` / `value`.

## 5. Developing a deployment target

Location: `deploy/providers/<id>/plugin.go`

```go
type plugin struct{}

func (plugin) ID() string        { return "example" }
func (plugin) Aliases() []string { return nil }
func (plugin) Deploy(ctx context.Context, req deploy.Request) error { ... }

func init() { deploy.Register(plugin{}) }
```

Optional capabilities:

| Interface | Purpose | Declaration |
|---|---|---|
| `deploy.Verifier` | Read-only credential/target check | `deploy.MarkVerifiable("example")` |
| `deploy.OptionLister` | Dynamic select options | catalog `options_source` |
| `deploy.Planner` | Read deployable objects before batch deploy | `deploy.MarkPlannable("example")` |

Steps:

1. Create `deploy/providers/<id>/plugin.go`.
2. Create `catalog/deploy/<id>.json` with `fields` and `deploy_fields`.
3. Create `i18n/providers/deploy/<id>/zh-CN.json` and `en-US.json`.
4. Run `make manifest` to generate `cmd/deploy-helper/imports_gen.go`.
5. Add `httptest` unit tests.

Security:

- User-controlled URLs must use `outbound.ValidateURL` / `outbound.ValidateWebhookURL`.
- Use `outbound.NewClient`; do not use `http.DefaultClient` for user URLs.
- `Verify` / `Plan` / `ListOptions` must not write certificates, create persistent objects, or reload services.
- Never include tokens or secrets in error messages.

Historical IDs are mapped to canonical targets via `deprecated_deploy_types` and `deploy_migrations` in `catalog/migrations.json`.

## 6. Developing a notification channel

Location: `notify/providers/channels/channel_<id>.go`

```go
package channels

func init() {
    registerChannel(newChannel("example", []notify.Field{
        text("url", "notifications.fieldServerUrl", true),
        password("token", "notifications.fieldToken", true),
    }, sendExample))
}

func sendExample(cfg map[string]any, msg notify.Message) error { ... }
```

Field helpers:

| Function | Purpose |
|---|---|
| `text` | Text |
| `password` | Password/secret |
| `number` | Number |
| `selectField` + `opt` | Select |
| `textarea` | Multi-line text |

Each channel is a separate file and self-registers via `init`; no shared list needs editing. Prefer `notifyJSON` / `notifyForm` / `notifyHTTP` and `outbound`.

## 7. Build

```bash
# all merged bundles
make bundle

# individual DNS variants
make bundle-lego
make bundle-native
make bundle-lego-v5
```

Build flags:

```bash
CGO_ENABLED=0 go build -trimpath \
  -tags "bundle_dns_all_native,nethttpomithttp2,http2legacy" \
  -ldflags "-s -w -X main.buildVersion=<version>" \
  -o lactssl-dns-all-native ./cmd/dns-helper
```

- `-trimpath` removes local paths.
- `-s -w` strips symbols and DWARF.
- `bundle_dns_all_lego` / `bundle_dns_all_native` select DNS groups.
- `nethttpomithttp2,http2legacy` avoids a Go 1.27 `net/http` / `x/net/http2` compatibility issue.
- lego v5 additionally uses `urfave_cli_no_template,ozzo_validation_no_template,grpcnotrace,validator_novalidatefn` to drop template code.

## 8. Packaging and index

Single package:

```bash
make plugin KIND=dns ID=all-native GOOS=linux GOARCH=amd64
```

Output:

```text
dist/
├── lactssl-dns-all-native_<version>_linux_amd64.tar.gz
└── lactssl-dns-all-native_<version>_linux_amd64.meta.json
```

Package contents:

```text
plugin.json
lactssl-dns-all-native
LICENSE
icons/<provider>.<svg|png|webp>
```

Index:

```bash
make index BASE_URL=https://github.com/AXmishell/LACTSSL-Plugins/releases/download
```

Index fields include `schema`, `channel`, `protocol`, `generated_at`, `plugins[]` (kind, id, version, bundle, providers, variant_of, conflicts_with, sdk, assets), per-platform `assets` with URL/SHA-256/size, and root-level inline `icons`.

### 8.1 Signing

```bash
go run scripts/pluginctl/main.go sign -key key.b64 -in index.json -out index.json.sig
```

`key.b64` is a base64-encoded Ed25519 private key (32-byte seed or 64-byte key). Production releases should require `PLUGIN_INDEX_SIGNING_KEY`; never publish an unsigned index by accident.

## 9. Version policy

- `all-lego` / `all-lego-v5` follow the lego versions in `go.mod`.
- Patch versions for `all-native`, `deploy/all`, and `notify/all` are derived from content fingerprints.
- Shared inputs (`protocol/`, `sdk/`, `i18n/`, `outbound/`, `catalog/`, `go.mod`) bump all affected bundles to avoid “same version, different binary”.
- Provider-specific source changes bump only the corresponding bundle type.
- Releases are driven by tags; manual non-tag releases use internal versions and must respect already published tag versions.

## 10. Collaboration

### 10.1 Branches and PRs

```text
main
  ↑
short-lived branch (1-3 days)
  ↑
PR → lint / generated / test / bundle / native → CODEOWNER review
  → merge queue → CI gate → merge
  → after-merge bot refreshes generated files
```

Requirements:

- No direct pushes to `main`.
- PR required; `CI gate` must pass.
- Merge Queue enabled.
- One provider / target / channel per PR.
- Let the bot regenerate aggregate files; do not hand-merge generated conflicts.

### 10.2 CODEOWNERS

The plugin repository `.github/CODEOWNERS` defines default owners. As the team grows, replace them with GitHub Teams for DNS native, lego, deploy, notify, and infra. Protocol/SDK/catalog schema/CI changes require core maintainer review.

### 10.3 Tiered CI

| Tier | Trigger | Contents |
|---|---|---|
| lint | every PR / merge queue | gofmt, go.mod/go.sum |
| generated | every PR / merge queue | `make manifest` + generated-file check |
| test | Go changes | `go vet ./...`, `go test ./...` |
| bundle | DNS/deploy/notify changes | build five helpers, manifest counts/parity, package smoke |
| native | DNS/SDK changes | `check_native.sh` |
| nightly | daily | `go test -race`, full build, govulncheck |

Branch protection only needs the **CI gate** check; skipped conditional jobs do not block the gate.

### 10.4 Merge Queue

Repository settings:

- Protect `main`.
- Require `CI gate`.
- Require linear history.
- Enable Merge Queue (max 5, timeout 5 minutes).
- Disallow direct pushes.
- Enable “Require branches to be up to date before merging”.

## 12. Testing requirements

- Use `httptest`; never call real APIs from unit tests.
- DNS: written value, cleanup only removes this value, idempotent missing-record cleanup, no matching zone.
- Deployment: success, auth failure, Verify/Plan perform no writes.
- Notification: missing config, request payload, non-2xx status.
- CI asserts manifest counts and fields.
- Native bundles additionally run `./scripts/check_native.sh`.

## 13. Pre-submit checklist

```text
[ ] only provider directory + matching catalog/i18n changed
[ ] init registration and unique ID/alias
[ ] catalog field keys match code
[ ] zh-CN and en-US translations added
[ ] unit tests use httptest
[ ] make manifest
[ ] gofmt / go vet / go test
[ ] check_native (native)
[ ] generated files committed or left to the bot
```
