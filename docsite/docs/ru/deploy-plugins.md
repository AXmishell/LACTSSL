# Плагины развёртывания

Плагины развёртывания доставляют сертификаты в FTP, Webhook, облачный CDN, панели и WAF. Это **высокорисковый компонент с доступом к закрытым ключам сертификатов**, поэтому включайте его в проверку и управление изменениями.

## Встроенные и плагинные цели

Все официальные цели встроены; категория «развёртывание» и цели по умолчанию включены, ненужные можно отключить.

| Цель | Описание |
| --- | --- |
| Локальный каталог / SSH / SFTP | Запись в путь или передача по SSH/SFTP; пароль или ключ, проверка отпечатка хоста |
| FTP / FTPS / Webhook | Обычный FTP, явный и неявный TLS; заголовки аутентификации, пропуск проверки TLS (не рекомендуется) |
| Alibaba Cloud CDN / Qiniu Cloud | Сертификат домена CDN или домен источника Kodo |
| Baota, Baota WAF, 1Panel, SafeLine WAF | Сайт, панель или WAF (по ID сертификата или домену) |
| Tencent Cloud / Volcano Engine / AcePanel и др. | Сверяйтесь с фактическим списком целей |

> **Цели развёртывания получают закрытые ключи сертификатов.** Устанавливайте helper только из доверенных источников; каталог плагинов должен быть доступен на запись только пользователю сервиса.

## Учётные данные и параметры развёртывания

«Учётные данные цели» хранят только аутентификацию и подключение: хост, порт, пользователя, пароль, адрес панели, API Token. Пути сертификатов, команды перезагрузки, домены и сайты задаются в узле «Развернуть сертификат» процесса задачи. Так одни учётные данные переиспользуются в задачах, ротация не влияет на оркестрацию, а параметры развёртывания попадают в историю версий задачи для аудита и отката.

## Конфигурация

```yaml
deploy_plugins:
  enabled: true           # цели включены по умолчанию; плагин получает доступ к закрытым ключам
  dir: ""                 # пусто означает <data_dir>/plugins/deploy
  memory_limit_mb: 128    # верхний предел постоянной памяти одного helper
  timeout_seconds: 300    # тайм-аут одного deploy, можно увеличить при загрузке больших файлов
  max_output_kb: 64       # верхний предел вывода helper
```

Изменения вступают в силу после перезапуска; при запуске выполняется автоматическое сканирование. После установки нового helper нажмите «Пересканировать плагины» или вызовите:

```bash
curl -X POST -H "Authorization: Bearer $LACTSSL_TOKEN" \
  https://ssl.example.com/api/plugins/rescan
```

## Установка и включение

1. Убедитесь, что в конфигурации указано `deploy_plugins.enabled: true` (значение по умолчанию), и перезапустите сервис после изменений.
2. Откройте вкладку развёртывания на странице «Плагины» и отключите ненужные цели.

Если категория отключена, доступны только локальный файл и SSH; прежние учётные данные не теряются. Состояние включения хранится в settings в `plugins.deploy.enabled_deployers`, сохраняется после перезапуска и пересканирования; объединённые цели отображаются в «Учётных данных цели» одной записью производителя.

## Рекомендации по целям

### Локальный каталог

- Пользователь сервиса должен иметь права на запись в целевой каталог; предпочитайте атомарную запись (временный файл, затем `rename`). Сбой команды перезагрузки (`nginx -s reload`, `systemctl reload nginx`) не откатывает файлы — сохраняйте предыдущую версию на целевой стороне.

### SSH / SFTP

- По умолчанию требуется отпечаток `SHA256:...`; TOFU применяется только при явном включении доверия при первом подключении, после смены ключа очистите старый отпечаток и запишите новый. Используйте выделенного пользователя с правом записи в целевой путь и точными правами на перезагрузку через sudoers; ключ храните под парольной фразой и ротируйте.

### FTP / FTPS

- По умолчанию используется явный TLS, открытый FTP — только при явном выборе `none`. Ключ и пароль передаются по сети, поэтому в производстве предпочитайте SFTP или FTPS и ограничивайте IP, порты и права на каталоги.

### Webhook

- Для публичных целей принудительно используется HTTPS; HTTP допускается для loopback, частных сетей, `.local`, `.internal`. Получатель Webhook должен быть доверенным (он получает сертификат и ключ): используйте отдельный Token, ограничение по IP и проверку подписи; не включайте «Пропускать проверку TLS», а внутренний CA импортируйте через «Системные настройки → Цепочка доверия TLS».

### Облачный CDN / панели / WAF

- Используйте выделённую субучётную запись с правами только на управление сертификатами; домен, сайт и имя сертификата должны совпадать с целевой системой (сайты Baota можно выбрать через API панели). Если включён белый список IP, разрешите исходящий адрес LACTSSL; после развёртывания проверьте действующий сертификат из-за кэша CDN/WAF.

## Записи развёртывания и проверка

- Каждое развёртывание создаёт запись; результат виден в сведениях о сертификате и журналах. При ручном развёртывании приоритетно используются параметры узла задачи; API-ключ с командой перезагрузки должен иметь `deploy:execute`. При сбое старый сертификат не откатывается автоматически — сохраняйте предыдущую версию или используйте атомарную публикацию.

Контрольный список проверки:

- [ ] Целевой путь/сайт указан верно, цепочка полная (fullchain), ключ соответствует сертификату.
- [ ] Служба перезагружена, все экземпляры/узлы обновлены, кэш CDN/WAF обновлён; клиент видит новый серийный номер или отпечаток.

## Офлайн- и ручная установка

- На странице «Плагины» загрузите один helper (не более 256 MB); он работает только при `deploy_plugins.enabled: true`. Проверяются `manifest`, ID цели и SHA-256, затем файл записывается в каталог плагинов и сразу выполняется пересканирование; перезапись одноимённого файла запрещена (старый сохраняется в копии), а плагин с ID встроенной цели помечается как «проигнорирован».

## Протокол Helper v1 (разработка интеграций)

```bash
deploy-helper manifest   # вывести JSON-манифест
deploy-helper deploy     # прочитать запрос из stdin и выполнить развёртывание
deploy-helper options    # прочитать динамические параметры раскрывающегося списка (необязательно)
deploy-helper verify     # проверить только для чтения аутентификацию и область действия цели (необязательно)
```

Пример вывода `manifest`:

```json
{
  "protocol": "v1",
  "capabilities": ["verify-v1"],
  "name": "example deploy helper",
  "version": "1.0.0",
  "sha256": "необязательная контрольная сумма файла helper",
  "deployers": [
    {
      "id": "example-panel",
      "name": "Example Panel",
      "name_i18n": {"zh-CN": "示例面板", "en-US": "Example Panel"},
      "capabilities": ["verify-v1"],
      "description": "Отправка сертификатов в панель Example",
      "description_i18n": {
        "zh-CN": "把证书推送到 Example 面板",
        "en-US": "Push certificates to an Example panel"
      },
      "aliases": ["example"],
      "fields": [
        {
          "key": "panel_url",
          "label": "Адрес панели",
          "label_i18n": {"zh-CN": "面板地址", "en-US": "Panel URL"},
          "type": "text",
          "required": true
        },
        {
          "key": "api_token",
          "label": "API Token",
          "label_i18n": {"zh-CN": "API Token", "en-US": "API Token"},
          "type": "password",
          "secret": true,
          "required": true
        }
      ],
      "deploy_fields": [
        {
          "key": "sites",
          "label": "Сайт",
          "label_i18n": {"zh-CN": "站点", "en-US": "Sites"},
          "type": "text",
          "required": true
        }
      ]
    }
  ]
}
```

Поля: `fields` — аутентификация и подключение в учётных данных цели (`secret: true` и `type: "password"` маскируются и шифруются), `deploy_fields` — параметры в узле «Развернуть сертификат». Ключи `key` не повторяются; типы полей: `text`, `password`, `textarea`, `number`, `select`, `switch`. `id` содержит только строчные буквы, цифры, подчёркивания и дефисы; плагины с ID встроенной цели игнорируются. Необязательные таблицы `*_i18n` задают тексты по языкам BCP 47 (до 32 языков).

stdin для `deploy`:

```json
{
  "action": "deploy",
  "protocol": "v1",
  "provider": "example-panel",
  "auth": {"panel_url": "https://panel.example.com", "api_token": "..."},
  "config": {"sites": "example.com,www.example.com"},
  "certificate": {
    "domain": "example.com",
    "domains": ["example.com", "www.example.com"],
    "issuer": "Let's Encrypt",
    "serial": "...",
    "not_before": "2026-01-01T00:00:00Z",
    "not_after": "2026-04-01T00:00:00Z",
    "cert_pem": "-----BEGIN CERTIFICATE-----...",
    "fullchain_pem": "-----BEGIN CERTIFICATE-----...",
    "key_pem": "-----BEGIN PRIVATE KEY-----..."
  }
}
```

stdin / stdout для `verify`:

```json
{"action": "verify", "provider": "example-panel", "auth": {"panel_url": "...", "api_token": "..."}, "config": {"sites": "example.com"}, "mode": "read", "locale": "zh-CN"}
```

```json
{"ok": false, "checks": [{"key": "auth", "status": "failed", "message": "invalid token"}]}
```

Соглашения:

- Код выхода `0` — успех, ненулевой — ошибка; stderr попадает в запись развёртывания с маскированием.
- stdout пуст или содержит одну строку JSON `{"ok": true, "message": "..."}`; `ok: false` считается ошибкой.
- `verify` — только чтение: не пишет сертификаты, не создаёт постоянные объекты и не выполняет `reload_command` (только тест записи `mode=write` создаёт и очищает временный объект); доступен целям с возможностью `verify-v1`, остальным показывается «версия плагина не поддерживает проверку». Значения `checks[].status`: `ok`, `failed`, `skipped`, `unsupported`, `error`.
- helper получает бюджет памяти из `LACTSSL_PLUGIN_MEMORY_LIMIT` (в байтах); при превышении `memory_limit_mb` завершается вся группа процессов, передаётся только минимальный набор переменных окружения.
- Дайджест файла записывается при сканировании и повторно проверяется перед развёртыванием; после замены helper требуется пересканирование.

## Рекомендации по безопасности

- Включайте только доверенные helper: цель может читать закрытые ключи и эквивалентна доверенному коду. Каталог `0700`, helper `0755`, владелец — пользователь сервиса; не размещайте его в общем пути с записью; указывайте `sha256` и обновляйте дайджест, а команды перезагрузки ограничивайте конкретным сервисом.

## Устранение неполадок

| Симптом | Причина | Действие |
| --- | --- | --- |
| В типах развёртывания только локальный/SSH | Категория не включена | Включите `deploy_plugins.enabled` и цели |
| Не удаётся загрузить helper или несовпадение отпечатка SSH | Права/дайджест/протокол/символическая ссылка; сервер сменил ключ | Исправьте права или переустановите; сверьте отпечаток и запишите заново |
| Целевая система использует старый сертификат | Нет перезагрузки/кэш/несколько экземпляров | Настройте перезагрузку, обновите кэш, проверьте узлы |
| Тайм-аут или отказ Webhook | Медленная цель, большой файл, публичный HTTP | Увеличьте `timeout_seconds`, проверьте сеть и TLS |
