# Быстрый старт

Запустите экземпляр в Docker, завершите инициализацию и выпустите первый сертификат. Обычно это занимает около 30 минут; перед производственной эксплуатацией см. раздел [Базовая безопасность](security.md).

## Подготовка

- Linux-хост с Docker (VPS, NAS или небольшой сервер)
- Домен и учётные данные DNS API
- Цель развёртывания (локальный каталог, SSH или панель)

## Запуск экземпляра

```bash
git clone https://github.com/AXmishell/LACTSSL.git
cd LACTSSL
mkdir -p config data
cp config.yaml.example config/config.yaml
chmod 600 config/config.yaml
chmod 700 data
docker compose up -d
docker compose logs -f lactssl
```

Репозиторий по умолчанию использует сеть `1panel-network`. Если 1Panel не используется, удалите оба блока `networks` в `docker-compose.yml` или сначала выполните `docker network create 1panel-network`. Образ GHCR доступен начиная с первого официального Release; если он ещё не опубликован, соберите локально по разделу [Установка и запуск](install.md).

## Инициализация

Журнал запуска выводит защищённую точку входа и одноразовый токен инициализации:

```text
Защищённая точка входа: http://127.0.0.1:8080/K7mQ2pX9vR4tY8nL6cWz/
Токен инициализации (действителен только для этого запуска): ...
```

Создайте учётную запись администратора через защищённую точку входа, включите TOTP или ключ доступа и задайте почту для восстановления. После завершения инициализации токен сразу становится недействительным; если точка входа забыта, задайте `security.entry` в `config.yaml` и перезапустите экземпляр, чтобы переопределить её.

> Защищённая точка входа не является границей безопасности. В продакшене обязательны HTTPS, надёжный пароль, TOTP/ключи доступа и контроль сетевого доступа.

## Включение плагинов

Официальные плагины DNS, развёртывания и уведомлений уже встроены, устанавливать их не нужно:

1. Откройте страницу «Плагины» и убедитесь, что соответствующие категории включены.
2. Включите нужных DNS-провайдеров, цели развёртывания или каналы уведомлений.
3. Для сторонних расширений при необходимости загрузите helper, см. [Управление плагинами](plugins.md).

DNS-провайдеры по умолчанию отключены, категория развёртывания включена по умолчанию.

## Выпуск первого сертификата

Сначала проверьте цепочку на частном CA, не зависящем от публичного DNS:

1. В разделе «Частный CA» создайте корневой CA (ECDSA P-256).
2. В разделе «Заявка на сертификат» создайте задачу, выберите этот частный CA в качестве удостоверяющего центра и укажите тестовый домен.
3. Добавьте узел «Развернуть сертификат», выберите «Локальный каталог», укажите пути к сертификату и закрытому ключу и необязательную команду перезагрузки.
4. Добавьте узел «Уведомление», выберите включённый канал и установите момент срабатывания «Всегда».
5. Запустите задачу вручную и убедитесь, что сертификат, запись о развёртывании и уведомление созданы успешно.

Затем добавьте публичную цепочку: создайте учётную запись DNS → выберите публичный CA → пройдите DNS-01 с тестовым доменом → разверните на цель → пронаблюдайте одно автопродление.

## Проверка

| Действие | Способ проверки |
| --- | --- |
| Резервное копирование и восстановление | Скачайте зашифрованную резервную копию и импортируйте её в изолированный экземпляр |
| Журналы | Фильтруйте и экспортируйте журналы операций и системные журналы |
| API | Вызовите `/api/certificates` с ключом только для чтения |
| Уведомления | Отправьте тестовое уведомление |
| Мониторинг | Добавьте внешний сайт и прочитайте его сертификат |

## Вывод в эксплуатацию

Проверьте 1–2 реальных домена, одну цель развёртывания и один сценарий внутреннего CA. Перед переключением продакшена выполните контрольный список вывода в эксплуатацию из [Базовой безопасности](security.md) и внедрите резервное копирование, мониторинг и процесс изменений согласно [Руководству по эксплуатации](operations.md).

Частые причины сбоев:

- Защищённая точка входа воспринимается как граница безопасности.
- Личная учётная запись DNS используется как API-учётные данные.
- Команда перезагрузки не проверена после обновления сертификата.
- Резервируется только база данных, но не `config.yaml`; после потери `salt` зашифрованные учётные данные невозможно расшифровать.
