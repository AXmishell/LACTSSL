# Справочник по конфигурации

Конфигурация берётся только из `config.yaml` и встроенных значений по умолчанию; переменные окружения уровня приложения не читаются. Изменения требуют перезапуска сервиса, но защищённая точка входа и состояние включения плагинов хранятся в базе данных и имеют приоритет над файлом.

## Модель файла конфигурации

По умолчанию читается `config.yaml` в рабочем каталоге, другой путь задаётся через `-config`.

- Если файла нет, он создаётся при первом запуске со случайными `jwt_secret` и `salt` (права `0600`); поведение HTTP-клиента Go настраивается переменными окружения, изменения вступают в силу после перезапуска, а точку входа можно менять в интерфейсе сразу. Пример — [`config.yaml.example`](https://github.com/AXmishell/LACTSSL/blob/main/config.yaml.example).

### Минимальная продуктивная конфигурация

```yaml
server:
  host: "127.0.0.1"
  port: 8080
  trusted_proxies: ["127.0.0.1"]

data_dir: "data"

security:
  public_url: "https://ssl.example.com"
  session_persistence: true

log:
  level: info
  format: json
  file: "data/logs/lactssl.log"
  also_stdout: true
  max_size_mb: 50
  max_backups: 10
  max_age_days: 30
  compress: true
  access_log: true
  system:
    enabled: true
    level: info
    access: false
    retention_days: 30
    max_rows: 200000
  archive:
    enabled: true
    compress: true
    retention_days: 0
    max_total_mb: 0
    quota_policy: fail
```

### Приоритет конфигурации

| Конфигурация | Источник | Описание |
| --- | --- | --- |
| Адрес прослушивания, журналы, ключи, ACME; защищённая точка входа | `config.yaml`; точка входа — база данных, `config.yaml` может переопределить | Файл — после перезапуска; точка входа меняется в интерфейсе сразу, непустой `security.entry` переопределяет при запуске |

### Редактирование файла конфигурации через веб-интерфейс

После входа в «Системные настройки → Файл конфигурации» можно изменить поля белого списка `config.yaml`: адрес прослушивания, доверенные прокси, `security.public_url`, сохранение сеансов, пороги ограничения скорости, ACME, журналы, обновление и параметры плагинов.

- Вкладка ограничения скорости показывает действующие правила, сохранение пишет их в `config.yaml` с перезапуском; высокорисковые поля (`jwt_secret`, `salt`, `data_dir`, `database.path`, журналы, каталоги плагинов, корни доверия) редактируются только на сервере. Перед сохранением создаётся снимок в `<data_dir>/config-backups/` (только `config.yaml`), восстановление возвращает только белый список. После сохранения нужен перезапуск, при смене порта сохраните доступ по SSH; автоопределение прокси использует TCP-адрес, поэтому с обратным прокси настройте `security.public_url`.

## Полный пример полей

```yaml
server:
  addr: ""              # полный адрес прослушивания, например ":8080"; если не пуст, имеет приоритет над host + port
  host: ""              # сетевой интерфейс; пусто — все интерфейсы
  port: 8080            # порт прослушивания
  trusted_proxies: []   # CIDR доверенных обратных прокси

data_dir: "data"        # каталог данных для плагинов, журналов и резервных копий обновлений

database:
  driver: "sqlite"      # sqlite (по умолчанию) или postgres
  path: ""              # путь SQLite; пусто — <data_dir>/lactssl.db
  dsn: ""               # DSN PostgreSQL; обязателен при driver=postgres
  max_open_conns: 10    # пул соединений PostgreSQL
  max_idle_conns: 5
  conn_max_lifetime_minutes: 30
  allow_multi_instance: false  # разрешать нескольким экземплярам совместно использовать одну базу PostgreSQL

log:
  level: info           # уровень журнала процесса: debug, info, warn, error
  format: text          # формат вывода: text или json
  file: ""              # файл журнала; пусто — только stdout
  also_stdout: true     # выводить ли одновременно в stdout при записи в файл
  max_size_mb: 20       # максимальный размер файла; после превышения выполняется ротация
  max_backups: 5        # число сохраняемых исторических файлов; 0 — без ограничения
  max_age_days: 30      # срок хранения исторических файлов в днях; 0 — без ограничения
  compress: true        # сжимать ли исторические файлы
  access_log: true      # записывать ли журнал доступа HTTP
  system:
    enabled: true       # записывать ли в базу данных для просмотра на вкладке «Журнал → Системный журнал»
    level: info         # минимальный уровень для записи в базу данных
    access: false       # записывать ли журнал доступа HTTP также в базу данных
    retention_days: 7   # срок хранения в днях
    max_rows: 20000     # максимальное число строк
  archive:
    enabled: true       # архивировать перед удалением/очисткой журналов; сбой архивирования блокирует удаление
    dir: ""             # пусто — <data_dir>/archives/logs
    compress: true      # сжимать ли gzip
    retention_days: 0   # срок хранения архивных файлов в днях; 0 — хранить бессрочно
    max_total_mb: 0     # верхний предел объёма каталога архивов (MB); 0 — без ограничения
    quota_policy: fail  # fail или prune_oldest

security:
  entry: ""             # защищённая точка входа; пусто — случайная генерация при первом запуске
  public_url: ""        # внешний адрес, например "https://ssl.example.com"
  session_persistence: true  # при false сеанс входа очищается при перезапуске процесса
  jwt_secret: ""        # ключ подписи JWT; пусто — автоматическая генерация и запись; при ручной настройке не менее 32 символов
  salt: ""              # соль шифрования чувствительных полей; пусто — автоматическая генерация и запись; при ручной настройке не менее 32 символов
  rate_limit:
    max_keys: 10000     # максимальное число key, сохраняемых в ограничителе скорости в памяти
    rules:
      # max — число попыток, разрешённых в окне (0 — без ограничения), window_seconds — длительность окна в секундах.
      # Для правил, не перечисленных здесь, используются встроенные значения по умолчанию; полный список правил см. в config.yaml.example.
      login_ip: {max: 10, window_seconds: 300}
      login_account: {max: 20, window_seconds: 900}
      api_ip: {max: 600, window_seconds: 60}
      acme_request: {max: 1200, window_seconds: 60}
      acme_order: {max: 300, window_seconds: 3600}

acme:
  enabled: true         # включать ли внутренний сервер ACME; по умолчанию включён
  addr: ""              # отдельный адрес прослушивания, например ":14000"; пусто — подключение к основному порту по /acme
  base_url: ""          # внешний адрес, например "https://pki.example.com:14000"
  tls:
    cert: ""            # TLS-сертификат отдельного прослушивания ACME
    key: ""             # TLS-закрытый ключ отдельного прослушивания ACME
  mtls:
    enabled: false      # требовать ли сертификат клиента
    client_ca: ""       # путь к сертификату CA клиентов

plugins:
  enabled: true
  dir: ""                 # пусто — <data_dir>/plugins/dns
  memory_limit_mb: 128
  timeout_seconds: 60
  max_output_kb: 64

deploy_plugins:
  enabled: true
  dir: ""                 # пусто — <data_dir>/plugins/deploy
  memory_limit_mb: 128
  timeout_seconds: 300
  max_output_kb: 64

notify_plugins:
  enabled: true
  dir: ""                 # пусто — <data_dir>/plugins/notify
  memory_limit_mb: 128
  timeout_seconds: 30
  max_output_kb: 64

upgrade:
  auto: true
  auto_optimize: true
  vacuum: true
  program:
    enabled: true
    repo: "AXmishell/LACTSSL"
    channel: stable
    check_interval_hours: 6
    max_download_mb: 128
    public_key: ""
    # официальные сборки автоматически встраивают открытый ключ выпуска; самостоятельные сборки без него отклоняют онлайн-обновление, если только неподписанные пакеты явно не разрешены в контролируемой среде
    allow_unsigned: false
    token: ""
```

## `server`

- `addr`: полный адрес, например `:8080`; `host`/`port` используются, если `addr` пуст (порт обслуживает страницы и API, фронтенд встроен в бинарник, `5173` только при `make dev`).
- `trusted_proxies`: IP/CIDR доверенных прокси; пусто — заголовки не доверяются, при TLS на прокси список обязателен, иначе `Secure` Cookie и IP клиента работают неверно. В продуктивной среде задайте `host` `127.0.0.1` или внутренний адрес и включайте только реальные адреса прокси (не `0.0.0.0/0`); при разных хостах используйте CIDR.

## `data_dir` и бэкенд базы данных

`data_dir` хранит плагины, журналы и копии обновлений; по умолчанию используется SQLite в `<data_dir>/lactssl.db`. PostgreSQL 18:

```yaml
database:
  driver: "postgres"
  dsn: "postgres://user:password@127.0.0.1:5432/lactssl?sslmode=verify-full"
```

- При `driver=postgres` `path` игнорируется, `dsn` обязателен; пароль можно не писать в файл, задав `LACTSSL_DATABASE_DSN`. `allow_multi_instance: false` удерживает advisory lock, второй экземпляр на той же базе не запустится.
- SQLite использует одно соединение и подходит для одного узла, PostgreSQL — для внешнего резервного копирования и централизованной эксплуатации; переключение — на карточке «Миграция базы данных» в `/upgrade`, см. [upgrade.md](upgrade.md#переключение-базы-данных-онлайн-sqlite--postgresql). Каталог создаётся с `0700`: не размещайте его на общем пути с записью или на NFS/SMB, область копирования — `config.yaml` + весь `data/`.

## `log`

Журнал операций фиксирует «кто, что и когда сделал»; журнал процесса нужен для диагностики и может писаться в базу, stdout и файл.

- `level`/`format`: `debug`, `info`, `warn`, `error`; `text` удобен для чтения и Docker, `json` — для систем сбора. `file`/`also_stdout`: пусто — только stdout, относительный путь считается от рабочего каталога; каталог создаётся `0700`, файл `0600`, в Docker оставляйте `also_stdout: true`. `max_size_mb` (1–1024), `max_backups` и `max_age_days` (0 — без ограничения), `compress` задают ротацию и хранение.
- `access_log`: метод, шаблон маршрута, код, длительность и IP клиента; параметры, тело и заголовки аутентификации не пишутся, точка входа заменяется на `:entry`, каждый ответ содержит `X-Request-ID`. `system.enabled`/`system.level`: запись в базу для «Журнал → Системный журнал» (уровень не ниже `log.level`), `system.access` по умолчанию `false`, чтобы не писать в SQLite на каждый запрос; `system.retention_days` (1–365) и `system.max_rows` (100–1000000) задают срок и лимит строк.
- `archive.enabled`: архивирование перед удалением, сбой блокирует удаление. `archive.dir` (по умолчанию `<data_dir>/archives/logs`), `compress` (`.gz` или `.ndjson`), `retention_days` (0–3650, 0 — бессрочно), `max_total_mb` и `quota_policy` (`fail` или `prune_oldest`; последний уничтожает аудит). Архив состоит из `*.ndjson.gz`/`.ndjson` и `*.manifest.json` (число строк, диапазон ID и времени, причина, оператор, SHA-256, размер) и не входит в стандартную ZIP-копию.
- Запись идёт через ограниченную асинхронную очередь и не блокирует запросы, при заполнении новые журналы отбрасываются; системный журнал содержит IP, домены и ошибки. В продуктивной среде вынесите журналы на отдельный диск, используйте `format: json` и `access_log: true`, а `system.access` оставьте `false`.

## `security`

- `entry`: 8–32 символа (буквы, цифры, `_`, `-`); пусто — при первом запуске генерируются 20 символов и сохраняются в базе. `public_url` — внешний HTTPS-адрес без пути, от него строится ссылка сброса пароля; если пусто, вывод из Host разрешён только для loopback и `localhost`.
- `session_persistence` (по умолчанию `true`): при `true` сеансы не очищаются, JWT подписан фиксированным `jwt_secret`; при `false` каждый запуск делает старые входы недействительными. `jwt_secret` и `salt`: пусто — генерируются 32 байта и записываются в файл; вручную — не менее 32 символов, иначе запуск отклоняется. `salt` шифрует учётные данные, ключи уведомлений, закрытые ключи CA и сертификатов.
- `rate_limit.max_keys` (по умолчанию `10000`) ограничивает число ключей в памяти; `rate_limit.rules` переопределяет `max` и `window_seconds`, `max: 0` отключает правило, неизвестное имя останавливает запуск. Без `window_seconds` используется окно по умолчанию.

Распространённые правила и значения по умолчанию:

| Правило | Значение по умолчанию | Описание |
| --- | --- | --- |
| `login_ip` / `login_account` / `login_totp` / `forgot_*` | 10 за 5 минут, 20 за 15 минут, 5 за 10 минут; 5 за 10 минут и 3 в час | Вход по IP, сбои учётной записи, TOTP и забытый пароль |
| `passkey_login_begin` / `passkey_login_fail` / `reauth` | 20 и 10 за 5 минут, 10 за 10 минут | Вход по ключу доступа и повторная аутентификация |
| `api_ip` / `api_anonymous` / `entry` | 600, 120 и 60 в минуту | `/api`, анонимные запросы и зондирование входа |
| `csr_create` / `acme_order` | 120, 300 в час | CSR и лимит заказов ACME |
| `acme_request` / `acme_account` / `acme_pki` | 1200 в минуту, 30 в час, 600 в минуту | Вход ACME, создание учётной записи, CRL/OCSP |

> **Обязательно создавайте резервную копию `config.yaml`.** Потеря `salt` делает зашифрованные учётные данные нерасшифровываемыми, замена `jwt_secret` — сеансы недействительными; при `session_persistence: false` каждый запуск очищает сеансы и ротирует ключ подписи. Изменения порогов вступают в силу после перезапуска, а «число заказов в час» конечной точки ACME задаётся в интерфейсе и приоритетнее `acme_order`.

- Держите `entry` случайной длинной строкой (не `admin`, `ssl`, `panel`) и фиксированный HTTPS `public_url`, не полагайтесь на Host; `jwt_secret` и `salt` храните в менеджере паролей, а не в системе контроля версий, замена `salt` требует плана миграции; `session_persistence` выбирайте по политике сеансов.

## `acme`

- `enabled`: включает внутренний сервер ACME (по умолчанию включён). Пока нет ни одной конечной точки, сертификаты наружу не выпускаются; `false` полностью закрывает протокольный вход.
- `addr`: отдельный адрес, например `:14000`; пусто — протокол ACME доступен на основном порту по `/acme`.
- `base_url`: адрес для directory, URL учётных записей и CRL/OCSP; при публичном развёртывании задайте фиксированный адрес, иначе используется `security.public_url`, а при пустоте — Host запроса с предупреждением. `tls.cert`/`tls.key` нужны при прямом TLS (при TLS на прокси пусты); `mtls.enabled`/`mtls.client_ca` требуют клиентский сертификат и TLS-сертификат с ключом ACME.

- При публичном развёртывании используйте отдельный порт, ограничьте источники, настройте белый список доменов, EAB и фиксированный `base_url`; если сервер ACME не нужен, установите `enabled: false`.

## `plugins`, `deploy_plugins`, `notify_plugins`

Три типа плагинов используют `<data_dir>/plugins/dns`, `/deploy` и `/notify`; подкаталоги не смешиваются.

### Плагины DNS

```yaml
plugins:
  enabled: true
  dir: ""                 # пусто — <data_dir>/plugins/dns
  memory_limit_mb: 128
  timeout_seconds: 60
  max_output_kb: 64
```

### Плагины развёртывания

Плагины развёртывания получают закрытые ключи сертификатов и по умолчанию включены:

```yaml
deploy_plugins:
  enabled: true
  dir: ""
  memory_limit_mb: 128
  timeout_seconds: 300
  max_output_kb: 64
```

### Плагины уведомлений

Плагины уведомлений по умолчанию включены; почта встроена:

```yaml
notify_plugins:
  enabled: true
  dir: ""
  memory_limit_mb: 128
  timeout_seconds: 30
  max_output_kb: 64
```

Права: каталог плагинов `0700`, helper `0755`, владелец — пользователь сервиса; в продуктивной среде настройте `public_key` и отключите `auto_update`. Подробнее — в разделе [Управление плагинами](plugins.md).

## `upgrade`

`upgrade` управляет миграцией при запуске и оптимизацией на странице `/upgrade`:

```yaml
upgrade:
  auto: true              # автоматически выполнять миграцию унаследованных данных при запуске
  auto_optimize: true     # при запуске дополнять индексы, обновлять статистику, сворачивать WAL; без VACUUM
  vacuum: true            # разрешить VACUUM при ручной оптимизации в /upgrade
  program:
    enabled: true
    repo: "AXmishell/LACTSSL"
    channel: stable       # stable или beta
    check_interval_hours: 6
    max_download_mb: 128
    public_key: ""
    token: ""
```

- Обновление скачивает пакет для платформы из GitHub Release, проверяет SHA-256 из `checksums.txt`, атомарно заменяет бинарник и сохраняет старую версию в `<data_dir>/upgrade-backups/program/`. На read-only ФС, платформах без пакетов выпуска и в сборках `dev` оно недоступно; контейнер не меняет образ (обновляйтесь тегом). При `public_key` проверяется `checksums.txt.sig`, `token` повышает лимит GitHub API.

## Ключевые моменты обратного прокси

### Граница доверия

- Доверенными считаются только TCP-адреса из `server.trusted_proxies`; пустой список означает недоверие ко всем заголовкам и подходит для прямого подключения. `X-Forwarded-For`, `X-Real-IP`, `Forwarded`, `CF-Connecting-IP` до доверия — подделываемые заявления клиента; автоопределение только подсказывает. Не указывайте `0.0.0.0/0`, `::/0` и слишком широкие внутренние диапазоны: любой хост в них сможет подделать IP.

### Режим перезаписи (рекомендуется)

Ближайший к LACTSSL прокси заменяет заголовки пересылки реальным адресом клиента:

```nginx
proxy_set_header X-Forwarded-For $remote_addr;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-Proto $scheme;
```

В этом режиме в `trusted_proxies` достаточно ближайшего прокси. В многоуровневой схеме пограничный прокси восстанавливает реального клиента, ближайший — перезаписывает заголовки, а промежуточный не должен дописывать адрес вышестоящего в XFF.

### Режим добавления

- Nginx `$proxy_add_x_forwarded_for` сохраняет XFF клиента и добавляет адрес текущего соединения; LACTSSL идёт по цепочке справа налево, пропуская доверенные элементы. Один прокси — доверяйте только Nginx; несколько — перечислите все прокси, которые могут появиться в XFF, иначе результат остановится на вышестоящем.
- Не доверяйте самый левый адрес клиента: при `client → CDN → Nginx → LACTSSL` режим добавления даёт `client, IP edge-узла CDN`, и при доверии только Nginx вы получите IP edge — доверяйте официальным диапазонам CDN или переключите Nginx на перезапись.

### CDN и облачные балансировщики

- Доверяйте `CF-Connecting-IP`, только если TCP-адрес принадлежит официальным диапазонам Cloudflare; включите `real_ip` и перезаписывайте XFF значением `$remote_addr`, тогда LACTSSL доверяет только этому Nginx. IP edge-узлов меняются — не добавляйте их по одному; L4/TCP балансировщик не передаёт HTTP-заголовки, поэтому нужен PROXY protocol или HTTP-прокси за ним.

### Docker и Kubernetes

- В контейнере peer часто является шлюзом моста или адресом Service, а не клиентом; доверяйте точному IP контейнера/узла прокси или минимальному CIDR, но не `172.16.0.0/12`, и проверьте, очищает ли Ingress Controller XFF.

### Применение и проверка

1. Добавьте адреса прокси в `trusted_proxies` и настройте `security.public_url`; при TLS на прокси передавайте `X-Forwarded-Proto: https`. Для восстановления копий и загрузки плагинов нужен больший лимит тела (например, `client_max_body_size 256m`) и тайм-аут чтения около 600 секунд.
2. После перезапуска проверьте в «Автоопределении» `peer_ip`, `applied_trusted_proxies`, `effective_client_ip`, `client_ip_source`; тест подделки — отправьте `X-Forwarded-For: 203.0.113.9` с недоверенного адреса, сервер должен использовать TCP-peer (в журнале `ip_source`, `ip_skipped`, `ip_warnings`).

### Расширенная идентификация прокси

Порядок разрешения: доверенный прокси → заголовок Cloudflare → `X-Forwarded-For` → `X-Real-IP` → RFC 7239 `Forwarded` → TCP-peer; ни один режим не принимает заголовки от недоверенного источника. `Forwarded` разбирается, если предыдущие заголовки недоступны: поддерживаются `for=203.0.113.9`, `for=203.0.113.9:4711`, `for="[2001:db8::1]:4711"`, значения `unknown` и `_hidden` отклоняются.
  ```yaml
  server:
    client_ip_mode: cloudflare
    trusted_proxies:
      - "173.245.48.0/20"
      - "103.21.244.0/22"
      # ... другие официальные диапазоны Cloudflare
  ```
  **Режим Cloudflare**: `CF-Connecting-IP` принимается только при peer из `trusted_proxies`; не используйте режим с локальным Nginx, который лишь перезаписывает заголовки.
- **PROXY protocol**:
  ```yaml
  server:
    proxy_protocol: true
  ```
  Заголовки v1/v2 принимаются только от peer из `trusted_proxies`, иначе соединение закрывается; обычный HTTP без заголовка работает.
- **Идентификация по mTLS**:
  ```yaml
  server:
    tls:
      cert: "/etc/lactssl/server.crt"
      key: "/etc/lactssl/server.key"
      proxy_client_ca: "/etc/lactssl/proxy-ca.pem"
  ```
  Соединение с клиентским сертификатом от `proxy_client_ca` считается доверенным прокси независимо от IP; браузеры без сертификата работают. Режим подходит только для прокси с прямым TLS к LACTSSL; используйте отдельный CA, не клиентский CA браузеров.

## Проверка конфигурации и обработка сбоев

| Ошибка | Причина | Обработка |
| --- | --- | --- |
| `jwt_secret`/`salt` короче 32 символов | Ручная настройка | Укажите не менее 32 символов или оставьте пустым |
| Сбой прослушивания, mTLS или проверки конфигурации | Порт занят/нет прав; нет TLS-сертификата или ключа; недопустимый пакет; нужен перезапуск | Проверьте порт и пользователя, настройте `acme.tls.cert/key`, исправьте по журналу и перезапустите сервис |
