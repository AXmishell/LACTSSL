# Плагины DNS

Плагины DNS обеспечивают интеграцию с API провайдеров доменов для проверки DNS-01 публичного CA. При выборе для предприятия важны не «сколько провайдеров поддерживается», а **минимальные права учётных данных, возможность ротации, аудит и возможность офлайн-развёртывания**.

## 1. Предварительные условия

- В разделе «Учётные записи DNS» созданы учётные данные соответствующего провайдера.
- На странице «Плагины» установлен и включён плагин DNS и конкретный провайдер.
- Зона, в которой находится домен, видна этим учётным данным и допускает создание/удаление записей TXT.
- Исходящий доступ к API провайдера доступен; при использовании прокси проверьте конфигурацию прокси Go HTTP-клиента.

Если не установлен ни один плагин DNS, список DNS-провайдеров пуст. Прежние учётные записи DNS не теряются, но если провайдер недоступен, при выпуске будет выдана явная ошибка.

## 2. Выбор пакета плагинов

Официальный репозиторий [LACTSSL-Plugins](https://github.com/AXmishell/LACTSSL-Plugins) предоставляет три DNS-пакета для всех примерно 194 провайдеров:

| Пакет | Охват | После распаковки | Применение |
| --- | --- | ---: | --- |
| DNS полный·рефакторинг | 194 провайдера | около 18 MiB | Большинство предприятий; 21 использует native-реализацию репозитория, остальные — lego v4 |
| DNS полный·lego | 194 провайдера | около 58 MiB | Требуется полная функциональность lego v4 (например, rfc2136 GSS-TSIG) |
| DNS полный·lego v5 | 235 записей (228 провайдеров v5 + 7 совместимых заглушек) | около 37 MiB | Отслеживание lego v5 и новых провайдеров |

Три пакета взаимоисключающие, их нельзя устанавливать одновременно.

- Проверка только для чтения (`verify-v1`) предоставляется нативной реализацией только в пакете «DNS полный·рефакторинг»; при использовании других пакетов режим `auto` автоматически переключается на тест записи TXT.
- Все пакеты совместно используют одну среду выполнения Go, что позволяет избежать затрат диска и процессов при упаковке для каждого провайдера.
- Основной пакет программы не содержит ни одного провайдера; устанавливайте по необходимости.
- Значки провайдеров поставляются с пакетом плагинов и индексом репозитория; после установки они кэшируются в `<data_dir>/plugin-icons/`.

## 3. Установка и включение

1. Откройте страницу «Плагины», проверьте адрес репозитория и нажмите «Обновить индекс».
2. Откройте «Магазин плагинов», отфильтруйте DNS и установите нужный пакет.
3. Сначала включите файл плагина, затем включите конкретного провайдера в списке DNS-провайдеров; новые загруженные файлы и записи по умолчанию отключены.
4. В разделе «Учётные записи DNS» создайте учётные данные и выберите этого провайдера.

Объединённый пакет не включается целиком одним переключателем в начале строки; при включении более 10 записей за один раз потребуется подтверждение. После отключения на уровне файла его записи не регистрируются в среде выполнения, но существующие отметки сохраняются.

Для установки, обновления и удаления достаточно сеанса входа или `plugins:write`. Пакет плагинов проверяет подпись индекса (если настроен открытый ключ), SHA-256 ресурса, `plugin.json` и ID провайдера в манифесте; при любом несоответствии установка отклоняется и выполняется откат.

## 4. Управление учётными данными

### 4.1 Минимальные права

- Используйте выделенную субучётную запись или API Token, не используйте личную учётную запись или глобальный ключ администратора.
- Предоставляйте только права чтения и записи DNS для целевой зоны; не предоставляйте права уровня учётной записи на оплату, регистрацию доменов, удаление зон и т. п.
- Если провайдер поддерживает авторизацию по домену/проекту, ограничьте её доменами, которые действительно нужно выпускать.
- Для тестирования и производства используйте разные учётные данные и разные субучётные записи DNS.

### 4.2 Ротация

- Фиксируйте ответственного за учётные данные, время создания, область прав и период ротации.
- При ротации сначала обновите учётные данные в LACTSSL, затем отзовите старые на стороне провайдера.
- После ротации запустите тестовую задачу и убедитесь, что создание/очистка TXT работает нормально.
- Немедленно выполняйте ротацию после увольнения сотрудника, утечки ключа или инцидента безопасности у провайдера.

### 4.3 Хранение

- Перед записью в базу данных учётные данные шифруются с помощью AES-256-GCM; при возврате через интерфейс они маскируются.
- Если при редактировании учётной записи оставить поле ключа пустым, сохраняется прежнее значение.
- Не записывайте учётные данные в имена задач, примечания, заявки или журналы.
- Пакет резервной копии содержит зашифрованные учётные данные; обращайтесь с ним как с конфиденциальным файлом.

- После установки официального плагина DNS поддерживаются все провайдеры lego (около 190).
- Провайдер `manual` требует ручного добавления записей TXT и не входит в автоматический процесс.
- Cloudflare, DNSimple, PowerDNS, Volcano Engine и другие поддерживают пользовательский адрес вышестоящего API, который можно использовать для прокси, собственных сервисов или совместимых шлюзов.
- Полный список провайдеров определяется раскрывающимся списком на странице «Учётные записи DNS».

## 6. Офлайн- и ручная установка

- На странице «Плагины» загрузите один исполняемый файл helper, не более 256 MB.
- После загрузки сначала проверьте `manifest` через временный файл, проверьте протокол, ID провайдера и SHA-256; только после успешной проверки запись выполняется в каталог плагинов и выполняется повторное сканирование.
- По умолчанию перезапись одноимённого файла запрещена; при обновлении отметьте «Разрешить перезапись одноимённого плагина», старый файл будет предварительно сохранён в резервной копии.
- Или укажите `plugins.repo.url` на индекс внутреннего зеркала:

```yaml
plugins:
  repo:
    url: "file:///srv/lactssl-plugins/index.json"
```

Вручную загруженный bundle с несколькими провайдерами всё ещё можно загрузить, но он будет помечен как `manual` и не участвует в обновлении из официального репозитория.

## 7. Проверка и устранение неполадок

### 7.1 Проверка

1. Создайте учётную запись DNS, сохранение прошло успешно.
2. Создайте тестовую задачу, выберите эту учётную запись и тестовый домен.
3. Запустите задачу, наблюдайте за созданием TXT, проверкой CA, очисткой TXT.
4. Проверьте журнал задачи и журнал операций.
5. Удалите тестовый сертификат или оставьте по необходимости.

### 7.2 Частые проблемы

| Симптом | Причина | Действие |
| --- | --- | --- |
| Раскрывающийся список провайдеров пуст | Плагин не установлен/не включён | Установите пакет DNS и включите провайдера |
| Не удаётся сохранить учётные данные | Отсутствуют обязательные поля/неверный формат | Исправьте по подсказкам формы и журнала |
| Не удаётся создать TXT | Права/зона/квота | Проверьте права API, домен и квоту |
| Не удаётся очистить TXT | Нет прав или запись уже удалена | Вручную очистите оставшийся TXT |
| Тайм-аут проверки | Медленное распространение DNS/авторитетный DNS не обновлён | Проверьте TTL, авторитетное разрешение и CAA |
| Ошибка пользовательского адреса API | Адрес недоступен/сертификат не доверен | Проверьте сеть, TLS и адрес вышестоящего API |
| Не удаётся загрузить плагин | Права/дайджест/протокол | Проверьте права каталога и запись установки |

## 8. Протокол Helper v1 (разработка интеграций)

Этот раздел предназначен для разработчиков плагинов; специалистам по эксплуатации обычно не требуется его знать.

helper — это исполняемый файл, поддерживающий четыре подкоманды:

```bash
dns-helper manifest   # вывести JSON-манифест
dns-helper present    # прочитать запрос из stdin и добавить запись TXT
dns-helper cleanup    # прочитать запрос из stdin и удалить запись TXT
dns-helper verify     # прочитать запрос из stdin и выполнить проверку только для чтения (необязательно)
```

Пример вывода `manifest`:

```json
{
  "protocol": "v1",
  "capabilities": ["verify-v1"],
  "name": "example dns helper",
  "version": "1.0.0",
  "sha256": "необязательная контрольная сумма файла helper",
  "providers": [
    {
      "id": "example-dns",
      "name": "Example DNS",
      "description": "Пример провайдера",
      "aliases": ["example"],
      "capabilities": ["verify-v1"],
      "fields": [
        {"key": "api_token", "label": "API Token", "type": "password", "required": true}
      ]
    }
  ]
}
```

stdin для `present` / `cleanup`:

```json
{
  "action": "present",
  "provider": "example-dns",
  "config": {"api_token": "..."},
  "domain": "example.com",
  "token": "acme-token",
  "key_auth": "key-authorization"
}
```

stdin / stdout для `verify`:

```json
{"action": "verify", "provider": "example-dns", "config": {"api_token": "..."}, "domain": "example.com", "mode": "read", "locale": "zh-CN"}
```

```json
{"ok": true, "checks": [{"key": "zone", "status": "ok", "message": "example.com"}]}
```

Соглашения:

- Код выхода `0` означает успех, отличный от `0` — ошибку; stderr попадает в журнал задачи (чувствительные значения маскируются).
- stdout должен оставаться пустым; вывод `present/cleanup` считается ошибкой.
- `verify` должен быть операцией только для чтения: разрешается только перечисление зон/запрос записей, запрещено создавать, изменять или удалять любые записи.
- Вызов `verify` получают только провайдеры, объявившие возможность `verify-v1`; для необъявивших провайдеров основная программа переходит к тесту записи `present/cleanup` (`mode=auto`), а при явном `mode=read` возвращает «не поддерживается».
- Значения `checks[].status`: `ok`, `failed`, `skipped`, `unsupported`, `error`.
- helper получает бюджет памяти из `LACTSSL_PLUGIN_MEMORY_LIMIT` (в байтах).
- Основная программа периодически проверяет `VmRSS` helper и при превышении `plugins.memory_limit_mb` завершает процесс и записывает ошибку.
- Основная программа передаёт только минимальный набор переменных окружения (PATH, HOME, прокси, сертификаты TLS и т. д.) и не раскрывает серверные ключи.
- Файл helper не должен допускать запись другими пользователями; если `manifest.sha256` не пуст, проверяется дайджест файла.
- `version` обозначает версию самой реализации helper/провайдера, а не версию сборки LACTSSL.

## 9. Рекомендации по безопасности

- Каталог плагинов должен допускать запись только пользователю, от имени которого работает сервис, предпочтительно `0700`.
- Устанавливайте helper только из доверенных источников и указывайте `sha256` в манифесте.
- Устанавливайте разумные `memory_limit_mb` и `timeout_seconds`, чтобы аномальный плагин не перегрузил хост.
- Плагины работают от имени служебной учётной записи; не давайте пользователю `lactssl` дополнительных прав.
- В производственной среде используйте внутреннее зеркало, фиксируйте версии и отключайте автоматическое обновление.
