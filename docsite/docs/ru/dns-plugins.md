# Плагины DNS

Плагины DNS интегрируются с API провайдеров доменов для проверки DNS-01 публичного CA. Важны минимальные права учётных данных, ротация, аудит и возможность офлайн-развёртывания.

## Предварительные условия

- В разделе «Учётные записи DNS» созданы учётные данные соответствующего провайдера.
- На странице «Плагины» включена категория DNS и нужный провайдер.
- Зона домена видна этим учётным данным и допускает создание/удаление записей TXT.
- Исходящий доступ к API провайдера открыт; при использовании прокси проверьте настройки прокси Go HTTP-клиента.

Если провайдер не включён, при выпуске будет выдана явная ошибка; прежние учётные записи не теряются.

## Выбор пакета плагинов

Официальная реализация DNS встроена: полная сборка охватывает около 235 записей (228 провайдеров lego v5 + 7 совместимых ID), устанавливать пакеты не нужно. Все провайдеры по умолчанию отключены — включайте их на странице «Плагины».

Для меньшего бинарника или потребления памяти используйте упрощённые сборки: `make backend-dns-common` подключает только часто используемый белый список, `make backend-dns-minimal` оставляет только Cloudflare, `make backend-no-dns` полностью исключает встроенный DNS. Упрощённые сборки по-прежнему поддерживают загрузку helper.

## Установка и включение

1. Откройте страницу «Плагины» и убедитесь, что категория DNS включена.
2. В списке DNS-провайдеров включите нужные; при включении более 10 записей за один раз потребуется подтверждение.
3. В разделе «Учётные записи DNS» создайте учётные данные и выберите этого провайдера.

Состояние включения хранится в таблице settings; после отключения категории записи не регистрируются в среде выполнения, но существующие отметки сохраняются.

## Управление учётными данными

### Минимальные права

- Используйте выделенную субучётную запись или API Token, а не личную учётную запись или глобальный ключ администратора; давайте только права чтения и записи DNS для целевой зоны, без прав на оплату, регистрацию доменов и удаление зон.
- Если провайдер поддерживает авторизацию по домену/проекту, ограничьте её действительно выпускаемыми доменами; для тестирования и производства используйте разные учётные данные.

### Ротация

- Фиксируйте ответственного, время создания, область прав и период ротации; при ротации сначала обновите учётные данные в LACTSSL, затем отзовите старые у провайдера.
- После ротации запустите тестовую задачу и убедитесь, что создание/очистка TXT работает; немедленно ротируйте данные после увольнения, утечки ключа или инцидента у провайдера.

### Хранение

- Перед записью в базу данных учётные данные шифруются (AES-256-GCM), при возврате через интерфейс маскируются; пустое поле ключа при редактировании сохраняет прежнее значение.
- Не записывайте учётные данные в имена задач, примечания, заявки или журналы; резервную копию храните как конфиденциальный файл.

| AWS Route 53 | AccessKey / SecretAccessKey | Необязательные Region, Hosted Zone, частная зона |
| Google Cloud DNS | JSON сервисной учётной записи | Необязательный ID проекта |

- Cloudflare, DNSimple, PowerDNS, Volcano Engine и другие поддерживают пользовательский адрес вышестоящего API для прокси, собственных сервисов или совместимых шлюзов.
- Полный список провайдеров — в раскрывающемся списке на странице «Учётные записи DNS».

## Офлайн- и ручная установка

Встроенные провайдеры поставляются с основной программой, в офлайн-среде дополнительная установка не нужна. Сторонний provider можно загрузить на странице «Плагины» одним helper (не более 256 MB): при загрузке проверяются протокол, ID и SHA-256, перезапись одноимённого файла по умолчанию запрещена, старый файл при обновлении сначала сохраняется в резервной копии. Загруженный вручную bundle с несколькими провайдерами помечается как `manual` и не участвует в автообновлении.

## Проверка и устранение неполадок

### Проверка

1. Создайте учётную запись DNS и тестовую задачу с тестовым доменом.
2. Запустите задачу и проследите создание TXT, проверку CA и очистку TXT; проверьте журнал задачи и журнал операций.

### Частые проблемы

| Симптом | Причина | Действие |
| --- | --- | --- |
| Список провайдеров пуст | Категория DNS отключена | Включите категорию и провайдера на странице «Плагины» |
| Не удаётся сохранить учётные данные | Нет обязательных полей/неверный формат | Исправьте по подсказкам формы и журнала |
| Не удаётся создать TXT | Права/зона/квота | Проверьте права API, домен и квоту |
| Не удаётся очистить TXT | Нет прав или запись уже удалена | Вручную очистите оставшийся TXT |
| Тайм-аут проверки | Медленное распространение DNS | Проверьте TTL, авторитетное разрешение и CAA |
| Ошибка пользовательского адреса API | Адрес недоступен/сертификат не доверен | Проверьте сеть, TLS и адрес вышестоящего API |
| Не удаётся загрузить helper | Права/дайджест/протокол | Проверьте права каталога и запись установки |

## Протокол Helper v1 (разработка интеграций)

helper — исполняемый файл с четырьмя подкомандами:

```bash
dns-helper manifest   # вывести JSON-манифест
dns-helper present    # прочитать запрос из stdin и добавить запись TXT
dns-helper cleanup    # прочитать запрос из stdin и удалить запись TXT
dns-helper verify     # прочитать запрос из stdin и выполнить проверку только для чтения (необязательно)
```

Пример вывода `manifest`:

```json
{
  "protocol": "v1",
  "capabilities": ["verify-v1"],
  "name": "example dns helper",
  "version": "1.0.0",
  "sha256": "необязательная контрольная сумма файла helper",
  "providers": [
    {
      "id": "example-dns",
      "name": "Example DNS",
      "description": "Пример провайдера",
      "aliases": ["example"],
      "capabilities": ["verify-v1"],
      "fields": [
        {"key": "api_token", "label": "API Token", "type": "password", "required": true}
      ]
    }
  ]
}
```

stdin для `present` / `cleanup`:

```json
{
  "action": "present",
  "provider": "example-dns",
  "config": {"api_token": "..."},
  "domain": "example.com",
  "token": "acme-token",
  "key_auth": "key-authorization"
}
```

stdin / stdout для `verify`:

```json
{"action": "verify", "provider": "example-dns", "config": {"api_token": "..."}, "domain": "example.com", "mode": "read", "locale": "zh-CN"}
```

```json
{"ok": true, "checks": [{"key": "zone", "status": "ok", "message": "example.com"}]}
```

Соглашения:

- Код выхода `0` — успех, ненулевой — ошибка; stderr попадает в журнал задачи с маскированием, а stdout `present`/`cleanup` должен оставаться пустым.
- `verify` — только чтение: разрешено перечисление зон и запрос записей, запрещено создавать, изменять или удалять записи.
- `verify` получают только провайдеры с возможностью `verify-v1`; остальные при `mode=auto` проходят тест записи `present/cleanup`, а при `mode=read` возвращают «не поддерживается».
- Значения `checks[].status`: `ok`, `failed`, `skipped`, `unsupported`, `error`.
- helper получает бюджет памяти из `LACTSSL_PLUGIN_MEMORY_LIMIT` (в байтах); при превышении `plugins.memory_limit_mb` основная программа завершает процесс и пишет ошибку, передавая только минимальный набор переменных окружения (PATH, HOME, прокси, сертификаты TLS) без серверных ключей.
- Файл helper не должен допускать запись другими пользователями; непустой `manifest.sha256` проверяется.

## Рекомендации по безопасности

- Каталог плагинов должен допускать запись только пользователю сервиса, предпочтительно `0700`.
- Устанавливайте helper только из доверенных источников, указывайте `sha256` и задавайте разумные `memory_limit_mb` и `timeout_seconds`, чтобы аномальный плагин не перегрузил хост; он работает от имени служебной учётной записи, не давайте пользователю `lactssl` дополнительных прав.
