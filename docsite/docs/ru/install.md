# Установка и запуск

Эта статья содержит готовые к продакшену шаги установки. При первой оценке рекомендуется сначала прочитать [Быстрый старт и ввод в эксплуатацию](getting-started.md), определить сценарий и критерии приёмки, а затем развернуть по этой статье. Владельцы личных сайтов и небольшие команды могут пропустить оценку и сразу развернуть в Docker согласно разделу 2.

## 1. Требования к среде

| Пункт | Требование |
| --- | --- |
| Операционная система | Linux amd64 / arm64; также поддерживаются пакеты для macOS и Windows |
| Контейнеры | Docker и Docker Compose v2 (рекомендуется) |
| Сборка из исходного кода | Go 1.27+, Node.js 22.12+, npm |
| Ресурсы хоста | См. [Архитектура развёртывания](architecture.md); для начала рекомендуется 2 vCPU / 1 GB, для личного сценария с одним доменом достаточно 1 vCPU / 1 GB |
| Сеть | Точка входа управления через HTTPS-обратный прокси; исходящий доступ к DNS API, CA, SMTP, целям развёртывания |
| Домены | Один домен управления и соответствующий TLS-сертификат; для сервера ACME опционально отдельный домен |

Основной программе не нужны внешняя база данных, Redis или очередь сообщений. Всё состояние находится в каталоге `data/`.

!!! tip "Частные лица / небольшие команды"
    Корпоративный процесс оценки не нужен: запустите Docker согласно разделу 2, завершите инициализацию согласно разделу 4, установите плагины согласно разделу 6.3. Для сайтов, развёрнутых через панели BaoTa, 1Panel и подобные, требуется соответствующий плагин развёртывания; автоматическое продление зависит от DNS API, поэтому рекомендуется использовать отдельную субучётную запись с правами только на нужные домены. Установка и обновление плагинов вызывают кратковременный пик памяти, не ограничивайте память контейнера ровно до объёма простоя.

## 2. Вариант 1: Docker Compose (рекомендуется)

### 2.1 Подготовка каталогов

```bash
git clone https://github.com/AXmishell/LACTSSL.git
cd LACTSSL
mkdir -p config data
cp config.yaml.example config/config.yaml
chmod 600 config/config.yaml
chmod 700 data
```

Входящий в репозиторий `docker-compose.yml` по умолчанию использует образ GHCR:

```yaml title="docker-compose.yml"
--8<-- "docker-compose.yml"
```

Файл по умолчанию использует внешнюю сеть `1panel-network` от 1Panel. Если 1Panel не используется, удалите `networks` в сервисе и блок `networks` в конце файла, чтобы Compose использовал сеть по умолчанию; также можно сначала создать эту сеть:

```bash
docker network create 1panel-network
```

### 2.2 Запуск

```bash
docker compose pull
docker compose up -d
docker compose logs -f lactssl
```

!!! note "Образ и сеть"
    Образ GHCR доступен с первого официального Release; если `docker compose pull` сообщает, что образ не существует, соберите его локально согласно разделу 2.4. Compose по умолчанию публикует 8080 на всех сетевых интерфейсах хоста; на публичном хосте рекомендуется ограничить источники с помощью брандмауэра или изменить `ports` на `127.0.0.1:8080:8080`, чтобы доступ разрешался только обратному прокси на локальной машине.

Монтирования по умолчанию:

- `./config/config.yaml`: файл конфигурации
- `./data`: SQLite, плагины, журналы и резервные копии обновления

Контейнер всегда читает `/app/config/config.yaml`, каталог данных — `/app/data`. Входной скрипт от имени root исправляет владельца смонтированных каталогов, затем понижает права и запускается от пользователя `lactssl`. Compose по умолчанию включает корневую файловую систему только для чтения, `no-new-privileges`, белый список capabilities и `pids_limit`.

### 2.3 Фиксация версии

Не используйте `latest` длительное время. Измените тег образа непосредственно в `docker-compose.yml`:

```yaml
image: ghcr.io/axmishell/lactssl:1.2.3
```

Стабильные теги: `<version>`, `<major>.<minor>`, `<major>` и `latest`; для предварительных версий публикуется только полный тег версии.

### 2.4 Локальная сборка образа

Dockerfile только копирует Linux-бинарник, собранный вне Docker; резервное копирование и восстановление баз данных реализованы нативно на Go, поэтому `pg_dump`/`mysqldump` не требуются. Сначала подготовьте фронтенд и бинарник для текущей архитектуры, затем соберите образ:

```bash
VERSION=1.2.3 make docker-context
docker build --build-arg VERSION=1.2.3 -t lactssl:1.2.3 .
docker run -d --name lactssl \
  -p 127.0.0.1:8080:8080 \
  -v "$PWD/data:/app/data" \
  -v "$PWD/config:/app/config" \
  --restart unless-stopped \
  lactssl:1.2.3
```

## 3. Вариант 2: бинарный файл + systemd

### 3.1 Установка

```bash
sudo useradd --system --home /opt/lactssl --shell /usr/sbin/nologin lactssl
sudo mkdir -p /opt/lactssl/data
sudo cp lactssl /opt/lactssl/
sudo cp config.yaml.example /opt/lactssl/config.yaml
sudo chown -R lactssl:lactssl /opt/lactssl
sudo chmod 600 /opt/lactssl/config.yaml
sudo chmod 700 /opt/lactssl/data
```

!!! note "Нативное резервное копирование"
    Логическое резервное копирование и восстановление PostgreSQL/MySQL реализованы непосредственно в Go-коде LACTSSL; клиенты `pg_dump`, `pg_restore`, `mysqldump` и `mysql` больше не требуются. SQLite по-прежнему использует снимок `VACUUM INTO`.

### 3.2 Модуль systemd

```ini title="/etc/systemd/system/lactssl.service"
[Unit]
Description=LACTSSL certificate manager
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=lactssl
Group=lactssl
WorkingDirectory=/opt/lactssl
ExecStart=/opt/lactssl/lactssl -config /opt/lactssl/config.yaml
Restart=on-failure
RestartSec=5
LimitNOFILE=65535
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/opt/lactssl/data

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now lactssl
sudo journalctl -u lactssl -f
```

Если журналы записываются в `/opt/lactssl/data/logs/`, указанный выше `ReadWritePaths` уже покрывает это; если в другой каталог, нужно дополнительно разрешить запись. При использовании привилегированных портов, таких как 80/443, рекомендуется передавать трафик через обратный прокси, а не повышать права бинарного файла.

### 3.3 Скрипт установки одной командой

Репозиторий предоставляет `scripts/install.sh` для загрузки бинарного файла Linux amd64/arm64 из GitHub Release, создания пользователя и каталога данных, установки службы systemd и генерации конфигурации обратного прокси Nginx. По умолчанию TLS не включается: бинарный файл слушает `127.0.0.1:8080`, Nginx слушает 80 и перенаправляет на этот порт.

```bash
sudo ./scripts/install.sh --port 8080 --domain ssl.example.com
```

Также можно не клонировать репозиторий, а сразу загрузить и выполнить скрипт:

```bash
curl -fsSL https://raw.githubusercontent.com/AXmishell/LACTSSL/main/scripts/install.sh \
  | sudo bash -s -- --port 8080 --domain ssl.example.com
```

В архивах релизов Linux также прилагается `install.sh`, который можно запустить сразу после распаковки.

Общие параметры:

| Параметр | Описание |
| --- | --- |
| `--port PORT` | Порт прослушивания бинарного файла, по умолчанию `8080`, должен быть >= 1024 |
| `--domain DOMAIN` | `server_name` Nginx, например `ssl.example.com`; по умолчанию `_` |
| `--version TAG` | Указать версию, например `v1.2.3`; по умолчанию последняя стабильная |
| `--no-nginx` | Развернуть только службу systemd, не устанавливать и не изменять Nginx |
| `--tls-cert` / `--tls-key` | Опционально, включить HTTPS в Nginx и настроить перенаправление 80 → 443 |
| `--no-tls` | Отключить существующую конфигурацию TLS в Nginx (по умолчанию TLS и так не включён) |
| `--read-write-path DIR` | Дополнительный каталог, разрешённый для записи службе, можно повторять; используется для цели локального развёртывания сертификатов |
| `--skip-checksum` | Пропустить проверку SHA-256 (не рекомендуется) |

Пример: включение HTTPS

```bash
sudo ./scripts/install.sh \
  --domain ssl.example.com \
  --port 8080 \
  --tls-cert /etc/nginx/certs/ssl.example.com.pem \
  --tls-key  /etc/nginx/certs/ssl.example.com.key
```

Скрипт проверяет `checksums.txt` в Release. При повторном выполнении заменяется только бинарный файл и перезапускается служба, существующие `config.yaml` и `data/` сохраняются; при указании `--port` синхронно обновляются `server.addr`, `server.host`, `server.port`. Если `--domain` / `--tls-cert` / `--tls-key` не указаны, используются домен и сертификат из существующей конфигурации Nginx, чтобы при обновлении случайно не вернуться к сайту по умолчанию или не отключить TLS; чтобы отключить TLS, явно используйте `--no-tls`. Если Nginx не установлен, скрипт попытается установить его через системный менеджер пакетов; если автоматическая установка нежелательна, добавьте `--no-install-deps`, если не нужно настраивать Nginx — `--no-nginx`. В модуле службы включён `ProtectSystem=strict`, поэтому самообновление со страницы программы может быть недоступно из-за каталога только для чтения; для обновления повторно запустите этот скрипт. Если нужно, чтобы встроенная цель развёртывания записывала в локальные каталоги вроде `/etc/nginx`, можно несколько раз использовать `--read-write-path`, чтобы разрешить запись, и убедиться, что пользователь `lactssl` имеет права на запись в эти каталоги.

Ключевая конфигурация, генерируемая по умолчанию:

```yaml
server:
  host: "127.0.0.1"
  port: 8080
  trusted_proxies: ["127.0.0.1", "::1"]
security:
  public_url: "http://ssl.example.com"
```

Конфигурация Nginx записывается в `/etc/nginx/conf.d/lactssl.conf` и содержит `client_max_body_size 256m` и тайм-аут чтения/записи 600 секунд. После развёртывания завершите инициализацию согласно разделу 4 через защищённую точку входа из журнала запуска.

### 3.4 Сборка из исходного кода

```bash
git clone https://github.com/AXmishell/LACTSSL.git
cd LACTSSL
cp config.yaml.example config.yaml && chmod 600 config.yaml
cd web && npm install && cd ..
make build
./bin/lactssl
```

`make build` сначала собирает фронтенд и копирует его в `internal/webui/dist`, затем компилирует `bin/lactssl` со встроенными ресурсами фронтенда. Для сборки только бэкенда можно использовать `make backend`, но артефакты фронтенда нужно подготовить самостоятельно.

## 4. Первичная инициализация

Журнал запуска выводит защищённую точку входа и одноразовый токен инициализации:

```text
Защищённая точка входа: http://127.0.0.1:8080/K7mQ2pX9vR4tY8nL6cWz/
Токен инициализации (действителен только для этого запуска): ...
```

1. Откройте страницу через защищённую точку входа.
2. Создайте учётную запись администратора по подсказкам.
3. При восстановлении из резервной копии импортируйте её в расширенных функциях на `/install` и укажите токен инициализации.
4. После успешной инициализации токен сразу становится недействительным.

До инициализации в разделе «Конфигурация выполнения» на `/install` можно изменить распространённые поля из белого списка: адрес прослушивания и доверенные обратные прокси, `public_url` и сохранение сеанса, ACME (отдельный прослушиватель, внешний адрес, TLS/mTLS), журналы (ротация, журнал доступа, системный журнал), обновление и самообновление программы, переключатели плагинов DNS/развёртывания/уведомлений, репозиторий плагинов и ограничения ресурсов. После сохранения нужно перезапустить службу, чтобы изменения вступили в силу.

Конфиденциальные или высокорисковые поля, такие как `jwt_secret`, `salt`, защищённая точка входа, каталог данных, файлы базы данных и журналов, каталог плагинов, репозиторий программы и публичный ключ подписи, не отображаются на странице; редактируйте `config.yaml` непосредственно на сервере. Защищённую точку входа можно изменить после инициализации и входа через «Настройки → Защищённая точка входа».

> Защищённая точка входа не является границей безопасности. В продакшене обязательно используйте HTTPS, надёжный пароль, TOTP/ключи доступа и сетевой контроль доступа.

## 5. Обратный прокси и HTTPS

Основная программа слушает только HTTP; в продакшене TLS завершается на Nginx, Caddy, Traefik, балансировщике нагрузки или WAF.

### 5.1 Обязательная конфигурация

```yaml
server:
  host: "127.0.0.1"
  port: 8080
  trusted_proxies: ["127.0.0.1"]

security:
  public_url: "https://ssl.example.com"
```

- `trusted_proxies` должен содержать адрес прокси, иначе определение IP клиента и ограничение частоты будут искажены, а проверка `Secure` Cookie также может быть неверной.
- Указывайте точный IP прокси. Если нужен диапазон, используйте минимальный CIDR и избегайте широких диапазонов вроде `10.0.0.0/8`.
- `public_url` используется для ссылок сброса пароля и т. п., нельзя полагаться на Host запроса.
- Если TLS завершается на прокси, убедитесь, что прокси передаёт `X-Forwarded-Proto: https`.

### 5.2 Пример Nginx

```nginx
server {
    listen 443 ssl;
    server_name ssl.example.com;

    ssl_certificate     /etc/nginx/certs/ssl.example.com.pem;
    ssl_certificate_key /etc/nginx/certs/ssl.example.com.key;
    ssl_protocols       TLSv1.2 TLSv1.3;

    client_max_body_size 256m;  # восстановление резервных копий и загрузка плагинов

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        # Режим перезаписи: отбрасываем XFF клиента и оставляем только реальный адрес
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }
}
```

Это рекомендуемый **режим перезаписи**: LACTSSL достаточно доверять только этому Nginx. При переходе на `$proxy_add_x_forwarded_for` (режим добавления) один прокси всё ещё работает корректно, но при нескольких прокси в `trusted_proxies` нужно включить все прокси, которые могут появиться в XFF; иначе IP клиента остановится на вышестоящем прокси. Различия для CDN, Docker/Kubernetes и L4-балансировщиков см. в разделе 11 [Конфигурации](configuration.md).

Рекомендуется дополнительно настроить на уровне прокси белый список исходных IP, VPN, стратегию доступа по принципу нулевого доверия или WAF. Журнал доступа обратного прокси может служить независимым источником аудита, но не записывайте в него Cookie и заголовок `Authorization`.

### 5.3 Сервер ACME (опционально)

Если нужно предоставлять ACME внутренним клиентам:

```yaml
acme:
  enabled: true
  addr: ":14000"
  base_url: "https://pki.example.com:14000"
  tls:
    cert: "/etc/lactssl/acme.crt"
    key: "/etc/lactssl/acme.key"
```

- Если `addr` оставить пустым, ACME монтируется под префиксом `/acme` основного порта; в продакшене рекомендуется отдельный порт.
- `base_url` должен быть адресом, по которому клиенты фактически обращаются; при развёртывании в публичной сети не полагайтесь на Host запроса.
- EAB, белый список доменов, mTLS и ограничения по источникам см. в [Базовая безопасность](security.md).

## 6. Минимальная конфигурация после установки

### 6.1 Безопасность учётной записи

- Сразу включите TOTP или добавьте ключ доступа.
- Настройте контролируемую почту восстановления; на самой почте должна быть включена многофакторная аутентификация.
- Явно закрепите, что учётная запись администратора принадлежит должности, и завершайте передачу при увольнении/переводе.
- В «Настройки → Сеансы» проверьте и отзовите неизвестные сеансы.

### 6.2 Данные и резервные копии

```bash
# Сначала остановите запись, затем копируйте, или используйте зашифрованную резервную копию в интерфейсе
tar czf lactssl-backup-$(date +%F).tar.gz config.yaml data
chmod 600 lactssl-backup-*.tar.gz
```

В продакшене рекомендуется использовать «Системные настройки → Резервное копирование и восстановление» для создания зашифрованного ZIP и хранить резервные копии на отдельном носителе. Пароль резервной копии и `config.yaml` храните раздельно.

### 6.3 Плагины

Основная программа не содержит встроенных плагинов DNS / развёртывания / уведомлений:

1. Перейдите на страницу «Плагины», подтвердите адрес репозитория, нажмите «Обновить индекс».
2. В «Магазине плагинов» установите нужные плагины.
3. В соответствующих списках включите провайдеров, цели развёртывания или каналы уведомлений.
4. В продакшене рекомендуется использовать внутреннее зеркало и фиксировать версии, см. [Управление плагинами](plugins.md).

Если плагины не установлены:

- Список DNS-провайдеров пуст, создать учётную запись DNS невозможно.
- Цели развёртывания — только локальный каталог и SSH.
- Уведомления — только электронная почта.

### 6.4 Проверка

```bash
# Процесс и порты
curl -I http://127.0.0.1:8080/          # без Cookie защищённой точки входа должен вернуть 404, это ожидаемо
ss -lntp | grep 8080

# Проверка аутентификации с помощью API-ключа
curl -H "Authorization: Bearer xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx" \
  https://ssl.example.com/api/status
```

Затем выполните в интерфейсе:

- Создайте учётную запись DNS и протестируйте.
- Создайте тестовую задачу и запустите её.
- Отправьте тестовое уведомление.
- Добавьте мониторинг сайта.
- Скачайте и расшифруйте резервную копию один раз.

## 7. Обновление и удаление

Перед обновлением обязательно сделайте резервную копию; шаги обновления см. в [Обновление и изменения](upgrade.md).

Docker:

```bash
docker compose pull
docker compose up -d
```

Бинарный файл:

```bash
sudo systemctl stop lactssl
sudo cp lactssl /opt/lactssl/lactssl
sudo chown lactssl:lactssl /opt/lactssl/lactssl
sudo systemctl start lactssl
```

Перед удалением сначала экспортируйте резервную копию. Удаление `data/` навсегда лишит вас базы данных, плагинов и зашифрованных учётных данных; удаление `config.yaml` лишит `salt` и `jwt_secret`.

## 8. Частые проблемы при установке

| Симптом | Причина | Решение |
| --- | --- | --- |
| `docker compose up` сообщает, что внешняя сеть не существует | По умолчанию зависит от `1panel-network` | Удалите оба `networks`, чтобы использовать сеть по умолчанию, или сначала создайте эту сеть |
| Доступ к корневому пути возвращает 404 | Запрос не через защищённую точку входа | Используйте адрес точки входа из журнала запуска |
| После входа Cookie работают некорректно/ограничение частоты неточное | Не настроены доверенные прокси | Настройте `trusted_proxies` и передавайте заголовки пересылки |
| Ссылка сброса пароля указывает на неверный домен | Не настроен `public_url` | Задайте фиксированный внешний адрес |
| Загрузка резервной копии/плагина не удалась | Ограничение размера тела запроса в прокси | Настройте `client_max_body_size` |
| Ключ доступа недоступен | Не HTTPS или доступ по IP | Используйте HTTPS-домен или localhost |
| После перезапуска контейнер возвращается к старой версии | Самообновление внутри контейнера | Обновляйтесь через тег образа |

Больше об устранении неполадок см. в [Мониторинг и устранение неполадок](troubleshooting.md).
