# Возможности продукта

Статья описывает по функциональным областям, что умеет LACTSSL, ключевые параметры и ограничения — для разработки и интеграции. Шаги операций — в разделах [Быстрый старт](getting-started.md), [Рабочая консоль](administration.md) и [Интеграция API](api.md).

## Карта возможностей

| Область | Основное содержание | Типичные пользователи |
| --- | --- | --- |
| Сертификатные активы | Заявки в публичный CA, автопродление, сведения и очистка | Платформа/эксплуатация |
| Оркестрация задач | Заявка → развёртывание (может быть несколько) → уведомление; целевой процесс Beta: чтение сайтов → группировка → заявка → развёртывание | Платформа/эксплуатация |
| Доставка сертификатов | Локальный каталог, SSH/SFTP, FTP, Webhook, облачные CDN, панели | Платформа/эксплуатация, целевые системы |
| Внутренний PKI | Создание/импорт частного CA, иерархия, адреса CRL/OCSP | Безопасность, инфраструктура |
| Сервер ACME | Стандартная конечная точка ACME v2 для внутренних клиентов | Внутренние платформы, устройства, тестовые среды |
| Мониторинг и оповещения | Сертификаты внешних сайтов, уведомления о задачах и развёртывании | Эксплуатация, дежурство |
| Аудит и восстановление | Журнал операций, системный журнал, зашифрованные резервные копии | Безопасность, аудит, эксплуатация |
| Интеграция | API-ключи, REST API, автоматизация | Разработка интеграций |

## Заявка и продление сертификатов

### Способы проверки

- Публичный CA использует только **DNS-01**; поддерживаются один, несколько и подстановочные домены.
- Для DNS-01 настройте API-учётные данные в «Учётных записях DNS»; TXT-записи создаются и очищаются автоматически.
- Частный CA выдаёт сертификат напрямую, без ACME-проверки.
- Встроенный сервер ACME поддерживает HTTP-01, DNS-01 и TLS-ALPN-01 для внутренних клиентов.

### Встроенные удостоверяющие центры

| CA | Пояснение |
| --- | --- |
| Let's Encrypt | Публичный CA по умолчанию, EAB не нужен |
| ZeroSSL | Требуется EAB |
| Google Trust Services | Требуется EAB |
| LiteSSL | Требуется EAB |
| ZoTrus | Требуется EAB; KID — зарегистрированная почта; ручная DNS-проверка, без подстановочных сертификатов |
| Actalis | Требуется EAB |
| SSL.com | Требуется EAB; эндпоинт ECDSA/RSA выбирается по типу ключа |

В «Публичных CA» можно добавить **универсальные ACME-апстримы**: адрес каталога, ACME v1/v2 и необязательный EAB. Апстрим появляется в выборе задач и CA по умолчанию; адрес каталога должен использовать HTTPS (HTTP — только loopback), ACME v1 поддерживает только DNS-01 и не поддерживает EAB.

### Ключи и продление

- Типы ключей: `ecdsa` (по умолчанию), `ecdsa384`, `rsa2048`, `rsa4096`.
- Автопродление по умолчанию — за 30 дней до истечения, настраивается для каждой задачи; планировщик проверяет задачи каждые 30 секунд.
- «Не хранить закрытый ключ на сервере»: ключ остаётся только в памяти при выпуске и развёртывании, не пишется в базу и недоступен для скачивания; при автопродлении нужен хотя бы один включённый узел развёртывания.
- Причина сбоя видна в журнале задачи; для учётных данных, доменов и CA выдаются понятные ошибки.
- Страница сертификатов поддерживает поиск, фильтрацию по статусу и источнику (задача, ACME-сервер, CSR), сведения и анализ безопасности.
- Скачивание цепочки требует сеанса или `certificates:read`; просмотр и скачивание ключа — дополнительно `certificates:key`.
- Очистка фильтрует по статусу, длительности, времени выдачи, домену, CA, источнику и «сохранить последний сертификат каждой задачи»; ссылки в задачах очищаются.

### Конфигурация по умолчанию

«Публичные CA» настраивает почту ACME, CA по умолчанию, тип ключа, дни продления и EAB-учётные данные для каждого CA.

### Целевой процесс Beta

Целевой процесс Beta подходит для сценария «сертификат следует за сайтом панели»: встроенная возможность `plan` цели развёртывания считывает реальные сайты и домены, сертификаты группируются по стратегии и развёртываются обратно.

- Вкладки «Все / Обычный процесс / Целевой процесс Beta» разделяют процессы; несколько источников сайтов берутся из целевой системы, а не вводятся вручную.
- Стратегии: умная рекомендация, один сертификат на сайт, объединение по основному домену, все выбранные сайты в один сертификат, один сертификат на источник, пользовательская группировка.
- Поддерживаются выбор сайтов, правила включения/исключения доменов и дополнительные домены.
- При автопродлении сайты читаются заново: «Все сайты» включает новые, «Только выбранные» сохраняет стабильные ключи.
- Задача Beta может быть связана с несколькими сертификатами (`certificates.task_id`); при очистке с «сохранить последний сертификат» сертификаты Beta не удаляются.

### Заявка CSR с клиента

- Клиент отправляет CSR; сервер проверяет DNS-01 в публичном CA или подписывает сертификат частным CA, не создавая и не сохраняя закрытый ключ.
- Заявка асинхронна: можно запросить статус, отменить, повторить и скачать цепочку по номеру заявки.
- Поддерживаются только публичные CA ACME v2 и DNS-01; для подстановочных сертификатов DNS-01 обязателен.
- Требуется право `certificates:request`; домены можно ограничить через `csr.allowed_domains`.

## DNS-провайдеры

- Официальная реализация встроена и покрывает около 235 записей (228 lego v5 + 7 совместимых ID); все провайдеры по умолчанию отключены и включаются в «Плагинах».
- Учётные данные шифруются перед записью в базу; `manual` требует ручного добавления TXT-записей и не входит в автоматический процесс.
- Часть провайдеров поддерживает собственный API-апстрим для прокси или совместимого шлюза. Полный список, требования к учётным данным и устранение неполадок — в [DNS-плагинах](dns-plugins.md).

## Оркестрация задач

Задача состоит из узлов: «заявка → развёртывание (может быть несколько) → уведомление».

| Узел | Ключевые параметры |
| --- | --- |
| Заявка | Домен, учётная запись DNS, CA, тип ключа, автопродление, дни заранее |
| Развёртывание | Учётные данные цели, путь к сертификату/ключу, сайт/домен/имя сертификата, команда перезагрузки |
| Уведомление | Канал и момент срабатывания (всегда / только успех / только сбой) |

- Узлы включаются, отключаются и упорядочиваются; один сертификат можно доставить на несколько целей.
- Старые задачи без явного процесса получают эквивалентный процесс по исходным полям; при обновлении пути развёртывания сайты и домены переносятся в узлы задачи.
- Список задач поддерживает массовый выбор, выполнение, паузу и включение автопродления; выполняющиеся задачи пропускаются, а переключение планирования не прерывает начатую выдачу.
- Перед выполнением повторно используется действительный сертификат вне окна продления — выполняется только развёртывание; для перевыпуска используйте «Принудительный перевыпуск» или `?force=1`. При ограничении частоты CA задача ждёт восстановления квоты, а не повторяется как обычный сбой.

## Развёртывание сертификатов

«Учётные данные цели» хранят только аутентификацию и подключение; путь к сертификату, команда перезагрузки, домен и сайт задаются в узле развёртывания, поэтому одни данные используются несколькими задачами.

### Встроенные цели

| Цель | Учётные данные | Параметры развёртывания |
| --- | --- | --- |
| Локальный каталог | Нет | Путь к сертификату/ключу, необязательная команда перезагрузки |
| SSH / SFTP | Хост, порт, пользователь, пароль или ключ, отпечаток хоста | Удалённые пути и необязательная команда перезагрузки |

SSH по умолчанию требует отпечаток хоста (`SHA256:...`); TOFU применяется только при явном включении, при последующем несовпадении подключение отклоняется.

### Цели плагинов

Официальные цели развёртывания встроены и включаются в «Плагинах»:

- FTP/FTPS: обычный FTP, явный и неявный TLS.
- Webhook: адрес, пользовательские заголовки аутентификации, пропуск проверки TLS.
- Alibaba Cloud CDN, Qiniu, BaoTa, 1Panel, SafeLine WAF и другие; продукт и параметры выбираются в узле развёртывания.

Цели получают сертификат и закрытый ключ и эквивалентны доверенному коду, поэтому включайте только нужные и доверенные; сторонние helper по умолчанию отключены, исторические учётные данные сохраняются. Подробнее — в [Плагинах развёртывания](deploy-plugins.md) и [Управлении плагинами](plugins.md).

### Цепочка доверия внутреннего CA

«Системные настройки → Цепочка доверия TLS» импортирует открытые ключи внутренних CA (PEM, корневой и подчинённые). Проверка TLS целей использует системные корни плюс импортированные CA; мониторинг доверяет выданным ими сертификатам, а частный CA программы добавляется автоматически. Развёртывание, команды и helper читают цепочку через `SSL_CERT_FILE` (также `CURL_CA_BUNDLE`, `REQUESTS_CA_BUNDLE`); файл `trusted-ca-bundle.pem` хранится в каталоге данных и доступен для скачивания.

Импортируйте только контролируемые CA: ошибочный CA ослабит TLS. После удаления CA его сертификаты снова станут недоверенными. Импорт не исправляет просроченный, ещё не вступивший в силу или несоответствующий домену сертификат.

### Записи о развёртывании

- Каждое развёртывание создаёт запись в сведениях о сертификате и журналах.
- Ручное развёртывание повторно использует параметры узла задачи или позволяет задать их отдельно.
- Для команды перезагрузки API-ключ должен явно иметь `deploy:execute`; при сбое старый сертификат в цели не откатывается — сохраняйте предыдущую версию или используйте атомарную публикацию.

## Мониторинг сертификатов сайтов

Служба периодически читает сертификат внешнего сайта через TLS:

- Цель: `example.com`, `example.com:8443` или URL; порт по умолчанию `443`.
- Проверка по умолчанию раз в 24 часа, настраивается для каждого элемента.
- Проверяются имя хоста, издатель, срок и статус; остаток менее 30 дней — «скоро истекает», просроченный сертификат, сбой подключения, недоверенная или неполная цепочка и несовпадение имени — аномалия.
- При переходе из нормы в «скоро истекает», «просрочен» или «аномалия» отправляется уведомление.
- Проверяется системная цепочка доверия, чтобы самоподписанный сертификат не скрыл проблему; импортированные и частные CA также доверенные.

## Уведомления

### Встроенные каналы

- **Электронная почта (SMTP)**: сервер, порт, пользователь, пароль, отправитель, SSL.
- По умолчанию используется неявный TLS (`smtp.ssl=true`); если сервер не поддерживает STARTTLS при отключённом неявном TLS, отправка отклоняется, чтобы не передавать токены сброса открытым текстом.

### Каналы плагинов

Официальные каналы встроены: Gotify, ServerChan, ntfy, GoCQHTTP, PushDeer, Bark, Telegram, DingTalk, робот WeCom, приложение WeCom, интеллектуальный робот WeCom, iGot, PushPlus, WePlus, WxPusher, WxPusher SPT, OpenILink, WPush, Synology Chat, Feishu, PushMe, ChronoCat и универсальный Webhook.

- Каналы включаются отдельно, поддерживают тестовые сообщения и выбираются в узле уведомления (конкретный или все включённые).
- Момент срабатывания: «всегда», «только успех», «только сбой».

## Частный CA

### Создание

- Ключи: ECDSA P-256/P-384, RSA 2048/4096; срок задаётся по необходимости.
- Можно создать корневой CA или промежуточный/выдающий от существующего частного CA.
- Настраиваются субъект (ST, L, OU, Email, серийный номер), расширения (длина пути, Key Usage, Extended Key Usage, SAN DNS/IP, Name Constraints) и инфраструктура (вышестоящий CA, CRL, OCSP, издатель CA, OID политики, CPS).
- SKI, AKI и базовые ограничения CA генерируются автоматически; срок и длина пути ограничиваются вышестоящим CA.

### Импорт

- Вставьте сертификат CA и ключ в PEM.
- Проверяются ограничения CA, назначение подписи и соответствие сертификата ключу.
- Для промежуточного CA можно выбрать вышестоящий: подпись проверяется, иерархия устанавливается.

### Скачивание и удаление

- Можно скачать сертификат CA, ключ или полную цепочку.
- Список не возвращает содержимое; для ключа требуется `private_cas:key`.
- Удаление убирает CA и ключ на сервере; подчинённые CA нужно удалить заранее.

### Ограничения

- Ключи частного CA шифруются в базе, но это не HSM/KMS.
- Корневой и промежуточный CA могут быть органом выдачи; полная цепочка сохраняется и развёртывается вместе с сертификатом.
- Срок сертификата по умолчанию 365 дней и не превышает срок CA.
- Адреса CRL/OCSP записываются в новые сертификаты, но списки отзыва и онлайн-статус предоставляет внешняя инфраструктура PKI; существующие сертификаты не получают CDP/AIA автоматически — нужен перевыпуск.

## Сервер ACME

Встроенный сервер ACME v2 включён по умолчанию и открывает частный CA клиентам certbot, lego, acme.sh и другим. Без созданной и включённой конечной точки сертификаты не выдаются.

### Конечные точки

- Конечная точка привязана к одному частному CA и использует случайный URL slug, например `/acme/internal/directory`.
- Поддерживаются EAB, белый список доменов, HTTP-01/DNS-01/TLS-ALPN-01, отдельный порт, прямой TLS и mTLS.
- Настраиваются срок сертификата, ограничение частоты заказов и белый список CIDR для HTTP-01.

### Возможности протокола

- Учётная запись хранит только открытый ключ; поддерживается ротация ключа (`keyChange`).
- ARI (RFC 9773): окно продления — примерно 1/3 срока, не более 30 дней; для отозванных и просроченных сертификатов возвращается прошлое окно. Поле `replaces` объявляет заменяемый сертификат, сервер проверяет принадлежность, пересечение идентификаторов и повторную замену.
- Поддерживаются DNS и IP-идентификаторы; для IP разрешены только HTTP-01/TLS-ALPN-01 и нужен белый список подсетей.
- В новые сертификаты записываются CRL Distribution Point и OCSP AIA; статус доступен через `/pki/{ca}/crl` и `/pki/{ca}/ocsp`. Частный CA должен иметь `cRLSign` — это проверяется при включении конечной точки.

### Диагностика и очистка

- «Диагностика ACME» показывает состояние учётных записей, заказов, авторизаций, проверок и сертификатов.
- Очистка недействительных заказов и неиспользуемых учётных записей фильтруется по конечной точке, статусу и времени; заказы удаляются, выданные сертификаты сохраняются.
- CRL/OCSP организуются по CA и остаются доступными после отключения конечной точки регистрации ACME.

## Панель управления и журналы

### Панель управления

Интерфейс поддерживает упрощённый китайский и английский языки, переключается в настройках. Главная страница показывает общее число сертификатов, «скоро истекает»/«просрочено», состояние задач и мониторинга, долю успешных развёртываний, распределение сроков и динамику выдачи.

### Журналы: журнал операций

- Находится в «Разное → Журналы» вместе с системным журналом, переключение по вкладкам.
- Записывает задачи, выдачу, развёртывание, уведомления, мониторинг и изменения настроек; фильтруется по источнику, уровню, ключевым словам и времени, поддерживает автообновление.
- Ключевые слова сопоставляются с исходным сохранённым содержимым и значениями параметров, а не с отрендеренным текстом.
- Экспорт в CSV/JSON (CSV с UTF-8 BOM) использует те же условия, что и список; доступны последние 90 дней.
- Очистка при включённом архивировании сначала пишет `data/archives/logs/`, затем удаляет; требуется `logs:write` и повторное подтверждение. Время экспорта — часовой пояс браузера или `TZ` сервера.

### Журналы: системный журнал

- Отфильтровывается из журнала процесса и асинхронно пишется в базу; фильтры по уровню, компоненту, ключевым словам и времени.
- Экспорт CSV/JSON и очистка с архивом; действие очистки записывается в журнал операций.
- По умолчанию уровни `info` и выше, хранение 7 дней или 20 000 строк; журнал доступа HTTP по умолчанию не пишется в базу (`log.system`).

### Журналы: архивы

- Третья вкладка «Разное → Журналы»; архивы создаются при ручной очистке, очистке операций старше 90 дней и системного журнала по сроку/строкам.
- Архив состоит из `*.ndjson.gz` и `*.manifest.json` и хранит исходные поля, число строк, диапазон ID/времени, причину, оператора, SHA-256 и размер.
- Фильтрация по категории, причине, ключевым словам и времени; скачивание и удаление. По умолчанию хранится бессрочно (`log.archive.retention_days`, `max_total_mb`, `quota_policy`).
- Сбой архивирования блокирует удаление; каталог архивов не входит в ZIP-копию по умолчанию и не является неизменяемым аудитом.

## Границы возможностей

| Граница | Пояснение |
| --- | --- |
| Проверка публичных сертификатов | Только DNS-01; HTTP-01 для публичного CA не поддерживается |
| Многопользовательский режим | Один администратор, без многопользовательского режима и RBAC |
| Федерация идентификации | Нет LDAP/OIDC/SAML/SCIM |
| Высокая доступность | Нет кластера/«активный-активный»; SQLite с одной записью |
| Хранение ключей | Локальное зашифрованное хранение, без HSM/KMS |
| Мониторинг | Нет метрик Prometheus; есть журналы и API аутентификации |
| Откат развёртывания | Старые сертификаты в цели автоматически не откатываются |
