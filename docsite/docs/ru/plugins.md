# Управление плагинами

DNS, развёртывание сертификатов и уведомления в LACTSSL реализуются плагинами. Официальные реализации находятся в `internal/plugin/` и компилируются в основную программу; `plugins/` — SDK для разработки внешних плагинов. Загруженные сторонние helper выполняются как одноразовые дочерние процессы и по умолчанию ограничены песочницей.

## Модель плагинов

- **Встроенные плагины**: официальные реализации DNS, развёртывания и уведомлений поставляются вместе с основной программой и не требуют установки через сеть.
- **Загружаемые плагины**: администратор может загрузить один helper для временной проверки или стороннего расширения; по умолчанию такой плагин отключён, после включения он выполняется как дочерний процесс.
- **Два уровня включения**: категории (`plugins.enabled`, `deploy_plugins.enabled`, `notify_plugins.enabled`) и отдельные элементы (DNS-провайдеры, цели развёртывания, каналы уведомлений по белому списку).
- **Репозитория плагинов больше нет**: нет индекса, подписанного индекса, магазина и автообновления; обновления официальных плагинов выходят вместе с версией основной программы.

Протокол плагинов остаётся v1:

```text
manifest / present / cleanup / deploy / options / plan / send
```

Встроенные реализации вызываются напрямую в процессе хоста; загруженные плагины обмениваются с хостом JSON через stdin/stdout.

## Конфигурация

```yaml
plugins:
  enabled: true
  dir: ""                 # каталог загруженных DNS helper; пусто — <data_dir>/plugins/dns
  sandbox: strict         # strict / basic / off
  memory_limit_mb: 128
  timeout_seconds: 60
  max_output_kb: 64

deploy_plugins:
  enabled: true           # цели развёртывания включены по умолчанию; плагин получает закрытые ключи
  dir: ""
  sandbox: strict
  memory_limit_mb: 128
  timeout_seconds: 300
  max_output_kb: 64

notify_plugins:
  enabled: true
  dir: ""
  sandbox: strict
  memory_limit_mb: 128
  timeout_seconds: 30
  max_output_kb: 64
```

Параметр `sandbox` **применяется только к загруженным/внешним helper**; встроенные плагины вызываются напрямую в процессе хоста. В Linux режим `strict` использует белый список доступа к файлам Landlock, rlimit, `no_new_privs` и отдельную группу процессов. Если ядро или контейнер не поддерживают Landlock, происходит автоматический переход на `basic` (минимальный набор переменных окружения, приватный временный каталог, ограничения времени/RSS/вывода) с записью в журнал. Если хост по-прежнему работает под root без `LACTSSL_RUN_UID`/`LACTSSL_RUN_GID`, загруженные плагины отклоняются: Landlock не может предотвратить обход через mount/ptrace для root. Режим `off` предназначен только для контролируемой отладки.

## Встроенные плагины и память

Все встроенные реализации по умолчанию компилируются в основную программу; отключение категории или элемента не выгружает код, но исключает регистрацию соответствующей реализации и создание провайдера. Для существенного уменьшения размера бинарника и памяти можно использовать теги сборки: `make backend-no-dns` полностью исключает встроенную реализацию DNS (RSS в простое около 36 MB), официальные сборки включают всё (RSS в простое около 70 MB). Основная память полной сборки приходится на страницы кода lego v5 в DNS; метаданные занимают всего около 1 MB. Включение всех 235 провайдеров добавляет к пустому списку примерно 3–5 MB. Встроенная реализация DNS через глобальную блокировку конструктора устанавливает и восстанавливает переменные окружения lego v5; `present/cleanup` могут выполняться параллельно.

## Включение и отключение

### Категории

Переключатель категории определяет, регистрируются ли встроенные реализации этого типа. После отключения встроенные элементы этой категории не отображаются в списке доступных, а загруженные helper того же типа не выполняются; при этом сохранённые учётные записи, задачи и белые списки сохраняются.

### Элементы

- DNS: по умолчанию ни один провайдер не включён; включайте их вручную на странице «Плагины».
- Развёртывание: категория и 25 канонических целей включены по умолчанию; ненужные можно отключить.
- Уведомления: по умолчанию включены 23 канала.

При включении более 10 элементов за раз требуется подтверждение, чтобы случайно не включить множество провайдеров.

## Загрузка плагинов и песочница

Порядок загрузки: выбрать категорию и файл helper → выполнить в песочнице `manifest` для проверки протокола, ID, версии, дайджеста и платформы → записать файл в каталог плагинов (новый файл по умолчанию отключён) → включить файл, а затем его элементы.

Ограничения: принимается только один исполняемый файл размером до 256 MB; символические ссылки и файлы, доступные на запись группе или другим пользователям, отклоняются; загруженные плагины не могут занимать ID или псевдонимы встроенных элементов. Песочница `strict` разрешает чтение только системных конфигураций CA/DNS и собственных файлов, запись — только в приватный временный каталог; доступ к каталогу данных, конфигурации, базе данных и другим плагинам запрещён. Песочница не изолирует сеть: загруженные плагины по-прежнему имеют исходящий доступ, поэтому загружайте только код из доверенных источников.

## Обновление, откат и удаление

- Встроенные плагины обновляются вместе с основной программой; их нельзя установить, обновить или удалить отдельно, а состояние включения сохраняется после обновления.
- Загруженные плагины администратор загружает повторно; старый файл сначала сохраняется в резервную копию, при сбое выполняется откат. Удаление загруженного файла также очищает отпечаток, метаданные элемента и белый список включения.

## Миграция старых плагинов из репозитория

Для развёртываний, где до обновления были установлены плагины официального репозитория: официальные плагины теперь предоставляются встроенными реализациями, поэтому старые файлы helper следует отключить или удалить; учётные записи, задачи и белые списки включения остаются без изменений. Сторонние плагины, не входящие в официальный набор, сохраняются как «устаревшие/загруженные» и по умолчанию выполняются в песочнице `strict`, но источника обновлений у них больше нет — рекомендуется заменить или удалить их.

## Меры безопасности

- Встроенные плагины — часть цепочки поставок основной программы и поставляются с её подписью/дайджестом образа; загруженные плагины по умолчанию выполняются в песочнице, не настраивайте `sandbox: off` в продакшене.
- Плагины развёртывания получают доступ к закрытым ключам и включены по умолчанию; оставляйте только доверенные цели. Каталог плагинов — `0700`, helper — `0755`; символические ссылки и запись для группы или других пользователей запрещены.
- Дайджест загруженного helper повторно проверяется при обнаружении, регистрации и перед каждым вызовом; для управления плагинами нужны `plugins:read` / `plugins:write`; загрузка, включение и отключение записываются в журнал аудита, а переход на резервный режим при недоступности strict — в журнал запуска хоста.

## API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/plugins` | Состояние встроенных и загруженных плагинов, элементы и файлы |
| POST | `/api/plugins/rescan` | Повторное сканирование загруженных плагинов |
| POST | `/api/plugins/upload` | Загрузка helper |
| DELETE | `/api/plugins/files/:kind/:file` | Удаление загруженного helper |
| PUT | `/api/plugins/files/:kind/:file` | Включение/отключение на уровне файла |
| PUT | `/api/plugins/providers/:id` | Включение/отключение DNS-элемента |
| PUT | `/api/plugins/deployers/:id` | Включение/отключение элемента развёртывания |
| PUT | `/api/plugins/notify-channels/:id` | Включение/отключение элемента уведомлений |
| GET | `/api/plugins/icons` | Значки |

API, связанные с репозиторием плагинов, удалены.

## Устранение неполадок

| Симптом | Причина | Обработка |
|---|---|---|
| Встроенный элемент недоступен | Категория отключена или элемент не включён | Проверьте конфигурацию категории и белый список элементов |
| После загрузки нет элементов | Файл по умолчанию отключён | Включите файл, затем элементы |
| Загруженный плагин не выполняется или Landlock недоступен | Ограничения песочницы strict или seccomp ядра/контейнера | Проверьте ошибку; при необходимости перейдите на `basic` с аудитом; для Docker проверьте seccomp |
| Конфликт ID или риск закрытых ключей развёртывания | Совпадение с ID встроенного элемента; категория развёртывания включена | Выберите другой ID; оставьте только доверенные цели и отключите ненужные элементы |
