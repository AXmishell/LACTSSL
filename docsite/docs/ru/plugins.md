# Управление плагинами

Возможности LACTSSL по работе с DNS, развёртыванию сертификатов и уведомлениям предоставляются плагинами. Основная программа только загружает плагины, запускает одноразовые подпроцессы helper и управляет установкой, включением и удалением. Для предприятия плагины — не обычные расширения, а **граница цепочки поставок**:

- Плагины DNS получают учётные данные API DNS-провайдеров.
- Плагины развёртывания получают сертификаты и закрытые ключи.
- Плагины уведомлений получают токены/Webhook каналов.
- Все плагины работают под учётной записью службы и считаются доверенным кодом.

Поэтому плагины следует включать в управление изменениями и проверку допуска, а не позволять произвольным пользователям устанавливать их в любое время.

## 1. Модель плагинов

- **Объединение пакетов по типу**: официальный репозиторий плагинов собирает объединённые пакеты по типам: DNS полный·переработанный, DNS полный·lego, DNS полный·lego v5, развёртывание, уведомления. Каждый пакет содержит несколько реализаций этого типа и использует общую среду выполнения Go.
- **Установка по необходимости**: пакет выпуска основной программы не содержит встроенных плагинов; устанавливайте объединённый пакет того типа, возможности которого нужны.
- **Протокол v1**: плагин — это исполняемый файл, который взаимодействует с основной программой через подкоманды `manifest`, `present/cleanup`, `deploy`, `send` и др.
- **Отдельные каталоги**:
  - DNS: `<data_dir>/plugins/dns`
  - развёртывание: `<data_dir>/plugins/deploy`
  - уведомления: `<data_dir>/plugins/notify`
- **Одноразовый подпроцесс**: запускается при каждом вызове, завершается после выполнения и не находится постоянно в памяти.

## 2. Репозиторий и доверие

```yaml
plugins:
  repo:
    enabled: true
    url: "https://github.com/AXmishell/LACTSSL-Plugins/releases/download/plugin-index/index.json"
    channel: stable
    auto_update: false
    public_key: "t7Q4vd0B1zh3mRf0t6Q6qlBViL7cKhoipgpGWx5WSss="
    timeout_seconds: 30
    max_download_mb: 256
    check_interval_hours: 24
```

Адрес репозитория, канал, автоматическое обновление и открытый ключ также можно изменить на странице «Плагины». Настройки интерфейса сохраняются в базе данных и имеют приоритет над `config.yaml`, но не записываются обратно в файл конфигурации.

### 2.1 Цепочка проверок

1. При настроенном открытом ключе принудительно проверяется `index.json.sig` (Ed25519).
2. Локально кешированный индекс дополнительно защищается HMAC с помощью серверного ключа.
3. Перед скачиванием требуется, чтобы индекс предоставлял SHA-256 артефакта; при отсутствии или неверном формате скачивание сразу отклоняется.
4. После скачивания принудительно проверяется SHA-256 артефакта.
5. При установке проверяются `plugin.json`, ID и версия в манифесте, платформа и `min_host`.
6. Запись установки сохраняет дайджест файлов; он повторно проверяется при обнаружении, регистрации и перед каждым вызовом DNS/развёртывания/уведомлений; при замене файла загрузка или выполнение отклоняется.
7. Сбой на любом шаге приводит к откату, и не остаётся незавершённых изменений.

Если открытый ключ подписи не настроен, отображается предупреждение о риске и пропускается автоматическое обновление без участия оператора. В продуктивной среде не рекомендуется отключать проверку подписи.

## 3. Модели развёртывания на предприятии

### 3.1 Прямое подключение к официальному репозиторию

Применимо: сеть имеет доступ к GitHub, плагинов немного, официальный репозиторий приемлем как источник доверия.

Требования:

- Настроить официальный открытый ключ и принудительно проверять подпись.
- Отключить автоматическое обновление и обновлять вручную в рамках окна изменений.
- Записывать версию и дайджест каждой установки/обновления.

### 3.2 Внутреннее зеркало (рекомендуется)

Применимо: продуктивная среда, офлайн/полуофлайн-режим, необходимость фиксированных версий и проверки допуска.

Способ первый: направить индекс на внутреннее HTTPS-зеркало:

```yaml
plugins:
  repo:
    url: "https://mirror.example.com/lactssl-plugins/index.json"
    public_key: "<открытый ключ подписи предприятия>"
```

Способ второй: офлайн-каталог:

```yaml
plugins:
  repo:
    url: "file:///srv/lactssl-plugins/index.json"
```

Внутреннее зеркало должно:

- Синхронизировать официальный индекс и артефакты с сохранением исходного SHA-256.
- Повторно подписывать индекс собственным ключом Ed25519 предприятия либо как минимум проверять официальную подпись перед предоставлением.
- Синхронизировать только версии, прошедшие допуск, и не следовать автоматически за `latest`.
- Каталог зеркала должен быть доступен только для чтения; запись разрешена только учётной записи синхронизации.
- Записывать версию, источник, дайджест, утверждающее лицо и версию для отката.

### 3.3 Ручная загрузка

На странице «Плагины» можно загрузить отдельный helper или поместить файл в каталог плагинов и запустить повторное сканирование. Подходит для временной проверки или сторонних плагинов.

- При загрузке принимается только один исполняемый файл helper размером не более 256 MB.
- После загрузки сначала во временном файле проверяется `manifest`, протокол, ID и SHA-256, и только после успешной проверки файл записывается в каталог плагинов и выполняется повторное сканирование.
- По умолчанию перезапись одноимённого файла запрещена; при обновлении можно установить флажок «Разрешить перезапись одноимённого плагина», и старый файл будет предварительно сохранён в резервную копию.
- Вручную загруженные плагины помечаются как `manual` и не участвуют в обновлении из официального репозитория.
- Загружайте только доверенные файлы; helper выполняется под учётной записью службы.

## 4. Установка и включение

### 4.1 Установка

1. Откройте страницу «Плагины», проверьте адрес репозитория и нажмите «Обновить индекс».
2. Откройте «Магазин плагинов» и отфильтруйте по категориям DNS / развёртывание / уведомления или выполните поиск.
3. Установите нужные плагины; после завершения сначала включите файл плагина, затем при необходимости включите элементы внутри него.

Для каждого плагина отображается:

- Название, ID, версия, размер.
- Наличие установочного пакета для текущей платформы.
- Совместимость с текущей версией хоста.
- Установленная версия и доступность обновления.

Новые скачанные или загруженные плагины по умолчанию отключены: файл helper записывается на диск в отключённом состоянии и не выполняет `manifest`; после включения файла элементы внутри него всё равно остаются отключёнными по умолчанию. При обновлении или перезаписи одноимённого файла прежнее состояние включения сохраняется.

### 4.2 Двухуровневое включение

Каждая строка на странице плагинов соответствует одному файлу helper; состояние включения делится на два уровня:

1. **Уровень файла**: переключатель в начале строки управляет участием helper в обнаружении и загрузке. После отключения `manifest` этого файла больше не выполняется, а его элементы не регистрируются во время выполнения; отметки существующих элементов сохраняются и восстанавливаются после повторного включения файла.
2. **Уровень элементов**: нажмите «Управление элементами», чтобы включить провайдеров, цели развёртывания или каналы уведомлений по одному, либо отметьте несколько и включите/отключите их пакетно. Элементы нового установленного плагина по-прежнему отключены по умолчанию.

Пояснения:

- Когда файл отключён, его элементы всё равно отображаются (из кешированного хостом дайджеста манифеста), но переключатели неактивны, и сначала нужно включить файл.
- Объединённые пакеты (например, `lactssl-dns-all-native`, предоставляющий 194 элемента) не включаются целиком одним переключателем в начале строки; при включении более 10 элементов за один раз требуется подтверждение.
- Удаление файла или удаление плагина одновременно очищает кеш манифеста, состояние уровня файла и удаляет все элементы этого файла из белого списка элементов.

## 5. Обновление, откат и удаление

- **Обновление**: нажмите «Обновить» в магазине плагинов либо после включения автоматического обновления регулярно проверяйте согласно `check_interval_hours`.
- **Пакетное обновление**: пустое тело запроса `POST /api/plugins/repo/update` означает обновление всех установленных плагинов.
- **Откат**: в продуктивной среде рекомендуется сохранять предыдущую версию во внутреннем зеркале; при сбое обновления переустановите старую версию.
- **Удаление**: разрешено удалять только плагины, установленные из репозитория плагинов; при удалении удаляются файлы плагина и запись установки, а сам плагин исключается из белого списка включённых.
- **Удаление файлов**: на каждой вкладке плагинов перечислены фактические файлы helper в каталоге плагинов (включая загруженные вручную и старые полные bundle-пакеты), которые можно удалить напрямую; удаление убирает все элементы, предоставляемые этим файлом, запись установки и состояние включения и немедленно запускает повторное сканирование.

Обновление выполняется по схеме «скачивание → проверка → резервная копия → атомарная замена → проверка манифеста»; сбой на любом шаге восстанавливает старый файл.

### 5.1 Рекомендуемый порядок изменений

1. Установите целевую версию в среде предварительного развёртывания.
2. Проверьте `manifest`, список элементов и ключевые цепочки (выпуск через DNS, развёртывание, уведомления).
3. Запишите версию, дайджест и результаты тестирования.
4. Обновите в окне изменений продуктивной среды и наблюдайте за журналами задач.
5. При сбое откатитесь к предыдущей версии в зеркале.

## 6. Размер пакетов и ресурсы

Размер, отображаемый в магазине плагинов, рассчитывается по **распакованному** виду, то есть соответствует фактическому размеру helper на диске. Текущие официальные объединённые пакеты (linux/amd64) имеют примерно следующие размеры:

| Пакет | После распаковки |
|---|---:|
| DNS полный·переработанный (194 провайдера) | около 18 MiB |
| DNS полный·lego (194 провайдера) | около 58 MiB |
| DNS полный·lego v5 (235 элементов) | около 37 MiB |
| Развёртывание (25 целей) | около 8 MiB |
| Уведомления (23 канала) | около 7 MiB |

- Большинству пользователей достаточно установить пакет DNS полный·переработанный размером около 18 MiB, который охватывает все 194 провайдера.
- Если нужны полные возможности lego v4 (например, rfc2136 GSS-TSIG), установите пакет DNS полный·lego размером около 58 MiB.
- Если нужно следовать за lego v5 и новыми провайдерами, установите пакет DNS полный·lego v5 размером около 37 MiB; три пакета DNS взаимоисключающие.
- При установке всех пакетов объём составляет около 73 MiB, что примерно на 96 % меньше суммарного распакованного объёма 224 отдельных пакетов плагинов — около 1,7 GiB.

Распаковка при установке/обновлении вызывает кратковременный пик памяти; при планировании ёмкости необходим запас, см. [Архитектура развёртывания](architecture.md).

## 7. Миграция старых полных плагинов

В развёртываниях, где до обновления использовались `lactssl-dns-helper-extra`, `lactssl-deploy-helper` или `lactssl-notify-helper`, на странице «Плагины» отображается подсказка о миграции:

1. Система читает манифест старого плагина и находит провайдеров, которые включены или всё ещё используются учётными записями/задачами.
2. Скачивает и устанавливает соответствующий объединённый пакет; объединённый пакет заменяет старые helper для отдельных провайдеров и старые полные helper.
3. После успешного завершения всех шагов удаляет старые файлы и выполняет повторное сканирование.
4. При сбое на любом шаге выполняется откат текущей установки, и старый плагин продолжает работать.

До завершения миграции старый плагин не удаляется, чтобы не прерывать сайты, которые в данный момент выпускают сертификаты.

## 8. Значки провайдеров

Логотипы DNS-провайдеров и провайдеров развёртывания относятся к метаданным плагина и предоставляются репозиторием плагинов; основная программа больше не содержит встроенной таблицы значков:

- **До установки**: индекс репозитория содержит встроенные значки в `icons`, которые проверяются вместе с подписью индекса и используются для отображения в магазине плагинов.
- **После установки**: каталог `icons/` из пакета плагина записывается в `<data_dir>/plugin-icons/<kind>/<ID плагина>/`, поэтому страница учётных данных может отображать значки и без сети или при отключённом репозитории.
- **Интерфейс чтения**: фронтенд получает значки одним запросом `GET /api/plugins/icons`; при отсутствии значка, повреждении значка или старой версии хоста используется аватар с первой буквой.
- **Псевдонимы**: исторические ID, такие как `aliyun_cdn`, `baota_site`, `qiniu_kodo`, сопоставляются с каноническими значками через `assets/icons/icons.json` репозитория.
- **Значки объединённых пакетов**: используется только значок уровня пакета, соответствующий ID пакета; если значок уровня пакета не предоставлен, он не отображается; элемент пакета также может принудительно отключить его, объявив `hide_icon: true`.

Для значков разрешены только svg / png / webp размером не более 64 KB на изображение; недопустимые элементы отбрасываются и не влияют на установку и обновление плагинов.

## 9. Меры безопасности

- Используйте только доверенные репозитории; в продуктивной среде настраивайте открытый ключ подписи и принудительно проверяйте подпись.
- Перед скачиванием требуйте SHA-256 артефакта, после установки повторно проверяйте дайджест файлов.
- Плагины развёртывания получают доступ к закрытым ключам, по умолчанию отключены; устанавливайте их только из доверенных источников.
- Каталог плагинов — `0700`, helper — `0755`; запись для группы или других пользователей не допускается.
- Символические ссылки не допускаются; при замене файла загрузка отклоняется.
- Ограничивайте `memory_limit_mb`, `timeout_seconds` и `max_output_kb`, чтобы аномальный плагин не вывел из строя хост.
- Плагины работают под учётной записью службы; не давайте пользователю `lactssl` дополнительных прав и не размещайте каталог плагинов на общем пути с правом записи.
- Записывайте операции установки/обновления/удаления плагинов и включайте их в аудит изменений.

## 10. API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/plugins` | Состояние плагинов, элементы и файлы helper в каталоге |
| GET | `/api/plugins/repo` | Конфигурация репозитория и состояние индекса |
| PUT | `/api/plugins/repo` | Изменение конфигурации |
| POST | `/api/plugins/repo/refresh` | Принудительное обновление индекса |
| GET | `/api/plugins/repo/plugins` | Список плагинов репозитория |
| POST | `/api/plugins/repo/install` | Установка `{kind,id,version}` |
| POST | `/api/plugins/repo/update` | Обновление `{kind,id}` или всех |
| DELETE | `/api/plugins/repo/plugins/:kind/:id` | Удаление |
| DELETE | `/api/plugins/files/:kind/:file` | Удаление файла helper в каталоге плагинов |
| GET | `/api/plugins/repo/legacy` | Обнаружение старых полных плагинов |
| POST | `/api/plugins/repo/migrate` | Миграция `{kind}` |

Для управления плагинами требуются `plugins:read` / `plugins:write`. Загрузка, установка, обновление, удаление и изменение конфигурации репозитория относятся к чувствительным операциям.

## 11. Устранение неполадок

| Симптом | Причина | Обработка |
| --- | --- | --- |
| Сбой загрузки индекса | Адрес репозитория, сетевой прокси, TLS-сертификат | Сначала откройте `index.json` в браузере; проверьте политику исходящих подключений |
| Сбой проверки подписи | Открытый ключ не соответствует ключу подписи репозитория | Сверьте открытый ключ; не очищайте `public_key` в продуктивной среде без необходимости |
| Платформа недоступна | Для текущей платформы нет пакета плагина | Проверьте `GOOS/GOARCH` и `assets` индекса |
| Несовместимость версии хоста | `min_host` плагина выше текущей версии | Обновите хост или установите совместимую версию |
| Конфликт ID | Провайдер уже предоставлен старым bundle-пакетом или вручную установленным плагином | Завершите миграцию или удалите старый файл |
| После установки ничего не появилось | Соответствующий тип плагина или элементы не включены | Проверьте `plugins.enabled`, `deploy_plugins.enabled`, `notify_plugins.enabled` и переключатели элементов |
| Файл отклонён | Каталог доступен на запись группе/другим пользователям, символическая ссылка, несовпадение дайджеста | Исправьте права или переустановите |

Дополнительно об устранении неполадок см. в разделе [Мониторинг и устранение неполадок](troubleshooting.md).

## 12. Чек-лист допуска плагинов

- [ ] Источник: официальный репозиторий или внутреннее корпоративное зеркало, версия зафиксирована.
- [ ] Целостность: подпись индекса, SHA-256 артефакта и проверка дайджеста записи установки пройдены.
- [ ] Права: права на каталог и файлы плагинов соответствуют требованиям.
- [ ] Риски: имеет ли плагин развёртывания доступ к закрытым ключам; хранит ли плагин уведомлений долгоживущий токен.
- [ ] Совместимость: версия хоста, платформа, `min_host` соответствуют.
- [ ] Тестирование: в среде предварительного развёртывания проверены цепочки DNS/развёртывания/уведомлений.
- [ ] Откат: сохранены предыдущая версия и шаги отката.
- [ ] Запись: версия, дайджест, утверждающее лицо, время установки, заявка на изменение.
