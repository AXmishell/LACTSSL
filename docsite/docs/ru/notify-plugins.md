# Плагины уведомлений

Плагины уведомлений отправляют события выпуска, развёртывания, мониторинга и системные события в IM, почту или Webhook. Основное внимание уделяйте маршрутизации, доступности каналов, ротации ключей и контролю шума.

## Встроенные и плагинные каналы

Официальные каналы встроены и включаются на странице «Плагины»; электронная почта доступна всегда. Выключенные каналы не отображаются на странице уведомлений, их прежняя конфигурация сохраняется.

| Канал | Описание |
| --- | --- |
| Электронная почта (SMTP) | Поддержка SSL; по умолчанию неявный TLS |
| Gotify, ServerChan, ntfy, Telegram, Bark, PushDeer | Собственные, сторонние и мобильные push-уведомления |
| DingTalk, WeCom (робот/приложение/умный робот), Feishu | IM |
| GoCQHTTP, iGot, PushPlus, WePlus, WxPusher, WxPusher SPT, OpenILink, WPush, Synology Chat, PushMe, ChronoCat | Другие каналы |
| Универсальный пользовательский Webhook | Интеграция с внутренней платформой оповещений |

## Конфигурация

```yaml
notify_plugins:
  enabled: true           # включено по умолчанию
  dir: ""                 # пусто означает <data_dir>/plugins/notify
  memory_limit_mb: 128    # верхний предел постоянной памяти одного helper
  timeout_seconds: 30     # тайм-аут одной отправки send
  max_output_kb: 64       # верхний предел вывода helper
```

Изменения вступают в силу после перезапуска; при запуске выполняется сканирование. После установки нового helper нажмите «Пересканировать плагины» или вызовите:

```bash
curl -X POST -H "Authorization: Bearer $LACTSSL_TOKEN" \
  https://ssl.example.com/api/plugins/rescan
```

## Установка и включение

1. Откройте вкладку уведомлений на странице «Плагины» и включите нужные каналы.
2. На странице «Уведомления» настройте учётные данные канала и отправьте тестовое сообщение.

Только включённые каналы появляются на странице «Уведомления» и в узле уведомлений задачи. Состояние хранится в settings в `plugins.notify.enabled_channels` и сохраняется после перезапуска. Электронная почта не является плагином и не может быть отключена.

## Проектирование оповещений

### Маршрутизация

| Событие | Рекомендуемое назначение | Описание |
| --- | --- | --- |
| Сбой выпуска сертификата | Канал эксплуатационных оповещений | Может повлиять на продление |
| Сбой развёртывания | Эксплуатация + ответственный за целевую систему | Проверьте цель и команду перезагрузки |
| Приближение срока действия | Эксплуатация + ответственный за целевую систему | Градация 30/14/7 дней |
| Аномалия мониторинга сайта | Эксплуатация | Различайте сеть, цепочку и имя хоста |
| Сбой резервного копирования | Платформа | Отдельно от оповещений о сертификатах |
| Инцидент безопасности | Безопасность | Аномальный вход, сбой проверки плагина и т. п. |

### Снижение шума

- Используйте разные каналы и группы для разных сред.
- В узле уведомлений задачи выбирайте «всегда/только успех/только ошибка», чтобы успех не заглушал ошибки; агрегацию и окно молчания настраивайте на стороне IM.
- Регулярно удаляйте недействительные и дублирующиеся каналы.

### Доступность

- Настройте минимум два независимых канала (например, почта + IM), чтобы избежать единой точки отказа.
- Регулярно отправляйте тестовые сообщения и проверяйте срок действия Token/Webhook; учитывайте ограничения скорости и модерацию провайдера.
- Сбой уведомления записывается в журнал; включите его в мониторинг.

## Управление учётными данными каналов

- Используйте выделенного робота/приложение, а не Token личной учётной записи, и давайте только права на отправку; для разных сред и команд берите разных роботов, фиксируйте ответственного и период ротации.
- Учётные данные шифруются перед записью в базу данных и маскируются при возврате через интерфейс; не записывайте Token и URL Webhook в имена задач, примечания или журналы.
- При утечке немедленно отзовите учётные данные на стороне канала и обновите конфигурацию LACTSSL.

## Электронная почта (SMTP)

- По умолчанию используется неявный TLS (`smtp.ssl=true`). Если при отключённом неявном TLS сервер не поддерживает STARTTLS, сервис откажется отправлять сообщение, чтобы не передавать письма со сбросом токена открытым текстом.
- Используйте SMTP-сервис, выделенную учётную запись отправителя и SPF/DKIM/DMARC.
- Почта восстановления и отправитель уведомлений должны быть раздельными; для тестовых писем используйте отдельных получателей.

## Протокол Helper v1 (разработка интеграций)

```bash
notify-helper manifest   # вывести JSON-манифест
notify-helper send       # прочитать запрос из stdin и отправить уведомление
```

Пример вывода `manifest`:

```json
{
  "protocol": "v1",
  "name": "example notify helper",
  "version": "1.0.0",
  "sha256": "необязательная контрольная сумма файла helper",
  "channels": [
    {
      "id": "example-push",
      "name": "Example Push",
      "description": "Отправка уведомлений в сервис Example",
      "fields": [
        {"key": "url", "label": "Адрес сервиса", "type": "text", "required": true},
        {"key": "token", "label": "Token", "type": "password", "secret": true, "required": true}
      ]
    }
  ]
}
```

Поля с `secret: true` или `type: "password"` маскируются и шифруются; поддерживаются `text`, `password`, `textarea`, `number`, `select`, `switch`. ID канала содержит только строчные буквы, цифры, подчёркивания и дефисы; плагины с ID `mail` игнорируются, `label_key` необязателен.

stdin для `send`:

```json
{
  "action": "send",
  "protocol": "v1",
  "channel": "example-push",
  "config": {"url": "https://push.example.com", "token": "..."},
  "title": "Сертификат успешно выпущен: example.com",
  "body": "Задача: example.com\nСтатус: успех"
}
```

Соглашения:

- Код выхода `0` — успех, ненулевой — ошибка; stderr попадает в журнал уведомлений с маскированием.
- stdout пуст или содержит одну строку JSON `{"ok": true, "message": "..."}`; `ok: false` и некорректный JSON считаются ошибкой.
- helper получает бюджет памяти из `LACTSSL_PLUGIN_MEMORY_LIMIT` (в байтах); при превышении `memory_limit_mb` завершается вся группа процессов.
- Передаётся только минимальный набор переменных окружения; файл должен быть исполняемым, а запись в него — недоступна группе и другим пользователям.
- Дайджест файла записывается при сканировании и проверяется перед каждой отправкой; после замены helper требуется пересканирование.

## Рекомендации по безопасности

- Включайте только доверенные helper: плагин читает ключи каналов и эквивалентен доверенному коду. Каталог `0700`, helper `0755`, владелец — пользователь сервиса; указывайте `sha256`, обновляйте дайджест и задавайте разумные `memory_limit_mb` и `timeout_seconds`.
- Уведомления содержат домены, ошибки и внутренние адреса; не отправляйте их в публичные каналы, для Webhook используйте HTTPS и проверку подписи.

## Устранение неполадок

| Симптом | Причина | Действие |
| --- | --- | --- |
| На странице уведомлений только почта | Каналы не включены | Включите каналы на странице «Плагины» |
| Канал отсутствует в узле задачи | Канал не включён | Включите его на странице уведомлений |
| Сбой тестового сообщения | Token/URL/сеть | Проверьте конфигурацию канала и исходящую политику |
| Сбой отправки почты | SMTP TLS/аутентификация/отправитель | Проверьте неявный TLS, STARTTLS, SPF/DKIM |
