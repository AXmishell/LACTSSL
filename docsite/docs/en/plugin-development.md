# Development: plugin protocol and contribution guide

For plugin developers, integrators, and platform developers. It covers the plugin protocol, repository layout, development workflow, build, packaging, and contribution process. **Usage and governance are covered in [Plugin governance](plugins.md) and the relevant DNS, deployment, or notification pages.**

Official DNS/deploy/notify implementations live in `internal/plugin/` and compile into the host. `plugins/` is the external plugin SDK (protocol, helper framework, shared utilities), and uploaded plugins still use protocol v1 subprocesses. The host no longer uses a plugin index or external repository. Generators and build tooling live in `internal/plugin/`; external plugins need only `plugins/protocol` and `plugins/sdk`.

## Architecture

A plugin is a **one-shot subprocess**, not a dynamic library:

```text
LACTSSL host
  └─ exec lactssl-dns-all-native <subcommand>
       ├─ manifest          emit self-describing JSON
       ├─ present / cleanup stdin JSON → write/remove TXT → exit
       ├─ verify            read-only probe (optional)
       └─ exit 0 on success; non-zero on failure, errors on stderr
```

Four helpers:

| Helper | Type | Subcommands |
|---|---|---|
| `tools/helpers/dns-helper` | DNS (v4 / native) | `manifest` / `present` / `cleanup` / `verify` |
| `tools/helpers/dns-helper-v5` | DNS (lego v5) | `manifest` / `present` / `cleanup` / `verify` |
| `tools/helpers/deploy-helper` | Certificate deployment | `manifest` / `deploy` / `options` / `plan` / `verify` |
| `tools/helpers/notify-helper` | Notification | `manifest` / `send` |

The plugin codebase is a modular monolith: one directory per provider, metadata/translations/icons split per provider, aggregate files generated by `make manifest` and never edited by hand, and contributors working in parallel with minimal conflicts.

## Protocol v1

The protocol remains `v1`; only breaking changes bump it to `v2`. New capabilities use optional fields and feature flags, and older hosts ignore unknown fields.

### Subcommands and output

DNS:

```text
dns-plugin manifest
dns-plugin present   # stdin JSON
dns-plugin cleanup   # stdin JSON
dns-plugin verify    # stdin JSON
```

Deployment:

```text
deploy-plugin manifest
deploy-plugin deploy
deploy-plugin options
deploy-plugin plan
deploy-plugin verify
```

Notification:

```text
notify-plugin manifest
notify-plugin send
```

Conventions:

- Exit code `0` means success; non-zero means failure, with stderr going to the host log.
- DNS `present` / `cleanup` keep stdout empty; deployment `deploy` keeps stdout empty on success, while `verify` / `options` / `plan` emit JSON. Notification `send` emits `{"ok":true,"message":""}` on success, and failures emit `{"ok":false,...}` and exit non-zero. Requests and responses are UTF-8 JSON with non-ASCII characters unescaped.

### Environment variables

| Variable | Meaning |
|---|---|
| `LACTSSL_PLUGIN_PROTOCOL` | Protocol version, currently `v1` |
| `LACTSSL_PLUGIN_MEMORY_LIMIT` | Resident memory budget in bytes; helpers should call `debug.SetMemoryLimit` |
| `LACTSSL_DNS_PLUGIN_FEATURES` | Comma-separated DNS feature flags |
| `LACTSSL_DEPLOY_PLUGIN_FEATURES` | Comma-separated deployment feature flags |

Current features:

| Feature | Meaning |
|---|---|
| `merged-deployers-v1` | Deployment targets emit only canonical merged IDs |
| `dynamic-options-v1` | Support `options` and `options_source` / `multiple` |
| `verify-v1` | Support read-only `verify` |
| `plan-v1` | Support `plan` pre-matching |

### Security conventions

- Private keys and tokens are passed only through stdin, never argv or environment variables, and the host passes a minimal environment.
- Helper files must be executable and not writable by group or other users; symbolic links are rejected. The host polls `VmRSS` and terminates the process group above `memory_limit_mb`. `manifest.sha256` may be empty; uploaded helpers rely on the installation record and digest checks.

## Repository layout

```text
plugins/                     external plugin SDK (separate module)
  protocol/                  protocol v1 wire format
  sdk/                       shared HTTP, signing, DNS, helper framework
  outbound/                  SSRF-safe outbound HTTP client
  i18n/                      plugin-side shared translations
internal/plugin/
  host/
    dns/                     DNS host adapter (interfaces, registry, discovery)
    deploy/                  deploy host adapter
    notify/                  notify host adapter
  providers/                 independent Go module (lactssl/providers)
    go.mod
    api/                     Native interfaces and registries (dns/deploy/notify)
    catalog/                 provider and deployment metadata
      dns/<id>.json          per-provider DNS metadata (hand-written)
      deploy/<id>.json       per-target deployment metadata (hand-written)
      data.json              generated: aggregated metadata
    dns/lego5/               lego v5 wrappers, groups, metadata (generated)
    deploy/<id>/             deployment targets (hand-written)
    notify/channels/         one channel_<id>.go per channel
  runtime/
    registry/                generic ID/alias/source registry
    discovery/               plugin discovery and shared helpers
    exec/                    one-shot subprocess execution
    sandbox/                 uploaded-plugin sandbox
    install/                 atomic install/rollback
    metadata/                manifest snapshot cache
    icon/                    icon MIME/data URI
  builtin/                   adapters from official implementations to host registries
  assets/icons/              icons
  tools/helpers/             standalone helpers / signer (compat/release)
  scripts/                   generators and build tooling
  plugins.json               generated: bundle manifest
```

Generated files:

```text
providers/catalog/data.json
plugins/i18n/locales/*.json
tools/helpers/deploy-helper/imports_gen.go
providers/dns/lego5/**
providers/dns/lego5/groups/**
plugins.json
```

After changing source files, run `make manifest`, which runs `catalog`, `i18n`, `deployimports`, `gen-v5`, then regenerates `plugins.json` and groups. CI verifies generated files; same-repository PRs are updated by the `Update generated files` bot.

## Developing a DNS provider

Official DNS providers use lego v5, with wrappers generated at `internal/plugin/providers/dns/lego5/providers/<id>/plugin.go`. Do not edit generated files. To add or update a provider:

1. Confirm `github.com/go-acme/lego/v5` contains the provider.
2. Add fields and environment-variable mappings in `catalog/dns/<id>.json`.
3. Add `zh-CN.json` and `en-US.json` under `plugins/i18n/providers/dns/<id>/`.
4. Run `make gen-v5`, then `make metadata-check`, `make manifest`, and `make test-providers`.

Example `catalog/dns/<id>.json`:

```json
{
  "value": "example",
  "label_key": "meta.dns.example.label",
  "desc_key": "meta.dns.example.desc",
  "fields": [
    {
      "key": "token",
      "label_key": "meta.field.token.label",
      "type": "password",
      "required": true,
      "env": "EXAMPLE_TOKEN"
    }
  ]
}
```

`env` is written by the helper into the environment variable read by lego v5. Translations live in `plugins/i18n/providers/dns/<id>/zh-CN.json` and `en-US.json`; shared field translations live in `plugins/i18n/core/<locale>.json`. Missing translations fall back to the default locale, then to `label` / `value`.

## Developing a deployment target

Location: `providers/deploy/<id>/plugin.go`

```go
type plugin struct{}

func (plugin) ID() string        { return "example" }
func (plugin) Aliases() []string { return nil }
func (plugin) Deploy(ctx context.Context, req deploy.NativeRequest) error { ... }

func init() { deploy.RegisterNative(plugin{}) }
```

Optional capabilities:

| Interface | Purpose | Declaration |
|---|---|---|
| `deploy.NativeVerifier` | Read-only credential/target check | `deploy.MarkNativeVerifiable("example")` |
| `deploy.NativeOptionLister` | Dynamic select options | catalog `options_source` |
| `deploy.NativePlanner` | Read deployable objects before batch deploy | `deploy.MarkNativePlannable("example")` |

Steps:

1. Create `providers/deploy/<id>/plugin.go`.
2. Create `catalog/deploy/<id>.json` with `fields` and `deploy_fields`.
3. Create `i18n/providers/deploy/<id>/zh-CN.json` and `en-US.json`.
4. Run `make manifest` to generate `tools/helpers/deploy-helper/imports_gen.go`, and add `httptest` unit tests for success, auth failure, and read-only Verify/Plan behavior.

Security: use `outbound.ValidateURL` / `outbound.ValidateWebhookURL` for user-controlled URLs and `outbound.NewClient` instead of `http.DefaultClient`; `Verify` / `Plan` / `ListOptions` must not write certificates, create persistent objects, or reload services; never include tokens or secrets in errors. Historical IDs map to canonical targets via `deprecated_deploy_types` and `deploy_migrations` in `catalog/migrations.json`.

## Developing a notification channel

Location: `providers/notify/channels/channel_<id>.go`

```go
package channels

func init() {
    registerChannel(newChannel("example", []notify.NativeField{
        text("url", "notifications.fieldServerUrl", true),
        password("token", "notifications.fieldToken", true),
    }, sendExample))
}

func sendExample(cfg map[string]any, msg notify.NativeMessage) error { ... }
```

Field helpers:

| Function | Purpose |
|---|---|
| `text` | Text |
| `password` | Password/secret |
| `number` | Number |
| `selectField` + `opt` | Select |
| `textarea` | Multi-line text |

Each channel is a separate file that self-registers via `init`; no shared list needs editing. Prefer `notifyJSON` / `notifyForm` / `notifyHTTP` and `outbound`.

## Build

```bash
CGO_ENABLED=0 go build -trimpath \
  -tags "bundle_dns_all_native,nethttpomithttp2,http2legacy" \
  -ldflags "-s -w -X main.buildVersion=<version>" \
  -o lactssl-dns-all-native ./tools/helpers/dns-helper
```

- `-trimpath` removes local paths; `-s -w` strips symbols and DWARF.
- `bundle_dns_all_lego` / `bundle_dns_all_native` select DNS groups.
- `nethttpomithttp2,http2legacy` avoids a Go 1.27 `net/http` / `x/net/http2` compatibility issue.
- lego v5 additionally uses `urfave_cli_no_template,ozzo_validation_no_template,grpcnotrace,validator_novalidatefn` to drop template code.

## Packaging and index

The host does not consume an index. Packaging produces single helper executables for upload or official distribution:

```bash
make plugin KIND=dns ID=all-native GOOS=linux GOARCH=amd64
```

Output:

```text
dist/
├── lactssl-dns-all-native_<version>_linux_amd64.tar.gz
└── lactssl-dns-all-native_<version>_linux_amd64.meta.json
```

Package contents:

```text
plugin.json
lactssl-dns-all-native
LICENSE
icons/<provider>.<svg|png|webp>
```

### Signing

Official release artifacts are protected by `checksums.txt` and its detached signature; uploaded helpers are verified through the manifest `sha256` and the installation record. There is no signed plugin index to generate or publish.

## Version policy

- Official DNS providers follow the lego versions in `go.mod`.
- Built-in implementation patch versions derive from content fingerprints. Shared inputs (`protocol/`, `sdk/`, `i18n/`, `outbound/`, `catalog/`, `go.mod`) bump every affected implementation to avoid "same version, different binary".
- Provider-specific changes bump only that implementation. Releases are tag-driven; manual non-tag releases use internal versions and must respect published tags.

## Collaboration

### Branches and PRs

```text
main
  ↑
short-lived branch (1-3 days)
  ↑
PR → lint / generated / test / bundle / native → CODEOWNER review
  → merge queue → CI gate → merge
  → after-merge bot refreshes generated files
```

Requirements: no direct pushes to `main`, a PR with a passing `CI gate`, Merge Queue enabled, one provider/target/channel per PR, and the bot regenerating aggregate files instead of hand-merging generated conflicts.

### CODEOWNERS

The plugin codebase's `.github/CODEOWNERS` defines default owners; replace them with GitHub Teams for DNS native, lego, deploy, notify, and infra as the team grows. Protocol/SDK/catalog schema/CI changes require core maintainer review.

### Tiered CI

| Tier | Trigger | Contents |
|---|---|---|
| lint | every PR / merge queue | gofmt, go.mod/go.sum |
| generated | every PR / merge queue | `make manifest` + generated-file check |
| test | Go changes | `go vet ./...`, `go test ./...` |
| bundle | DNS/deploy/notify changes | build five helpers, manifest counts/parity, package smoke |
| native | DNS/SDK changes | `check_native.sh` |
| nightly | daily | `go test -race`, full build, govulncheck |

Branch protection only needs the **CI gate** check; skipped conditional jobs do not block it.

### Merge Queue

Protect `main`, require `CI gate` and linear history, enable Merge Queue (max 5, timeout 5 minutes), disallow direct pushes, and require branches to be up to date before merging.

## Testing requirements

- Use `httptest`; never call real APIs from unit tests.
- DNS: written value, cleanup only removes this value, idempotent missing-record cleanup, no matching zone. Deployment: success, auth failure, Verify/Plan perform no writes. Notification: missing config, request payload, non-2xx status.
- CI asserts manifest counts and fields; native bundles also run `./scripts/check_native.sh`.

## Pre-submit checklist

```text
[ ] only provider directory + matching catalog/i18n changed
[ ] init registration and unique ID/alias
[ ] catalog field keys match code
[ ] zh-CN and en-US translations added
[ ] unit tests use httptest
[ ] make manifest
[ ] gofmt / go vet / go test
[ ] check_native (native)
[ ] generated files committed or left to the bot
```
