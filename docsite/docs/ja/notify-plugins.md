# 通知プラグイン

通知プラグインは、証明書の発行、デプロイ、監視、システムイベントを IM、メール、Webhook へプッシュします。**アラートルーティング、チャンネルの可用性、キーのローテーション、ノイズ制御**に重点を置きます。

## 組み込みチャンネルとプラグインチャンネル

| 種別 | チャンネル | 説明 |
| --- | --- | --- |
| 組み込み | メール（SMTP） | SSL をサポート。デフォルトは暗黙的 TLS |
| 組み込み | Gotify、ServerChan、ntfy | セルフホスト/サードパーティのプッシュ |
| 組み込み | Telegram、Bark、PushDeer | モバイルプッシュ |
| 組み込み | DingTalk、WeCom ロボット/アプリ/スマートロボット、Feishu | IM |
| 組み込み | GoCQHTTP、iGot、PushPlus、WePlus、WxPusher、OpenILink、WPush、Synology Chat など | その他のチャンネル |
| 組み込み | 汎用カスタム Webhook | 内部アラートプラットフォームとの連携 |
| プラグイン | サードパーティ製 helper | 必要に応じてアップロードして有効化 |

メールは常に利用可能で無効化できません。その他のチャンネルは「プラグイン」ページで有効化したものだけが「通知」ページとタスクの通知ノードに表示されます。過去のチャンネル設定は失われません。

## 設定

```yaml
notify_plugins:
  enabled: true           # デフォルトで有効
  dir: ""                 # 空の場合は <data_dir>/plugins/notify
  memory_limit_mb: 128    # 単一 helper の常駐メモリ上限
  timeout_seconds: 30     # 1 回の send のタイムアウト
  max_output_kb: 64       # helper 出力の上限
```

3 種類のプラグインは `<data_dir>/plugins` 配下の独立したサブディレクトリ（`dns`、`deploy`、`notify`）を使用します。設定変更後は再起動で反映され、起動時に自動スキャンします。新しい helper をインストールした後は、「プラグイン」ページで再スキャンするか、次を呼び出します:

```bash
curl -X POST -H "Authorization: Bearer $LACTSSL_TOKEN" \
  https://ssl.example.com/api/plugins/rescan
```

## インストールと有効化

1. 「プラグイン」ページの通知タブを開き、必要なチャンネルを有効化します。
2. 「通知」ページでチャンネル認証情報を設定し、テストメッセージを送信します。

有効化したチャンネルのみが「通知」ページとタスクの通知ノードに表示されます。メールは常に利用可能で、無効化できません。

## アラート設計

### ルーティング

| イベント | 推奨送信先 | 説明 |
| --- | --- | --- |
| 証明書の発行失敗 | 運用アラート | 直ちに対応が必要。更新に影響する可能性 |
| デプロイ失敗 | 運用 + ターゲットシステム責任者 | ターゲットシステムとリロードコマンドを確認 |
| 証明書の期限接近 | 運用 + ターゲットシステム責任者 | 30/14/7 日の段階分け |
| サイト監視の異常 | 運用 | ネットワーク、チェーン、ホスト名の問題を区別 |
| バックアップ失敗 / セキュリティインシデント | プラットフォーム / セキュリティ | 証明書アラートと分離。異常ログインやプラグイン検証失敗を含む |

### ノイズ削減

- 環境ごとに異なる通知チャンネルと投稿先を使用してください。
- タスク通知ノードは「常に/成功時のみ/失敗時のみ」で選択し、成功メッセージが失敗を埋もれさせないようにします。
- 同種のイベントには集約またはサイレントウィンドウを設定し、監視項目は重要度で段階分けします。無効なチャンネルと重複設定は定期的に削除してください。

### 可用性

- 少なくとも 2 つの独立したチャンネル（例: メール + IM）を設定し、単一障害点を避けてください。
- 定期的にテストメッセージを送信し、Token/Webhook の期限切れを確認します。
- チャンネルプロバイダーのレート制限とコンテンツ審査に注意し、通知失敗自体も監視対象にしてください。

## チャンネル認証情報のガバナンス

- 専用のボット/アプリを使用し、個人アカウントの Token を使用しないでください。メッセージ送信に必要な権限のみを付与し、組織管理や連絡先読み取りの権限は付与しません。
- 環境/チームごとに異なるボットを使用し、Token の責任者、作成日時、ローテーション周期を記録してください。
- 認証情報はデータベースへ書き込む前に暗号化され、API レスポンスではマスクされます。
- Token、Webhook URL をタスク名、備考、ログに書き込まないでください。漏洩時はチャンネル側で失効させ、LACTSSL の設定を更新します。

## メール（SMTP）

- デフォルトでは暗黙的 TLS を使用します（`smtp.ssl=true`）。
- 暗黙的 TLS を無効にした場合、SMTP サーバーが STARTTLS をサポートしていなければ送信を拒否し、パスワードリセットトークンなどの機密メールが平文で送信されるのを防ぎます。
- SMTP サービス、専用送信アカウント、SPF/DKIM/DMARC を使用してください。復旧用メールアドレスと通知送信アカウント、テストと本番の受信者は分離します。

## Helper プロトコル v1（連携開発）

helper は実行ファイルで、2 つのサブコマンドをサポートします:

```bash
notify-helper manifest   # JSON マニフェストを出力
notify-helper send       # stdin からリクエストを読み取り、通知を送信
```

`manifest` の要点:

- `protocol` は `v1`、`channels[]` にチャンネルを記述します。`id` は小文字、数字、アンダースコア、ハイフンのみで、組み込みの `mail` と重複できません。
- `fields` は設定項目です。`secret: true` または `type: "password"` は API レスポンスでマスクされ、暗号化して保存されます。
- フィールド型は `text`、`password`、`textarea`、`number`、`select`、`switch` に対応します。
- `label_key` は任意です。公式フロントエンドは i18n key を優先し、サードパーティは `label` を直接指定できます。
- `sha256` は任意で、helper ファイルのチェックサムを記録します。

`send` の stdin:

```json
{
  "action": "send",
  "protocol": "v1",
  "channel": "example-push",
  "config": {"url": "https://push.example.com", "token": "..."},
  "title": "証明書の発行に成功: example.com",
  "body": "タスク：example.com\n状態：成功"
}
```

規約:

- 終了コード `0` は成功、非 `0` は失敗です。stderr は通知ログに入ります（機密値はマスクされます）。
- stdout は空、または 1 行の JSON `{"ok": true, "message": "..."}` を出力できます。`ok` が `false` の場合は失敗です。
- 不正な JSON はエラーです。デバッグログは stderr に書き込んでください。
- helper は `LACTSSL_PLUGIN_MEMORY_LIMIT`（バイト）からメモリ予算を取得します。メインプログラムは `VmRSS` を監視し、上限超過時にプロセスグループを終了します。
- メインプログラムは最小限の環境変数のみを渡します。helper は実行可能で他のユーザーに書き込みを許可せず、`manifest.sha256` を検証します。置き換え後は再スキャンが必要です。

## セキュリティ推奨事項

- 信頼できる helper のみを有効化してください。通知プラグインはチャンネルキーを読み取れるため、信頼されたコードと同等です。
- プラグインディレクトリは `0700`、helper は `0755`、所有者はサービスの実行ユーザーにします。
- 本番ではマニフェストに `sha256` を記入し、アップグレード後にダイジェストを更新してください。
- 通知内容にはドメイン、エラー詳細、内部アドレスが含まれる場合があります。公開チャンネルへ送信せず、Webhook は HTTPS と署名検証で偽造/リプレイを防いでください。

## トラブルシューティング

| 現象 | 原因 | 対処 |
| --- | --- | --- |
| 通知ページにメールのみ表示 | チャンネルが未有効化 | 「プラグイン」ページで対象チャンネルを有効化 |
| チャンネルがタスクノードにない | チャンネルが未有効化 | 「プラグイン」ページと「通知」ページで有効化 |
| テストメッセージの失敗 | Token/URL/ネットワーク | チャンネル設定とアウトバウンドポリシーを確認 |
| メール送信の失敗 | SMTP TLS/認証/送信者 | 暗黙的 TLS、STARTTLS、SPF/DKIM を確認 |
| 通知内容に機密情報が含まれる | テンプレート/ログのマスク不足 | 内容を調整し、認証情報と秘密キーの送信を避ける |

その他のトラブルシューティングは[監視とトラブルシューティング](troubleshooting.md)を参照してください。
