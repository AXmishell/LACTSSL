# デプロイプラグイン

デプロイプラグインは、証明書を FTP、Webhook、クラウド CDN、パネル、WAF などのターゲットへ配信します。これは**証明書の秘密キーに触れる高リスクコンポーネント**であり、導入審査と変更管理の対象にしてください。

## 組み込みターゲットとプラグインターゲット

| 種別 | ターゲット | 説明 |
| --- | --- | --- |
| 組み込み | ローカルディレクトリ | ローカルパスへ書き込み、リロードコマンドは任意 |
| 組み込み | SSH / SFTP | パスワードまたは秘密キー認証、ホストフィンガープリント検証 |
| 組み込み | FTP / FTPS | 通常の FTP、明示的 TLS、暗黙的 TLS |
| 組み込み | Webhook | カスタム認証ヘッダー、TLS 検証のスキップ可能（非推奨） |
| 組み込み | Alibaba Cloud CDN / Tencent Cloud / Volcengine | CDN ドメインの証明書を更新 |
| 組み込み | Qiniu Cloud | CDN アクセラレーションドメインまたは Kodo カスタムオリジンドメイン |
| 組み込み | BaoTa パネル / BaoTa WAF / 1Panel / SafeLine WAF | サイト、パネル、WAF、証明書 ID またはドメインでマッチ |
| プラグイン | サードパーティ製 helper | 必要に応じてアップロードして有効化 |

> **デプロイプラグインは証明書の秘密キーを受け取ります。** 信頼できるソースの helper のみを使用し、プラグインディレクトリがサービスの実行ユーザーのみ書き込み可能であることを確認してください。デプロイカテゴリと公式ターゲットは既定で有効です。不要なターゲットは無効化してください。

## 認証情報とデプロイパラメータ

「ターゲット認証情報」は認証と接続情報（ホスト、ポート、ユーザー名、パスワード、パネルアドレス、API Token など）のみを保存します。証明書パス、リロードコマンド、デプロイドメイン、サイトなどは、タスクフローの「証明書をデプロイ」ノードで入力します。

この分離により、同じ認証情報を複数のタスクで再利用でき、ローテーションがタスク編成に影響せず、デプロイパラメータはタスクバージョンとともに記録されます。

## 設定

```yaml
deploy_plugins:
  enabled: true           # 公式ターゲットは既定で有効。プラグインは秘密キーに触れる
  dir: ""                 # 空の場合は <data_dir>/plugins/deploy
  memory_limit_mb: 128    # 単一 helper の常駐メモリ上限
  timeout_seconds: 300    # 1 回の deploy のタイムアウト。大きなファイルのアップロード時は増やせる
  max_output_kb: 64       # helper 出力の上限
```

3 種類のプラグインは `<data_dir>/plugins` 配下の独立したサブディレクトリ（`dns`、`deploy`、`notify`）を使用します。設定変更後は再起動で反映され、起動時に自動スキャンします。新しい helper をインストールした後は、「プラグイン」ページで再スキャンするか、次を呼び出します:

```bash
curl -X POST -H "Authorization: Bearer $LACTSSL_TOKEN" \
  https://ssl.example.com/api/plugins/rescan
```

## インストールと有効化

1. 設定で `deploy_plugins.enabled: true` を設定し、再起動します。
2. 「プラグイン」ページのデプロイタブを開き、カテゴリと必要なデプロイターゲットを有効化します。

カテゴリが無効な場合はローカルファイルと SSH のみが表示されます。過去の認証情報は失われません。有効状態は settings テーブルに保存され、再起動と再スキャン後も保持されます。

## ターゲット別のベストプラクティス

### ローカルディレクトリ

- 実行ユーザーに対象ディレクトリの書き込み権限を付与します。
- 一時ファイルへ書き込んでから `rename` で上書きするアトミック書き込みを推奨します。
- リロードコマンドの例: `nginx -s reload`、`systemctl reload nginx`、`systemctl reload postfix`。失敗しても証明書ファイルはロールバックされないため、ターゲット側で前バージョンを保持してください。

### SSH / SFTP

- 既定では対象ホストのフィンガープリント（`SHA256:...`）の入力が必要です。「初回接続時にホストキーを自動信頼」を明示的に有効にした場合のみ TOFU を採用します。
- サーバーのキー交換後は、古いフィンガープリントをクリアして再記録してください。
- 専用のデプロイユーザーを使用し、対象パスへの書き込みと必要なリロード権限のみを付与します（sudoers はコマンド単位）。秘密キー認証を優先し、パスフレーズを設定して定期的にローテーションしてください。

### FTP / FTPS

- 既定は明示的 TLS です。`none` を明示的に選択した場合のみ平文 FTP を使用します。
- 証明書の秘密キーとログインパスワードがネットワークを通過するため、本番では SFTP または FTPS を優先してください。
- 対象 IP、ポート、ディレクトリ権限を制限し、共有アカウントを使用しないでください。

### Webhook

- パブリックターゲットには HTTPS を強制します。ループバック、プライベートネットワーク、`.local`、`.internal` は HTTP を許可します。
- 受信側は信頼できる必要があります。専用 Token と送信元 IP 制限を推奨し、冪等性と署名検証でリプレイを防いでください。
- 「TLS 検証をスキップ」は推奨しません。必須の場合は内部の自己署名ターゲットに限定し、内部 CA は「システム設定 → TLS 信頼チェーン」で公開キーをインポートします。

### クラウド CDN / パネル / WAF

- 認証情報は専用のサブアカウントを使用し、証明書管理関連の権限のみを付与してください。
- デプロイパラメータ（ドメイン、サイト、証明書名）をターゲットシステムと一致させます。BaoTa のサイトと Docker サイト名はパネル API から選択でき、取得できない場合は手動入力します。
- ターゲットで IP ホワイトリストが有効な場合は LACTSSL の出口を許可し、デプロイ後に CDN/WAF が実際に返す証明書を確認してください。

## デプロイ記録と検証

- デプロイごとに記録が生成され、証明書詳細とログで結果を確認できます。手動デプロイはタスクのデプロイノードパラメータを再利用できます。
- ローカル/SSH デプロイはリロードコマンドを実行します。API キーは `deploy:execute` を明示的に持つ必要があります。
- デプロイ失敗時にターゲットの旧証明書は自動ロールバックされません。ターゲット側で前バージョンを保持するか、アトミックリリースを使用してください。

検証チェックリスト:

- [ ] 対象パス/サイトが正しい。
- [ ] 証明書チェーンが完全（fullchain）で、秘密キーと一致している。
- [ ] サービスがリロードされ、新しい証明書を実際にロードしている。
- [ ] マルチインスタンス/マルチノードと CDN/WAF のキャッシュがすべて更新されている。

## オフラインと手動インストール

- 「プラグイン」ページで単一の helper をアップロードできます（最大 256 MB）。`deploy_plugins.enabled: true` が必要です。
- アップロード時に `manifest`、デプロイターゲット ID、SHA-256 を検証し、通過後にデプロイプラグインディレクトリへ書き込んで再スキャンします。
- 既定では同名ファイルの上書きを拒否します。アップグレード時に「同名プラグインの上書きを許可」をチェックすると、旧ファイルは先にバックアップされます。組み込みターゲット ID と重複するプラグインは「無視済み」とマークされます。

## Helper プロトコル v1（連携開発）

helper は実行ファイルで、以下のサブコマンドをサポートします:

```bash
deploy-helper manifest   # JSON マニフェストを出力
deploy-helper deploy     # stdin からリクエストを読み取り、デプロイを実行
deploy-helper options    # 動的ドロップダウンオプションを読み取る（任意）
deploy-helper verify     # 認証とターゲットスコープを読み取り専用で検証（任意）
```

`manifest` の要点:

- `protocol` は `v1`、`deployers[]` に各ターゲットを記述します。`id` は小文字、数字、アンダースコア、ハイフンのみです。
- `fields` はターゲット認証情報、`deploy_fields` は「証明書をデプロイ」ノードのパラメータです。両者の `key` は重複できません。
- フィールド型は `text`、`password`、`textarea`、`number`、`select`、`switch` に対応します。`secret: true` または `type: "password"` は API レスポンスでマスクされ、暗号化して保存されます。
- `name`、`description`、`label` などは `*_i18n` テーブルで言語ごとに上書きできます（最大 32 言語）。
- `sha256` は任意で、helper ファイルのチェックサムを記録します。

`deploy` の stdin:

```json
{
  "action": "deploy",
  "protocol": "v1",
  "provider": "example-panel",
  "auth": {"panel_url": "https://panel.example.com", "api_token": "..."},
  "config": {"sites": "example.com,www.example.com"},
  "certificate": {
    "domain": "example.com",
    "domains": ["example.com", "www.example.com"],
    "issuer": "Let's Encrypt",
    "serial": "...",
    "not_before": "2026-01-01T00:00:00Z",
    "not_after": "2026-04-01T00:00:00Z",
    "cert_pem": "-----BEGIN CERTIFICATE-----...",
    "fullchain_pem": "-----BEGIN CERTIFICATE-----...",
    "key_pem": "-----BEGIN PRIVATE KEY-----..."
  }
}
```

規約:

- 終了コード `0` は成功、非 `0` は失敗です。stderr はデプロイ記録に入ります（機密値はマスクされます）。
- stdout は空、または 1 行の JSON `{"ok": true, "message": "..."}` を出力できます。`ok` が `false` の場合は失敗です。
- `verify` は読み取り専用でなければならず、証明書の書き込み、永続オブジェクトの作成、`reload_command` の実行はできません。
- `verify-v1` を宣言したターゲットのみが `verify` 呼び出しを受け取ります。`checks[].status` の値は `ok`、`failed`、`skipped`、`unsupported`、`error` です。
- helper は `LACTSSL_PLUGIN_MEMORY_LIMIT`（バイト）からメモリ予算を取得します。メインプログラムは `VmRSS` を監視し、上限超過時にプロセスグループを終了します。
- メインプログラムは最小限の環境変数のみを渡します。helper は実行可能で他のユーザーに書き込みを許可せず、`manifest.sha256` を検証します。置き換え後は再スキャンが必要です。

## セキュリティ推奨事項

- 信頼できる helper のみを有効化してください。デプロイプラグインは証明書の秘密キーを読み取れるため、信頼されたコードと同等です。
- プラグインディレクトリは `0700`、helper は `0755`、所有者はサービスの実行ユーザーにします。
- 本番ではマニフェストに `sha256` を記入し、アップグレード後にダイジェストを更新してください。
- 適切な `memory_limit_mb` と `timeout_seconds` を設定し、異常なプラグインがホストを停止させないようにしてください。
- `lactssl` ユーザーに追加権限を与えず、プラグインディレクトリを共有書き込み可能なパスに置かないでください。デプロイターゲットには最小権限のアカウントを使用します。

## トラブルシューティング

| 現象 | 原因 | 対処 |
| --- | --- | --- |
| デプロイ種別がローカル/SSH のみ | カテゴリまたはターゲットが未有効化 | `deploy_plugins.enabled` を有効化し、対象ターゲットを有効化 |
| プラグインのロードに失敗 | 権限/ダイジェスト/プロトコル/シンボリックリンク | 権限を修正するか再インストール |
| SSH フィンガープリントの不一致 | サーバーのキー交換/設定ミス | フィンガープリントを確認し、古い記録をクリアして再試行 |
| デプロイ成功だがサービスは旧証明書のまま | 未リロード/キャッシュ/マルチインスタンス | リロードコマンドを設定し、キャッシュとすべてのノードを確認 |
| Webhook が拒否される | パブリック HTTP/証明書が信頼されていない | HTTPS または内部アドレスを使用し、TLS を確認 |
| デプロイタイムアウト | ターゲットが遅い/大きなファイル | `timeout_seconds` を増やし、ネットワークを確認 |

その他のトラブルシューティングは[監視とトラブルシューティング](troubleshooting.md)を参照してください。
