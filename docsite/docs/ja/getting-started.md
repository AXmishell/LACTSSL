# クイックスタート

Docker でインスタンスを起動し、初期化を完了して、最初の証明書を発行します。通常 30 分以内に一通り動かせます。本番導入前のチェックは[セキュリティベースライン](security.md)を参照してください。

## 準備

- Docker を実行できる Linux ホスト 1 台（VPS、NAS、小型マシンなど）
- ドメイン 1 つと DNS API 資格情報
- デプロイ先 1 つ（ローカルディレクトリ、SSH、パネル）

## インスタンスを起動

```bash
git clone https://github.com/AXmishell/LACTSSL.git
cd LACTSSL
mkdir -p config data
cp config.yaml.example config/config.yaml
chmod 600 config/config.yaml
chmod 700 data
docker compose up -d
docker compose logs -f lactssl
```

リポジトリは既定で `1panel-network` を使用します。1Panel を使わない場合は、`docker-compose.yml` 内の 2 か所の `networks` セクションを削除するか、先に `docker network create 1panel-network` を実行してください。GHCR イメージは最初の正式 Release から利用可能です。未リリースの場合は[インストールと起動](install.md)に従ってローカルでビルドしてください。

## 初期化

起動ログにセキュアエントリとワンタイムの初期化トークンが出力されます：

```text
セキュアエントリ: http://127.0.0.1:8080/K7mQ2pX9vR4tY8nL6cWz/
初期設定トークン（今回の起動時のみ有効）: ...
```

セキュアエントリから管理者アカウントを作成し、TOTP またはパスキーを有効にして、復旧用メールアドレスを設定します。初期化が完了するとトークンは直ちに無効になります。エントリを忘れた場合は `config.yaml` で `security.entry` を設定して再起動すると上書きできます。

> セキュアエントリはセキュリティ境界ではありません。本番環境では HTTPS、強力なパスワード、TOTP/パスキー、ネットワークアクセス制御を必ず使用してください。

## プラグインを有効化

公式の DNS、デプロイ、通知プラグインは内蔵済みで、インストールは不要です：

1. 「プラグイン」ページを開き、該当カテゴリが有効になっていることを確認します。
2. 必要な DNS サービスプロバイダー、デプロイ先、通知チャネルを有効にします。
3. サードパーティ拡張は必要に応じて helper をアップロードします。[プラグインガバナンス](plugins.md)を参照してください。

DNS サービスプロバイダーは既定ですべて無効、デプロイカテゴリは既定で有効です。

## 最初の証明書を発行

まずプライベート CA で経路を通し、パブリック DNS に依存しないようにします：

1. 「プライベート CA」でルート CA を生成します（ECDSA P-256）。
2. 「証明書申請」でタスクを作成し、発行機関にそのプライベート CA を選択して、テスト用ドメインを入力します。
3. 「証明書をデプロイ」ノードを追加し、「ローカルファイル」を選択して、証明書/秘密鍵のパスと任意のリロードコマンドを入力します。
4. 「通知を送信」ノードを追加し、有効なチャネルを選択して、トリガーを「毎回の実行」にします。
5. タスクを手動で実行し、証明書、デプロイ記録、通知がすべて成功することを確認します。

続いてパブリック経路を追加します：DNS アカウントを作成 → パブリック CA を選択 → テスト用ドメインで DNS-01 を実行 → 対象へデプロイ → 自動更新を 1 回確認します。

## 検証

| 操作 | 検証方法 |
| --- | --- |
| バックアップと復元 | 暗号化バックアップをダウンロードし、分離したインスタンスでインポート |
| ログ | 操作ログとシステムログを絞り込んでエクスポート |
| API | 読み取り専用キーで `/api/certificates` を呼び出す |
| 通知 | テスト通知を送信 |
| 監視 | 外部サイトを 1 つ追加して証明書を読み取る |

## 本番導入

実ドメイン 1〜2 件、デプロイ先 1 つ、社内 CA シナリオ 1 つで検証します。本番切り替え前に[セキュリティベースライン](security.md)の本番チェックリストを完了し、[運用マニュアル](operations.md)に従ってバックアップ、監視、変更プロセスを整備してください。

よくある失敗原因：

- セキュアエントリだけをセキュリティ境界とみなす。
- 個人の DNS アカウントを API 資格情報として使う。
- 証明書更新後にリロードコマンドを検証しない。
- データベースだけをバックアップし、`config.yaml` をバックアップしない。`salt` を失うと暗号化資格情報を復号できなくなる。
