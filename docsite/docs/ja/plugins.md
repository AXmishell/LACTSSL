# プラグインガバナンス

LACTSSL の DNS、証明書デプロイ、通知の機能はプラグインが提供します。公式実装は `internal/plugin/` にありメインプログラムへコンパイルされます。`plugins/` は外部プラグイン開発用の SDK です。アップロードされたサードパーティ helper は一時的な子プロセスとして実行され、既定でサンドボックスに制限されます。

## プラグインのモデル

- **内蔵プラグイン**: 公式の DNS / デプロイ / 通知実装はメインプログラムと共に配布され、ネットワーク経由のインストールは不要です。
- **アップロードプラグイン**: 管理者は単一の helper をアップロードできます。一時的な検証やサードパーティ拡張に使用します。既定では無効で、有効化すると子プロセスとして実行されます。
- **2 段階の有効化**: カテゴリ単位（`plugins.enabled`、`deploy_plugins.enabled`、`notify_plugins.enabled`）と項目単位（DNS サービスプロバイダー、デプロイ先、通知チャネルのホワイトリスト）。
- **プラグインリポジトリは廃止**: インデックス、署名付きインデックス、マーケット、自動更新はありません。公式プラグインの更新はメインプログラムのバージョンと共に提供されます。

プラグインのプロトコルは v1 のままです。

```text
manifest / present / cleanup / deploy / options / plan / send
```

内蔵実装はホストプロセス内で直接呼び出され、アップロードプラグインは stdin/stdout の JSON でホストと通信します。

## 設定

```yaml
plugins:
  enabled: true
  dir: ""                 # アップロードされた DNS helper のディレクトリ。空の場合は <data_dir>/plugins/dns
  sandbox: strict         # strict / basic / off
  memory_limit_mb: 128
  timeout_seconds: 60
  max_output_kb: 64

deploy_plugins:
  enabled: true           # デプロイ先は既定で有効。プラグインは秘密鍵に触れる
  dir: ""
  sandbox: strict
  memory_limit_mb: 128
  timeout_seconds: 300
  max_output_kb: 64

notify_plugins:
  enabled: true
  dir: ""
  sandbox: strict
  memory_limit_mb: 128
  timeout_seconds: 30
  max_output_kb: 64
```

`sandbox` は**アップロード/外部 helper にのみ適用**され、内蔵プラグインはホストプロセス内で直接呼び出されます。`strict` は Linux で Landlock によるファイルアクセスのホワイトリスト、rlimit、`no_new_privs`、独立したプロセスグループを使用し、カーネルやコンテナが対応していない場合は自動的に `basic`（最小限の環境変数、専用の一時ディレクトリ、タイムアウト/RSS/出力の制限）へ降格して降格ログを記録します。ホストが root のまま実行され、`LACTSSL_RUN_UID`/`LACTSSL_RUN_GID` が設定されていない場合、Landlock は mount/ptrace による root の回避を防げないため、アップロードプラグインの実行は拒否されます。`off` は管理されたデバッグにのみ使用してください。

## 内蔵プラグインとメモリ

内蔵実装は既定ですべてメインプログラムにコンパイルされます。カテゴリや項目を無効にしてもコードはアンロードされませんが、対応する実装の登録と provider の構築が行われなくなります。バイナリやメモリを大幅に削減したい場合はビルドタグを使用できます。`make backend-no-dns` は DNS 内蔵実装をまったくコンパイルしません（アイドル時 RSS 約 36 MB）。公式リリースは既定で全量ビルドです（アイドル時 RSS 約 70 MB）。全量ビルドのメモリの大部分は DNS の lego v5 のコードページによるもので、メタデータは約 1 MB にすぎません。235 のサービスプロバイダーをすべて有効化しても、既定の空リストと比べて約 3〜5 MB 増えるだけです。DNS 内蔵実装はグローバルなコンストラクタロックで lego v5 の環境変数を設定・復元し、`present/cleanup` は並行して実行できます。

## 有効化と無効化

### カテゴリ

カテゴリスイッチは、そのカテゴリの内蔵実装を登録するかどうかを決めます。無効にすると、そのカテゴリの内蔵項目は利用可能な一覧に表示されず、アップロードされた同カテゴリの helper も実行されません。ただし、保存済みのアカウント、タスク、ホワイトリストは保持されます。

### 項目

- DNS: 既定ではどのサービスプロバイダーも有効になっていません。「プラグイン」ページで手動で有効化します。
- デプロイ: カテゴリと 25 の標準ターゲットが既定で有効です。不要なものは無効にできます。
- 通知: 既定で 23 のチャネルが有効です。

一度に 10 を超える項目を有効化すると確認を求められ、大量の provider の誤有効化を防ぎます。

## アップロードプラグインとサンドボックス

アップロードの流れ: カテゴリと helper ファイルを選択 → サンドボックス内で `manifest` を実行してプロトコル、ID、バージョン、ダイジェスト、プラットフォームを検証 → プラグインディレクトリへ書き込み（新しいファイルは既定で無効）→ 管理者がファイルを有効化してから項目を有効化します。

制限: 受け付けるのは単一の実行ファイルで、最大 256 MB です。シンボリックリンクとグループ・その他ユーザーが書き込み可能なファイルは拒否します。アップロードプラグインは内蔵項目の ID/エイリアスを使用できません。`strict` サンドボックスではシステムの CA/DNS 設定と自身のファイルのみ読み取り可能で、書き込みは専用の一時ディレクトリのみ、データディレクトリ、設定、データベース、他のプラグインは読み取れません。サンドボックスはネットワーク分離ではないため、アップロードプラグインは外部ネットワークへアクセスできます。信頼できる提供元のものだけをアップロードしてください。

## 更新、ロールバック、アンインストール

- 内蔵プラグインはメインプログラムのアップグレードと共に更新され、個別のインストール/更新/アンインストールはできません。アップグレード後も有効状態は保持されます。
- アップロードプラグインは管理者が再アップロードします。旧ファイルは先にバックアップされ、失敗時はロールバックします。アップロードファイルを削除すると、フィンガープリント、項目メタデータ、有効化ホワイトリストも同時に整理されます。

## 旧リポジトリプラグインの移行

アップグレード前に公式リポジトリのプラグインを導入していた環境では、公式プラグインは現在内蔵実装が提供します。旧 helper ファイルは無効化または削除してください。アカウント、タスク、有効化ホワイトリストは変更されません。公式セットに含まれないカスタムプラグインは「旧版/アップロード」プラグインとして残り、既定では `strict` サンドボックスで実行されますが、更新元はなくなるため、置き換えまたは削除を推奨します。

## セキュリティ制御

- 内蔵プラグインはメインプログラムのサプライチェーンの一部であり、プログラムの署名/イメージダイジェストと共に配布されます。アップロードプラグインは既定でサンドボックス実行され、本番では `sandbox: off` を設定しないでください。
- デプロイプラグインは秘密鍵に触れるため既定で有効です。信頼できるターゲットのみを残してください。プラグインディレクトリは `0700`、helper は `0755` とし、シンボリックリンクとグループ・その他ユーザーによる書き込みを許可しません。
- アップロード helper のダイジェストは検出時、登録時、および呼び出しのたびに再確認されます。プラグイン管理には `plugins:read` / `plugins:write` が必要で、アップロードと有効化・無効化の書き込みは監査ログに記録され、strict が利用できない場合の降格はホストの起動ログに記録されます。

## API

| メソッド | パス | 説明 |
|---|---|---|
| GET | `/api/plugins` | 内蔵/アップロードプラグインの状態、項目、ファイル |
| POST | `/api/plugins/rescan` | アップロードプラグインを再スキャン |
| POST | `/api/plugins/upload` | helper をアップロード |
| DELETE | `/api/plugins/files/:kind/:file` | アップロード helper を削除 |
| PUT | `/api/plugins/files/:kind/:file` | ファイル単位の有効化・無効化 |
| PUT | `/api/plugins/providers/:id` | DNS 項目の有効化・無効化 |
| PUT | `/api/plugins/deployers/:id` | デプロイ項目の有効化・無効化 |
| PUT | `/api/plugins/notify-channels/:id` | 通知項目の有効化・無効化 |
| GET | `/api/plugins/icons` | アイコン |

プラグインリポジトリ関連の API は削除されました。

## トラブルシューティング

| 現象 | 原因 | 対処 |
|---|---|---|
| 内蔵項目が利用できない | カテゴリが無効、または項目が未有効 | カテゴリ設定と項目ホワイトリストを確認 |
| アップロード後に項目が表示されない | ファイルが既定で無効 | ファイルを有効化してから項目を有効化 |
| アップロードプラグインの実行に失敗する、または Landlock が利用できない | strict サンドボックスの制限、またはカーネル/コンテナの seccomp 制限 | エラーを確認し、必要に応じて `basic` へ降格して監査。Docker では seccomp を検証 |
| ID の衝突やデプロイ秘密鍵のリスク | 内蔵項目と同名、デプロイカテゴリが有効 | 別の ID を使用し、信頼できるターゲットのみを残して不要な項目を無効化 |
