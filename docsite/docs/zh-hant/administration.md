# 管理工作臺
本文面向部署和維護 LACTSSL 的開發者，說明帳戶、權限、金鑰、審計和日常維護方式。產品目前是**單管理員 + API 金鑰分權**模型。

## 運營模型
### 三類身份
| 身份 | 能力 | 適用物件 |
| --- | --- | --- |
| 管理員帳戶 | 瀏覽器登入後可執行全部操作，包括匯出私鑰、恢復備份、修改設定 | 平臺負責人 |
| API 金鑰 | 按 `資源:動作` 授權，適合自動化和只讀整合 | CI/CD、巡檢、CMDB、部署腳本 |
| ACME 客戶端帳戶 | 僅訪問某個 ACME 端點，按 EAB/網域白名單限制 | certbot、lego、acme.sh 等 |

管理員帳戶是單點，應由固定負責人持有。API 金鑰不能替代人工確認，也不能訪問帳戶安全類介面（改密、通行金鑰、會話管理等）。

### 建議的職責分離
| 職責 | 建議歸屬 | 是否使用管理員帳戶 |
| --- | --- | --- |
| 日常證書簽發與部署 | 平臺/運維 | 是，或使用受限 API 金鑰 |
| DNS/部署憑據保管 | 對應系統負責人 | 否，憑據由管理員錄入後按需輪換 |
| 自動化整合 | 整合開發 | 否，使用獨立 API 金鑰 |
| 安全審計 | 安全/審計 | 否，使用 `logs:read` / `system_logs:read` 只讀金鑰 |
| 備份恢復 | 運維負責人 | 是，恢復會重啟服務 |
| 外掛與升級 | 平臺負責人 | 是，屬於高權限變更 |

## 初始化與交接
### 初始化
1. 使用啟動日誌中的門禁入口和一次性初始化令牌建立管理員。
2. 立即啟用 TOTP 或通行金鑰，設定並驗證恢復郵箱。
3. 配置 `security.public_url`、可信代理和日誌。
4. 建立第一份加密備份，確認恢復密碼可用。
5. 啟用所需的內建外掛類別和條目。

### 負責人交接
- 管理員密碼、TOTP 種子或通行金鑰裝置，以及恢復郵箱控制權。
- API 金鑰清單：用途、權限、過期時間、責任人；DNS/部署/通知憑據清單。
- 備份位置、恢復密碼、最近一次恢復演練記錄，以及未完成任務、監控項和告警路由。

不要透過聊天工具傳遞明文密碼、API 金鑰或備份密碼；使用密碼管理器或密封交接流程。

## 帳戶安全
### 登入方式
- 密碼使用 bcrypt 雜湊儲存，長度至少 8 位；生產建議 16 位以上隨機密碼。
- TOTP 啟用後，密碼登入仍需動態驗證碼；同一驗證碼在有效視窗內不能重複使用。
- 通行金鑰（WebAuthn/Passkey）可作為額外登入方式，但不會替代密碼；必須透過 HTTPS 網域或 localhost 使用。
- 修改密碼會提升令牌版本並刪除全部服務端會話、API 金鑰和通行金鑰；透過郵箱重置密碼會同時關閉 TOTP、刪除通行金鑰和 API 金鑰，作為丟失驗證器後的恢復手段。

### 會話
會話保持預設開啟，後臺重啟後保留會話；設為 `security.session_persistence: false` 後，每次重啟都會清空會話。開啟狀態延長了會話生命週期，需結合部署策略決定。在「設定 → 會話」中定期檢查並撤銷未知裝置；已登入會話等價於管理員權限，不要在共享瀏覽器或不可信裝置上保持登入。

### 恢復路徑
至少準備兩條獨立恢復路徑：

1. **郵箱重置**：適用於忘記密碼但郵箱可控；會清除 TOTP、通行金鑰和 API 金鑰。
2. **備份恢復**：適用於帳戶、資料庫或配置損壞；需要備份解密密碼和初始化令牌（未初始化例項）。

把恢復流程寫成 Runbook 並定期演練；不要把恢復密碼與備份檔案放在同一位置。

## API 金鑰治理
API 金鑰適合機器身份，不適合人。建議按“一個系統一把鑰匙”管理。

### 角色到權限的對映
| 使用方 | 建議權限 | 說明 |
| --- | --- | --- |
| 只讀巡檢/CMDB | `system:read`、`dashboard:read`、`certificates:read`、`tasks:read`、`monitors:read`、`deployments:read` | 不授予任何 `*:write` |
| 證書清單同步 | `certificates:read`、`tasks:read` | 不授予私鑰權限 |
| CI/CD 觸發續期 | `tasks:read`、`tasks:run`；如含部署節點再加 `deploy:execute` | 按任務範圍控制 |
| 證書下載與分發 | `certificates:read`、`certificates:key`、`deploy:execute` | 高敏感，必須限制來源和過期時間 |
| 日誌審計 | `logs:read`、`system_logs:read` | 只讀金鑰，設定短期過期 |
| 監控告警 | `system:read`、`monitors:read` | 用於 `/api/status` 和監控讀取 |
| 平臺自動化 | 按實際需要組合，避免 `*` | `*` 等價於全部系統能力 |

### 生命週期
1. 登記用途、責任人、權限和過期時間。
2. 建立後立即寫入密碼管理器或金鑰管理系統，不落明文到程式碼倉庫。
3. 在呼叫方配置金鑰，驗證最小權限；到期前輪換，舊令牌立即失效。
4. 系統下線或人員變更時立即停用/刪除。

### 防護要求
- 不把金鑰放在日誌、截圖、工單或公開倉庫；只在 HTTPS 上傳輸，避免經過不可信代理。
- 為金鑰設定來源 IP 限制（在網路層或閘道器層實現）。
- 定期檢查 `api_keys:read` 權限的金鑰，防止權限蔓延；懷疑洩露時立即輪換或刪除，並檢查操作日誌中的異常呼叫。

> API 金鑰不能修改密碼、繫結通行金鑰或退出其他會話；這些操作只允許瀏覽器登入會話。

## 證書與 CA 治理
### 公共 CA
- 為 ACME 帳戶使用專用郵箱，不要繫結個人郵箱；按 CA 維護 EAB 憑據。
- 關注 CA 的速率限制和網域驗證要求；為關鍵網域準備備用 CA。
- 通用 ACME 上游必須使用 HTTPS（本機迴環除外）。

### 私有 CA
- 根 CA 私鑰只用於簽發中間 CA，不建議直接簽發終端證書。
- 為中間 CA 設定路徑長度、Key Usage、Name Constraints 和有效期。
- 根 CA 私鑰匯出後應離線保管；資料庫中的私鑰仍受 `security.salt` 保護，但不是 HSM。
- 刪除 CA 前確認沒有下級 CA 和依賴證書；存量證書不會自動獲得 CRL/OCSP 擴充套件，需要重新簽發。

### ACME 服務端
- 每個端點繫結一個私有 CA，並配置網域白名單。
- 生產預設開啟 EAB；關閉 EAB 時任何能訪問端點的人都可建立帳戶。
- 公網端點使用獨立埠、來源限制和 mTLS（如客戶端支援）。
- 定期清理失效訂單和長期未使用帳戶；清理帳戶會刪除歷史訂單，但不影響已簽發證書。

## 外掛與供應鏈
- 官方 DNS、部署、通知實現已內建，隨主程式版本釋出；升級主程式即完成更新。
- 部署類別會接觸證書私鑰，預設開啟；只保留可信的內建目標，按需上傳 helper。
- 上傳 helper 只接受可信來源，目錄 `0700`、檔案 `0755`，屬主為服務執行使用者。
- 保留 helper 版本、上傳時間和變更記錄，便於回滾。

詳細流程見[外掛治理](plugins.md)。

## 審計與證據
| 日誌 | 內容 | 用途 |
| --- | --- | --- |
| 操作日誌 | 任務、證書、部署、通知、監控、設定變更 | 操作審計、變更追蹤 |
| 系統日誌 | 啟動、HTTP、排程、外掛、ACME 等程序日誌 | 執行排障、安全事件分析 |
| 程序日誌 | stdout 或 `log.file` | 日誌平臺採集、panic 分析 |

- 操作日誌保留至少 90 天（匯出範圍上限）；需要更長保留時定期匯出到外部日誌系統。
- 系統日誌預設保留 7 天或 20,000 行，按需調整 `log.system.retention_days` 和 `max_rows`。
- 反向代理訪問日誌獨立儲存，記錄來源 IP、狀態碼和 `X-Request-ID`；匯出 CSV 時注意公式注入防護，不要把含憑據的日誌外發。
- 關鍵變更（CA 生成、私鑰匯出、備份恢復、外掛上傳、門禁入口修改）應有變更單或工單關聯。

## 日常運營清單
### 每日
- [ ] 檢視任務失敗、部署失敗和證書異常告警。
- [ ] 檢查站點監控中的異常/臨期項，確認備份任務成功（步驟見[運維手冊](operations.md)）。

### 每週
- [ ] 檢查即將到期證書和自動續期狀態。
- [ ] 檢視系統日誌中的錯誤、限流和異常登入，核對新增/停用的 API 金鑰和憑據。

### 每月
- [ ] 檢查磁碟、資料庫大小、WAL 和日誌保留。
- [ ] 檢查外掛版本與安全公告，抽查操作日誌和變更記錄，驗證通知渠道可達。

### 每季度
- [ ] 完成一次備份恢復演練。
- [ ] 複核管理員帳戶、恢復郵箱、TOTP/通行金鑰與 API 金鑰權限，評估升級視窗和回滾方案。

## 變更管理
高風險操作建議走變更單：

| 操作 | 風險 | 建議控制 |
| --- | --- | --- |
| 修改門禁入口 | 可能鎖死管理入口 | 記錄新入口，保留 `config.yaml` 覆蓋方式 |
| 修改 `security.salt` | 已有加密憑據無法解密 | 禁止隨意更換；必須配套遷移 |
| 刪除私有 CA | 影響下級 CA 和依賴證書 | 先確認依賴，匯出備份 |
| 恢復備份 | 覆蓋當前資料並重啟 | 二次確認，選擇低峰期 |
| 啟用部署外掛 | 可讀取證書私鑰 | 來源審查、最小權限、停用不需要的目標 |
| 程式升級 | 資料遷移不可逆 | 備份、預發驗證、回滾計劃 |
| 批次清理證書/日誌 | 資料不可恢復 | 先預覽、匯出、二次確認 |
