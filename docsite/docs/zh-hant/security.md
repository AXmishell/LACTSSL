# 安全基線
本文面向部署和整合 LACTSSL 的開發者，說明 LACTSSL 的安全模型、已實現的控制，以及上線前的加固清單。

## 安全模型與信任邊界
LACTSSL 按“自託管單例項”設計，信任邊界如下：

```text
[不可信] 網際網路/外部網路使用者
    │ HTTPS（反向代理終止）
[邊界] 反向代理 / WAF / 網路 ACL
    │ HTTP（迴環或內網）
[可信] LACTSSL 程序
    ├─ 管理員會話：等同完全控制
    ├─ API 金鑰：按權限範圍受限
    ├─ 私有 CA 私鑰：加密儲存在本地資料庫
    └─ 外掛子程序：以服務帳號執行，視為受信程式碼
[外部] DNS API / CA / SMTP / 部署目標 / 通知渠道
```

- **管理員會話等價於完全控制**，包括執行本地部署命令、匯出私鑰和恢復備份。
- **API 金鑰是機器身份**，用於降低自動化場景的權限，不是多使用者 RBAC。
- **外掛是受信程式碼**，尤其是部署外掛會接觸證書私鑰；供應鏈安全由部署方把關。
- **資料庫和 `config.yaml` 同等敏感**；丟失 `salt` 會導致加密憑據不可用，洩露則可能導致憑據被解密。

## 身份與訪問控制
### 管理員帳戶
- 單管理員帳戶，不提供多使用者或 RBAC。
- 密碼使用 bcrypt 雜湊儲存，長度至少 8 位；生產建議 16 位以上隨機密碼。
- 支援 TOTP 兩步驗證和通行金鑰（WebAuthn/Passkey）；通行金鑰必須透過 HTTPS 網域或 localhost 使用，直接使用 IP 不能作為 WebAuthn 來源。
- 啟用 TOTP、註冊通行金鑰必須現場再認證（目前為密碼；啟用 TOTP 時還需動態驗證碼），避免失竊會話把帳號繫結到攻擊者的認證器。修改 SMTP/通知目標、傳送測試訊息只要求登入會話或對應 API 權限。
- 一次再認證成功後，同一瀏覽器會話在 5 分鐘內可連續執行敏感操作；改密、改信箱、TOTP/通行金鑰變更仍要求現場驗證。
- 使用通行金鑰登入後不會再次要求 TOTP；修改密碼會提升令牌版本並刪除全部服務端會話、API 金鑰與通行金鑰。
- 透過郵箱重置密碼會同時關閉 TOTP、刪除通行金鑰與 API 金鑰；必須確保恢復郵箱本身安全。

### API 金鑰
- 金鑰為 86 位 Base64URL 隨機串（64 位元組熵），不含固定字首，服務端只儲存 SHA-256 摘要。
- 權限按「資源:動作」劃分；`*` 表示全部系統 API 能力。敏感權限包括 `certificates:key`、`private_cas:key`、`deploy:execute`、`deploy:command`、`plugins:write`、`settings:write`、`api_keys:write`、`monitors:internal`。備份下載/恢復、入口修改與資料庫切換僅瀏覽器會話。
- 透過 API 金鑰管理其他金鑰時，不能授予自身沒有的權限，也不能修改/輪換/刪除權限高於自身的金鑰。
- 帳戶安全類操作（改密、通行金鑰、會話管理）只允許瀏覽器登入會話；建議每個自動化系統獨立金鑰、設定過期時間並定期輪換。

## 網路與 TLS
### 入站
- 管理控制台必須透過 HTTPS 反向代理訪問；主程式只監聽 HTTP，後端埠只監聽迴環或內網。
- 在代理層配置來源 IP 白名單、VPN、零信任策略或 WAF，並配置 HSTS、TLS 1.2+、禁用弱套件和請求體大小限制。
- 代理必須覆蓋或正確追加 `X-Forwarded-For` 並傳遞 `X-Forwarded-Proto`；LACTSSL 只信任 `server.trusted_proxies` 中的精確 IP/最小 CIDR，多級追加鏈路需信任鏈上所有代理。
- 未配置可信代理時，所有請求會被視為來自代理 IP，導致限流失效、`Secure` Cookie 判斷錯誤。

### 出站
服務端會主動向 DNS 服務商 API、公共 ACME CA、SMTP、通知渠道、SSH/SFTP、FTP/FTPS、雲 CDN、面板、WAF 和站點監控目標發起請求。

- 生產環境按網域或網段做 egress 白名單，只放行實際需要的目標；需要經代理時，透過系統環境變數配置。
- 對部署 Webhook、通知 Webhook 等自定義目標做來源審查，避免把私鑰或令牌發到不可信地址。
- 內網 HTTPS 目標應透過「系統設定 → TLS 信任鏈」匯入內部 CA 公鑰，而不是關閉 TLS 校驗；匯入的 CA 與私有 CA 會合並進 `SSL_CERT_FILE` 供外掛和部署命令使用。

### SSRF 防護
- 字面量與解析後的目標地址會拒絕雲後設資料、鏈路本地、保留、文件、NAT64 等網段（如 `169.254.169.254`、`100.100.100.200`、`fd00:ec2::254`、`0.0.0.0/8`、`240.0.0.0/4`）。
- 迴環與私網地址仍允許，便於 Gotify、自建面板、內網 Webhook；如不需要可在網路層進一步限制。
- 站點監控預設只允許公網目標；監控私網/迴環需要 API 金鑰具備 `monitors:internal`，撥號時按最終解析 IP 再校驗，防止 DNS rebinding。
- 部署 Webhook 會攜帶證書私鑰，公網目標強制 `https://`；迴環、私網、`.local`、`.internal` 允許 HTTP。第三方請求失敗寫入日誌前會脫敏 URL 路徑與查詢引數，避免 Token 進入日誌或備份。

## 門禁入口、會話與 CSRF
### 門禁入口
管理頁面不直接暴露在根路徑，而是先透過隨機生成的入口進入：

```text
https://your-domain/<entry>/
```

- 入口預設隨機生成 20 位大小寫字母與數字組合，儲存在資料庫中；未透過入口的頁面統一返回 `404`，包括裸 `/` 等探測路徑。
- 介面固定掛在裸 `/api` 下，由登入會話或 API 金鑰保護；舊版 `/<entry>/api` 保留為相容別名。
- 訪問正確入口後寫入有效期 24 小時的簽名 `HttpOnly` 門禁 Cookie，服務端同時校驗過期時間；入口探測有頻率限制。
- 可在「設定 → 門禁入口」中修改，修改後立即生效；手工入口要求 8–32 位。忘記入口時可修改 `config.yaml` 的 `security.entry` 並重啟覆蓋，或在資料庫 `settings` 表中檢視。
- 系統未初始化時，啟動日誌輸出一次性初始化令牌；建立管理員、修改初始化配置、重啟初始化程序和從備份恢復都必須攜帶該令牌（`X-LACTSSL-SETUP-TOKEN`）。令牌在初始化成功後立即失效。

> 入口是額外一層防護，不能替代 HTTPS、強密碼和網路訪問控制。

### 會話
- 登入會話儲存在 `HttpOnly` Cookie 中，前端腳本無法讀取；Cookie 使用 `SameSite=Lax`，寫入操作由雙重提交 CSRF 與 Origin 校驗保護。
- 會話令牌使用緊湊 JWT，會話 ID 為 24 位元組（192 位元）隨機數；CSRF 令牌為 32 個字元。
- 首次訪問門禁入口或登入時下發有效期 1 年的 `HttpOnly` 裝置標識 Cookie（`lactssl_device`，32 個十六進位制字元）。HTTPS 部署時會話、CSRF 與入口 Cookie 自動使用 `__Host-` 字首。
- 預設開啟會話保持：啟動不清空服務端會話，使用固定 `jwt_secret` 簽名。設定 `security.session_persistence: false` 後恢復嚴格模式，每次啟動清空會話，所有舊登入立即失效。

### CSRF 與跨站防護
- 所有改變服務端狀態的請求（POST/PUT/DELETE 等）必須攜帶 `X-LACTSSL-CSRF` 請求頭，且與 `lactssl_csrf` Cookie 一致；舊會話首次請求會自動補發 Cookie。
- 登入、初始化、忘記密碼和密碼重置等未認證介面額外校驗 `Origin`/`Sec-Fetch-Site`。
- 顯式使用 `Authorization: Bearer <token>` 呼叫 API 時不受 CSRF 校驗約束，便於腳本或外部整合。
- 頁面回應使用每次請求隨機 CSP nonce，`script-src` 不再允許任意內聯腳本；樣式仍允許內聯以滿足元件庫需要。

## 密碼重置與對外地址
密碼重置郵件中的連結必須基於固定地址生成：

```yaml
security:
  public_url: "https://ssl.example.com"
```

- 未配置 `public_url` 時，僅允許本機迴環地址且 Host 為 `localhost`/迴環 IP 的請求按當前 Host 推導連結；其他請求呼叫“忘記密碼”會被拒絕。
- 不信任客戶端可偽造的 `X-Forwarded-Host`。反向代理場景必須配置 `public_url`，避免攻擊者偽造 Host 把重置連結（含 token 與門禁入口）指向自己的網域。

## 憑據與資料保護
### 加密
- DNS 憑據、部署憑據、SMTP 密碼、通知 Token、TOTP 金鑰、私有 CA 私鑰和證書私鑰等敏感欄位使用 AES-256-GCM 加密後寫入資料庫；舊版本明文資料會在啟動時自動遷移。
- 加密金鑰來自 `config.yaml` 的 `security.salt`；JWT 使用 `security.jwt_secret` 簽名，實際使用由 `jwt_secret` 與啟動隨機值經 HKDF 派生的獨立子金鑰，與資料庫 AES-GCM 金鑰分離。
- `security.jwt_secret` 和 `security.salt` 手動配置時至少 32 個字元，過短會拒絕啟動。
- 介面返回配置時會對金鑰欄位脫敏；編輯時留空表示保留原值。

### 檔案與備份
- `config.yaml` 保持 `0600`，`data/` 保持 `0700`，屬主為服務執行使用者；資料庫、WAL、外掛、日誌和升級備份都位於 `data/` 下。
- 下載備份時必須設定至少 12 位的加密密碼；備份包使用 PBKDF2-HMAC-SHA256（600,000 次迭代）+ AES-256-GCM 加密，包含資料庫、配置和版本資訊，按機密檔案管理。
- 恢復包會先完整校驗配置（金鑰長度、門禁入口、監聽地址、TLS/mTLS 組合等），非法配置會被拒絕。
- 首次初始化成功後會清理尚未應用的恢復包，防止初始化前暫存的內容在後續重啟時覆蓋新帳戶。

### 憑據輪換
- DNS/部署/通知憑據使用專用帳號，定期輪換。
- SSH 預設要求填寫主機指紋；只有顯式開啟“首次連線自動信任主機金鑰”時才採用 TOFU，後續指紋不一致會拒絕連線。FTP 部署預設使用顯式 TLS，只有明確選擇 `none` 才使用明文 FTP。
- API 金鑰設定過期時間，按系統獨立發放，洩露時立即輪換。

## 審計與日誌
| 日誌 | 內容 | 保留/匯出 |
| --- | --- | --- |
| 操作日誌 | 任務、證書、部署、通知、監控、設定變更 | 可按來源/級別/時間篩選，匯出最近 90 天 CSV/JSON；刪除前寫入歸檔 |
| 系統日誌 | 啟動、HTTP、排程、外掛、ACME | 預設 7 天/20,000 行，可調整和清空；刪除前寫入歸檔 |
| 日誌歸檔 | 操作日誌/系統日誌的原始 NDJSON 與 manifest | `data/archives/logs/`，預設永久保留；可在「日誌 → 歸檔」下載或刪除 |
| 程序日誌 | stdout 或 `log.file` | 按大小/天數輪轉，可輸出 JSON |
| 反向代理日誌 | 訪問、來源 IP、狀態碼 | 由外部日誌系統管理 |

- 將操作日誌、系統日誌和歸檔檔案定期匯出到 SIEM 或日誌平臺，避免管理員清空、刪除歸檔或資料損壞導致審計缺失。
- 操作日誌與系統日誌共用 `logs` 表，但按 `category` 隔離；每個回應帶 `X-Request-ID`，可用於關聯訪問日誌、panic 和錯誤。
- 訪問日誌不記錄查詢引數、請求體和認證頭；門禁入口在路徑中統一替換為 `:entry`。日誌與歸檔可能包含客戶端 IP、網域、錯誤詳情和操作者資訊，按運維資料管理。
- 歸檔檔案權限 `0600`、目錄 `0700`，但不是不可篡改審計：擁有資料目錄權限的管理員可以刪除或修改。如需防篡改審計，可同步到外部 WORM 儲存或 SIEM；關鍵操作建議關聯變更記錄。

## 外掛與供應鏈安全
- 官方 DNS、部署、通知實現已內建，屬於主程式供應鏈，隨程式簽名或容器映象摘要釋出。
- 官方釋出建置會自動內建 `upgrade.program.public_key` 並預設校驗釋出簽名；自編譯版本未配置時拒絕線上升級，只有受控環境可顯式開啟 `upgrade.program.allow_unsigned`。
- 上傳 helper 必須提供協議、ID、版本、平臺和 SHA-256；安裝時校驗 `manifest`，任一步失敗都會回滾。
- 安裝記錄中的檔案摘要會在發現、註冊和每次呼叫前複核；檔案被替換時拒絕載入或執行。
- 外掛目錄權限 `0700`，helper `0755`，不允許組或其他使用者寫入；符號連結會被拒絕。
- 部署外掛會接收證書私鑰，預設開啟，只應啟用可信來源並保持最小啟用範圍；主程式限制 helper 的超時、常駐記憶體與輸出大小，並在錯誤資訊中脫敏憑據與私鑰。
- 生產只上傳經審查的 helper，記錄來源、版本、摘要、審核人和回滾版本，並在預發環境驗證後再進入生產。

## ACME 服務端安全
- 內建 ACME 服務端預設開啟，但在建立並啟用端點前不會對外簽發證書。啟用後提供獨立協議入口，不使用管理端門禁入口、會話 Cookie 或 CSRF 校驗；不需要時可將 `acme.enabled` 設為 `false`。
- 公網部署建議使用獨立埠，並在防火牆或反向代理層限制訪問；每個端點必須配置網域白名單，白名單為空會被拒絕。
- EAB 可開關，預設建議開啟。關閉 EAB 時任何能訪問該埠的人都可以建立帳戶，必須配合網域白名單、mTLS 或網路 ACL；mTLS 是傳輸層門禁，不能替代 ACME 的 JWS 帳戶認證。
- `acme.base_url` 應配置為固定公網地址，避免 Host 頭注入；未配置時會按請求 Host 推導，公網部署不應依賴該回退。
- HTTP-01 驗證預設拒絕迴環、私網、鏈路本地及 CGNAT/保留網段（如 `100.64.0.0/10`、`192.0.0.0/24`）；內網場景需透過端點級 CIDR 白名單顯式放行。
- ACME 協議資源使用隨機公開 ID；自定義 ACME 上游目錄地址必須使用 HTTPS，只有本機迴環允許 HTTP。單例項部署使用記憶體 nonce，重啟後客戶端會收到 `badNonce` 並自動重試。
- CRL 與 OCSP 端點位於 `/pki/{ca}/...`，按 CA 組織並按 IP 限流；即使停用 ACME 報名端點也應保持可達。CRL 會快取相同吊銷集合，只有內容變化才遞增 CRL Number。
- 吊銷狀態儲存在獨立 `revocations` 表，刪除或清理證書行不會抹掉記錄。簽發葉子證書前會校驗 CA 的 `ExtKeyUsage`（必須包含 `serverAuth` 或 `any`）與 NameConstraints；存量證書需要重新簽發才能帶上 CRL/OCSP 地址。

## 部署與容器加固
- 使用獨立使用者執行服務，`config.yaml` 保持 `0600`，資料目錄保持 `0700`；不要把 `data/`、`config.yaml` 提交到版本庫或放入公開目錄。
- Docker 映象透過入口腳本修正卷權限後，使用非 root 的 `lactssl` 使用者執行主程式；Compose 預設丟棄全部 capabilities 後按需新增 `CHOWN`/`SETUID` 等，並啟用只讀根檔案系統、`/tmp` tmpfs、`pids_limit` 與 `init`。
- 服務預設限制普通介面請求體為 2 MiB（備份恢復和外掛上傳除外），並設定讀寫超時；反向代理層也應配置請求體大小和超時。
- 生產固定映象/二進位制版本，定期掃描映象漏洞並關注釋出安全公告；使用 80/443 等特權埠時優先由反向代理轉發，不要給二進位制額外 capability。

## 已知限制
- 不提供多使用者和 RBAC；管理員會話是單點。
- 不提供 SSO、LDAP、OIDC、SAML、SCIM。
- 不提供 HSM/KMS；私鑰在本地資料庫中加密儲存。
- 不提供雙活叢集；SQLite 單寫，不能多例項共享資料目錄。
- 不提供不可篡改審計；管理員可以清空日誌或刪除本地歸檔。如需防篡改審計，應外部歸檔並啟用 WORM/保留鎖。
- 不提供 Prometheus 指標端點；監控依賴日誌、認證 API 和外部探測。
- 不提供部署目標側的自動回滾；需目標系統保留舊版本或使用原子釋出。

## 上線安全檢查清單
### 身份
- [ ] 管理員使用強密碼，啟用 TOTP 或通行金鑰。
- [ ] 恢復郵箱受控並啟用 MFA，已清理未知會話。
- [ ] API 金鑰按系統獨立、最小權限、設定過期時間。

### 網路
- [ ] 管理入口僅 HTTPS，後端埠不直接暴露公網。
- [ ] 已配置 `trusted_proxies` 和 `public_url`。
- [ ] 代理傳遞 `X-Forwarded-For`/`X-Forwarded-Proto`。
- [ ] 已配置來源限制、WAF 或零信任策略，出站按目標白名單。

### 資料
- [ ] `config.yaml` 0600、`data/` 0700、屬主正確。
- [ ] 已生成並異地儲存加密備份，備份密碼與檔案分離保管。
- [ ] 已完成一次恢復演練，日誌保留和匯出滿足審計要求。

### 外掛與 ACME
- [ ] 只使用內建實現或經審查的 helper，校驗摘要。
- [ ] 停用不需要的部署目標，只保留可信目標。
- [ ] ACME 端點配置網域白名單，生產開啟 EAB。
- [ ] ACME 入口限制來源，必要時啟用 mTLS。

## 安全事件回應
1. **確認範圍**：是帳戶、API 金鑰、DNS/部署憑據、外掛還是主機。
2. **隔離**：撤銷會話/API 金鑰，停用外掛，關閉 ACME 端點，必要時從網路層切斷。
3. **取證**：匯出操作日誌、系統日誌、反向代理日誌，記錄 `X-Request-ID`，不要先清空日誌。
4. **輪換**：修改密碼會清除全部會話和 API 金鑰；輪換 DNS/部署/通知憑據；如懷疑 `salt` 洩露，按金鑰洩露流程處理。
5. **恢復**：從可信備份恢復，驗證配置與資料一致性，重新簽發可能受影響的證書。
6. **覆盤**：更新 Runbook、權限清單和監控規則。

具體排障步驟見[監控與排障](troubleshooting.md)，備份恢復見[運維手冊](operations.md)。
