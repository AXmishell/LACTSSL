# 產品能力
本文按功能域說明 LACTSSL 能做什麼、關鍵引數和限制，便於開發和整合。具體操作步驟見[快速開始](getting-started.md)、[管理工作臺](administration.md)和[API 整合](api.md)。

## 能力地圖
| 能力域 | 主要內容 | 典型使用方 |
| --- | --- | --- |
| 證書資產 | 公共 CA 申請、自動續期、證書詳情與清理 | 平臺/運維 |
| 任務編排 | 普通流程：申請 → 部署（可多個）→ 通知；目標流程 Beta：讀取站點 → 證書分組 → 申請 → 部署 | 平臺/運維 |
| 證書交付 | 本地目錄、SSH/SFTP、FTP、Webhook、雲 CDN、面板 | 平臺/運維、目標系統 |
| 內部 PKI | 私有 CA 生成/匯入、層級、CRL/OCSP 地址 | 安全、基礎設施 |
| ACME 服務端 | 對內提供標準 ACME v2 端點 | 內部平臺、裝置、測試環境 |
| 監控與告警 | 外部站點證書監控、任務/部署通知 | 運維、監控 |
| 審計與恢復 | 操作日誌、系統日誌、加密備份 | 安全、審計、運維 |
| 整合 | API 金鑰、REST API、自動化 | 整合開發 |

## 證書申請與續期
### 驗證方式
- 公共 CA 申請僅使用 **DNS-01** 驗證，支援單網域、多網域和萬用字元證書。
- DNS-01 需要在「DNS 帳戶」中配置服務商 API 憑據，任務執行時自動建立/清理 TXT 記錄。
- 私有 CA 簽發不經過 ACME 驗證，由系統直接簽發。
- 內建 ACME 服務端支援 HTTP-01、DNS-01、TLS-ALPN-01，供內部客戶端使用。

### 內建證書頒發機構
| CA | 說明 |
| --- | --- |
| Let's Encrypt | 預設公共 CA，無需 EAB |
| ZeroSSL | 需要 EAB |
| Google Trust Services | 需要 EAB |
| LiteSSL | 需要 EAB |
| 零信 ZoTrus | 需要 EAB，KID 為註冊信箱；使用手動 DNS 驗證，不支援萬用字元 |
| Actalis | 需要 EAB |
| SSL.com | 需要 EAB，依私密金鑰類型自動選擇 ECDSA/RSA 端點 |

「公共CA」中還可以新增多個**通用 ACME 上游**：

- 配置 ACME 目錄地址、ACME v1/v2 協議版本和可選 EAB；通用上游會出現在任務和預設 CA 選擇列表中。
- 自定義目錄地址必須使用 HTTPS；只有本機迴環允許 HTTP。
- ACME v1 僅支援 DNS-01，且不支援 EAB。

### 金鑰與續期
- 私鑰型別：`ecdsa`（預設）、`ecdsa384`、`rsa2048`、`rsa4096`；自動續期預設在到期前 30 天觸發，可按任務調整。
- 申請模組可勾選「不儲存憑證私鑰在伺服器端」：私鑰僅在本次簽發與部署期間暫存於記憶體，不寫入資料庫、不可下載；自動續期會重新簽發並部署，一般流程需至少一個啟用的部署模組。
- 後臺排程器每 30 秒檢查到期任務；任務失敗可在任務日誌中檢視原因，憑據、網域和 CA 問題會給出明確錯誤。
- 證書管理頁支援搜尋、狀態/來源篩選、詳情和安全分析；下載證書鏈需要 `certificates:read`，檢視或下載私鑰還需要 `certificates:key`。
- 一鍵清理可按狀態、時長、簽發時間、網域、頒發機構、來源和“保留每個任務最新證書”篩選；清理後相關任務的證書引用會被清空。

### 預設配置
「公共CA」支援配置 ACME 帳戶郵箱、預設 CA、預設私鑰型別、預設續期天數和各 CA 的 EAB 憑據。

### 目標流程 Beta
目標流程 Beta 適合「證書跟隨面板網站」的場景：先透過部署外掛的 `plan` 能力讀取目標中的真實網站和繫結網域，再按策略分組申請證書，最後部署回對應網站。

- 任務頁用「全部 / 普通流程 / 目標流程 Beta」標籤分離兩種流程，新建/編輯彈窗使用同一套分段切換。
- 支援多個站點來源，網站清單來自目標系統，不依賴手工填寫站點名稱。
- 證書分配策略：智慧推薦、一站點一證書、按主網域合併、全部選中站點合併、每個目標來源一張、自定義分組。
- 支援站點勾選、網域包含/排除規則、額外網域追加；自動續期時會重新讀取站點，`全部站點` 自動納入新增站點，`僅選中站點` 只保留已儲存的穩定站點鍵。
- 一個 Beta 任務可以關聯多張證書，`certificates.task_id` 保留全部證書；開啟「保留每個任務最新證書」時不會清理 Beta 任務的證書。

### 客戶端 CSR 申請
- API 支援客戶端提交 CSR，服務端作為中間環節向公共 CA 完成 DNS-01 驗證並簽發證書。
- 服務端不生成、不儲存私鑰；證書繫結客戶端 CSR 中的公鑰，私鑰始終由客戶端持有。
- 申請非同步執行，可查詢狀態、取消、重試，並按申請單下載證書鏈。
- 僅支援 ACME v2 公共 CA 和 DNS-01；萬用字元證書必須使用 DNS-01。
- 需要 `certificates:request` 權限，並可透過 `csr.allowed_domains` 限制可申請網域。

## DNS 服務商
官方 DNS 實現已內建，覆蓋約 235 個條目（含 lego v5 與相容 ID），預設全部停用，在「外掛」頁按需啟用。憑據在寫入資料庫前加密；`manual` 服務商需要人工新增 TXT 記錄，不納入自動流程；部分服務商支援自定義 API 上游地址，可用於代理或相容閘道器。完整服務商列表、憑據要求和排障見[DNS 外掛](dns-plugins.md)。

## 任務編排
任務由節點組成，預設流程是「申請 → 部署（可多個）→ 通知」。

| 節點 | 關鍵引數 |
| --- | --- |
| 申請 | 網域、DNS 帳戶、CA、私鑰型別、自動續期、提前天數 |
| 部署 | 目標憑據、證書/私鑰路徑、站點/網域/證書名稱、過載命令 |
| 通知 | 渠道、觸發時機（始終 / 僅成功 / 僅失敗） |

- 節點可以啟用/禁用和排序；任務可以包含多個部署節點，把同一張證書交付到多個目標。
- 舊任務沒有顯式流程時，系統會根據原有網域、目標憑據等欄位推導等效流程；升級時會把舊憑據中的部署引數遷移到任務部署節點。
- 任務列表支援批次執行、暫停或啟動自動續期；批次執行會跳過正在執行的任務，批次啟停不中斷已開始的簽發。
- 執行前會複用仍在有效期內且未進入續期視窗的同網域證書，只重新執行部署；需要重新簽發時使用「強制重新簽發」或 API `?force=1`。上游 CA 限流時任務進入「限流等待」，按 CA 給出的恢復時間重試，不按普通失敗每 6 小時重試。

## 證書部署
「目標憑據」只儲存認證與連線資訊；證書路徑、過載命令、部署網域、站點等引數在任務部署節點中填寫，因此同一憑據可被多個任務複用。

### 內建目標
| 目標 | 憑據 | 部署引數 |
| --- | --- | --- |
| 本地目錄 | 無 | 證書/私鑰路徑，可選過載命令 |
| SSH / SFTP | 主機、埠、使用者名稱、密碼或私鑰、主機指紋 | 遠端證書/私鑰路徑，可選遠端過載命令 |

SSH 預設要求填寫目標主機指紋（`SHA256:...`）。只有顯式開啟“首次連線自動信任主機金鑰”時才採用 TOFU 記錄；後續指紋不一致會拒絕連線。

### 外掛目標
FTP/FTPS、Webhook、阿里雲 CDN、七牛雲、寶塔面板、1Panel、雷池 WAF 等目標已內建，啟用部署類別後在任務部署節點的「部署物件」中選擇；第三方目標可上傳 helper。部署目標會接收證書與私鑰，等同受信程式碼，類別預設開啟；關閉類別時只顯示本地檔案與 SSH，歷史憑據仍會保留。具體引數見[部署外掛](deploy-plugins.md)。

### 內部 CA 信任鏈
「系統設定 → TLS 信任鏈」可以匯入內部 CA 公鑰（PEM，可同時包含根 CA 與下級 CA）：

- 目標憑據和外掛訪問內部 HTTPS 服務時，使用系統根證書加匯入的 CA 完成 TLS 校驗，無需跳過校驗。
- 證書監控會信任由這些 CA 簽發的站點證書；本程式私有 CA 的證書自動加入信任鏈。
- 部署、過載命令與 helper 子程序透過合併後的 `SSL_CERT_FILE` 讀取信任鏈，也相容 `CURL_CA_BUNDLE` 與 `REQUESTS_CA_BUNDLE`；信任鏈儲存在 `trusted-ca-bundle.pem`，可在設定頁下載。

只應匯入確實受控的內部 CA；錯誤的 CA 會削弱 TLS 校驗。移除 CA 後，使用其簽發證書的目標會重新變為不受信任。匯入 CA 只解決“證書不受信任”；證書過期、尚未生效或與訪問網域/IP 不匹配時，仍需更新證書或改用匹配的地址。

### 部署記錄
- 每次部署生成部署記錄，可在證書詳情和日誌中檢視結果。
- 手動部署優先複用證書所屬任務的部署節點引數，也可以按目標單獨填寫本次引數；本地/SSH 部署會執行過載命令，API 金鑰必須顯式擁有 `deploy:execute`。
- 部署失敗不會自動回滾目標系統上的舊證書；需要在目標側保留上一版檔案或使用原子釋出機制。

## 站點證書監控
新增外部站點後，服務會定期透過 TLS 連線讀取證書：

- 目標支援 `example.com`、`example.com:8443` 或完整 URL，預設埠 `443`；預設每 24 小時檢查一次，可按監控項調整。
- 校驗證書主機名、簽發者、到期時間和狀態；剩餘 30 天以內標記為即將過期，過期、連線失敗、鏈不受信任、鏈不完整或主機名不匹配標記為異常。
- 狀態從正常變為即將過期、已過期或異常時傳送通知。
- 監控會校驗系統信任鏈，避免中間人用自簽證書掩蓋真實證書問題；管理員匯入的內部 CA 與私有 CA 也會納入信任鏈。

## 通知
### 內建渠道
- **郵件（SMTP）**：伺服器、埠、使用者名稱、密碼、發件人，支援 SSL。
- 預設使用隱式 TLS（`smtp.ssl=true`）；關閉隱式 TLS 時，如果伺服器不支援 STARTTLS，服務會拒絕傳送，避免重置令牌等敏感郵件明文傳輸。

### 外掛渠道
Gotify、ServerChan、ntfy、GoCQHTTP、PushDeer、Bark、Telegram、釘釘、企業微信機器人、企業微信應用、企業微信智慧機器人、iGot、PushPlus、WePlus、WxPusher、WxPusher SPT、OpenILink、WPush、Synology Chat、飛書、PushMe、ChronoCat，以及通用自定義 Webhook。

- 除郵件外的渠道隨主程式提供，可單獨啟用並傳送測試訊息；渠道治理見[外掛治理](plugins.md)，完整引數見[通知外掛](notify-plugins.md)。
- 任務通知節點可選擇具體渠道，或使用全部已啟用渠道；觸發時機支援始終、僅成功、僅失敗。

## 私有 CA
在「私有CA」中管理內部證書頒發機構。

### 生成
- 私鑰型別：ECDSA P-256 / P-384、RSA 2048 / 4096；有效期按需要設定。
- 可生成根 CA，也可選擇「中間/頒發 CA」，由已有私有 CA 簽發下級 CA。
- 生成時可配置主題（ST、L、OU、Email、自定義序列號）、擴充套件（路徑長度、Key Usage、Extended Key Usage、SAN、Name Constraints）和基礎設施（上級 CA、CRL 分發點、OCSP 回應地址、CA 頒發者地址、證書策略 OID 與 CPS 地址）。
- SKI、AKI、CA 基本約束由系統自動生成；選擇上級 CA 時，有效期和路徑長度會自動收斂到上級 CA 允許的範圍。

### 匯入
- 貼上 PEM 格式的 CA 證書與私鑰。
- 校驗 CA 基本約束、證書籤名用途、證書與私鑰是否匹配。
- 匯入中間 CA 時可選擇上級 CA，系統會校驗簽名並建立層級關係。

### 下載與刪除
- 可下載 CA 證書、私鑰或完整證書鏈（中間 CA + 上級 CA 鏈）。
- 列表介面不返回證書或私鑰內容；私鑰下載需要 `private_cas:key`。
- 刪除會移除服務端儲存的 CA 記錄與私鑰；存在下級 CA 時需先刪除下級 CA。

### 限制
- 私有 CA 私鑰在寫入資料庫前加密，但不是 HSM/KMS 託管。
- 根 CA 和中間/頒發 CA 都可以在「證書申請」中作為簽發機構；完整證書鏈隨證書儲存和部署。
- 證書預設有效期 365 天，且不超過 CA 的到期時間。
- CRL/OCSP 分發地址會寫入新證書，但實際吊銷列表和線上狀態服務需要外部 PKI 基礎設施；存量證書不會自動獲得 CDP/AIA 擴充套件，需要重新簽發。

## ACME 服務端
內建 ACME v2 服務端預設開啟，可把私有 CA 暴露給 certbot、lego、acme.sh 等客戶端。未建立並啟用端點時不會簽發證書。

### 端點
- 每個端點繫結一個私有 CA，使用隨機 URL slug，例如 `/acme/internal/directory`。
- 支援 EAB 開關、網域白名單、HTTP-01 / DNS-01 / TLS-ALPN-01 能力開關。
- 可獨立監聽埠，支援直接 TLS 與可選 mTLS；可配置證書有效期、訂單限流和 HTTP-01 內網 CIDR 白名單。

### 協議能力
- 帳戶只儲存公鑰，不儲存客戶端私鑰；支援帳戶金鑰輪換（`keyChange`）。
- 支援 ARI（RFC 9773）續期建議：預設在證書到期前約 1/3 生命週期（最多 30 天）給出續期視窗；已撤銷或過期證書返回過去視窗以提示立即續期。
- 支援 ARI `replaces` 欄位：新訂單可宣告替換的舊證書，服務端校驗舊證書歸屬、標識重疊和重複替換。
- 支援 DNS 與 IP 標識；IP 標識僅允許 HTTP-01 / TLS-ALPN-01，並要求配置 IP 網段白名單。
- 新簽發證書會寫入 CRL Distribution Point 和 OCSP AIA 擴充套件，可透過 `/pki/{ca}/crl` 與 `/pki/{ca}/ocsp` 檢查撤銷狀態；私有 CA 需具備 `cRLSign` 用途，啟用端點時會校驗。

### 診斷與清理
- 「ACME 診斷」頁面可檢視帳戶、訂單、授權、挑戰和證書狀態。
- 支援按端點、狀態和時間清理失效訂單與長期未使用帳戶；清理帳戶會刪除其歷史訂單，但不影響已簽發的證書。
- CRL/OCSP 按 CA 組織，停用 ACME 報名端點後仍應保持可達（如客戶端需要檢查吊銷）。

## 儀表盤與日誌
### 儀表盤
介面支援簡體中文與英文，可在設定中切換。首頁彙總證書總數、即將過期/已過期數量、任務與監控狀態、部署成功率、到期分佈和簽發趨勢。

### 日誌：操作日誌
- 與系統日誌同屬「雜項 → 日誌」頁面，記錄任務執行、證書簽發、部署、通知、監控和設定變更。
- 支援按來源、級別、關鍵字和時間範圍篩選，可開啟自動重新整理；關鍵字匹配原始儲存內容與引數值，不匹配渲染後的模板文案。
- 可匯出 CSV 或 JSON（CSV 帶 UTF-8 BOM），匯出範圍僅限最近 90 天；匯出時間預設跟隨瀏覽器時區。
- 可清空；啟用歸檔時先寫入 `data/archives/logs/` 再刪除，清空動作會寫入審計日誌，需要 `logs:write` 並二次確認。

### 日誌：系統日誌
- 與操作日誌同屬「雜項 → 日誌」頁面，從程序日誌中篩選後非同步寫入資料庫。
- 可按級別、元件、關鍵字和時間範圍篩選，可匯出 CSV/JSON、清空並在刪除前歸檔。
- 預設記錄 `info` 及以上級別，保留 7 天或 20,000 行；HTTP 訪問日誌預設不寫庫，可在 `log.system` 中調整。

### 日誌：歸檔
- 手動清空、90 天操作日誌清理、系統日誌保留天數/最大行數清理在刪除前自動生成歸檔。
- 歸檔由 `*.ndjson.gz` 和 `*.manifest.json` 組成，儲存原始欄位、行數、ID/時間範圍、觸發原因、操作者、SHA-256 和檔案大小。
- 支援按分類、原因、關鍵字和時間範圍篩選，下載或刪除歸檔；預設永久保留，可配置 `log.archive.retention_days`、`max_total_mb` 與 `quota_policy`。
- 歸檔失敗會阻止刪除；歸檔目錄不進入預設 ZIP 備份，需單獨轉存，也不屬於不可篡改審計。

## 能力邊界
| 邊界 | 說明 |
| --- | --- |
