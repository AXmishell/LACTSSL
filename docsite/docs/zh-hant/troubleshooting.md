# 監控與排障

本文給出部署和執行階段最常見的故障、診斷路徑和應急處理。排障時先保留現場，再按“依賴 → 認證 → 應用 → 資料”的順序定位，避免直接重啟或清空日誌。

## 首輪排查

### 確認影響範圍

- 是單個證書、單個任務，還是全部任務失敗？
- 是管理入口不可用，還是只有簽發/部署失敗？影響單個目標還是所有目標？
- 是升級/配置變更後出現，還是執行中突然出現？是否同時影響通知、監控或 ACME？

### 收集基礎資訊

```bash
# 版本與程序
curl -fsS -H "Authorization: Bearer $LACTSSL_TOKEN" \
  https://ssl.example.com/api/status

# Docker 日誌
docker compose logs --since=30m lactssl

# systemd 日誌
sudo journalctl -u lactssl --since "30 min ago"

# 埠
ss -lntp | grep -E '8080|14000'
```

記錄發生時間、時區、是否在變更視窗內，相關任務/證書/部署記錄 ID，回應頭 `X-Request-ID`，以及脫敏後的錯誤原文。

### 檢查依賴

| 依賴 | 檢查方式 |
| --- | --- |
| 反向代理 | 代理日誌、後端埠、轉發頭 |
| DNS API | 憑據權限、配額、網域/Zone、TXT 記錄 |
| 公共 CA | 狀態頁、速率限制、CAA、EAB |
| 部署目標 | 網路、認證、路徑、權限、過載命令 |
| SMTP/IM | 連通性、認證、頻道配置 |
| 主機 | 磁碟、記憶體、檔案權限、時間同步 |

## 訪問與登入

### 根路徑返回 404

**現象**：訪問 `https://ssl.example.com/` 返回 404。

**原因**：未透過門禁入口。入口是隨機路徑，裸根路徑統一返回 404。

**處理**：

1. 檢視啟動日誌中的門禁入口。
2. 或查詢資料庫 `settings` 表中的 `security.entry`。
3. 或設定 `config.yaml` 的 `security.entry` 並重啟覆蓋。

### 忘記門禁入口

- 啟動日誌（初始化時會列印完整入口）或資料庫 `settings` 表 `security.entry`。
- 啟動前修改 `config.yaml` 的 `security.entry`，重啟後覆蓋。

修改入口後舊連結立即失效；記錄新入口並通知相關方。

### 登入後立即掉線/會話失效

**可能原因**：服務重啟且關閉了 `security.session_persistence`；修改密碼使全部會話被刪除；使用不同的 `jwt_secret` 啟動；反向代理未傳遞 `X-Forwarded-Proto` 導致 `Secure` Cookie 異常；瀏覽器/代理快取了舊 Cookie。

**處理**：

1. 確認是否剛重啟或改密。
2. 檢查代理頭與 `trusted_proxies`。
3. 清理瀏覽器 Cookie 後重新從門禁入口進入。
4. 會話保持預設開啟；如曾設為 `security.session_persistence: false`，改回 `true` 可在重啟後保留會話。

### Cookie 異常、限流不準

**現象**：登入迴圈、CSRF 失敗、所有請求共享同一 IP 配額。

**原因**：未配置可信代理、代理未傳遞轉發頭，或多級代理只信任了最近一跳。

**處理**：

```yaml
server:
  trusted_proxies: ["127.0.0.1"]
security:
  public_url: "https://ssl.example.com"
```

確認代理設定了：

```nginx
proxy_set_header X-Real-IP $remote_addr;
# 推薦覆蓋模式：只信任這一層代理即可
proxy_set_header X-Forwarded-For $remote_addr;
proxy_set_header X-Forwarded-Proto $scheme;
```

使用追加模式 `$proxy_add_x_forwarded_for` 時，多級鏈路（如 CDN → Nginx → LACTSSL）必須把鏈上所有會出現在 XFF 的代理加入 `trusted_proxies`，否則客戶端 IP 會停在上游代理。

在「設定 → 配置檔案 → 自動檢測」中對照 `peer_ip`、`applied_trusted_proxies`、`effective_client_ip`/`client_ip_source`、`trusted_skipped` 和 `header_warnings`。存取日誌中的 `ip_source`、`ip_skipped`、`ip_warnings` 也可用於排障；儲存配置後需要重啟。

### 429 請求過多

- 按回應 `Retry-After` 退避；檢查是否共享了代理 IP，配置可信代理後按真實客戶端 IP 計數。
- 登入、TOTP、密碼重置、備份下載、私鑰匯出、ACME 協議等都有獨立限流；不要透過提高閾值掩蓋暴力破解或腳本失控。

### 通行金鑰不可用

- 必須透過 HTTPS 網域或 localhost 訪問；IP 地址不能作為 WebAuthn 來源。
- 檢查瀏覽器是否支援 WebAuthn、系統是否啟用生物識別/PIN；通行金鑰不能替代密碼，丟失裝置時使用密碼 + TOTP 或其他恢復路徑。

## 證書簽發失敗

### DNS-01 驗證失敗

| 可能原因 | 檢查 |
| --- | --- |
| 憑據無權限 | API Key 是否有目標 Zone 的讀寫權限 |
| 網域/Zone 不匹配 | 網域是否在當前帳號可見的 Zone 內 |
| TXT 傳播慢 | 等待 TTL；檢查權威 DNS 是否返回 TXT |
| 多級網域/CNAME | 確認 `_acme-challenge` 的解析路徑 |
| 萬用字元 | 萬用字元必須使用 DNS-01 |
| 服務商限制或代理 | 配額、頻率限制；自訂 API 地址是否可達、證書是否受信 |

處理：

1. 在任務日誌中檢視具體 DNS 服務商錯誤。
2. 用 `dig`/`nslookup` 檢查 `_acme-challenge.<domain>` 的 TXT，並用同一憑據在服務商控制台手動建立/刪除 TXT 確認權限。
3. 檢查 CA 的 CAA 記錄是否允許該 CA；修正後重新執行任務。

### CA 速率限制/EAB 錯誤

- Let's Encrypt 等公共 CA 有帳戶、網域、失敗驗證等速率限制；檢視 CA 狀態頁和錯誤詳情。
- ZeroSSL、Google Trust Services、LiteSSL、零信 ZoTrus、Actalis、SSL.com 需要 EAB；確認 EAB KID/HMAC 正確且未過期（零信 ZoTrus 的 KID 為註冊信箱）。
- 零信 ZoTrus 的 dns-01 記錄名由服務端 `tokenPath` 決定（通常形如 `_<tokenPath>.<domain>`），不是標準的 `_acme-challenge`。使用零信的任務執行後會進入「等待 DNS 驗證」，請在任務日誌或「DNS 驗證」面板新增記錄後點擊「繼續驗證」。零信暫不支援萬用字元、CA 調度群組與目標流程 Beta。
- 通用 ACME 上游目錄必須是 HTTPS（本機迴環除外）；為關鍵網域準備備用 CA，避免單一 CA 限流導致全部失敗。

### 證書簽發成功但瀏覽器不信任

- 公共 CA 證書應受信任；檢查是否部署了完整鏈（fullchain）。
- 私有 CA 證書需要把根 CA 安裝到客戶端信任庫。
- 檢查是否部署了錯誤的證書/私鑰配對，以及 SNI、網域、證書 SAN 和系統時間是否匹配。

### 私有 CA 簽發失敗

- 確認 CA 未過期、具備簽發用途、路徑長度允許下級 CA。
- 確認證書有效期不超過 CA 到期時間；匯入的 CA 必須證書與私鑰匹配，且具備 CA 基本約束；刪除 CA 前先刪除下級 CA。

## 部署失敗

### SSH/SFTP

| 現象 | 原因 | 處理 |
| --- | --- | --- |
| 主機指紋不匹配 | 伺服器更換金鑰或配置錯誤 | 核對指紋；清空舊指紋重新記錄 |
| 首次連線被拒絕 | 未填寫指紋且未開啟 TOFU | 填寫 `SHA256:...` 或顯式開啟首次信任 |
| 認證失敗 | 使用者名稱/密碼/私鑰錯誤 | 檢查憑據和目標 SSH 配置 |
| 路徑無權限 | 部署使用者無寫權限 | 調整目錄權限或使用有權限的使用者 |
| 過載命令失敗 | 命令不存在/權限不足/服務名錯誤 | 在目標主機手動執行驗證 |

### 本地目錄

- 執行使用者對目標目錄無寫權限，或路徑不存在（需要預先建立目錄）；也可能是 SELinux/AppArmor 限制。
- 過載命令失敗，但證書檔案已更新；檢查服務是否實際載入新檔案。

### 面板/CDN/Webhook

- 憑據過期、權限不足或 API 版本不匹配；部署引數（站點、網域、證書名稱）與目標系統不一致。
- 目標系統開啟了 IP 白名單，未放行 LACTSSL 出口。
- Webhook 公網目標必須 HTTPS；迴環/私網允許 HTTP。
- 部署類別/目標未啟用，或第三方 helper 校驗失敗。

### 證書更新了但目標仍使用舊證書

- 部署節點未配置過載命令，或命令未生效。
- 目標系統有快取（CDN、WAF、負載均衡），或部署到了錯誤路徑/站點。
- 多例項部署只更新了其中一臺；檢查證書序列號/指紋是否與目標系統一致。

## 通知與監控

### 通知未送達

- 渠道是否在「外掛」頁的通知標籤啟用，通知頁面是否啟用；Token/Webhook 是否過期，目標是否可達。
- SMTP 是否使用隱式 TLS；伺服器不支援 STARTTLS 時會拒絕傳送。
- 任務通知節點是否啟用，觸發時機是否匹配；檢查操作日誌/系統日誌中的傳送錯誤（敏感值會脫敏）。

### 站點監控誤報

- 監控會校驗主機名和系統信任鏈；自籤、鏈不完整、主機名不匹配都會標記異常。
- 檢查目標埠、SNI、系統 CA 信任庫和時間；負載均衡後面的不同節點可能返回不同證書，確認監控目標穩定，並設定合理的頻率和超時。

### 沒有收到到期提醒

- 任務自動續期是否開啟，`RenewDays` 是否合理。
- 排程器是否執行（日誌中檢視排程記錄），通知渠道是否可用，證書是否已被清理或任務引用被清空。

## 外掛問題

| 現象 | 原因 | 處理 |
| --- | --- | --- |
| 部署/通知目標缺失 | 類別或條目未啟用 | 在「外掛」頁啟用類別和具體條目 |
| helper 上傳失敗 | 簽名、SHA-256、協議、`min_host` 不匹配 | 檢視錯誤詳情；核對公鑰、摘要和版本 |
| 啟用後服務商不出現 | 條目未生效或未重掃 | 重啟或點選「重掃外掛」 |
| 外掛被拒絕載入 | 組/其他使用者可寫、符號連結、摘要變化 | 修正權限或重新上傳 |
| 舊外掛遷移失敗 | 舊 helper 佔用/檔案衝突 | 按遷移提示處理，失敗會回滾 |
| 部署外掛不可用 | `deploy_plugins.enabled: false`（被顯式關閉） | 改為 true 並重啟 |
| 通知渠道缺失 | 渠道未啟用 | 在「外掛」頁通知標籤啟用 |

外掛目錄：

```text
data/plugins/dns
data/plugins/deploy
data/plugins/notify
```

權限要求：目錄 `0700`，helper `0755`，屬主為服務執行使用者。

### 匯入信任鏈後外掛仍提示 TLS 校驗失敗

先根據具體提示判斷原因：

- **證書已過期或尚未生效**：續簽或更新目標證書；匯入 CA 不能延長證書有效期。
- **證書與訪問地址不匹配**：改用證書 SAN 中的網域訪問；用 IP 訪問時證書必須包含對應的 IP SAN。
- **證書不受信任**：確認匯入的是簽發該證書的 CA 公鑰（根 CA 或中間 CA），而不是站點葉證書；一次匯入 PEM 可包含多張 CA，匯入後無需重啟。
- 其他情況：用 `openssl s_client -connect host:port -servername host -showcerts` 檢查目標實際返回的證書鏈是否完整。

外掛子程序透過 `SSL_CERT_FILE` 讀取 `<data_dir>/trusted-ca-bundle.pem`；信任鏈會合併系統根證書、匯入的 CA 與私有 CA，只有確實受控的內部 CA 才應匯入。

## 備份與恢復

### 備份下載失敗

- 需要重新輸入當前密碼；啟用 TOTP 時還需動態驗證碼；備份密碼至少 12 位。
- 反向代理請求體/回應體限制，或磁碟空間不足；檢查操作日誌和系統日誌。

### 恢復後無法解密憑據

- 備份中的 `config.yaml` 與資料庫不配套，`salt` 不同；或只恢復了資料庫、丟失了配置。
- 解決：使用完整 ZIP 備份恢復，不要單獨替換資料庫。

### 恢復後登入不上

- 使用備份中的管理員帳戶，並重新登入（會話可能已清空）。
- 門禁入口可能已變化，檢視啟動日誌；`jwt_secret` 不同會導致舊令牌失效。
- 恢復包在 `data/restore-pending/`，檢查是否已應用。

### 恢復後服務未自動拉起

- Docker 確認 `restart: unless-stopped`；systemd 確認服務已啟動；直接執行二進位制需手動重啟。檢查啟動日誌中的配置校驗錯誤。

## 資料庫、磁碟與記憶體

### 資料庫變大

- 證書、任務日誌、操作日誌、系統日誌、ACME 訂單都會增長。
- 使用證書一鍵清理、ACME 診斷清理、系統日誌清空。
- 在低峰期執行 `/upgrade` 的“僅最佳化資料庫與配置”，必要時開啟 VACUUM；檢查 WAL 大小，最佳化工具會執行 `wal_checkpoint(TRUNCATE)`。

### 磁碟不足

- 檢查 `data/`、日誌、`upgrade-backups/`、備份檔案，清理舊升級快照和舊二進位制備份。
- 確認備份沒有寫回同一資料目錄。
- VACUUM 需要臨時空間，磁碟不足會失敗。

### 記憶體高/被 OOM

- 主程序空閒基線約幾十 MB；外掛是一次性子程序，受 `memory_limit_mb` 限制。
- 上傳/更新解包、多任務併發會同時拉起多個 helper，產生瞬時峰值；檢查容器記憶體上限是否過低，為峰值留餘量，降低併發或調低 helper 記憶體限制，但要確保外掛能正常工作。

### 資料庫鎖/寫入失敗

- 確認只有一個例項掛載資料目錄，不要把 SQLite 放在多寫共享儲存上。
- 檢查磁碟滿、權限、檔案系統只讀；備份/恢復期間避免大量併發任務。

## 升級與遷移

### 啟動時遷移失敗

- 檢視日誌中的失敗步驟，檢查磁碟、權限、資料庫完整性。
- 修復後直接重啟重試；遷移步驟冪等，不會推進失敗版本號，也不要手動刪除 `upgrade.schema_version`。

### 升級後頁面不可用

- 檢查反向代理/靜態資源快取，強制重新整理或清理 CDN 快取。
- 檢查二進位制/映象版本是否匹配，並檢視啟動日誌和瀏覽器控制台。

### 程式自升級被拒絕

- 只讀檔案系統、`dev` 構建、無釋出包平臺、缺少校驗和/簽名都會拒絕。
- 容器內升級不改變映象，使用映象標籤升級；檢查 GitHub API 速率限制和出站代理。

## ACME 服務端排障

| 客戶端錯誤 | 可能原因 | 處理 |
| --- | --- | --- |
| `badNonce` | 服務重啟或 nonce 過期 | 客戶端自動重試；檢查是否多例項共享 |
| `unauthorized` | 帳戶/JWS 錯誤、EAB 缺失 | 檢查 EAB、帳戶金鑰、端點 |
| `rejectedIdentifier` | 網域不在白名單 | 檢查端點網域白名單 |
| `caa` | CAA 不允許該 CA | 調整 CAA 或換 CA |
| `orderNotReady` | 挑戰未完成 | 完成授權後 finalize |
| `rateLimited` | 觸發端點限流 | 按 `Retry-After` 退避 |
| HTTP-01 失敗 | 目標不可達/私網被拒絕 | 檢查 CIDR 白名單、埠、路由 |
| mTLS 失敗 | 客戶端證書不受信 | 檢查 `mtls.client_ca` 和客戶端證書鏈 |
| 資源 URL 錯誤 | `base_url` 未配置 | 配置固定 `acme.base_url` |

診斷：在「ACME 診斷」檢視帳戶、訂單、授權、挑戰和證書，檢查 `acme.base_url`、端點白名單、EAB、挑戰型別。公網部署不要依賴請求 Host 推導 URL；CRL/OCSP 端點按 CA 組織，確認客戶端可訪問。

## 應急處理

### 懷疑 API 金鑰洩露

1. 在「API 金鑰」頁面停用或刪除該金鑰，建立新金鑰並更新呼叫方。
2. 檢查操作日誌中的異常呼叫、部署和私鑰下載。
3. 如涉及部署目標，輪換對應憑據；記錄事件並覆盤。

### 懷疑管理員帳戶洩露

1. 立即修改密碼；這會刪除全部會話、API 金鑰和通行金鑰。
2. 檢查恢復郵箱是否被篡改，並檢查操作日誌、系統日誌和反向代理日誌。
3. 輪換 DNS/部署/通知憑據。
4. 如懷疑 `salt` 洩露，按金鑰洩露流程處理，必要時重建例項並重新錄入憑據；評估是否需要重新簽發受影響證書。

### 證書被錯誤部署/覆蓋

1. 暫停相關任務，避免繼續覆蓋。
2. 從目標系統備份或證書歷史恢復上一版；檢查任務部署節點引數和過載命令，重新部署正確證書並驗證序列號/指紋，記錄根因並補充部署前校驗。

### ACME 端點被濫用

1. 停用端點或關閉 `acme.enabled`。
2. 檢查帳戶、訂單和來源 IP。
3. 開啟 EAB、mTLS 或網路 ACL，清理異常帳戶和訂單；評估是否簽發過非預期證書。
