# 管理工作台

本文面向部署和维护 LACTSSL 的开发者，说明账户、权限、密钥、审计和日常维护方式。产品当前是**单管理员 + API 密钥分权**模型。

## 运营模型

### 三类身份

| 身份 | 能力 | 适用对象 |
| --- | --- | --- |
| 管理员账户 | 浏览器登录后可执行全部操作，包括导出私钥、恢复备份、修改设置 | 平台负责人 |
| API 密钥 | 按 `资源:动作` 授权，适合自动化和只读集成 | CI/CD、巡检、CMDB、部署脚本 |
| ACME 客户端账户 | 仅访问某个 ACME 端点，按 EAB/域名白名单限制 | certbot、lego、acme.sh 等 |

管理员账户是单点，应由固定负责人持有。API 密钥不能替代人工确认，也不能访问账户安全类接口（改密、通行密钥、会话管理等）。

### 建议的职责分离

| 职责 | 建议归属 | 是否使用管理员账户 |
| --- | --- | --- |
| 日常证书签发与部署 | 平台/运维 | 是，或使用受限 API 密钥 |
| DNS/部署凭据保管 | 对应系统负责人 | 否，凭据由管理员录入后按需轮换 |
| 自动化集成 | 集成开发 | 否，使用独立 API 密钥 |
| 安全审计 | 安全/审计 | 否，使用 `logs:read` / `system_logs:read` 只读密钥 |
| 备份恢复 | 运维负责人 | 是，恢复会重启服务 |
| 插件与升级 | 平台负责人 | 是，属于高权限变更 |

## 初始化与交接

### 初始化

1. 使用启动日志中的门禁入口进入，用一次性初始化令牌创建管理员。
2. 立即启用 TOTP 或通行密钥，设置并验证恢复邮箱。
3. 配置 `security.public_url`、可信代理和日志。
4. 创建第一份加密备份，确认恢复密码可用。
5. 启用所需插件类别和对应条目。

### 负责人交接

交接时至少完成：

- 管理员密码、TOTP 种子或通行密钥设备，以及恢复邮箱控制权的移交。
- API 密钥与 DNS/部署/通知凭据清单核对：用途、权限、过期时间、责任人。
- 备份位置、恢复密码和最近一次恢复演练记录，以及未完成任务、监控项和告警路由说明。

不要通过聊天工具传递明文密码、API 密钥或备份密码；使用密码管理器或密封交接流程。

## 账户安全

### 登录方式

- 密码使用 bcrypt 哈希存储，至少 8 位，生产建议 16 位以上随机密码；TOTP 启用后密码登录仍需动态验证码，同一验证码在有效窗口内不能重复使用。
- 通行密钥（WebAuthn/Passkey）是额外登录方式，不替代密码，必须通过 HTTPS 域名或 localhost 使用。
- 修改密码会提升令牌版本并删除全部服务端会话、API 密钥和通行密钥；邮箱重置密码会同时关闭 TOTP、删除通行密钥和 API 密钥。

### 会话

- 会话保持默认开启，后台重启后保留会话；设为 `security.session_persistence: false` 则每次重启清空。
- 在「设置 → 会话」中定期检查并撤销未知设备；已登录会话等价于管理员权限，不要在共享或不可信设备上保持登录。
- 在「设置 → 安全提醒」中保持核心凭据变更提醒开启，按需开启新设备登录和登录失败聚合（默认 5 次 / 10 分钟）；换邮箱会同时通知新旧邮箱，修改通知目标会通知旧收件人和旧渠道。每小时提醒默认最多 10 条，仅限制登录/失败等高频提醒，关键凭据变更和新设备登录不受上限影响；「最近安全事件」可查看逐目标投递状态并导出 JSON。
- 安全提醒与证书通知开关独立，不要用关闭证书通知的方式关闭安全提醒；插件渠道会收到登录 IP、设备和账户邮箱，只勾选可信渠道。

### 恢复路径

至少准备两条独立恢复路径：**邮箱重置**（忘记密码但邮箱可控，会清除 TOTP、通行密钥和 API 密钥）和**备份恢复**（账户、数据库或配置损坏，需要备份解密密码和未初始化实例的初始化令牌）。把恢复流程写成 Runbook 并定期演练，不要把恢复密码与备份文件放在同一位置。

## API 密钥治理

API 密钥适合机器身份，不适合人，建议按“一个系统一把钥匙”管理。

### 角色到权限的映射

| 使用方 | 建议权限 | 说明 |
| --- | --- | --- |
| 只读巡检/CMDB | `system:read`、`dashboard:read`、`certificates:read`、`tasks:read`、`monitors:read`、`deployments:read` | 不授予任何 `*:write` |
| 证书清单同步 | `certificates:read`、`tasks:read` | 不授予私钥权限 |
| CI/CD 触发续期 | `tasks:read`、`tasks:run`；如含部署节点再加 `deploy:execute` | 按任务范围控制 |
| 证书下载与分发 | `certificates:read`、`certificates:key`、`deploy:execute` | 高敏感，必须限制来源和过期时间 |
| 日志审计 | `logs:read`、`system_logs:read` | 只读密钥，设置短期过期 |
| 监控告警 | `system:read`、`monitors:read` | 用于 `/api/status` 和监控读取 |
| 平台自动化 | 按实际需要组合，避免 `*` | `*` 等价于全部系统能力 |

### 生命周期

1. 登记用途、责任人、权限和过期时间，创建后立即写入密码管理器或密钥管理系统，在调用方配置并验证最小权限。
2. 到期前轮换，旧令牌立即失效；系统下线或人员变更时立即停用/删除。

### 防护要求

- 不把密钥放在日志、截图、工单或公开仓库，只在 HTTPS 上传输，并为密钥设置来源 IP 限制（优先使用密钥自带的 IP/CIDR 白名单，并在网关层做纵深防御）。
- 定期检查 `api_keys:read` 权限的密钥，防止权限蔓延；怀疑泄露时立即轮换或删除，并检查操作日志中的异常调用。

> API 密钥不能修改密码、绑定通行密钥或退出其他会话；这些操作只允许浏览器登录会话。

## 证书与 CA 治理

### 公共 CA

- 为 ACME 账户使用专用邮箱，不要绑定个人邮箱；按 CA 维护 EAB 凭据并限制可访问范围，关注 CA 的速率限制和域名验证要求，为关键域名准备备用 CA；通用 ACME 上游必须使用 HTTPS（本机回环除外）。

### 私有 CA

- 根 CA 私钥只用于签发中间 CA，不建议直接签发终端证书；中间 CA 配置路径长度、Key Usage、Name Constraints 和有效期，导出后根 CA 私钥应离线保管。数据库中的私钥受 `security.salt` 保护，但不是 HSM。
- 删除 CA 前确认没有下级 CA 和依赖证书；存量证书不会自动获得 CRL/OCSP 扩展，需要重新签发。

### ACME 服务端

- 每个端点绑定一个私有 CA，并配置域名白名单；生产默认开启 EAB，关闭后任何能访问端点的人都能创建账户。
- 公网端点使用独立端口、来源限制和 mTLS（如客户端支持）；定期清理失效订单和长期未使用账户，清理账户会删除历史订单但不影响已签发证书。

## 插件与供应链

- 生产只使用随主程序发布的官方实现，或上传经审查的 helper；配置 Ed25519 公钥并强制验签，未配置时 UI 会提示风险且跳过无人值守自动更新。生产关闭自动更新，按变更窗口手动升级；部署插件会接触证书私钥，默认开启，只启用可信 helper 并保持最小启用范围。
- 插件目录 `0700`、helper `0755`，属主为服务运行用户；保留插件版本、安装时间和变更记录，便于回滚。详细流程见[插件治理](plugins.md)。

## 审计与证据

| 日志 | 内容 | 用途 |
| --- | --- | --- |
| 操作日志 | 任务、证书、部署、通知、监控、设置变更 | 操作审计、变更追踪 |
| 系统日志 | 启动、HTTP、调度、插件、ACME 等进程日志 | 运行排障、安全事件分析 |
| 进程日志 | stdout 或 `log.file` | 日志平台采集、panic 分析 |

- 操作日志保留至少 90 天（导出范围上限），需要更长保留时定期导出到外部日志系统；系统日志默认保留 7 天或 20,000 行，按需调整 `log.system.retention_days` 和 `max_rows`。
- 反向代理访问日志独立保存，记录来源 IP、状态码和 `X-Request-ID`；导出 CSV 时注意公式注入防护，不要把含凭据的日志外发。
- 关键变更（CA 生成、私钥导出、备份恢复、插件安装、门禁入口修改）应有变更单或工单关联。

## 日常运营清单

### 每日

- [ ] 查看任务失败、部署失败和证书异常告警。
- [ ] 确认备份任务成功（如由外部调度），检查站点监控中的异常/临期项。

### 每周

- [ ] 检查即将到期证书和自动续期状态。
- [ ] 核对新增/停用的 API 密钥和凭据，查看系统日志中的错误、限流和异常登录。

### 每月

- [ ] 检查磁盘、数据库大小、WAL 和日志保留。
- [ ] 检查插件版本和安全公告，抽查操作日志与变更记录是否一致。

### 每季度

- [ ] 完成一次备份恢复演练，检查管理员账户、恢复邮箱和 TOTP/通行密钥。
- [ ] 复核 API 密钥权限和过期时间，评估升级窗口和回滚方案。

## 变更管理

高风险操作建议走变更单：

| 操作 | 风险 | 建议控制 |
| --- | --- | --- |
| 修改门禁入口 | 可能锁死管理入口 | 记录新入口，保留 `config.yaml` 覆盖方式 |
| 修改 `security.salt` | 已有加密凭据无法解密 | 禁止随意更换；必须配套迁移 |
| 删除私有 CA | 影响下级 CA 和依赖证书 | 先确认依赖，导出备份 |
| 恢复备份 | 覆盖当前数据并重启 | 二次确认，选择低峰期 |
| 安装部署插件 | 可读取证书私钥 | 来源审查、签名校验、最小权限 |
| 程序升级 | 数据迁移不可逆 | 备份、预发验证、回滚计划 |
| 批量清理证书/日志 | 数据不可恢复 | 先预览、导出、二次确认 |
