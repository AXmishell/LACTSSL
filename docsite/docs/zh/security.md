# 安全基线

本文面向部署和集成 LACTSSL 的开发者，说明 LACTSSL 的安全模型、已实现的控制，以及上线前的加固清单。

## 安全模型与信任边界

LACTSSL 按“自托管单实例”设计，信任边界如下：

```text
[不可信] 互联网/外部网络用户
    │ HTTPS（反向代理终止）
[边界] 反向代理 / WAF / 网络 ACL
    │ HTTP（回环或内网）
[可信] LACTSSL 进程
    ├─ 管理员会话：等同完全控制
    ├─ API 密钥：按权限范围受限
    ├─ 私有 CA 私钥：加密存储在本地数据库
    └─ 插件子进程：以服务账号运行，视为受信代码
[外部] DNS API / CA / SMTP / 部署目标 / 通知渠道
```

关键结论：

- **管理员会话等价于完全控制**，包括执行本地部署命令、导出私钥和恢复备份。
- **API 密钥是机器身份**，用于降低自动化场景的权限，不是多用户 RBAC。
- **插件是受信代码**，尤其是部署插件会接触证书私钥，供应链安全由部署方把关。
- **数据库和 `config.yaml` 同等敏感**；丢失 `salt` 会导致加密凭据不可用，泄露则可能导致凭据被解密。

## 身份与访问控制

### 管理员账户

- 单管理员账户，不提供多用户或 RBAC；密码使用 bcrypt 哈希存储，至少 8 位，生产建议 16 位以上随机密码。
- 支持 TOTP 两步验证和通行密钥（WebAuthn/Passkey）。启用 TOTP、注册通行密钥必须现场再认证（当前密码，启用 TOTP 时还需动态验证码），避免失窃会话把账号绑定到攻击者的认证器；一次再认证成功后 5 分钟内可连续执行敏感操作，改密、改邮箱、TOTP/通行密钥变更仍要求现场验证。
- 通行密钥必须通过 HTTPS 域名或 localhost 使用，直接使用 IP 地址不能作为 WebAuthn 来源；使用通行密钥登录后不再要求 TOTP。
- 修改密码会提升令牌版本并删除全部服务端会话、API 密钥与通行密钥；通过邮箱重置密码会同时关闭 TOTP、删除通行密钥与 API 密钥，必须确保恢复邮箱本身安全。
- 密码、邮箱、TOTP、通行密钥、API 密钥和通知目标变更会发送安全提醒，换邮箱同时通知新旧地址；新设备登录默认 30 天窗口内只提醒一次，登录失败默认 5 次 / 10 分钟聚合、1 小时内最多一次。
- 安全提醒默认只走邮件，插件渠道需管理员显式勾选，勾选后登录 IP、设备和账户邮箱会发送到第三方；修改安全提醒策略会使用旧 SMTP 配置快照向旧收件人和旧渠道发送提醒。
- 安全提醒有每小时上限（默认 10 条），仅限制登录成功/失败等高频提醒，核心凭据变更和新设备登录不受影响；设置页可查看最近事件的逐目标投递状态。安全提醒不能替代邮箱自身的 MFA、强密码和转发规则检查。

### API 密钥

- 密钥为 86 位 Base64URL 随机串（64 字节熵），不含固定前缀，服务端只保存 SHA-256 摘要；权限按「资源:动作」划分，`*` 表示全部系统 API 能力。
- 敏感权限单独列出：`certificates:key`、`private_cas:key`、`deploy:execute`、`deploy:command`、`plugins:write`、`settings:write`、`api_keys:write`、`monitors:internal` 等。
- 导出/恢复备份、修改门禁入口、数据库切换和账户安全类操作（改密、通行密钥、会话管理）只允许浏览器登录会话，API 密钥不能调用。
- 通过 API 密钥管理其他密钥时，不能授予自身没有的权限，也不能修改/轮换/删除权限高于自身的密钥；建议为每个自动化系统创建独立密钥，设置过期时间并定期轮换。

## 网络与 TLS

### 入站

- 管理控制台必须通过 HTTPS 反向代理访问，主程序只监听 HTTP；后端端口只监听回环或内网，不直接暴露公网。
- 在代理层配置来源 IP 白名单、VPN、零信任策略或 WAF，并配置 HSTS、TLS 1.2+、禁用弱套件；备份恢复和插件上传需要较大的请求体上限。
- 代理必须覆盖或正确追加 `X-Forwarded-For` 并传递 `X-Forwarded-Proto`；LACTSSL 只信任 `server.trusted_proxies` 中的精确 IP/最小 CIDR，多级追加链路需信任链上所有代理。
- 未配置可信代理时，所有请求会被视为来自代理 IP，导致限流失效、`Secure` Cookie 判断错误。

### 出站

服务端会主动向 DNS 服务商 API、公共 ACME CA 与通用上游、SMTP/Gotify/Telegram/钉钉/企业微信/Webhook 等通知渠道、SSH/SFTP/FTP/云 CDN/面板等部署目标，以及站点监控目标发起请求。

- 生产环境按域名或网段做 egress 白名单，只放行实际需要的目标；需要经代理时通过系统环境变量配置（Go HTTP 客户端行为）。
- 对部署 Webhook、通知 Webhook 等自定义目标做来源审查，避免把私钥或令牌发到不可信地址。
- 内网 HTTPS 目标应通过「系统设置 → TLS 信任链」导入内部 CA 公钥，而不是关闭 TLS 校验；导入的 CA 与私有 CA 会合并进 `SSL_CERT_FILE` 供插件和部署命令使用。

### SSRF 防护

- 字面量与解析后的目标地址会拒绝云元数据、链路本地、保留、文档、NAT64 等网段（如 `169.254.169.254`、`100.100.100.200`、`fd00:ec2::254`、`0.0.0.0/8`、`240.0.0.0/4`）。
- 回环与私网地址仍允许使用，便于 Gotify、自建面板、内网 Webhook 等场景；如不需要可在网络层进一步限制。
- 站点监控默认只允许公网目标，监控私网/回环需要 API 密钥额外具备 `monitors:internal`；拨号阶段会按最终解析出的 IP 再校验一次并直接连接，防止 DNS rebinding。
- 部署 Webhook 会携带证书私钥，公网目标强制使用 `https://`；回环、私网、`.local`、`.internal` 目标允许 HTTP。第三方请求失败写入日志前会脱敏 URL 路径与查询参数，避免 bot token、SendKey 等进入日志或备份。

## 门禁入口、会话与 CSRF

### 门禁入口

管理页面不直接暴露在根路径，而是先通过随机生成的入口进入：

```text
https://your-domain/<entry>/
```

- 入口默认随机生成 20 位大小写字母与数字组合，保存在数据库中；未通过入口的页面统一返回 `404`，包括裸 `/` 等常见探测路径。
- 接口固定挂在裸 `/api` 下，由登录会话或 API 密钥保护；旧版 `/<entry>/api` 保留为兼容别名。
- 访问正确入口后写入有效期为 24 小时的签名 `HttpOnly` 门禁 Cookie，服务端同时校验过期时间；入口探测有频率限制，避免被暴力枚举。
- 可在「设置 → 门禁入口」中修改，修改后立即生效，手工入口要求 8–32 位；忘记入口时可修改 `config.yaml` 的 `security.entry` 并重启覆盖，或在数据库 `settings` 表中查看。
- 系统未初始化时，启动日志会输出一次性初始化令牌；创建管理员、修改初始化配置、重启初始化进程和从备份恢复都必须携带该令牌（`X-LACTSSL-SETUP-TOKEN`），初始化成功后立即失效，服务重启后重新生成。

> 入口是额外一层防护，不能替代 HTTPS、强密码和网络访问控制。

### 会话

- 登录会话保存在 `HttpOnly` Cookie 中，前端脚本无法读取；Cookie 使用 `SameSite=Lax`，允许从邮件或外部链接直接打开控制台，写操作仍由双提交 CSRF 与 Origin 校验保护。
- 会话令牌使用紧凑 JWT，会话 ID 为 24 字节随机数（192 位），CSRF 令牌为 32 个字符；首次访问门禁入口或登录时会下发长期有效（1 年）的 `HttpOnly` 设备标识 Cookie（`lactssl_device`，32 个十六进制字符）。
- HTTPS 部署时会话、CSRF 与入口 Cookie 自动使用 `__Host-` 前缀，避免共享父域下的兄弟子域覆盖。
- 默认开启会话保持：启动不清空服务端会话，并使用固定 `jwt_secret` 签名，后台重启后可继续使用原会话；设置 `security.session_persistence: false` 后每次启动清空会话，并把启动随机值混入 JWT 签名子密钥。
- 修改密码会提升令牌版本并删除全部会话、API 密钥和通行密钥。

### CSRF 与跨站防护

- 所有改变服务端状态的请求（POST/PUT/DELETE 等）必须携带 `X-LACTSSL-CSRF` 请求头，且与 `lactssl_csrf` Cookie 一致；旧会话首次请求会自动补发该 Cookie，不接受仅携带请求头的降级校验。
- 登录、初始化、忘记密码和密码重置等未认证接口额外校验 `Origin`/`Sec-Fetch-Site`；显式使用 `Authorization: Bearer <token>` 调用 API 时不受 CSRF 校验约束。
- 页面响应使用每次请求随机 CSP nonce，`script-src` 不再允许任意内联脚本；样式仍允许内联以满足组件库需要。

## 密码重置与对外地址

密码重置邮件中的链接必须基于固定地址生成：

```yaml
security:
  public_url: "https://ssl.example.com"
```

- 未配置 `public_url` 时，仅允许本机回环地址且 Host 为 `localhost`/回环 IP 的请求按当前 Host 推导链接，其他请求调用“忘记密码”会被拒绝。
- 不信任客户端可伪造的 `X-Forwarded-Host`；反向代理场景必须配置 `public_url`，避免攻击者伪造 Host 把含 token 与门禁入口的重置链接指向自己的域名。

## 凭据与数据保护

### 加密

- DNS 凭据、部署凭据、SMTP 密码、通知 Token、TOTP 密钥、私有 CA 私钥和证书私钥等敏感字段使用 AES-256-GCM 加密后写入数据库，旧版本明文数据会在启动时自动迁移；加密密钥来自 `config.yaml` 的 `security.salt`。
- JWT 使用 `security.jwt_secret` 签名，实际使用由 `jwt_secret` 与启动随机值经 HKDF 派生的独立子密钥，与数据库 AES-GCM 密钥分离；`security.jwt_secret` 和 `security.salt` 手动配置时至少 32 个字符，过短会拒绝启动。
- 接口返回配置时会对密钥字段脱敏，编辑时留空表示保留原值。

### 文件与备份

- `config.yaml` 保持 `0600`，`data/` 保持 `0700`，属主为服务运行用户；数据库、WAL、插件、日志和升级备份都位于 `data/` 下。
- 下载备份时必须设置至少 12 位的加密密码，备份包使用 PBKDF2-HMAC-SHA256（600,000 次迭代）+ AES-256-GCM 加密，包含数据库、配置和版本信息，按机密文件管理。
- 恢复包会先完整校验配置（密钥长度、门禁入口、监听地址、TLS/mTLS 组合等），非法配置会被拒绝；首次初始化成功后会清理尚未应用的恢复包，防止暂存内容在后续重启时覆盖新账户。

### 凭据轮换

- DNS/部署/通知凭据使用专用账号，定期轮换。
- SSH 默认要求填写主机指纹，只有显式开启“首次连接自动信任主机密钥”时才采用 TOFU，后续指纹不一致会拒绝连接。
- FTP 部署默认使用显式 TLS，只有明确选择 `none` 才使用明文 FTP。
- API 密钥设置过期时间，按系统独立发放，泄露时立即轮换。

## 审计与日志

| 日志 | 内容 | 保留/导出 |
| --- | --- | --- |
| 操作日志 | 任务、证书、部署、通知、监控、设置变更 | 可按来源/级别/时间筛选，导出最近 90 天 CSV/JSON；删除前写入归档 |
| 系统日志 | 启动、HTTP、调度、插件、ACME | 默认 7 天/20,000 行，可调整和清空；删除前写入归档 |
| 日志归档 | 操作日志/系统日志的原始 NDJSON 与 manifest | `data/archives/logs/`，默认永久保留；可在「日志 → 归档」下载或删除 |
| 进程日志 | stdout 或 `log.file` | 按大小/天数轮转，可输出 JSON |
| 反向代理日志 | 访问、来源 IP、状态码 | 由外部日志系统管理 |

- 将操作日志、系统日志和归档文件定期导出到 SIEM 或日志平台，避免管理员清空、删除归档或数据损坏导致审计缺失；操作日志与系统日志共用 `logs` 表但按 `category` 隔离，清空系统日志不会删除操作日志。
- 每个响应带 `X-Request-ID`，可用于关联访问日志、panic 和错误；访问日志不记录查询参数、请求体和认证头，门禁入口在路径中统一替换为 `:entry`。
- 日志与归档文件可能包含客户端 IP、域名、错误详情和操作者信息，按运维数据管理；归档文件权限为 `0600`，目录为 `0700`，但不属于不可篡改审计；如需防篡改审计，可同步到外部 WORM 存储或 SIEM。

## 插件与供应链安全

- 官方插件已编译进主程序，随发布包签名/镜像摘要分发；上传插件默认在 Linux Landlock/rlimit 沙箱中执行，并对 manifest 探测与每次调用复核摘要。宿主仍以 root 运行且未设置 `LACTSSL_RUN_UID`/`LACTSSL_RUN_GID` 时，上传插件会被拒绝执行。
- 官方发布构建会自动内置 `upgrade.program.public_key` 并默认强制校验发布签名；自编译版本未配置时拒绝在线升级，只有受控环境可显式开启 `upgrade.program.allow_unsigned`。
- 资产必须提供 64 位十六进制 SHA-256，下载后强制校验；安装时校验 `plugin.json`、manifest 中的 ID 与版本，任一步失败都会回滚。
- 安装记录中的文件摘要会在发现、注册和每次 DNS/部署/通知调用前复核，文件被替换时拒绝加载或执行；未配置签名公钥时会显示风险提示，且跳过无人值守自动更新。
- 插件目录权限 `0700`，helper `0755`，不允许组或其他用户写入，符号链接会被拒绝；部署插件会接收证书私钥，默认开启，只应启用可信来源并保持最小启用范围。
- 主程序限制 helper 的超时、常驻内存与输出大小，并在错误信息中脱敏凭据与私钥。生产建议使用内部镜像、固定版本并关闭自动更新，记录插件来源、版本、摘要、审核人和回滚版本，先在预发环境验证升级。

## ACME 服务端安全

- 内置 ACME 服务端默认开启，但在创建并启用端点前不会对外签发证书；启用后提供独立的协议入口，不使用管理端门禁入口、会话 Cookie 或 CSRF 校验，不需要时可将 `acme.enabled` 设为 `false`。
- 公网部署建议使用独立端口，并在防火墙或反向代理层限制访问；每个端点必须配置域名白名单，启用时白名单为空会被拒绝。
- EAB 可开关，默认建议开启。关闭后任何能访问该端口的人都可以创建账户，必须配合域名白名单、mTLS 或网络 ACL；mTLS 是传输层门禁，不能替代 ACME 的 JWS 账户认证。
- `acme.base_url` 应配置为固定公网地址，避免 Host 头注入导致资源 URL 指向错误位置；启用 ACME 时建议固定 `acme.base_url`（或 `security.public_url`），公网部署不应依赖按请求 Host 推导的回退。
- HTTP-01 验证默认拒绝回环、私网、链路本地及 CGNAT/保留网段（如 `100.64.0.0/10`、`192.0.0.0/24`），内网场景需通过端点级 CIDR 白名单显式放行。
- ACME 协议资源使用随机公开 ID，不使用数据库自增 ID；自定义 ACME 上游目录地址必须使用 HTTPS，只有本机回环允许 HTTP。
- 单实例部署使用内存 nonce，服务重启后客户端会收到 `badNonce` 并自动重试；限流会读取 `server.trusted_proxies` 中的可信代理，并按真实客户端 IP 计数。
- CRL 与 OCSP 端点位于 `/pki/{ca}/...`，通常需要公网可达，按 CA 组织并按 IP 限流；即使停用 ACME 报名端点也应保持可用。CRL 会缓存相同吊销集合的结果，只有吊销内容变化时才递增 CRL Number。
- CRL/OCSP 只对主动检查吊销状态的客户端生效，浏览器对私有 CA 的检查行为不一致；存量证书需要重新签发才能带上 CRL/OCSP 地址。吊销状态保存在独立的 `revocations` 表中，删除或清理证书行不会抹掉吊销记录。
- 签发叶子证书前会校验 CA 的 `ExtKeyUsage`（必须包含 `serverAuth` 或 `any`）与 NameConstraints（Permitted/Excluded DNS·IP），任务签发与 ACME finalize 共用同一套校验。

## 部署与容器加固

- 使用独立用户运行服务，`config.yaml` 保持 `0600`，数据目录保持 `0700`；不要把 `data/`、`config.yaml` 提交到版本库或放入公开目录。
- Docker 镜像通过入口脚本修正卷权限后，使用非 root 的 `lactssl` 用户运行；Compose 默认丢弃全部 capabilities 后按需添加 `CHOWN`/`SETUID` 等，并启用只读根文件系统、`/tmp` tmpfs、`pids_limit` 与 `init`。
- 服务默认限制普通接口请求体为 2 MiB（备份恢复和插件上传除外），并设置读写超时；反向代理层也建议配置请求体大小和超时。
- 生产固定镜像/二进制版本，定期扫描镜像漏洞并关注发布安全公告；使用 80/443 等特权端口时优先由反向代理转发，不要给二进制额外 capability。

## 已知限制

- 不提供多用户和 RBAC，管理员会话是单点；不提供 SSO、LDAP、OIDC、SAML、SCIM。
- 不提供 HSM/KMS，私钥在本地数据库中加密存储；不提供双活集群，SQLite 单写，不能多实例共享数据目录。
- 不提供不可篡改审计，管理员可以清空日志或删除本地归档；如需防篡改审计，应外部归档并启用 WORM/保留锁。
- 不提供 Prometheus 指标端点，监控依赖日志、认证 API 和外部探测；也不提供部署目标侧的自动回滚，需目标系统保留旧版本或使用原子发布。

## 上线安全检查清单

### 身份

- [ ] 管理员使用强密码，启用 TOTP 或通行密钥；恢复邮箱受控并启用 MFA。
- [ ] 已清理未知会话。
- [ ] API 密钥按系统独立、最小权限、设置过期时间。

### 网络

- [ ] 管理入口仅 HTTPS，后端端口不直接暴露公网。
- [ ] 已配置 `trusted_proxies` 和 `public_url`，代理传递 `X-Forwarded-For`/`X-Forwarded-Proto`。
- [ ] 已配置来源限制、WAF 或零信任策略。
- [ ] 出站按目标白名单，必要时经代理。

### 数据

- [ ] `config.yaml` 0600、`data/` 0700、属主正确。
- [ ] 已生成并异地保存加密备份，备份密码与备份文件分离保管。
- [ ] 已完成一次恢复演练。
- [ ] 日志保留和导出满足审计要求。

### 插件与 ACME

- [ ] 只使用可信来源或内部镜像，配置签名公钥。
- [ ] 生产关闭自动更新，部署插件按需启用且来源已审查。
- [ ] ACME 端点配置域名白名单，生产开启 EAB。
- [ ] ACME 入口限制来源，必要时启用 mTLS。

## 安全事件响应

1. **确认范围**：是账户、API 密钥、DNS/部署凭据、插件还是主机。
2. **隔离**：撤销会话/API 密钥，停用插件，关闭 ACME 端点，必要时从网络层切断。
3. **取证**：导出操作日志、系统日志、反向代理日志，记录 `X-Request-ID`，不要先清空日志。
4. **轮换**：修改密码会清除全部会话和 API 密钥；轮换 DNS/部署/通知凭据；如怀疑 `salt` 泄露，按密钥泄露流程处理。
5. **恢复**：从可信备份恢复，验证配置与数据一致性，重新签发可能受影响的证书。
6. **复盘**：更新 Runbook、权限清单和监控规则。

具体排障步骤见[监控与排障](troubleshooting.md)，备份恢复见[运维手册](operations.md)。
