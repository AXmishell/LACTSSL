# 产品能力

本文按功能域说明 LACTSSL 能做什么、关键参数和限制，便于开发和集成。操作步骤见[快速开始](getting-started.md)、[管理工作台](administration.md)和[API 集成](api.md)。

## 能力地图

| 能力域 | 主要内容 | 典型使用方 |
| --- | --- | --- |
| 证书资产 | 公共 CA 申请、自动续期、证书详情与清理 | 平台/运维 |
| 任务编排 | 普通流程：申请 → 部署（可多个）→ 通知；目标流程 Beta：读取站点 → 证书分组 → 申请 → 部署 | 平台/运维 |
| 证书交付 | 本地目录、SSH/SFTP、FTP、Webhook、云 CDN、面板 | 平台/运维、目标系统 |
| 内部 PKI | 私有 CA 生成/导入、层级、CRL/OCSP 地址 | 安全、基础设施 |
| ACME 服务端 | 对内提供标准 ACME v2 端点 | 内部平台、设备、测试环境 |
| 监控与告警 | 外部站点证书监控、任务/部署通知 | 运维、监控 |
| 审计与恢复 | 操作日志、系统日志、加密备份 | 安全、审计、运维 |
| 集成 | API 密钥、REST API、自动化 | 集成开发 |

## 证书申请与续期

### 验证方式

- 公共 CA 申请仅使用 **DNS-01** 验证，支持单域名、多域名和通配符证书；需在「DNS 账户」中配置服务商 API 凭据，任务运行时自动创建/清理 TXT 记录。
- 私有 CA 签发不经过 ACME 验证，由系统直接签发。
- 内置 ACME 服务端支持 HTTP-01、DNS-01、TLS-ALPN-01，供内部客户端使用。

### 内置证书颁发机构

| CA | 说明 |
| --- | --- |
| Let's Encrypt | 默认公共 CA，无需 EAB |
| ZeroSSL | 需要 EAB |
| Google Trust Services | 需要 EAB |
| LiteSSL | 需要 EAB |
| 零信 ZoTrus | 需要 EAB，KID 为注册邮箱；使用手动 DNS 验证，不支持通配符 |
| Actalis | 需要 EAB |
| SSL.com | 需要 EAB，按私钥类型自动选择 ECDSA/RSA 端点 |

「公共CA」中还可以添加多个**通用 ACME 上游**：配置目录地址、ACME v1/v2 协议版本和可选 EAB，会出现在任务和默认 CA 选择列表中。自定义目录地址必须使用 HTTPS（只有本机回环允许 HTTP）；ACME v1 仅支持 DNS-01，且不支持 EAB。

### 密钥与续期

- 私钥类型：`ecdsa`（默认）、`ecdsa384`、`rsa2048`、`rsa4096`；自动续期默认在到期前 30 天触发，可按任务调整；后台调度器每 30 秒检查到期任务。
- 可勾选「不存储证书私钥在服务端」：私钥仅在签发和部署期间驻留内存，不写入数据库、不可下载；自动续期会重新签发并重新部署，普通流程需至少一个启用的部署模块。
- 任务失败可在任务日志中查看原因，凭据、域名和 CA 问题会给出明确错误；同一证书在有效期内复用，需要重新签发时使用「强制重新签发」或 API `?force=1`。
- 证书管理页支持搜索、状态筛选、按来源（任务签发、ACME 服务端、CSR 申请）筛选、详情和安全分析。
- 下载证书链、查看或下载私钥都依赖登录会话；API 下载证书链需要 `certificates:read`，查看或下载私钥还需要 `certificates:key`。
- 一键清理可按状态（已过期、已撤销或全部）、时长、签发时间、域名、颁发机构、来源和“保留每个任务最新证书”筛选；清理后相关任务的证书引用会被清空。

### 默认配置

「公共CA」支持配置 ACME 账户邮箱、默认 CA、默认私钥类型、默认续期天数和各 CA 的 EAB 凭据。

### 目标流程 Beta

目标流程 Beta 适合「证书跟随面板网站」的场景：先通过部署插件的 `plan` 能力读取目标中的真实网站和绑定域名，再按策略分组申请证书，最后部署回对应网站。

- 任务页用「全部 / 普通流程 / 目标流程 Beta」标签分离两种流程；支持多个站点来源，网站清单来自目标系统。
- 证书分配策略：智能推荐、一站点一证书、按主域名合并、全部选中站点合并为一张证书、每个目标来源一张证书、自定义分组。
- 支持站点勾选、域名包含/排除规则、额外域名追加；自动续期时 `全部站点` 模式自动纳入新增站点，`仅选中站点` 模式只保留已保存的稳定站点键。
- 一个 Beta 任务可以关联多张证书，`certificates.task_id` 保留全部证书；一键清理开启「保留每个任务最新证书」时不会清理 Beta 任务的证书。

### 客户端 CSR 申请

- API 支持客户端提交 CSR，服务端作为中间环节向公共 CA 完成 DNS-01 验证并签发证书。
- 服务端不生成、不保存私钥；证书绑定 CSR 中的公钥，私钥始终由客户端持有。
- 申请异步执行，可查询状态、取消、重试，并按申请单下载证书链；仅支持 ACME v2 公共 CA 和 DNS-01，通配符证书必须使用 DNS-01。
- 需要 API 密钥权限 `certificates:request`，并可通过 `csr.allowed_domains` 限制可申请域名。

## DNS 服务商

官方 DNS 实现已内置，覆盖约 235 个条目（含 lego v5 与兼容 ID），默认全部停用，在「插件」页按需启用。凭据在写入数据库前加密；`manual` 服务商需要人工添加 TXT 记录，不纳入自动流程；部分服务商支持自定义 API 上游地址，可用于代理或兼容网关。完整服务商列表、凭据要求和排障见[DNS 插件](dns-plugins.md)。

## 任务编排

任务由节点组成，默认流程是「申请 → 部署（可多个）→ 通知」。

| 节点 | 关键参数 |
| --- | --- |
| 申请 | 域名、DNS 账户（可自动按域名绑定跨账户）、CA、私钥类型、自动续期、提前天数 |
| 部署 | 目标凭据、证书/私钥路径、站点/域名/证书名称、重载命令 |
| 通知 | 渠道、触发时机（始终 / 仅成功 / 仅失败） |

- 节点可以启用/禁用和排序；任务可包含多个部署节点，把同一张证书交付到多个目标。
- 申请节点支持「自动按域名绑定」：一张证书可以包含来自多个 DNS 账户的域名，运行时为每个域名使用对应账户写入和清理 TXT；显式选择账户时表示该账户覆盖全部域名。
- 旧任务没有显式流程时，系统会根据原有域名、目标凭据等字段推导等效流程；升级时会把旧凭据中的部署路径、站点和域名迁移到部署节点。
- 任务列表支持表头全选和多选，可批量执行、暂停或启动自动续期；批量执行会跳过正在运行的任务，批量启停只调整调度状态。
- 上游 CA 限流时任务进入「限流等待」，按 CA 给出的恢复时间重试，不会按普通失败每 6 小时重试。

## 证书部署

「目标凭据」只保存认证与连接信息；证书路径、重载命令、部署域名、站点等参数在任务部署节点中填写，因此同一凭据可被多个任务复用。

### 内置目标

| 目标 | 凭据 | 部署参数 |
| --- | --- | --- |
| 本地目录 | 无 | 证书/私钥路径，可选重载命令 |
| SSH / SFTP | 主机、端口、用户名、密码或私钥、主机指纹 | 远程证书/私钥路径，可选远程重载命令 |

SSH 默认要求填写目标主机指纹（`SHA256:...`）。只有显式开启“首次连接自动信任主机密钥”时才采用 TOFU 记录；后续指纹不一致会拒绝连接。

### 插件目标

FTP / FTPS（普通 FTP、显式 TLS、隐式 TLS）、Webhook（回调地址、自定义认证头、是否跳过 TLS 校验）、阿里云 CDN、七牛云、宝塔面板、1Panel、雷池 WAF 等由内置部署实现提供，具体产品和参数在任务部署节点的「部署对象」中选择。

部署实现会接收证书与私钥，等同受信代码，部署类别默认开启；关闭类别时只显示本地文件与 SSH，历史凭据仍会保留。细节见[部署插件](deploy-plugins.md)。

### 内部 CA 信任链

「系统设置 → TLS 信任链」可以导入内部 CA 公钥（PEM，可同时包含根 CA 与下级 CA）。导入后，目标凭据访问内部 HTTPS 服务、证书监控都会信任这些 CA，本程序私有 CA 的证书自动加入；部署、重载命令与插件子进程通过合并后的 `SSL_CERT_FILE` 读取信任链，也兼容 `CURL_CA_BUNDLE` 与 `REQUESTS_CA_BUNDLE`。信任链文件保存在数据目录的 `trusted-ca-bundle.pem`，也可在设置页下载。

只应导入确实受控的内部 CA，错误的 CA 会削弱 TLS 校验；移除后使用其签发证书的目标会重新变为不受信任。导入 CA 只解决“证书不受信任”，证书过期、尚未生效或与访问域名/IP 不匹配时仍需更新证书或改用匹配的地址。

### 部署记录

- 每次部署生成部署记录，可在证书详情和日志中查看结果；手动部署优先复用证书所属任务的部署节点参数，也可按目标单独填写本次参数。
- 本地/SSH 部署会执行重载命令，API 密钥必须显式拥有 `deploy:execute` 才能触发。
- 部署失败不会自动回滚目标系统上的旧证书；需要在目标侧保留上一版文件或使用原子发布机制。

## 站点证书监控

添加外部站点后，服务会定期通过 TLS 连接读取证书：

- 目标支持 `example.com`、`example.com:8443` 或完整 URL，默认端口 `443`；默认每 24 小时检查一次，可按监控项调整。
- 校验证书主机名、签发者、到期时间和状态；剩余 30 天以内标记为即将过期，过期、连接失败、链不受信任、链不完整或主机名不匹配标记为异常。
- 状态从正常变为即将过期、已过期或异常时发送通知。
- 监控会校验系统信任链，避免中间人用自签证书掩盖真实证书问题；管理员导入的内部 CA 与私有 CA 也会纳入信任链。

## 通知

### 内置渠道

- **邮件（SMTP）**：服务器、端口、用户名、密码、发件人，支持 SSL；收件人默认引用系统账户邮箱，可改为自定义收件人，保存后只按配置的收件人投递。
- 默认使用隐式 TLS（`smtp.ssl=true`）；关闭隐式 TLS 时，如果服务器不支持 STARTTLS，服务会拒绝发送，避免重置令牌等敏感邮件明文传输。

### 插件渠道

Gotify、ServerChan、ntfy、GoCQHTTP、PushDeer、Bark、Telegram、钉钉、企业微信机器人、企业微信应用、企业微信智能机器人、iGot、PushPlus、WePlus、WxPusher、WxPusher SPT、OpenILink、WPush、Synology Chat、飞书、PushMe、ChronoCat，以及通用自定义 Webhook。

除邮件外的渠道随主程序内置，可单独启用并发送测试消息；任务通知节点可选择具体渠道或全部已启用渠道，触发时机支持始终、仅成功、仅失败。

### 安全提醒

- 安全提醒与证书通知开关相互独立，关闭证书邮件不会让安全提醒一起失明；默认在密码/邮箱修改、TOTP 启停、通行密钥增删、密码重置、API 密钥变更和通知设置变更时发送。
- 默认在**新设备**登录成功时提醒，同一浏览器在免打扰窗口内只提醒一次（默认 30 天）；登录失败按账户维度聚合，默认 5 次 / 10 分钟触发，1 小时内最多提醒一次，未知邮箱按来源 IP 聚合。
- 邮件只发送到配置的收件人（最多 10 个），修改邮箱时会同时通知新旧邮箱，避免“换邮箱后重置密码”接管账户。
- 支持邮件和已启用的通知渠道，默认只走邮件；勾选插件渠道后，登录 IP、设备和账户邮箱会发送到第三方，请只选择可信渠道。通知正文不包含密码、TOTP、API 密钥或完整通行密钥标识。
- 可配置每小时提醒上限（默认 10 条），仅限制登录成功/失败等高频提醒，超出后只发送一条摘要；核心凭据变更、新设备登录、换邮箱、修改通知策略和测试提醒不受上限影响。「最近安全事件」可查看逐目标状态并导出 JSON，事件默认保留 90 天。
- 修改安全提醒策略会使用旧 SMTP 配置快照向旧收件人和旧渠道发送提醒；SMTP 未配置且只选择邮件渠道时提醒无法送达，界面会显示提示并按退避重试。

## 私有 CA

在「私有CA」中管理内部证书颁发机构。

### 生成

- 私钥类型：ECDSA P-256 / P-384、RSA 2048 / 4096，有效期按需要设置。
- 可生成根 CA，也可选择「中间/颁发 CA」，由已有私有 CA 签发下级 CA。
- 可配置完整 X.509 字段与 PKI 参数：主题（ST、L、OU、Email、自定义序列号）、扩展（路径长度、Key Usage、Extended Key Usage、SAN、Name Constraints）和基础设施（上级 CA、CRL 分发点、OCSP 响应地址、CA 颁发者地址、证书策略 OID 与 CPS 地址）。
- SKI、AKI、CA 基本约束由系统自动生成；选择上级 CA 时，有效期和路径长度会自动收敛到上级 CA 允许的范围。

### 导入

粘贴 PEM 格式的 CA 证书与私钥，系统会校验 CA 基本约束、证书签名用途、证书与私钥是否匹配。导入中间 CA 时可选择上级 CA，系统校验签名并建立层级关系。

### 下载与删除

可下载 CA 证书、私钥或完整证书链。列表接口不返回证书或私钥内容，私钥下载需要 `private_cas:key`；删除会移除服务端保存的 CA 记录与私钥，存在下级 CA 时需先删除下级 CA。

### 限制

- 私有 CA 私钥在写入数据库前加密，但不是 HSM/KMS 托管。
- 根 CA 和中间/颁发 CA 都可以在「证书申请」中作为签发机构，完整证书链随证书保存和部署。
- 证书默认有效期 365 天，且不超过 CA 的到期时间；CRL/OCSP 分发地址会写入新证书，但实际吊销列表和在线状态服务需要外部 PKI 基础设施提供。
- 存量证书不会自动获得 CDP/AIA 扩展，需要重新签发。

## ACME 服务端

内置 ACME v2 服务端默认开启，可把私有 CA 暴露给 certbot、lego、acme.sh 等客户端；未创建并启用端点时不会签发证书。

### 端点

- 每个端点绑定一个私有 CA，使用随机 URL slug，例如 `/acme/internal/directory`。
- 支持 EAB 开关、域名白名单、HTTP-01 / DNS-01 / TLS-ALPN-01 能力开关。
- 可独立监听端口，支持直接 TLS 与可选 mTLS；可配置证书有效期、订单限流和 HTTP-01 内网 CIDR 白名单。

### 协议能力

- 账户只保存公钥，不保存客户端私钥；支持账户密钥轮换（`keyChange`）。
- 支持 ARI（RFC 9773）续期建议：默认在证书到期前约 1/3 生命周期（最多 30 天）给出续期窗口，已撤销或过期证书返回过去窗口；支持 ARI `replaces` 字段并校验旧证书归属、标识重叠和重复替换。
- 支持 DNS 与 IP 标识；IP 标识仅允许 HTTP-01 / TLS-ALPN-01，并要求配置 IP 网段白名单。
- 新签发证书会写入 CRL Distribution Point 和 OCSP AIA 扩展，可通过 `/pki/{ca}/crl` 与 `/pki/{ca}/ocsp` 检查撤销状态；私有 CA 需具备 `cRLSign` 用途，启用端点时会校验。

### 诊断与清理

「ACME 诊断」页面可查看账户、订单、授权、挑战和证书状态；支持按端点、状态和时间清理失效订单与长期未使用账户，清理账户会删除其历史订单但不影响已签发证书。CRL/OCSP 按 CA 组织，停用 ACME 报名端点后仍应保持可达。

## 仪表盘与日志

### 仪表盘

界面支持简体中文与英文，可在设置中切换。首页汇总证书总数与即将过期/已过期数量、任务与监控状态、部署成功率、到期分布和签发趋势。

### 日志：操作日志

- 与系统日志同属「杂项 → 日志」页面，通过顶部页签切换，记录任务执行、证书签发、部署、通知、监控和设置变更。
- 支持按来源、级别、关键字和时间范围筛选，可开启自动刷新；关键字匹配原始存储内容与参数值，不匹配按当前语言渲染后的模板文案。
- 可导出 CSV 或 JSON，CSV 带 UTF-8 BOM；导出与列表使用同一组筛选条件，范围仅限最近 90 天，时间默认跟随浏览器时区。
- 可清空；启用归档时先写入 `data/archives/logs/` 再删除，清空动作本身会写入一条审计日志；该能力需要 `logs:write` 并在页面二次确认。

### 日志：系统日志

- 与操作日志同属「杂项 → 日志」页面，从进程日志中筛选后异步写入数据库。
- 可按级别、组件、关键字和时间范围筛选，导出 CSV/JSON 或清空；启用归档时先写入归档，清空操作会写入操作日志。
- 默认记录 `info` 及以上级别，保留 7 天或 20,000 行；HTTP 访问日志默认不写库，可在 `log.system` 中调整。

### 日志：归档

- 通过第三个页签进入；手动清空、90 天操作日志清理、系统日志保留天数/最大行数清理在删除前自动生成归档。
- 归档由 `*.ndjson.gz` 和 `*.manifest.json` 组成，保存原始字段、行数、ID/时间范围、触发原因、操作者、SHA-256 和文件大小。
- 支持按分类、原因、关键字和时间范围筛选，下载或删除归档；默认永久保留，可配置 `log.archive.retention_days`、`max_total_mb` 与 `quota_policy`。
- 归档失败会阻止删除，手动清空返回错误，自动清理等待下一轮重试；归档目录不进入默认 ZIP 备份，需单独转存，且不属于不可篡改审计。

## 能力边界

| 边界 | 说明 |
| --- | --- |
| 公共证书验证 | 仅 DNS-01；不支持 HTTP-01 向公共 CA 申请 |
| 多用户 | 单管理员账户，无多用户或 RBAC |
| 身份联邦 | 无 LDAP/OIDC/SAML/SCIM |
| 高可用 | 无内置集群/双活；SQLite 单写 |
| 私钥托管 | 本地加密存储，无 HSM/KMS |
| 监控输出 | 无 Prometheus 指标端点；提供日志和认证 API |
| 部署回滚 | 不自动回滚目标系统旧证书；需目标侧保留版本 |
